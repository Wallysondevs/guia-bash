Bash printf e echo

Todo script precisa mostrar alguma coisa: uma mensagem, um relatório, uma tabela. O echo serve para o simples. O printf serve para todo o resto: ele alinha colunas, controla casas decimais, completa com zeros e funciona igual em qualquer shell.

Você vai aprender
  • As armadilhas do echo (-e, -n, diferenças entre shells) e por que o printf é previsível.
  • Como o printf junta um formato com argumentos: %s, %d, %f, largura, alinhamento e zeros.
  • A regra de ouro: o formato se repete para os argumentos que sobram (tabelas com uma linha só).
  • %b, %q, printf -v e datas sem o comando date.
  • Por que printf "%.2f" 3.5 dá erro no Brasil, e o que é LC_NUMERIC.

O problema: o echo não é sempre igual

O echo (em inglês, "eco") repete o que recebe e pula uma linha no fim. Para uma mensagem, é perfeito:

$ echo "Olá, Ana"
Olá, Ana

Os problemas aparecem quando você quer algo a mais. O echo do Bash tem duas opções:

-n
Não pula linha no fim (no newline).
-e
Interpreta escapes como \t (tab) e \n (nova linha) — escapes. Sem ele, o Bash mostra a barra literalmente.
$ echo -n "sem quebra"; echo " <- veio colado"
sem quebra <- veio colado          « o -n não pulou linha
$ echo "a\tb"
a\tb                               « sem -e, o \t sai como texto
$ echo -e "a\tb"
a	b                                « com -e, virou um tab

Até aqui, tudo bem. Agora veja três armadilhas reais:

Armadilha 1: o valor da variável parece uma opção

$ texto="-n"
$ echo "$texto"
$                                  « não apareceu nada!

O echo recebeu -n e achou que era a opção, não o texto. Isso acontece com qualquer valor que comece com -n, -e ou -E, como um nome de arquivo ou uma linha lida de um arquivo.

Armadilha 2: outro shell, outro comportamento

Muitos sistemas usam o dash como sh (Debian e Ubuntu, por exemplo). O echo dele não conhece o -e e interpreta os escapes sempre:

$ sh -c 'echo -e "a\tb"'
-e a	b                             « o "-e" foi impresso como texto
$ sh -c 'echo "a\tb"'
a	b                                « e o \t virou tab sem pedir

Ou seja, o mesmo echo dá resultados diferentes no Bash e no sh. Até dentro do Bash isso muda: a opção shopt -s xpg_echo faz o echo do Bash interpretar escapes sem -e.

A solução: printf

O printf (print formatted, "imprimir formatado") vem da linguagem C e é definido pelo padrão POSIX. Ele faz sempre a mesma coisa, em qualquer shell:

$ printf "Olá, Ana"
Olá, Ana$                          « sem \n, o prompt fica colado
$ printf "Olá, Ana\n"
Olá, Ana

Repare na primeira linha: o printf não pula linha sozinho. Você coloca o \n onde quiser. Isso parece trabalho a mais, mas é justamente o que dá controle.

Regra prática

Use echo para mensagens fixas, que você mesmo escreveu (echo "Backup concluído"). Use printf sempre que houver escapes, falta de quebra de linha, números formatados ou o conteúdo de uma variável que você não controla.

Formato e argumentos

O printf recebe primeiro um formato: um texto-modelo com "buracos". Depois vêm os argumentos, que preenchem os buracos em ordem.

printf "FORMATO" argumento1 argumento2 …
printf
O comando (é interno do Bash: type printf diz "printf é um comando interno do shell").
"%s tem %d anos\n"
O formato. %s é um buraco para texto (string), %d é um buraco para número inteiro (decimal), \n pula linha. O resto sai como está.
Ana
Primeiro argumento: vai para o primeiro buraco (%s).
29
Segundo argumento: vai para o segundo buraco (%d).
$ printf "%s tem %d anos\n" Ana 29
Ana tem 29 anos

Cada % seguido de uma letra é um especificador (ou "conversão"). Os mais usados:

EspecificadorRecebeExemploResultado
%stextoprintf "%s\n" AnaAna
%dnúmero inteiroprintf "%d\n" 4242
%fnúmero com casas decimaisprintf "%.2f\n" 3,53,50
%x / %ointeiro, mostrado em hexadecimal / octalprintf "%x %o\n" 255 255ff 377
%enúmero em notação científicaprintf "%e\n" 1234,51,234500e+03
%csó o primeiro caractereprintf "%c\n" AnaA
%%nada: imprime um %printf "100%%\n"100%

E os escapes que o formato entende (sem precisar de -e): \n (nova linha), \t (tab), \\ (uma barra), \" (aspas).

$ printf "%d em hexa: %x, em octal: %o\n" 255 255 255
255 em hexa: ff, em octal: 377
$ printf "100%%\n"
100%
Sempre coloque o formato entre aspas

Sem aspas, o shell come a barra antes de o printf ver o formato: printf [%s]\n Ana mostra [Ana]n e não pula linha. Prefira aspas simples ('%s\n') ou duplas; com duplas, lembre que $ dentro do formato é trocado pelo shell.

Largura, alinhamento e zeros

Entre o % e a letra você pode pôr um número: a largura mínima do campo. Os colchetes abaixo são só para você enxergar os espaços.

$ printf "[%5s]\n" Ana
[  Ana]                            « 5 posições, alinhado à direita
$ printf "[%-10s]\n" Ana
[Ana       ]                       « o - alinha à esquerda, 10 posições
$ printf "[%05d]\n" 42
[00042]                            « o 0 completa com zeros
$ printf '%.3s\n' Bananada
Ban                                « em texto, .3 corta em 3 letras
%5s
Texto em um campo de pelo menos 5 posições. Sobrou espaço? Ele vai para a esquerda (alinha à direita, como números numa planilha).
%-10s
O - inverte: texto à esquerda, espaços à direita. É o certo para nomes.
%05d
Inteiro em 5 posições, completando com 0 em vez de espaço. Ótimo para numerar arquivos: foto-007.jpg.
%.2f
Número com exatamente 2 casas depois da vírgula (arredonda).
%8.2f
As duas coisas juntas: 8 posições no total, 2 casas decimais.

Se o texto for maior que a largura, nada é cortado: a largura é um mínimo. Para numerar com zeros, junte com as chaves:

$ printf "%03d\n" {8..11}
008
009
010
011

A regra de ouro: o formato se repete

Quando há mais argumentos que buracos, o printf usa o formato de novo com os que sobraram, até acabarem. Isso é diferente de quase todas as outras linguagens e é muito útil:

$ printf "Nome: %s\n" Ana Bruno Carla
Nome: Ana                          « 1ª volta do formato
Nome: Bruno                        « 2ª volta
Nome: Carla                        « 3ª volta
$ printf "%s=%s\n" a 1 b 2 c
a=1
b=2
c=                                 « faltou argumento: %s vazio (%d viraria 0)

Com isso, uma lista vira "um por linha" sem laço nenhum: printf '%s\n' *.txt lista os arquivos de texto, um por linha, mesmo os que têm espaço no nome.

Tabela alinhada com o alunos.csv

Vamos juntar tudo. O arquivo Documentos/alunos.csv da Ana tem uma linha de cabeçalho e cinco alunos, separados por vírgula. Este script mostra o arquivo como uma tabela de verdade. A leitura linha a linha com while read é explicada em Ler Arquivos Linha a Linha; aqui o foco é o printf.

#!/usr/bin/env bash
# Mostra o alunos.csv como uma tabela alinhada
printf "%-8s %5s  %-13s %4s\n" NOME IDADE CIDADE NOTA
while IFS=, read -r nome idade cidade nota; do
  printf "%-8s %5d  %-13s %4s\n" "$nome" "$idade" "$cidade" "$nota"
done < <(tail -n +2 Documentos/alunos.csv)

$ bash tabela.sh
NOME     IDADE  CIDADE        NOTA
Ana         29  Recife         9.5
Bruno       34  Curitiba       7.0
Carla       22  Salvador       8.5
Diego       41  Manaus         6.0
Elisa       27  Porto Alegre  10.0
LinhaO que faz
3O cabeçalho usa as mesmas larguras das linhas de dados. É isso que faz as colunas baterem.
4Lê cada linha, separando os campos na vírgula, em quatro variáveis.
5%-8s: nome à esquerda em 8 posições; %5d: idade à direita em 5; %-13s: cidade à esquerda em 13 ("Porto Alegre" tem 12); %4s: nota à direita em 4, como texto (já vamos ver por quê).
6tail -n +2 entrega o arquivo a partir da linha 2, pulando o cabeçalho.

Repare nas aspas em "$cidade": sem elas, "Porto Alegre" viraria dois argumentos, e a regra de ouro faria o printf começar uma linha nova no meio da tabela.

Missão: o script abaixo mostra nome e cidade, mas as colunas ficam tortas. Mude o formato do printf para que o nome ocupe 10 posições, alinhado à esquerda. Rode e veja as cidades se alinharem.

#!/usr/bin/env bash
tail -n +2 Documentos/alunos.csv | while IFS=, read -r nome idade cidade nota; do
  printf "%s %s\n" "$nome" "$cidade"
done

#!/usr/bin/env bash
tail -n +2 Documentos/alunos.csv | while IFS=, read -r nome idade cidade nota; do
  printf "%-10s%s\n" "$nome" "$cidade"
done

Números com vírgula: o printf no Brasil

Tente imprimir a nota da Ana com uma casa decimal num sistema em português:

$ printf "%.2f\n" 3.5
bash: printf: 3.5: número inválido
3,00                               « e ainda jogou fora o ,5!
$ echo $?
1
$ printf "%.2f\n" 3,5
3,50                               « com vírgula, funciona

O que aconteceu? O printf do Bash lê e escreve números do jeito do idioma do sistema (o locale). Com LANG=pt_BR.UTF-8, o separador decimal é a vírgula. Então 3.5 não é um número válido: o Bash lê o que consegue (3), avisa o erro e devolve código 1. A saída também sai com vírgula.

Quem decide o formato dos números é a variável LC_NUMERIC (locale category numeric). A hierarquia é:

VariávelPapel
LC_ALLSe estiver definida, vence todas as outras. Use só para testes.
LC_NUMERICSó o formato dos números (separador decimal e de milhar).
LANGO padrão para tudo o que não foi definido acima. Na máquina da Ana: pt_BR.UTF-8.

Para um comando só usar o ponto, mude LC_NUMERIC na frente dele. O locale C é o "neutro", em inglês, com ponto:

$ LC_NUMERIC=C printf "%.2f\n" 3.5
3.50
$ LC_ALL=pt_BR.UTF-8 LC_NUMERIC=C printf "%.2f\n" 3.5
bash: printf: 3.5: número inválido   « LC_ALL vence o LC_NUMERIC
3,00

Num script que lê números de arquivos (como as notas do CSV, que usam ponto), coloque no começo:

#!/usr/bin/env bash
export LC_NUMERIC=C      # números com ponto, em qualquer computador
printf "%.1f\n" 9.5

O efeito colateral é a saída também sair com ponto. Se você quiser ler com ponto e mostrar com vírgula, troque o caractere com uma expansão de parâmetro: printf "%.1f\n" "${nota/./,}". Por isso a tabela de cima usa %4s para a nota: como texto, ela sai exatamente como está no arquivo.

Bônus do locale: milhar com ponto

A flag ' agrupa os milhares do jeito do idioma: printf "%'d\n" 1234567 mostra 1.234.567 em pt_BR.

Outro detalhe: o Bash só sabe fazer contas com inteiros (veja Contas). O printf formata números com casas decimais, mas não calcula com eles.

%b e %q: escapes e aspas

Os escapes do formato são interpretados, mas os dos argumentos não. Para interpretar escapes vindos de uma variável, use %b (de backslash):

$ printf "%s\n" "a\tb"
a\tb                               « %s mostra o texto como ele é
$ printf "%b\n" "a\tb"
a	b                                « %b interpreta o \t, como o echo -e

O %q (de quote) faz o contrário: mostra o texto com as aspas e barras necessárias para colá-lo de volta no shell sem estragar. É ótimo para mensagens de depuração e para gerar comandos:

$ printf "%q\n" "nome com espaço" 'aspas"duplas' 'R$ 10'
nome\ com\ espaço
aspas\"duplas
R\$\ 10

printf -v: guardar numa variável

Em vez de mostrar na tela, o printf -v NOME grava o resultado na variável NOME.

-v linha
"Guarde o resultado na variável linha" (variable). É uma opção só do Bash.
"%s-%s"
O formato de sempre.
Ana 29
Os argumentos.
$ printf -v linha "%s-%s" Ana 29
$                                  « nada na tela: foi para a variável
$ echo "$linha"
Ana-29

É o mesmo que linha=$(printf "%s-%s" Ana 29), só que mais rápido (não cria um subshell) e preserva quebras de linha no fim. Em funções, é uma das formas de "devolver" um valor (veja local, return e Saída).

Missão: use printf -v para criar a variável codigo com o valor A-007, a partir do número 7 (com o formato completando os zeros). Confira com echo "$codigo".

Datas sem o date: %(…)T

O printf do Bash formata datas com %(FORMATO)T. Dentro dos parênteses vão os mesmos códigos do comando date: %d dia, %m mês, %Y ano, %H:%M hora e minuto, %A dia da semana.

%(%d/%m/%Y)T
"Mostre uma data neste formato" (T de time).
-1
O argumento é um instante em segundos desde 1970. -1 (ou nenhum argumento) quer dizer "agora".
$ printf '%(%d/%m/%Y)T\n' -1
15/10/2026
$ printf 'Hoje é %(%A)T\n' -1
Hoje é quinta                      « o nome do dia vem em português
$ printf -v hoje '%(%Y-%m-%d)T' -1; echo "backup-$hoje.tar"
backup-2026-10-15.tar

A data mostrada é a do momento em que você roda (aqui, 15/10/2026). Use aspas simples: dentro de aspas duplas o %( funciona, mas é fácil esquecer um $ e confundir com $( ). A vantagem sobre $(date +%F) é não rodar um programa externo, o que conta dentro de laços.

Quando não funciona

"número inválido" 
$ printf "%d\n" abc
bash: printf: abc: número inválido
0
$ printf "%d\n" 3.7
bash: printf: 3.7: número inválido
3

O que aconteceu: %d só aceita inteiros. Com texto, o Bash imprime 0; com casas decimais, imprime o que leu até o ponto. Nos dois casos o código de saída é 1. Com %f, o mesmo erro aparece quando o número usa ponto e o sistema está em português (veja a seção da vírgula).

Como resolver: confira o valor antes ([[ $x =~ ^[0-9]+$ ]], veja Regex), use %s se for só para mostrar, ou LC_NUMERIC=C para números com ponto.

"opção inválida" quando o formato começa com - 
$ printf "-n\n"
bash: printf: -n: opção inválida
printf: uso: printf [-v var] formato [argumentos]

O que aconteceu: o printf achou que -n era uma opção dele.

Como resolver: -- avisa que as opções acabaram: printf -- "-n\n". Ou não comece o formato com o texto: printf '%s\n' "-n".

Tudo saiu numa linha só (ou o prompt grudou no texto) 
$ printf "%s" Ana Bruno Carla
AnaBrunoCarla$

O que aconteceu: o printf não pula linha sozinho, e o formato %s se repetiu três vezes sem nenhum separador.

Como resolver: coloque o \n no formato: printf "%s\n" Ana Bruno Carla.

A tabela "quebrou" no meio 
$ cidade="Porto Alegre"
$ printf "%-8s|%s\n" Elisa $cidade
Elisa   |Porto
Alegre  |

O que aconteceu: sem aspas, $cidade virou dois argumentos (Porto e Alegre), e o formato foi repetido para a sobra.

Como resolver: aspas duplas em toda variável: "$cidade".

O echo não mostrou nada

Se a variável vale -n, -e ou -E, o echo a trata como opção. Troque por printf '%s\n' "$variavel".

Resumo

  • echo é bom para mensagens fixas; -n e -e mudam de shell para shell, e um valor como -n some.
  • printf "FORMATO" args…: %s texto, %d inteiro, %.2f decimal, %% um por cento; o \n é você quem põe.
  • Largura e alinhamento: %5s (direita), %-10s (esquerda), %05d (zeros). O formato se repete para os argumentos que sobram.
  • %b interpreta escapes, %q põe aspas, printf -v var grava numa variável, %(%d/%m/%Y)T mostra datas.
  • Em pt_BR, decimais usam vírgula: use LC_NUMERIC=C para ler números com ponto.
