Bash Lendo o Prompt

O prompt é o texto que o Bash mostra antes do cursor, como ana@notebook:~$. Ele quer dizer "pode digitar", mas também conta quem você é, em que máquina está e em que pasta. Saber lê-lo evita os erros mais comuns de quem começa: rodar um comando na pasta errada, como o usuário errado, ou ficar preso num > sem saber por quê.

Você vai aprender
  • O que significa cada pedaço de ana@notebook:~$.
  • A diferença entre $ e # (usuário comum × root).
  • Como o prompt acompanha o cd e o que é o ~.
  • O prompt secundário > (PS2): quando aparece e como sair dele.

O prompt, parte por parte

Abra um terminal. Antes de você digitar qualquer coisa, aparece:

$

No guia, o prompt é desenhado como na janela acima: ana@notebook:~$. Leia da esquerda para a direita:

ana
O usuário: quem está usando este shell. É a resposta do whoami.
@notebook
A máquina. O @ se lê "em": "ana em notebook". É a resposta do hostname.
:~
Os dois-pontos separam; depois vem a pasta atual. ~ (til) é a pasta pessoal, /home/ana.
$
O fim do prompt: "usuário comum, pode digitar". Vira # para o administrador (root).

Depois do $ vem um espaço e o cursor. Tudo o que você digitar a partir dali é o comando.

O prompt não faz parte do comando

Ao copiar um comando de um tutorial, não copie o $ nem o ana@notebook:~$. Se você digitar $ ls, o Bash tenta rodar um comando chamado $. Os botões "copiar" deste guia já copiam só o comando.

De onde vem esse texto?

O prompt é montado pelo Bash a partir de uma variável chamada PS1 (de prompt string 1, "texto do prompt 1"). Na Ana, ela é definida no arquivo .bashrc:

$ echo "$PS1"
\u@\h:\w\$                         « o "molde" do prompt
CódigoViraOrigem do nome
\uanauser, usuário
@ e :eles mesmostexto fixo
\hnotebookhost, máquina
\w~, ~/Documentos…working directory, pasta atual
\$$ ou ## se você for root

Cada sistema monta o seu prompt de um jeito: o do Fedora é [ana@notebook ~]$, o do macOS com zsh é ana@MacBook ~ %. As partes são as mesmas, em outra ordem. Mudar cores e conteúdo do prompt é o assunto de Personalizar o Prompt (PS1).

O prompt muda com o cd

A parte entre : e $ acompanha a pasta onde você está. Cada cd ("mudar de pasta") muda o prompt seguinte:

$ cd Documentos
$ cd projetos/site
$ cd /etc
$ cd /
$ cd "Área de trabalho"
$ cd

Leia o prompt de cada linha acima, de cima para baixo:

PromptOnde a Ana está
ana@notebook:~$/home/ana, a pasta pessoal
ana@notebook:~/Documentos$/home/ana/Documentos
ana@notebook:~/Documentos/projetos/site$Duas pastas mais fundo
ana@notebook:/etc$/etc, fora da pasta pessoal: o caminho aparece inteiro, sem ~
ana@notebook:/$/, a raiz de tudo
ana@notebook:~/Área de trabalho$Uma pasta com espaços: o prompt mostra sem aspas

O último cd, sem nada, levou de volta à pasta pessoal, e o prompt voltou a ~.

O til ~

O ~ é um apelido curto para a sua pasta pessoal. Ele também funciona dentro dos comandos: o Bash troca ~ pelo caminho antes de executar.

$ echo ~
/home/ana
$ echo $HOME
/home/ana                          « a variável HOME guarda o mesmo caminho

Mais sobre caminhos e o cd em Navegar (pwd, cd).

Missão: entre na pasta Documentos/projetos e observe como o prompt mudou. Confira com pwd.

$ ou #: usuário comum ou root

O último caractere do prompt é um aviso importante. $ quer dizer usuário comum: você só pode mexer nos seus arquivos. # quer dizer que você é o root, o administrador, que pode mexer em tudo, inclusive apagar o sistema. Exemplo ilustrativo (o simulador não tem sudo):

$ sudo -i
[sudo] senha para ana:             « a senha não aparece enquanto você digita
#> whoami
root
#> exit
exit                               « volta a ser a ana, com o prompt terminando em $

Repare como o prompt muda: root@notebook:~#. O nome é outro, a pasta pessoal é outra (~ agora é /root) e o fim é #. Quando vir #, desacelere e leia o comando duas vezes antes de apertar Enter.

Tutoriais usam $ e # do mesmo jeito

Na internet, um comando escrito como # apt update quer dizer "rode como root" (o # não é para digitar). E $ ls quer dizer "rode como usuário comum". Cuidado: dentro de um script, # no começo da linha é um comentário.

O prompt secundário: >

Às vezes, depois do Enter, em vez do resultado aparece só um >. Isso não é um erro: é o prompt secundário, guardado na variável PS2. O Bash está dizendo: "o comando ainda não terminou, continue".

$ echo "$PS2"
>                                  « um sinal de maior e um espaço

Ele aparece quando a linha está incompleta. Os casos mais comuns:

Aspas abertas

$ echo "Olá
> mundo"
Olá
mundo

A aspa aberta na primeira linha só fechou na segunda. Tudo entre as aspas, inclusive a quebra de linha, virou um argumento só.

Um comando que pede continuação

Um | no fim da linha, ou um for sem done, também deixam o comando "em aberto":

$ cat frutas.txt |
> sort -u
banana
laranja
maçã
uva
$ for fruta in banana uva
> do
>   echo "Eu gosto de $fruta"
> done
Eu gosto de banana
Eu gosto de uva

No for, o Bash só executa depois do done; até lá, cada Enter mostra um novo >. Escrever assim, em várias linhas, é útil para comandos longos. O for tem aula própria: for. O | está em Pipes.

A barra invertida no fim

Como você viu em Anatomia de um Comando, uma \ no fim da linha pede continuação de propósito.

O que deixou a linha incompletaExemploComo completar
Aspa dupla ou simples abertaecho "OláFeche a aspa
|, && ou || no fimcat frutas.txt |Digite o próximo comando
\ no fimwc -l \Continue o comando
Bloco sem fecharfor … do sem done, if sem fi, { sem }Digite o fechamento

Missão: digite um for em várias linhas, apertando Enter no fim de cada uma: for fruta in banana uva, depois do, depois echo $fruta, depois done. Repare no > em cada linha de continuação.

Preso no >: como sair

O problema é quando você não queria continuar. O caso clássico é o apóstrofo do português: d'água abre uma aspa simples que nunca fecha.

$ echo Copo d'água
> e gelo                          « o Bash ainda espera a aspa fechar
> ^C                              « Ctrl+C: desiste do comando
$ echo $?
130                                « 130 = interrompido pelo Ctrl+C

Aperte Ctrl+C: o comando inteiro é descartado, nada é executado, e o prompt normal volta. O código 130 registra que a linha foi interrompida. Depois, digite de novo do jeito certo:

$ echo "Copo d'água"
Copo d'água                        « a aspa simples dentro das duplas é só uma letra
$ echo Copo d\'água
Copo d'água                        « ou a barra invertida antes do apóstrofo
Forma de sairO que aconteceUse quando…
Completar (fechar a aspa, digitar done…)O comando rodaVocê queria mesmo um comando de várias linhas.
Ctrl+CDescarta tudo, volta ao prompt $Foi engano. É a forma mais segura.
Ctrl+DAvisa "acabou o texto": o Bash dá erro de sintaxe e voltaEvite: fora do >, ele fecha o terminal.

As aspas têm várias outras armadilhas e soluções: Aspas e Escapes.

Quando não funciona

O terminal "não responde": só aparece > 
$ echo "Relatório de vendas
>
>

O que aconteceu: uma aspa (ou um bloco) ficou aberta. O Bash não travou: está esperando o fim do comando.

Como resolver: Ctrl+C e digite de novo. Use a seta ↑ para trazer a linha de volta e corrigir.

"encontrado EOF inesperado" 
$ echo 'it's
>
bash: encontrado EOF inesperado enquanto procurava por `'' correspondente

(No terminal, a mensagem aparece na mesma linha do >, logo depois dele.)

O que aconteceu: no >, alguém apertou Ctrl+D (fim do texto, em inglês end of file, EOF). O Bash procurava a aspa que fecha e encontrou o fim. Em scripts, o mesmo erro aparece quando falta fechar uma aspa no arquivo, com o nome do script e a linha.

Como resolver: feche a aspa. Para um apóstrofo, use aspas duplas em volta ("it's").

Rodei o comando na pasta errada

O que aconteceu: o prompt mostrava outra pasta, e o comando trabalhou nela. Um rm * no lugar errado é o pior caso.

Como evitar: olhe a parte entre : e $ antes de comandos que mudam arquivos, ou confira com pwd.

O meu prompt é diferente do guia

O que aconteceu: cada sistema (e cada pessoa) configura o PS1 de um jeito. Pode ter cores, hora, o ramo do git, ou ser só $ (no sh) ou % (no zsh).

Como resolver: nada a resolver; identifique as mesmas partes (usuário, máquina, pasta, $). Se o prompt for % ou estiver muito diferente, confira se você está no Bash (Terminal e Shell).

Resumo

  • ana@notebook:~$ = usuário @ máquina : pasta, e $ (comum) ou # (root).
  • A pasta do prompt muda a cada cd; ~ é a pasta pessoal.
  • O prompt vem da variável PS1; personalizar é assunto de PS1.
  • > (PS2) quer dizer "comando incompleto": aspa aberta, | no fim, \, bloco sem fechar.
  • Preso no >? Ctrl+C e redigite.
