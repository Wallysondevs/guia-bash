Projeto Uma Ferramenta de Verdade

Até aqui, nossos scripts eram "./algo.sh e pronto". Agora vamos escrever um comando no sentido completo: você digita tarefas add Comprar café de qualquer pasta, ele tem ajuda (-h), versão (-V), subcomandos, mensagens de erro claras, códigos de saída documentados, passa no ShellCheck e completa com Tab. É a mesma estrutura de ferramentas como git e apt, em umas 120 linhas de Bash.

Ao terminar você terá
  • O comando tarefas, com add, list, done e rm, guardando tudo em ~/.local/share/tarefas/tarefas.txt.
  • Opções globais com getopts (-f ARQUIVO, -h, -V) e uma opção de subcomando (list -a).
  • Códigos de saída: 0 = ok, 1 = erro, 2 = uso errado.
  • O script instalado em ~/.local/bin e um arquivo de completar para o Tab.

Antes de programar: o desenho da ferramenta

Ferramenta boa começa pela interface: como a pessoa vai usar. Escrevemos o uso antes do código:

$ tarefas add Comprar café          « acrescenta
$ tarefas list                      « mostra as pendentes, numeradas
$ tarefas done 2                    « marca a 2 como feita
$ tarefas rm 1                      « apaga a 1
$ tarefas -f compras.txt list       « outra lista
$ tarefas -h                        « ajuda

E o formato do arquivo: texto puro, uma tarefa por linha, com [ ] (pendente) ou [x] (feita) na frente. O número da tarefa é o número da linha. Texto puro tem vantagens enormes: dá para abrir no editor, versionar com git, sincronizar, e ler com grep e sed.

[ ] Comprar café
[x] Estudar getopts
[ ] Ligar para o João

A pasta ~/.local/share é o lugar padrão (a especificação XDG) para dados de programas do usuário. Se a variável XDG_DATA_HOME existir, ela manda.

  3. Etapa 3 — done e rm, com o número validado

    O que vamos fazer e por quê: estes dois comandos recebem um número, e números vindos do usuário precisam ser conferidos (lembre do jogo da adivinhação). Uma função faz a checagem para os dois. Para mudar uma linha do arquivo no lugar, usamos o sed -i. Veja grep, sed, awk e cia.

    # confere que $1 é o número de uma tarefa que existe
validar_numero() {
  local n=$1 total
  [[ $n =~ ^[1-9][0-9]*$ ]] || uso_errado "número de tarefa inválido: '$n'"
  total=$(wc -l < "$arquivo")
  (( n <= total )) || falhar "não existe a tarefa $n (a lista tem $total)"
}

cmd_done() {
  (( $# == 1 )) || uso_errado "done: informe um número (ex.: $PROG done 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  [[ $linha == '[ ] '* ]] || falhar "a tarefa $1 já estava feita"
  sed -i "${1}s/^\[ \]/[x]/" "$arquivo"
  echo "Feito: ${linha#'[ ] '}"
}

cmd_rm() {
  (( $# == 1 )) || uso_errado "rm: informe um número (ex.: $PROG rm 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  sed -i "${1}d" "$arquivo"
  echo "Apagada: ${linha:4}"
}

  4. Etapa 4 — Opções com getopts: -f, -h, -V e list -a

    O que vamos fazer e por quê: opções que valem para qualquer comando (-f ARQUIVO) vêm antes do subcomando, como em git -C pasta status. Opções de um subcomando vêm depois dele (list -a). O getopts cuida das duas: uma vez no main e outra dentro do cmd_list. Veja Opções com getopts.

    readonly VERSAO=1.0          # no começo do arquivo

main() {
  local opt
  while getopts ':f:hV' opt; do
    case $opt in
      f)  arquivo=$OPTARG ;;
      h)  uso; exit 0 ;;
      V)  echo "$PROG $VERSAO"; exit 0 ;;
      :)  uso_errado "a opção -$OPTARG precisa de um valor" ;;
      \?) uso_errado "opção inválida: -$OPTARG" ;;
    esac
  done
  shift $(( OPTIND - 1 ))
  (( $# > 0 )) || { uso >&2; exit 2; }

  mkdir -p -- "$(dirname -- "$arquivo")"
  touch -- "$arquivo"

  local comando=$1
  shift
  case $comando in
    add)       cmd_add "$@" ;;
    list|ls)   cmd_list "$@" ;;
    done)      cmd_done "$@" ;;
    rm)        cmd_rm "$@" ;;
    help)      uso ;;
    *)         uso_errado "comando desconhecido: '$comando'" ;;
  esac
}

cmd_list() {
  local todas=0 opt OPTIND=1
  while getopts ':a' opt; do
    case $opt in
      a) todas=1 ;;
      *) uso_errado "list: opção inválida: -$OPTARG" ;;
    esac
  done
  local n=0 pendentes=0 linha
  while IFS= read -r linha; do
    n=$(( n + 1 ))
    if [[ $linha == '[ ] '* ]]; then
      pendentes=$(( pendentes + 1 ))
      printf '%3d  [ ] %s\n' "$n" "${linha#'[ ] '}"
    elif (( todas )); then
      printf '%3d  %s\n' "$n" "$linha"
    fi
  done < "$arquivo"
  if (( pendentes == 0 && ! todas )); then
    echo "Nenhuma tarefa pendente."
  fi
}

    Aceita -f com valor (o : depois do f), -h e -V. O : do começo é o "modo silencioso": o getopts não escreve mensagens próprias e nos avisa dos problemas pelo próprio opt.
    :)
    No modo silencioso, opt vale : quando faltou o valor de uma opção (tarefas -f) e OPTARG diz qual.
    \?)
    E vale ? para uma opção desconhecida. A barra impede o ? de ser um curinga no case.
    shift $(( OPTIND - 1 ))

    O Bash deixa você ensinar a ele o que completar depois de um comando: uma função recebe a linha já quebrada em palavras e devolve as sugestões. Os detalhes estão em Completar Programável. O nosso arquivo:

    # completar para o comando tarefas — carregue com: source tarefas-completar.bash
_tarefas() {
  local atual=${COMP_WORDS[COMP_CWORD]}
  case $COMP_CWORD in
    1)
      mapfile -t COMPREPLY < <(compgen -W 'add list done rm help' -- "$atual")
      ;;
    2)
      case ${COMP_WORDS[1]} in
        done|rm) mapfile -t COMPREPLY < <(compgen -W "$(tarefas list | awk '{print $1}')" -- "$atual") ;;
        list)    mapfile -t COMPREPLY < <(compgen -W '-a' -- "$atual") ;;
      esac
      ;;
  esac
}

O comando completo

Todas as etapas juntas, ShellCheck limpo:

#!/usr/bin/env bash
# tarefas — uma lista de tarefas guardada num arquivo de texto.
# Licença: domínio público. Requer bash 4.0+.
set -euo pipefail

readonly VERSAO=1.0
readonly PROG=${0##*/}
arquivo=${TAREFAS_ARQUIVO:-${XDG_DATA_HOME:-$HOME/.local/share}/tarefas/tarefas.txt}

uso() {
  cat <<FIM
Uso: $PROG [-f ARQUIVO] COMANDO [ARGUMENTOS]

Comandos:
  add TEXTO...   acrescenta uma tarefa
  list [-a]      mostra as tarefas pendentes (-a: todas)
  done N         marca a tarefa N como feita
  rm N           apaga a tarefa N

Opções:
  -f ARQUIVO     usa outro arquivo (padrão: $arquivo)
  -h             mostra esta ajuda
  -V             mostra a versão

Códigos de saída: 0 = ok, 1 = erro, 2 = uso errado.
FIM
}

erro()       { printf '%s: %s\n' "$PROG" "$*" >&2; }
falhar()     { erro "$*"; exit 1; }
uso_errado() { erro "$*"; echo "Tente '$PROG -h'." >&2; exit 2; }

# confere que $1 é o número de uma tarefa que existe
validar_numero() {
  local n=$1 total
  [[ $n =~ ^[1-9][0-9]*$ ]] || uso_errado "número de tarefa inválido: '$n'"
  total=$(wc -l < "$arquivo")
  (( n <= total )) || falhar "não existe a tarefa $n (a lista tem $total)"
}

cmd_add() {
  (( $# > 0 )) || uso_errado "add: falta o texto da tarefa"
  printf '[ ] %s\n' "$*" >> "$arquivo"
  echo "Tarefa $(wc -l < "$arquivo") adicionada: $*"
}

cmd_list() {
  local todas=0 opt OPTIND=1
  while getopts ':a' opt; do
    case $opt in
      a) todas=1 ;;
      *) uso_errado "list: opção inválida: -$OPTARG" ;;
    esac
  done
  local n=0 pendentes=0 linha
  while IFS= read -r linha; do
    n=$(( n + 1 ))
    if [[ $linha == '[ ] '* ]]; then
      pendentes=$(( pendentes + 1 ))
      printf '%3d  [ ] %s\n' "$n" "${linha#'[ ] '}"
    elif (( todas )); then
      printf '%3d  %s\n' "$n" "$linha"
    fi
  done < "$arquivo"
  if (( pendentes == 0 && ! todas )); then
    echo "Nenhuma tarefa pendente."
  fi
}

cmd_done() {
  (( $# == 1 )) || uso_errado "done: informe um número (ex.: $PROG done 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  [[ $linha == '[ ] '* ]] || falhar "a tarefa $1 já estava feita"
  sed -i "${1}s/^\[ \]/[x]/" "$arquivo"
  echo "Feito: ${linha#'[ ] '}"
}

cmd_rm() {
  (( $# == 1 )) || uso_errado "rm: informe um número (ex.: $PROG rm 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  sed -i "${1}d" "$arquivo"
  echo "Apagada: ${linha:4}"
}

main() {
  local opt
  while getopts ':f:hV' opt; do
    case $opt in
      f)  arquivo=$OPTARG ;;
      h)  uso; exit 0 ;;
      V)  echo "$PROG $VERSAO"; exit 0 ;;
      :)  uso_errado "a opção -$OPTARG precisa de um valor" ;;
      \?) uso_errado "opção inválida: -$OPTARG" ;;
    esac
  done
  shift $(( OPTIND - 1 ))
  (( $# > 0 )) || { uso >&2; exit 2; }

  mkdir -p -- "$(dirname -- "$arquivo")"
  touch -- "$arquivo"

  local comando=$1
  shift
  case $comando in
    add)       cmd_add "$@" ;;
    list|ls)   cmd_list "$@" ;;
    done)      cmd_done "$@" ;;
    rm)        cmd_rm "$@" ;;
    help)      uso ;;
    *)         uso_errado "comando desconhecido: '$comando'" ;;
  esac
}

main "$@"

Quando não funciona

tarefas: comando não encontrado depois de instalar

O que aconteceu: o ~/.local/bin não está no PATH (a pasta foi criada depois do login, ou sua distribuição não a inclui). Como confirmar: echo "$PATH" | tr ':' '\n' | grep local. Como resolver: saia e entre de novo; se não resolver, acrescente PATH="$HOME/.local/bin:$PATH" ao ~/.bashrc. Veja PATH.

bash: /home/ana/.local/bin/tarefas: Permissão negada

O que aconteceu: o arquivo foi copiado sem permissão de execução. Como resolver: chmod +x ~/.local/bin/tarefas. Veja Formas de Executar.

env: ‘bash\r’: Arquivo ou diretório inexistente 
$ ./tarefas
env: ‘bash\r’: Arquivo ou diretório inexistente
env: usa -[v]S para passar opções em linhas shebang

O que aconteceu: o arquivo foi salvo com finais de linha do Windows (CRLF), e o \r grudou no nome do interpretador. Como resolver: sed -i 's/\r$//' tarefas (ou dos2unix tarefas).

O list -a é ignorado ou dá "opção inválida"

O que aconteceu: faltou o local OPTIND=1 no cmd_list, e o segundo getopts começou a ler de onde o primeiro parou. Como confirmar: bash -x tarefas list -a. Veja Depurar.

O Tab não completa nada

O que aconteceu: o arquivo de completar não foi carregado neste terminal. Como confirmar: complete -p tarefas responde bash: complete: tarefas: nenhuma especificação de completação (código 1). Como resolver: source tarefas-completar.bash, e coloque-o no lugar certo para os próximos terminais.
