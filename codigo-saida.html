Bash Código de Saída ($?)

Todo comando, quando termina, devolve um número ao shell: o código de saída. Ele não aparece na tela, mas diz se o comando deu certo (0) ou errado (qualquer outro número). É com esse número que o Bash decide o que fazer depois, nos operadores && e ||, no if e nos seus scripts.

Você vai aprender
  • Como ver o código de saída com $?, e por que ele muda a cada comando.
  • O que significam os códigos 0, 1, 2, 126, 127 e 128+N (como o 130 do Ctrl+C).
  • Como usar comandos "silenciosos" (grep -q, test, pgrep) que respondem só pelo código.
  • true, false, o ! que inverte o resultado e o exit N dos scripts.

O problema: "não apareceu nada… deu certo?"

Muitos comandos não mostram nada quando dão certo. Veja a Ana procurando a palavra banana na lista dela com o grep -q (o -q manda o grep ficar quieto):

$ grep -q banana frutas.txt
$ grep -q kiwi frutas.txt

Os dois comandos ficaram em silêncio. Mas um achou a palavra e o outro não. Como saber? Pelo código de saída. Pense nele como o bilhete que todo comando deixa na mesa do shell ao terminar: "deu certo" (0) ou "deu errado, motivo número tal" (1, 2, 127…).

Vendo o código: echo $?

O Bash guarda o código do último comando numa variável especial chamada ?. Para ver o valor dela, use echo $? logo em seguida.

echo
Mostra um texto na tela.
$?
O valor da variável especial ?: o código de saída do comando que acabou de rodar. Leia como "e aí, deu certo?".
$ grep -q banana frutas.txt
$ echo $?
0                     « 0 = sucesso: "banana" está na lista
$ grep -q kiwi frutas.txt
$ echo $?
1                     « 1 = "não achei": kiwi não está na lista

Agora o silêncio tem significado. O grep devolve 0 quando acha o texto e 1 quando não acha. Nenhum dos dois é um "erro" no sentido de algo quebrado: 1 é só a resposta "não".

Por que zero é sucesso?

Parece ao contrário da matemática, mas faz sentido: só existe um jeito de dar certo e muitos jeitos de dar errado. O zero fica para o sucesso, e os outros números (1 a 255) servem para dizer qual foi o problema.

O $? muda a cada comando

Esta é a pegadinha mais comum. O $? é sempre o código do último comando, e o próprio echo $? é um comando. Veja:

$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
$ echo $?
2                     « o código do ls
$ echo $?
0                     « agora é o código do echo anterior, que deu certo

O segundo echo $? mostrou o código do primeiro echo $?, que funcionou (0). O código do ls se perdeu. Se você vai precisar dele mais tarde, guarde-o numa variável logo na linha seguinte:

codigo
O nome da variável (você escolhe).
=
Atribuição, sem espaço dos lados.
$?
O código do comando anterior, copiado antes que se perca.
$ grep -q banana frutas.txt
$ codigo=$?
$ echo "O grep devolveu $codigo"
O grep devolveu 0     « o valor ficou guardado

O que cada número significa

O código é um número de 0 a 255. Alguns valores têm significado fixo, dado pelo próprio Bash; os outros cada programa define do seu jeito (está no manual dele, na seção EXIT STATUS).

CódigoSignificadoQuem define
0Sucesso.Todos
1Falha geral, ou a resposta "não" (grep não achou, teste falso).Cada programa
2Uso errado (opção que não existe) ou problema sério (no ls e no grep: arquivo inexistente).Cada programa
126O comando existe, mas não pode ser executado (sem permissão, ou é uma pasta).Bash
127Comando não encontrado.Bash
128+NO programa foi morto pelo sinal número N.Bash

Vamos provocar cada um deles.

1 e 2: falha e uso errado

$ cat /etc/shadow
cat: /etc/shadow: Permissão negada
$ echo $?
1                     « falha geral: o cat não conseguiu ler
$ ls --xpto
ls: opção não reconhecida “--xpto”
Tente "ls --help" para mais informações.
$ echo $?
2                     « uso errado: a opção não existe
$ grep kiwi nada.txt
grep: nada.txt: Arquivo ou diretório inexistente
$ echo $?
2                     « para o grep, 2 = erro de verdade (1 seria só "não achei")

Repare na diferença no grep: 1 quer dizer "procurei e não achei"; 2 quer dizer "nem consegui procurar". Num script, isso permite separar "a palavra não está lá" de "o arquivo sumiu".

126: não pode executar

A Ana criou um arquivo com um comando dentro, mas esqueceu de dar permissão de execução. O shell achou o arquivo e se recusou a rodá-lo:

$ echo "echo oi" > oi.sh
$ ./oi.sh
bash: ./oi.sh: Permissão negada
$ echo $?
126
$ ./Documentos
bash: ./Documentos: É um diretório
$ echo $?
126                   « também 126: pasta não é programa

Como dar a permissão (chmod +x) é assunto de Seu Primeiro Script.

127: comando não encontrado

$ Ls
bash: Ls: comando não encontrado
$ echo $?
127                   « o Bash procurou "Ls" e não achou (L maiúsculo)

O 127 quase sempre é um erro de digitação, um programa que não está instalado ou uma pasta que não está no PATH.

128+N: morto por um sinal

Quando você aperta Ctrl+C, o terminal manda o sinal INT (de interrupt, número 2) ao programa. Ele morre, e o Bash registra 128 + 2 = 130:

$ sleep 30
^C                    « Ana apertou Ctrl+C antes dos 30 segundos
$ echo $?
130
$ kill -l 2 9 15
INT
KILL
TERM                  « os nomes dos sinais 2, 9 e 15

Com kill -9 o código seria 137 (128 + 9) e o Bash avisa Morto; com kill sem número, 143 (128 + 15). Sinais são estudados em trap e Sinais.

Comandos que respondem só com o código

Alguns comandos foram feitos para perguntar algo. A resposta é o código de saída, não um texto. São perfeitos para scripts.

grep -q: "esse texto está no arquivo?"

grep
Procura um texto em arquivos.
-q
quiet, "quieto": não mostra as linhas encontradas, só devolve o código.
"Estudar Bash"
O texto procurado (com aspas, por causa do espaço).
Documentos/notas.txt
Onde procurar.
$ grep -q "Estudar Bash" Documentos/notas.txt
$ echo $?
0                     « está nas notas da Ana

test e [ ]: "isso é verdade?"

O test confere uma condição e devolve 0 (verdadeiro) ou 1 (falso). O [ ] é o mesmo comando com outra cara. Os detalhes estão em Testes.

$ test -f frutas.txt
$ echo $?
0                     « -f: existe e é um arquivo comum
$ test -d frutas.txt
$ echo $?
1                     « -d: é uma pasta? não
$ [ 5 -gt 3 ]
$ echo $?
0                     « 5 é maior (greater than) que 3

pgrep: "esse programa está rodando?"

O pgrep procura processos pelo nome. Ele mostra o número (PID) de cada um que achar, mas o que importa num script é o código:

$ pgrep firefox
2210                  « o Firefox da Ana está aberto (no seu computador o número será outro)
$ echo $?
0
$ pgrep -x xyzprocesso
$ echo $?
1                     « nenhum processo com esse nome

true e false

São os dois comandos mais simples do mundo: não fazem nada, só devolvem um código. true sempre devolve 0 e false sempre devolve 1. Eles parecem inúteis, mas servem para testar operadores e para laços infinitos (while true, em while).

$ true; echo $?
0
$ false; echo $?
1
$ type true false
true é um comando interno do shell
false é um comando interno do shell

O ; separa dois comandos na mesma linha (você verá em ; && ||). O : (dois-pontos) é um apelido antigo de true.

Inverter o resultado: !

Um ! seguido de espaço, antes do comando, troca o resultado: sucesso vira 1 e qualquer falha vira 0. Leia como "não".

!
"Não": inverte o código de saída. Precisa de um espaço depois.
grep -q kiwi frutas.txt
O comando normal, que devolveria 1 (não achou).
$ ! true; echo $?
1
$ ! grep -q kiwi frutas.txt; echo $?
0                     « "é verdade que kiwi NÃO está na lista"

Seu script também devolve um código: exit N

Um script é um comando como outro qualquer, e também devolve um código. Por padrão, é o código do último comando que ele rodou. Para escolher o número, use exit:

echo "vou sair com 3"
exit 3
echo "nunca aparece"
LinhaO que faz
echo "vou sair com 3"Mostra o aviso.
exit 3Termina o script na hora, devolvendo 3.
echo "nunca aparece"Nunca roda: o script já acabou.
$ bash sai.sh
vou sair com 3
$ echo $?
3

Regras do exit:

  • exit sem número devolve o código do último comando.
  • O número vai de 0 a 255. Acima disso, o Bash pega o resto da divisão por 256: exit 300 vira 44 e exit 256 vira 0 (sucesso, sem querer!).
  • Use 0 para sucesso, 1 para falha geral e 2 para uso errado (faltou argumento), como os programas do sistema. Veja em Argumentos.
  • Não digite exit no seu terminal para testar: ele fecha o terminal! Teste com bash -c 'exit 7', que roda um Bash separado.
$ bash -c 'exit 7'
$ echo $?
7
$ bash -c 'exit 300'
$ echo $?
44                    « 300 - 256 = 44

Experimente

Missão 1: digite um comando que não existe (por exemplo, xyz) e, logo depois, mostre o código de saída dele. O número deve ser 127.

Missão 2: use o ! com grep -q para perguntar "é verdade que kiwi não está em frutas.txt?". O código final deve ser 0. Confira com echo $? (e lembre: depois disso o $? já é o do echo).

Missão 3: rode o script com o argumento kiwi. Ele diz o que o grep devolveu, mas o script em si termina com 0 (porque o último comando, o echo, deu certo). Mude o script para que ele termine com o mesmo código do grep: guarde o $? numa variável logo depois do grep, use-a no echo e termine com exit.

#!/usr/bin/env bash
echo "Procurando $1 na lista..."
grep -q "$1" frutas.txt
echo "O grep devolveu $?"

#!/usr/bin/env bash
echo "Procurando $1 na lista..."
grep -q "$1" frutas.txt
codigo=$?
echo "O grep devolveu $codigo"
exit $codigo

Com a solução, a saída real é:

$ bash procura.sh kiwi
Procurando kiwi na lista...
O grep devolveu 1
$ echo $?
1                     « agora o script inteiro "responde" como o grep
$ bash procura.sh uva
Procurando uva na lista...
O grep devolveu 0
$ echo $?
0

Formas de usar o código de saída

Ver o número com echo $? é ótimo para aprender e investigar. Nos scripts, quase sempre você usa o código sem olhar para ele:

FormaExemploQual usar?
echo $?ls nada; echo $?Para investigar no terminal: "que número saiu?"
Guardar em variávelcodigo=$?Quando você precisa do número depois (para mostrar ou repassar com exit).
&& e ||grep -q kiwi frutas.txt || echo "falta kiwi"Uma ação curta que depende de sucesso ou falha. Veja ; && ||.
if comandoif grep -q kiwi frutas.txt; then …Decisões com mais de uma linha. Veja if. É o jeito mais claro.
if [ $? -eq 0 ]grep …; if [ $? -eq 0 ]; thenEvite: funciona, mas é mais longo e quebra se alguém colocar um comando no meio.

E num pipe? PIPESTATUS

Quando você liga comandos com | (um pipe), o $? é o código do último comando da fila. Os códigos de todos ficam no array PIPESTATUS:

$ grep kiwi frutas.txt | sort | wc -l
0
$ echo "${PIPESTATUS[@]}"
1 0 0                 « grep falhou (1), sort e wc deram certo

Por enquanto, só saiba que ele existe. Você vai usá-lo (junto com set -o pipefail) em Pipes e set -euo pipefail.

Quando não funciona

O $? sempre dá 0 
$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
$ echo "Testando..."
Testando...
$ echo $?
0

O que aconteceu: o $? mostrou o código do echo "Testando...", não do ls. Qualquer comando no meio, até um echo, apaga o código anterior.

Como resolver: olhe o $? imediatamente depois do comando, ou guarde-o: ls nada; codigo=$?.

"comando não encontrado" (127) 
$ Documentos
bash: Documentos: comando não encontrado
$ echo $?
127

O que aconteceu: o Bash entendeu a primeira palavra como o nome de um programa e não achou nenhum com esse nome. Causas: erro de digitação (maiúscula/minúscula conta), programa não instalado, ou você quis entrar na pasta e esqueceu o cd.

Como confirmar: type nome diz se o Bash conhece o comando (veja Obtendo Ajuda).

Como resolver: corrija o nome, instale o programa, ou use cd Documentos. Para um script seu, rode com ./ na frente (Formas de Executar).

"Permissão negada" ao rodar (126) 
$ ./oi.sh
bash: ./oi.sh: Permissão negada
$ echo $?
126

O que aconteceu: o arquivo existe, mas não tem permissão de execução.

Como resolver: chmod +x oi.sh, ou rode com bash oi.sh. Detalhes em Seu Primeiro Script.

O script falhou, mas devolveu 0

O que aconteceu: o código do script é o do último comando. Se um comando no meio falhou e o último foi um echo "fim", o script devolve 0. Foi o que aconteceu na Missão 3 antes da correção.

Como resolver: termine com exit $codigo (como na missão), ou pare na hora do erro com comando || exit 1 (veja ; && ||). Para scripts maiores, veja Tratar Erros.

Usei exit 256 (ou exit -1) e veio outro número

O que aconteceu: o código só tem espaço para 0 a 255. O Bash usa o resto da divisão por 256: 256 vira 0 e -1 vira 255.

Como resolver: use sempre números de 0 a 125. Evite 126 a 255, que o Bash usa para "não executável", "não encontrado" e sinais.

Esperava 1 e veio 2 (ou o contrário)

O que aconteceu: fora 0, cada programa escolhe seus números. O ls devolve 2 para arquivo inexistente; o cat devolve 1 para o mesmo problema.

Como resolver: nos scripts, teste "é zero ou não é" (que é o que &&, || e if fazem). Quando o número exato importar, procure a seção EXIT STATUS no man do programa.

Resumo

  • Todo comando devolve um código de 0 a 255: 0 é sucesso, o resto é falha (ou "não").
  • $? é o código do último comando e muda a cada comando, até com echo. Guarde em variável se precisar.
  • 126 = não pode executar; 127 = não encontrado; 128+N = morto pelo sinal N (130 = Ctrl+C).
  • grep -q, test e pgrep respondem só pelo código. true devolve 0, false devolve 1, ! inverte.
  • Um script devolve o código do último comando, ou o número do exit N.
