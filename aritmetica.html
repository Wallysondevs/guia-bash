Bash Contas: $(( )), let e bc

Para o Bash, tudo é texto: 5+3 é só uma sequência de três caracteres. Para ele calcular, você precisa pedir, e a forma de pedir é a expansão aritmética $(( )). Nesta aula você aprende a fazer contas inteiras, usar contas como condição, e o que fazer quando precisa de casas decimais.

Você vai aprender
  • Calcular com $(( )) e alterar variáveis com (( )), let e declare -i.
  • Por que (( )) devolve um código de saída e como usar isso em testes.
  • Os operadores, a divisão inteira (7/2 dá 3!) e as bases (2#1010, 16#ff, e a pegadinha do 08).
  • Números com vírgula com bc, awk e printf, e as armadilhas do português.
  • Números aleatórios com $RANDOM e $SRANDOM.

O problema: o Bash não faz conta sozinho

$ echo 5+3
5+3                     « só texto
$ echo $((5+3))
8                       « agora sim

Isso confunde quem vem de outras linguagens, mas faz sentido: o shell foi feito para rodar comandos, e a maior parte do que você digita é texto (nomes de arquivos, opções). Contas são a exceção, e por isso têm uma sintaxe própria.

A expansão aritmética: $(( ))

$((
"Calcule o que vem a seguir e coloque o resultado aqui."
a + b
A conta. Dentro dos parênteses duplos os espaços são livres e as variáveis não precisam de $.
))
Fim da conta.
$ a=10
$ b=3
$ echo $((a + b))
13
$ echo $(( $a * $b ))
30                      « com $ também funciona; sem $ é mais limpo
$ echo $((a - b)) $((a * b)) $((a / b)) $((a % b)) $((2 ** 10))
7 30 3 1 1024

Leia a última linha da saída na ordem: 10-3=7, 10×3=30, 10÷3=3 (inteiro!), resto de 10÷3 é 1, e 2 elevado a 10 é 1024.

O $(( )) é uma expansão, como $nome: ele vira um texto (o resultado) e esse texto entra no comando. Por isso você o usa dentro de echo, de uma atribuição, de um argumento:

$ ano=2026
$ echo "Daqui a 10 anos será $((ano + 10))"
Daqui a 10 anos será 2036
$ idade=$((ano - 1997))
$ echo $idade
29

Ordem das operações

Como na escola: ** antes de * / %, que vêm antes de + -. Use parênteses para mudar a ordem:

$ echo $(( 2 + 3 * 4 ))
14
$ echo $(( (2 + 3) * 4 ))
20

A divisão é inteira

O Bash só trabalha com números inteiros. Na divisão, a parte depois da vírgula é simplesmente jogada fora (não é arredondada):

$ echo $((7 / 2))
3                       « 3,5 virou 3
$ echo $((-7 / 2))
-3                      « corta em direção ao zero, também para negativos

Para saber "quanto sobrou", use o resto, % (chamado de módulo). Ele é ótimo para saber se um número é par: o resto da divisão por 2 é zero.

$ echo $((7 % 2))
1                       « 7 é ímpar

Se precisar de decimais, pule para Números com vírgula.

Mudar a variável: (( )), let e declare -i

(( )) sem o $

Sem o cifrão, (( )) é um comando: calcula, pode alterar variáveis, e não coloca o resultado em lugar nenhum. É a forma preferida para contadores.

$ n=5
$ ((n++))
$ echo $n
6                       « ++ soma 1
$ ((n += 10))
$ echo $n
16                      « += soma e guarda
$ ((n *= 2)); echo $n
32
EscritoEquivale aNome
((n++)) / ((n--))n = n + 1 / n = n - 1incremento / decremento
((n += 5))n = n + 5atribuição composta (também -= *= /= %=)
((n = a * 2))atribui o resultadoatribuição

Há uma diferença entre n++ e ++n que aparece quando você usa o valor na mesma conta: n++ devolve o valor antigo e depois soma; ++n soma primeiro.

$ n=16
$ echo $((n--)) $n
16 15                   « mostrou 16, depois virou 15
$ echo $((++n)) $n
16 16                   « somou primeiro, mostrou 16

let: a forma antiga

let faz o mesmo que (( )), mas cada conta é um argumento: sem espaços, ou tudo entre aspas.

$ let total=5*4
$ echo $total
20
$ let "total = total + 1"
$ echo $total
21
$ let total = total + 1
bash: let: =: erro de sintaxe aritmética: esperava operando (token de erro é "=")

No último caso, o let recebeu cinco argumentos separados (total, =, total, +, 1) e tentou calcular cada um. Por isso, hoje se prefere (( )), onde os espaços são livres.

declare -i: a variável que sempre calcula

Com o atributo -i (de integer), toda atribuição já é uma conta. O += passa a somar em vez de colar texto:

$ declare -i soma=0
$ soma+=5
$ soma+=10
$ echo $soma
15                      « sem o -i, o resultado seria o texto "0510"

O declare e seus outros atributos estão em Variáveis, Escopo e export.

Missão: guarde na variável r o resultado de 2 elevado a 16, usando $(( )). Confira com echo $r.

(( )) como teste: o código de saída

Todo comando devolve um código de saída, e (( )) também. A regra é:

  • se o resultado da conta é diferente de zero, o código é 0 (sucesso, "verdadeiro");
  • se o resultado é zero, o código é 1 (falha, "falso").

Parece invertido, mas segue a lógica do shell: 0 é sucesso. Isso faz de (( )) um ótimo teste numérico:

$ (( 3 > 2 ))
$ echo $?
0                       « verdadeiro
$ (( 3 < 2 ))
$ echo $?
1                       « falso
$ (( 0 ))
$ echo $?
1                       « resultado zero = falso
$ n=7
$ (( n > 5 )) && echo "maior que 5"
maior que 5
$ if (( n % 2 == 0 )); then echo par; else echo ímpar; fi
ímpar

Dentro de (( )), > e < são comparações, não redirecionamentos. O if está em if, elif, else, e a comparação de números com [ ] (-gt, -lt…) em Testes.

Já o $(( )) devolve o resultado da comparação como número: 1 para verdadeiro, 0 para falso (o contrário do código de saída!):

$ echo $(( 3 > 2 )) $(( 3 < 2 ))
1 0
$ echo $(( 5 == 5 )) $(( 5 != 5 ))
1 0
A pegadinha do contador que começa em zero 
$ x=0
$ ((x++))
$ echo $?
1                       « "falhou"?!
$ ((x++))
$ echo $?
0

O x++ devolve o valor antigo. Na primeira vez, ele era 0, então ((x++)) deu código 1. A conta funcionou (x virou 1), mas o código diz "falso". Num script com set -e (veja modo estrito), isso encerra o script. Use ((++x)) ou x=$((x + 1)) para não cair nisso.

O ternário (do latim, "de três partes") é um if de uma linha, mas só devolve números. Os operadores de bits trabalham com o número em binário; você vai usá-los raramente, em permissões e máscaras.

!0 sem espaço no terminal 
$ echo $(( !0 ))
bash: !0: event not found

No terminal interativo, ! seguido de texto é a expansão do histórico. Escreva ! 0, com espaço. Em scripts, o problema não acontece.

Bases: binário, hexadecimal e a pegadinha do 08

Você pode escrever números em outras bases com BASE#número, e o Bash entende os prefixos da linguagem C:

$ echo $((2#1010)) $((16#ff)) $((8#17)) $((0x1F)) $((010))
10 255 15 31 8
EscritoBaseVale
2#10102 (binário)10
16#ff ou 0xff16 (hexadecimal)255
8#17 ou 0178 (octal)15
0108 (octal!), por causa do zero à esquerda8, não 10
10#01010 (decimal, forçado)10

A última linha é a mais importante: um número que começa com 0 é lido em octal. Em octal só existem os dígitos de 0 a 7. Isso estoura com datas e horas, que adoram zero à esquerda:

$ mes=08
$ echo $((mes + 1))
bash: 08: valor muito grande para esta base de numeração (token de erro é "08")
$ echo $((10#$mes + 1))
9                       « 10# força a base 10

Em agosto e setembro (08 e 09), um script que soma meses ou horas quebra de repente. A solução é sempre pôr 10# na frente da variável. Atenção: aqui o $ é obrigatório (10#$mes), porque o 10# precisa colar no valor.

Números com vírgula

O Bash não sabe fazer 3.5 + 1:

$ echo $((3.5 + 1))
bash: 3.5 + 1: erro de sintaxe aritmética: operador aritmético inválido (token de erro é ".5 + 1")
$ echo $((3,5 + 1))
6                       « sem erro, mas errado! a vírgula é o operador "faça as duas"

Repare no segundo: em português escrevemos 3,5, mas para o Bash a vírgula é o operador da tabela acima. Ele calculou 3, depois 5 + 1, e devolveu 6. Não confie em contas com vírgula dentro de $(( )). Para decimais, chame um programa que saiba fazê-las.

bc: a calculadora do terminal

bc (basic calculator) lê contas da entrada e responde. Por padrão ele também corta os decimais; a variável scale diz quantas casas você quer. Ele usa ponto, nunca vírgula.

echo "scale=2; 7 / 2"
Duas instruções para o bc, separadas por ;: "use 2 casas decimais" e a conta.
|
O pipe entrega o texto ao bc.
bc
Calcula e mostra o resultado.
$ echo "7 / 2" | bc
3                       « sem scale: inteiro
$ echo "scale=2; 7 / 2" | bc
3.50
$ echo "scale=2; 10 / 3" | bc
3.33                    « corta, não arredonda
$ echo "scale=2; 2 / 3" | bc
.66                     « o bc omite o zero antes do ponto
$ bc -l <<< "10 / 3"
3.33333333333333333333  « -l carrega a biblioteca matemática e usa 20 casas

Com variáveis do Bash é igual: o Bash troca as variáveis antes, e o bc recebe só números.

$ preco=19.90
$ qtd=3
$ echo "$preco * $qtd" | bc
59.70

Para guardar o resultado numa variável, use substituição de comando: total=$(echo "$preco * $qtd" | bc).

awk

O awk faz contas com decimais direto, o que é ótimo para somar colunas de arquivos (ele é apresentado em grep, sed, awk e cia.). Mas veja o que acontece na máquina da Ana, que está em português:

$ awk 'BEGIN { print 7 / 2 }'
3,5                     « saiu com vírgula, por causa do LANG=pt_BR
$ awk -F, 'NR > 1 { soma += $4 } END { print soma / (NR - 1) }' Documentos/alunos.csv
8                       « ERRADO: a média das notas é 8,2
$ LC_ALL=C awk -F, 'NR > 1 { soma += $4 } END { print soma / (NR - 1) }' Documentos/alunos.csv
8.2                     « certo

O awk do Debian e do Ubuntu (o mawk) segue o idioma do sistema: ele espera vírgula nos números. Ao ler 9.5 do arquivo, ele parou no ponto e entendeu 9. Rodar com LC_ALL=C (idioma neutro, só para aquele comando; veja VAR=valor comando) faz ele usar o ponto. O gawk (GNU awk, padrão no Fedora e no Arch) usa ponto sempre.

printf "%.2f": arredondar para mostrar

O printf formata números com um número fixo de casas, arredondando. A mesma armadilha do idioma aparece aqui:

$ printf "%.2f\n" 3.14159
bash: printf: 3.14159: número inválido
3,00
$ printf "%.2f\n" 3,14159
3,14                    « em pt_BR, o printf espera vírgula
$ LC_NUMERIC=C printf "%.2f\n" 3.14159
3.14

Como o bc sempre devolve com ponto, a combinação segura é LC_NUMERIC=C printf "%.2f\n" "$(echo "10/3" | bc -l)". Mais sobre formatos em printf e echo.

Missão: o script deveria mostrar a média das três notas recebidas, mas o Bash não faz conta com decimais e dá erro. Troque a conta para usar o bc com 2 casas, de forma que a saída seja 8.33.

#!/usr/bin/env bash
echo $(( ($1 + $2 + $3) / 3 ))

#!/usr/bin/env bash
echo "scale=2; ($1 + $2 + $3) / 3" | bc

expr: a forma antiga

Antes do $(( )), as contas eram feitas com o programa expr. Você ainda vai encontrá-lo em scripts velhos. Ele exige espaço entre tudo, e o * precisa de barra, senão vira curinga:

$ expr 5 + 3
8
$ expr 5+3
5+3                     « sem espaços: um argumento só, que ele devolve como texto
$ expr 5 * 3
expr: erro de sintaxe: argumento inesperado ‘Área de trabalho’   « o * virou a lista de arquivos!
$ expr 5 \* 3
15

Use $(( )) em scripts novos: é mais legível e mais rápido (não cria um processo).

Números aleatórios: $RANDOM e $SRANDOM

Cada vez que você lê $RANDOM, ele vale um número inteiro diferente, de 0 a 32767. Para um intervalo, use o resto da divisão:

RANDOM
Um número de 0 a 32767.
% 6
O resto da divisão por 6: um número de 0 a 5.
+ 1
Desloca para 1 a 6: um dado.
$ echo $RANDOM
30315
$ echo $RANDOM
32091                   « outro número a cada leitura
$ echo $((RANDOM % 6 + 1))
6

Os números da sua tela serão outros. Se você atribuir um valor a RANDOM (a "semente"), a sequência passa a se repetir, o que é útil para testes:

$ RANDOM=42
$ echo $RANDOM $RANDOM
17772 26794
$ RANDOM=42
$ echo $RANDOM $RANDOM
17772 26794             « mesma semente, mesma sequência

$SRANDOM bash 5.1+ dá números de 32 bits (até cerca de 4 bilhões) vindos do gerador do sistema, sem sequência previsível. Use-o para coisas que precisam ser difíceis de adivinhar. Nenhum dos dois serve para senhas e criptografia de verdade.

$ echo $SRANDOM
955208759

Brinque: rode várias vezes. Depois mude para um dado de 20 faces, ou sorteie um número de 10 a 20 (RANDOM % 11 + 10).

#!/usr/bin/env bash
dado=$((RANDOM % 6 + 1))
echo "Você tirou $dado"

Missão: o script recebe o ano de nascimento e deveria mostrar a idade em 2026, mas mostra Você tem 2026-1997 anos. Corrija a conta.

#!/usr/bin/env bash
idade=2026-$1
echo "Você tem $idade anos"

#!/usr/bin/env bash
idade=$((2026 - $1))
echo "Você tem $idade anos"

Quando não funciona

"valor muito grande para esta base de numeração" 
$ echo $((08))
bash: 08: valor muito grande para esta base de numeração (token de erro é "08")
$ echo $((2#102))
bash: 2#102: valor muito grande para esta base de numeração (token de erro é "2#102")

O que aconteceu: o número tem um dígito que não existe na base. Zero à esquerda = octal, e 8 não existe em octal. Em binário só existem 0 e 1.

Como resolver: para valores com zero à esquerda (meses, dias, horas de date), use $((10#$mes)).

"erro de sintaxe aritmética: esperava operando" 
$ echo $((3 +))
bash: 3 +: erro de sintaxe aritmética: esperava operando (token de erro é "+")

O que aconteceu: faltou um número depois do operador. O caso mais comum é uma variável com valor vazio sendo usada com $: $((3 + $x)) com x vazio vira 3 +. O "token de erro" mostra onde o Bash se perdeu.

Como resolver: escreva sem $ ($((3 + x)), que trata vazio como 0) ou dê um padrão: $((3 + ${x:-0})) (veja Expansão de Parâmetros).

"operador aritmético inválido" com decimais 
$ echo $((3.5 + 1))
bash: 3.5 + 1: erro de sintaxe aritmética: operador aritmético inválido (token de erro é ".5 + 1")

Como resolver: o Bash só faz contas inteiras. Use bc (veja Números com vírgula).

"divisão por 0" 
$ echo $((10 / 0))
bash: 10 / 0: divisão por 0 (token de erro é "0")
$ echo $?
1

Como resolver: teste o divisor antes: (( d != 0 )) && echo $((10 / d)). O mesmo erro aparece com %.

A conta deu um número estranho e negativo 
$ echo $(( 2**63 ))
-9223372036854775808

O que aconteceu: o Bash usa inteiros de 64 bits; o maior é 9223372036854775807. Passou disso, o número "dá a volta" (overflow) sem nenhum aviso.

Como resolver: para números gigantes, use bc, que não tem limite.

Uma palavra virou zero, sem erro 
$ x=abc
$ echo $((x + 1))
1

O que aconteceu: dentro de uma conta, abc é lido como o nome de outra variável; como ela não existe, vale 0. Valide a entrada antes de calcular (veja Testes e Regex).

Resumo

  • $(( )) calcula e vira texto; (( )) calcula como comando. Dentro deles, variáveis dispensam o $.
  • (( )) devolve código 0 quando o resultado é diferente de zero: serve de teste. Cuidado com ((x++)) quando x é 0.
  • Tudo é inteiro: 7/2 é 3. Use % para o resto.
  • Zero à esquerda é octal: use 10#$var para datas e horas.
  • Decimais: bc com scale; awk e printf seguem o idioma (use LC_ALL=C/LC_NUMERIC=C).
  • $((RANDOM % N + 1)) sorteia de 1 a N; $SRANDOM é a versão moderna.
