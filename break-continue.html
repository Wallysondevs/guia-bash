Bash break e continue

Um laço (for, while, until) repete tudo, do começo ao fim. Às vezes você quer parar antes, porque já achou o que procurava, ou pular só esta volta, porque a linha está vazia. Para isso existem dois comandos curtinhos: break e continue.

Você vai aprender
  • Como break encerra o laço na hora, e o que acontece depois dele.
  • Como continue pula para a próxima volta (linhas vazias, comentários, cabeçalho).
  • O que fazem break 2 e continue 2 quando há um laço dentro de outro.
  • A diferença entre break, return e exit.
  • As armadilhas: continue que trava o while, break dentro de case e dentro de função.

O problema: o laço não sabe a hora de parar

Pense numa fila de alunos entrando na sala. Você procura a Carla. Quando ela chega, você não precisa continuar olhando o resto da fila: para. Já quando passa alguém de outra turma, você não para a fila inteira: só ignora essa pessoa e olha a próxima.

continue"continuar" (com a próxima)Esse não é da turma, próximo!Abandona o resto desta volta e começa a próxima.

break: achou, para

O uso mais comum é procurar e parar. Este laço olha uma lista de números e para no primeiro maior que 10:

$ for n in 4 8 15 16 23 42; do
>   if (( n > 10 )); then
>     echo "achei: $n"
>     break
>   fi
>   echo "olhei $n"
> done
olhei 4
olhei 8
achei: 15                 « no 15 o break encerrou o laço: 16, 23 e 42 nem foram olhados
$ echo "código: $?"
código: 0                 « o break em si não é erro: código 0
for n in 4 8 15 16 23 42
O laço vai dar uma volta para cada número (veja for).
if (( n > 10 ))
A condição de parada: "o número é maior que 10?" (veja contas com (( ))).
echo "achei: $n"
Faz o que precisa antes de sair.
break
Encerra o laço agora. O Bash pula direto para o que vem depois do done.
echo "olhei $n"
Só roda nas voltas em que o break não aconteceu. Na volta do 15 ele foi pulado.

Repare na ordem da saída: "olhei 4", "olhei 8" e então "achei: 15". Na volta do 15, o echo "olhei" não apareceu, porque o break veio antes dele.

Um script de verdade: procurar um aluno pela cidade

Agora com o arquivo Documentos/alunos.csv da Ana. O script recebe uma cidade e mostra o primeiro aluno que mora nela. Ele lê o arquivo linha a linha com while read (a técnica é explicada em Ler Arquivos Linha a Linha) e usa os dois comandos desta aula:

#!/usr/bin/env bash
cidade=$1
achou=""
while IFS=, read -r nome idade cidade_aluno nota; do
  if [[ $nome == nome ]]; then
    continue                     # pula o cabeçalho
  fi
  echo "conferi $nome"
  if [[ $cidade_aluno == "$cidade" ]]; then
    achou=$nome
    break                        # achou: não precisa ler o resto
  fi
done < Documentos/alunos.csv

if [[ -n $achou ]]; then
  echo "Mora em $cidade: $achou"
else
  echo "Ninguém mora em $cidade"
fi
LinhaO que faz
cidade=$1Guarda a cidade que a pessoa passou como argumento (veja argumentos).
achou=""Começa vazia. Se continuar vazia no fim, ninguém foi encontrado.

if [[ $nome == nome ]]; then continueA primeira linha é o cabeçalho (nome,idade,cidade,nota). O continue pula essa volta e vai para a próxima linha.
echo "conferi $nome"Mostra quem foi olhado (só para você ver o laço trabalhando).
achou=$nome + breakGuarda o nome e sai do laço. As linhas seguintes do arquivo nem são lidas.

$ bash procura.sh Salvador

conferi Bruno
conferi Carla
Mora em Salvador: Carla          « parou na Carla: Diego e Elisa não foram lidos
$ bash procura.sh Natal
conferi Ana
conferi Bruno
conferi Carla
conferi Diego
conferi Elisa
Ninguém mora em Natal            « sem break: o laço foi até o fim do arquivo

Nas duas rodadas, "nome" (o cabeçalho) nunca aparece em "conferi": o continue fez o laço pular aquela linha. Com 5 alunos a economia do break é pequena; com um arquivo de 1 milhão de linhas, parar na terceira faz muita diferença.

"Sentinela": a variável que conta o que aconteceu no laço

Depois de um break, o resto do script não sabe por que o laço acabou: foi porque achou, ou porque a lista terminou? Por isso guardamos o resultado numa variável (achou) antes do break e olhamos para ela depois do done.

continue: pular só esta volta

O continue não encerra o laço. Ele diz: "o resto desta volta não interessa, vá para a próxima". Aqui, os números pares são pulados:

$ for n in 1 2 3 4 5 6; do
>   if (( n % 2 == 0 )); then
>     continue
>   fi
>   echo "ímpar: $n"
> done
ímpar: 1
ímpar: 3
ímpar: 5              « 2, 4 e 6 entraram no laço, mas o continue pulou o echo
(( n % 2 == 0 ))
"O resto da divisão por 2 é zero?", ou seja, "é par?".
continue
Larga esta volta. O Bash volta ao for e pega o próximo número.
echo "ímpar: $n"
Só chega aqui quem não foi pulado.

Uso clássico: ignorar linhas vazias e comentários

Arquivos de configuração têm linhas em branco e comentários (começando com #). Um script que lê esse arquivo quer só as linhas úteis. Este é o config.txt:

# Configuração do site
nome=loja

# porta do servidor
porta=8080
   # comentário com espaços antes
tema=escuro

#!/usr/bin/env bash
while IFS= read -r linha; do
  if [[ -z $linha ]]; then
    continue                 # linha vazia: pula
  fi
  if [[ $linha =~ ^[[:space:]]*# ]]; then
    continue                 # comentário: pula
  fi
  echo "config: $linha"
done < config.txt
[[ -z $linha ]]
"A linha está vazia?" (-z = zero length).
[[ $linha =~ ^[[:space:]]*# ]]
"A linha começa com #, talvez depois de espaços?". O =~ compara com uma expressão regular: ^ = começo da linha, [[:space:]]* = zero ou mais espaços, # = o caractere. Detalhes em Regex com [[ =~ ]].
continue
Em cada caso, desiste desta linha e lê a próxima.
$ bash le-config.sh
config: nome=loja
config: porta=8080
config: tema=escuro          « as 4 linhas de comentário e branco foram puladas
Por que usar continue em vez de um if grande?

Daria para escrever if [[ -n $linha ]] && ...; then e colocar todo o trabalho dentro. Mas quando o trabalho tem 20 linhas, ficar tudo "dentro do if" empurra o código para a direita. Com continue, você descarta os casos ruins logo no começo (guard clauses, "cláusulas de guarda") e o resto do laço fica limpo.

Missão: a Ana vai à feira com a lista frutas.txt (banana, maçã, laranja, banana, uva, maçã, banana). Ela já tem bananas em casa, então quer pular toda banana com continue. E o dinheiro só dá até chegar na uva: quando aparecer uva, ela para com break (sem comprar a uva). Complete os dois if e rode. O resultado deve terminar com Total: 2.

#!/usr/bin/env bash
total=0
while IFS= read -r fruta; do
  # 1) se for banana, pule para a próxima fruta

  # 2) se for uva, pare o laço

  echo "comprar: $fruta"
  total=$((total + 1))
done < frutas.txt
echo "Total: $total"

#!/usr/bin/env bash
total=0
while IFS= read -r fruta; do
  if [[ $fruta == banana ]]; then
    continue
  fi
  if [[ $fruta == uva ]]; then
    break
  fi
  echo "comprar: $fruta"
  total=$((total + 1))
done < frutas.txt
echo "Total: $total"

Com a solução, a saída é esta (conferida no Bash real):

$ bash compras.sh
comprar: maçã
comprar: laranja
Total: 2                « banana pulada duas vezes, parou na uva; a segunda maçã nem foi lida

Laço dentro de laço: break 2 e continue 2

Quando há um laço dentro de outro (laços aninhados), o break sozinho sai só do laço mais de dentro, aquele em que ele está. O de fora continua girando:

$ for i in 1 2 3; do
>   for j in 1 2 3; do
>     if (( j == 2 )); then break; fi
>     echo "$i-$j"
>   done
> done
1-1
2-1
3-1                « o break saiu só do laço do j; o laço do i deu as 3 voltas

Para sair dos dois de uma vez, diga quantos níveis: break 2.

$ for i in 1 2 3; do
>   for j in 1 2 3; do
>     if (( i * j == 4 )); then break 2; fi
>     echo "$i-$j"
>   done
> done
1-1
1-2
1-3
2-1                « em i=2, j=2 (2×2 = 4) o break 2 encerrou os dois laços
break
O mesmo que break 1: sai de 1 laço, o mais interno.
break 2
Sai do laço atual e do que está em volta dele. O número conta "quantos done pular".
continue 2
Abandona o laço de dentro e começa a próxima volta do laço de fora.

Veja o continue 2: quando j chega a 2, larga o resto dos j e passa para o próximo i.

$ for i in 1 2 3; do
>   for j in 1 2 3; do
>     if (( j == 2 )); then continue 2; fi
>     echo "$i-$j"
>   done
> done
1-1
2-1
3-1

A saída é igual à do break simples do primeiro exemplo. Faz sentido: nos dois casos, o laço de dentro é abandonado e o de fora segue. A diferença aparece quando há código depois do done de dentro: com break ele roda, com continue 2 ele é pulado.

Exemplo prático: a primeira foto em várias pastas

#!/usr/bin/env bash
for pasta in Downloads Imagens Documentos; do
  echo "Procurando em $pasta..."
  for arq in "$pasta"/*; do
    if [[ $arq == *.jpg ]]; then
      echo "Primeira foto: $arq"
      break 2
    fi
  done
done
echo "Fim da busca"

$ bash busca-foto.sh
Procurando em Downloads...
Primeira foto: Downloads/foto.jpg
Fim da busca              « nem chegou a "Procurando em Imagens"

Com break simples no lugar de break 2, o script sairia só do laço dos arquivos e continuaria com "Procurando em Imagens...", achando também Imagens/ferias.jpg.

Missão: no terminal, escreva um for n in {1..20} que procure o primeiro múltiplo de 7, mostre achei 7 e pare com break. Dica: múltiplo de 7 é (( n % 7 == 0 )).

break, return ou exit?

Os três "param alguma coisa", mas o tamanho do que param é diferente:

ComandoEncerra…E continua em…
breako laçoa linha depois do done.
returna função (veja local, return e saída)a linha depois de onde a função foi chamada.
exito script inteiro (ou o terminal, se digitado nele!)lugar nenhum: o script acabou.

Este script tem três funções iguais, mudando só o comando usado na volta 2:

#!/usr/bin/env bash
com_break() {
  for i in 1 2 3; do
    if (( i == 2 )); then break; fi
    echo "  volta $i"
  done
  echo "  fim da função"
}
com_return() {
  for i in 1 2 3; do
    if (( i == 2 )); then return; fi
    echo "  volta $i"
  done
  echo "  fim da função"
}
com_exit() {
  for i in 1 2 3; do
    if (( i == 2 )); then exit 3; fi
    echo "  volta $i"
  done
  echo "  fim da função"
}
echo "break:";  com_break
echo "return:"; com_return
echo "exit:";   com_exit
echo "fim do script"

$ bash sair.sh
break:
  volta 1
  fim da função           « break: saiu do laço, mas a função continuou
return:
  volta 1                 « return: saiu da função inteira ("fim da função" não aparece)
exit:
  volta 1                 « exit: o script acabou; "fim do script" nunca aparece
$ echo $?
3                         « o número passado ao exit vira o código de saída do script
Não digite exit no terminal para "sair do laço"

No terminal, exit fecha o shell, e a janela do terminal some. Para interromper um laço que você digitou e que não para, use Ctrl+C (veja while e until).

Formas diferentes de "parar de procurar"

Nem sempre você precisa de break. Compare:

FormaExemploMelhor quando…
break no laçoif [[ … ]]; then achou=$x; break; fiVocê precisa fazer várias coisas com o que achou, ou a condição é complicada.
Condição no próprio whilewhile [[ -z $achou ]] && read -r l; do …A condição de parada é simples e faz parte do "enquanto".
return numa funçãoprocura() { for …; do [[ … ]] && { echo "$x"; return 0; }; done; return 1; }A busca é reaproveitada em vários lugares. O código de saída diz se achou (veja return).

Quando não funciona

O script travou depois de um continue 
#!/usr/bin/env bash
i=0
while (( i < 5 )); do
  if (( i == 2 )); then
    continue
  fi
  echo "i = $i"
  i=$((i + 1))
done

$ bash conta.sh
i = 0
i = 1
^C                       « parado para sempre, até apertar Ctrl+C

O que aconteceu: quando i vale 2, o continue pula o resto da volta, inclusive o i=$((i + 1)). O i fica 2 para sempre, a condição i < 5 é sempre verdadeira e o laço gira sem fim (consumindo 100% de um processador).

Como confirmar: rode com bash -x conta.sh e veja as mesmas linhas se repetindo (veja depurar).

Como resolver: incremente antes do continue (if (( i == 2 )); then i=$((i + 1)); continue; fi) ou troque por um for ((i=0; i<5; i++)), em que o i++ roda mesmo depois de um continue.

"significativo apenas em um loop de `for', `while' ou `until'" 
$ break
bash: break: significativo apenas em um loop de `for', `while' ou `until'
$ echo $?
0                       « repare: mesmo com a mensagem, o código é 0

O que aconteceu: o break (ou continue) foi usado fora de qualquer laço. O Bash avisa e ignora o comando.

O caso mais traiçoeiro é o break dentro de uma função chamada no laço. A função não "enxerga" o laço de quem a chamou:

#!/usr/bin/env bash
verifica() {
  if [[ $1 == uva ]]; then
    break
  fi
}
for fruta in banana uva maçã; do
  verifica "$fruta"
  echo "$fruta"
done

$ bash func-break.sh
banana
func-break.sh: linha 4: break: significativo apenas em um loop de `for', `while' ou `until'
uva
maçã                    « o laço não parou

Como resolver: faça a função responder com um código de saída e deixe o break no laço: verifica() { [[ $1 == uva ]]; } e, no laço, if verifica "$fruta"; then break; fi.

Coloquei break no case e o laço inteiro acabou 
$ for opcao in ver sair apagar; do
>   case $opcao in
>     sair) echo "saindo do case?"; break ;;
>     *) echo "opção: $opcao" ;;
>   esac
> done
opção: ver
saindo do case?          « "apagar" nunca foi processado

O que aconteceu: quem vem de C, Java ou JavaScript usa break para sair do switch. No Bash, o case não precisa disso: quem termina cada caso é o ;;. Um break lá dentro sai do laço em volta. Isso é ótimo num menu ("sair" encerra o laço), mas é um erro se você só queria encerrar o caso.

Como resolver: tire o break; o ;; já basta (veja case).

"número de loops fora dos limites" / "requer argumento numérico" 
$ for i in 1 2; do break 0; done
bash: break: 0: número de loops fora dos limites
$ echo $?
1
$ for i in 1 2; do break abc; done
bash: break: abc: requer argumento numérico
$ echo $?
2

O que aconteceu: o número depois de break/continue tem que ser 1 ou mais. Um número maior que a quantidade de laços não dá erro: break 5 dentro de 2 laços simplesmente sai de todos.

O break funcionou, mas a variável sumiu depois do laço

Se o laço está do lado direito de um pipe (cat arq | while read …; do …; break; done), ele roda num subshell: o break funciona, mas as variáveis criadas lá dentro (como achou) desaparecem no done. Use while …; done < arquivo, como no procura.sh. A explicação completa está em Ler Arquivos Linha a Linha.

Referência

FormaO que fazCódigo de saída
breakSai do laço mais interno.0
break NSai de N laços aninhados (N ≥ 1; N maior que o total sai de todos).0; 1 se N < 1
continuePula o resto desta volta; começa a próxima do laço mais interno.0
continue NComeça a próxima volta do N-ésimo laço, contando de dentro para fora.0; 1 se N < 1

Funcionam em for, while, until e select. Ajuda rápida no terminal: help break e help continue.

Exercícios

1. Parar no primeiro

Complete para o laço parar assim que encontrar um arquivo .pdf:

for f in Downloads/*; do [[ $f == *.pdf ]] && { echo "$f"; ; }; done

2. Pular comentários

Complete para ignorar as linhas que começam com #:

while IFS= read -r l; do [[ $l == \#* ]] && ; echo "$l"; done < config.txt

3. Sair dos dois laços

Dentro de um laço que está dentro de outro, qual comando encerra os dois de uma vez?

4. O que mostra for n in 1 2 3 4; do (( n == 3 )) && continue; echo $n; done?

5. Um break foi escrito dentro de uma função, e a função é chamada dentro de um for. O que acontece?

6. Qual destes encerra o script inteiro, e não só o laço ou a função?

Resumo

  • break sai do laço; o script segue depois do done. Use para "procurar e parar".
  • continue pula o resto desta volta e começa a próxima. Use para ignorar linhas vazias, comentários e cabeçalhos.
  • break 2 e continue 2 agem sobre o laço de fora, em laços aninhados.
  • break para o laço, return para a função, exit para o script.
  • Cuidado: continue antes do incremento trava o while; break no case sai do laço; break numa função não alcança o laço de quem chamou.
