Bash Arrays

Uma variável comum guarda um valor. Um array (em português, "vetor" ou "lista") guarda vários valores, cada um numa posição numerada. Com ele, você mantém uma lista de arquivos, de nomes ou de cidades sem se preocupar com espaços dentro dos itens.

Você vai aprender
  • Como criar um array, ler um item pelo índice e contar os itens.
  • A diferença entre "${a[@]}" e "${a[*]}", com e sem aspas (a parte mais importante da aula).
  • Como acrescentar, remover (e o "buraco" que fica), pegar fatias e percorrer.
  • Por que a=($(comando)) quebra seus dados, e o que usar no lugar.
  • Como passar um array para uma função, aplicar uma expansão em todos os itens e ordenar.

O problema que o array resolve

A Ana quer guardar a lista de cidades dos alunos numa variável. A primeira ideia é separar por espaço:

$ cidades="Recife Curitiba Porto Alegre"
$ for c in $cidades; do echo "[$c]"; done
[Recife]
[Curitiba]
[Porto]           « "Porto Alegre" virou duas cidades
[Alegre]

Uma variável comum é só um texto. O Bash não sabe onde termina um item e começa o outro: ele corta onde houver espaço (a separação de palavras). O array resolve isso: cada item fica guardado separado, numa posição própria, e continua inteiro mesmo que tenha espaços.

  índice →    0          1           2
            ┌────────┬──────────┬──────────────┐
  cidades   │ Recife │ Curitiba │ Porto Alegre │
            └────────┴──────────┴──────────────┘

As posições são chamadas de índices (do inglês index) e começam em 0, não em 1. Esse tipo de array, com índices numéricos, é o array indexado. Existe também o array com nomes no lugar dos números, o array associativo, assunto da próxima aula.

Criar um array

Você cria um array com parênteses depois do =. Os itens ficam separados por espaço.

frutas
O nome do array. Mesmas regras de nome de qualquer variável.
=
Atribuição, sem espaço dos lados (como em toda variável).
(banana maçã uva)
Os itens entre parênteses, separados por espaço. O primeiro vai para o índice 0, o segundo para o 1…
$ frutas=(banana maçã uva)
$ declare -p frutas
declare -a frutas=([0]="banana" [1]="maçã" [2]="uva")

A criação não mostra nada (e devolve código 0). Para conferir o que ficou guardado, use declare -p (print), que mostra a variável do jeito que o Bash a enxerga:

  • -a diz que é um array indexado (array).
  • Cada item aparece como [índice]="valor". Ótimo para ver exatamente o que está em cada posição.

Itens com espaço vão entre aspas, como em qualquer comando:

$ cidades=("Porto Alegre" Recife "Rio de Janeiro")
$ echo ${#cidades[@]}
3                       « três itens, não seis

As chaves não são opcionais

$ echo $frutas[1]
banana[1]               « o Bash leu $frutas e colou "[1]" como texto
$ echo $frutas
banana                  « o nome sozinho é o item 0

Sem chaves, o Bash entende $frutas (que vale o item 0) seguido do texto [1]. Escreva sempre ${frutas[1]}.

Todos os itens, contar e listar índices

$ echo ${frutas[@]}
banana maçã uva         « todos os itens
$ echo ${#frutas[@]}
3                       « quantos itens
$ echo ${!frutas[@]}
0 1 2                   « quais índices existem
$ echo ${#frutas[1]}
4                       « tamanho do item 1 ("maçã" tem 4 letras)

${frutas[@]}"todos os itens" (@ = at, "em todos")banana maçã uva
${#frutas[@]}"quantos itens" (# = número)3
${!frutas[@]}"quais índices" (! = as chaves, não os valores)0 1 2

Sem o [@], o nome do array vale o item 0. Por isso ${#frutas} devolve 6, o tamanho de "banana". Para contar itens, é sempre ${#frutas[@]}.

"${a[@]}" × "${a[*]}": com e sem aspas

Esta é a parte mais importante da aula. Existem dois jeitos de pedir "todos os itens", e cada um se comporta de forma diferente com e sem aspas. Vamos usar um array com espaços dentro dos itens e o printf '[%s]\n', que mostra cada palavra recebida entre colchetes, numa linha:

$ cidades=("Porto Alegre" Recife "Rio de Janeiro")
$ printf '[%s]\n' "${cidades[@]}"
[Porto Alegre]          « cada item virou UMA palavra, inteira
[Recife]
[Rio de Janeiro]
$ printf '[%s]\n' "${cidades[*]}"
[Porto Alegre Recife Rio de Janeiro]      « tudo colado numa palavra só
$ printf '[%s]\n' ${cidades[*]}
[Porto]                 « sem aspas: cortado em cada espaço
[Alegre]
[Recife]
[Rio]
[de]
[Janeiro]

E ${cidades[@]} sem aspas dá o mesmo estrago da última forma. O resumo:

FormaViraQuando usar
"${a[@]}"Uma palavra por item, preservando espaços e itens vazios.Quase sempre. Laços, passar para comandos e funções, copiar arrays.
"${a[*]}"Uma palavra só, com os itens unidos pelo primeiro caractere de IFS (normalmente um espaço).Para montar um texto: mensagens, juntar com vírgula.
${a[@]} e ${a[*]} sem aspasOs itens são cortados em cada espaço e passam pelos curingas.Praticamente nunca. É a origem de muitos bugs.

A mesma regra vale para "$@" e "$*" dos argumentos de um script: os argumentos são, na prática, um array.

Juntar com vírgula: o * e o IFS

O "${a[*]}" usa o primeiro caractere da variável IFS como "cola". Trocando o IFS, você junta com outro separador:

$ IFS=,; echo "${cidades[*]}"; unset IFS
Porto Alegre,Recife,Rio de Janeiro
IFS=,
Muda o separador para vírgula.
echo "${cidades[*]}"
Junta os itens numa palavra só, colando com a vírgula.
unset IFS
Devolve o IFS ao comportamento padrão. Não esqueça: um IFS trocado muda o resto da sessão.

Mais receitas de juntar e dividir texto estão em Manipular Strings.

Acrescentar e alterar itens

$ frutas=(banana maçã uva)
$ frutas+=(kiwi)                 « += com parênteses: acrescenta no fim
$ frutas[10]=limão               « grava direto no índice 10
$ declare -p frutas
declare -a frutas=([0]="banana" [1]="maçã" [2]="uva" [3]="kiwi" [10]="limão")
$ echo ${#frutas[@]}
5

Repare: os índices pularam de 3 para 10, e o array tem 5 itens, não 11. No Bash, um array pode ter buracos (o nome técnico é array esparso). As posições de 4 a 9 não existem.

frutas
O array.
+=
"Acrescente". Sem espaço dos lados.
(kiwi "pão de queijo")
Os novos itens, entre parênteses. Pode ser mais de um.
Esqueceu os parênteses? 
$ frutas=(banana maçã uva)
$ frutas+=laranja
$ declare -p frutas
declare -a frutas=([0]="bananalaranja" [1]="maçã" [2]="uva")

Sem parênteses, o += trata frutas como texto comum e cola "laranja" no fim do item 0. Para acrescentar um item, é frutas+=(laranja).

Para trocar um item, basta gravar no índice: frutas[1]=pera.

Missão: acrescente o item pão de queijo (com espaços!) ao array compras usando +=, sem mexer na linha que cria o array. A saída deve dizer Itens: 4 e listar - pão de queijo numa linha só.

#!/usr/bin/env bash

  echo "- $item"

#!/usr/bin/env bash

Remover: unset e o buraco que fica

$ cores=(azul verde vermelho)
$ unset 'cores[1]'
$ declare -p cores
declare -a cores=([0]="azul" [2]="vermelho")      « o 1 sumiu; o vermelho NÃO foi para o 1
$ echo ${#cores[@]}
2
$ echo ${cores[1]}
                         « vazio
$ echo "${!cores[@]}"
0 2
unset
Apaga uma variável ou, com índice, um item.
'cores[1]'
O item a apagar. As aspas simples protegem os colchetes (veja o porquê em "Quando não funciona").

O unset remove o item, mas não renumera os outros. Fica um buraco no índice 1. Isso é importante na hora de percorrer, como você vai ver já já. Para "fechar os buracos", recrie o array a partir dele mesmo:

$ cores=("${cores[@]}")
$ declare -p cores
declare -a cores=([0]="azul" [1]="vermelho")

Para apagar o array inteiro: unset cores. Para esvaziá-lo, mantendo a variável: cores=().

Missão: crie o array cores com azul verde vermelho, remova o verde com unset e confira com declare -p cores que o vermelho continuou no índice 2.

Fatias: ${a[@]:início:quantos}

Igual ao recorte de texto de expansão de parâmetros, mas aplicado a itens:

$ nums=(10 20 30 40 50)
$ echo "${nums[@]:1:2}"
20 30                    « a partir do índice 1, pegue 2 itens
$ echo "${nums[@]:2}"
30 40 50                 « do índice 2 até o fim
$ echo "${nums[@]: -2}"
40 50                    « os 2 últimos (repare no espaço antes do -)
nums[@]
Todos os itens.
:1
Comece no índice 1.
:2
Pegue 2 itens (opcional: sem ele, vai até o fim).
O espaço antes do número negativo 
$ echo "${nums[@]:-2}"
10 20 30 40 50

Sem o espaço, :- vira outra coisa: "valor padrão se estiver vazio". Como o array não está vazio, o Bash mostra tudo. Escreva ${nums[@]: -2}.

Uma fatia também serve para criar outro array: primeiros=("${nums[@]:0:3}").

Percorrer um array

Pelos valores (o mais comum)

$ for c in "${cidades[@]}"; do echo "[$c]"; done
[Porto Alegre]
[Recife]
[Rio de Janeiro]

Com as aspas, cada volta do for recebe um item inteiro. É a forma que você vai usar 90% das vezes.

Pelos índices: quando você precisa da posição

$ nums=(10 20 30 40 50)
$ for i in "${!nums[@]}"; do echo "$i -> ${nums[i]}"; done
0 -> 10
1 -> 20
2 -> 30
3 -> 40
4 -> 50

"${!nums[@]}" devolve os índices que existem, então funciona até com buracos.

Com contador (cuidado com os buracos)

Quem vem de outras linguagens escreve o laço clássico com contador. Ele funciona em arrays sem buracos, mas falha depois de um unset:

$ cores=(azul verde vermelho)
$ unset 'cores[1]'
$ for ((i = 0; i < ${#cores[@]}; i++)); do echo "$i: ${cores[i]}"; done
0: azul
1:                       « o 1 não existe, e o vermelho (índice 2) nunca foi visitado
$ for i in "${!cores[@]}"; do echo "$i: ${cores[i]}"; done
0: azul
2: vermelho
LaçoExemploQual usar?
Pelos valoresfor x in "${a[@]}"Quando só importa o item. É o padrão.
Pelos índicesfor i in "${!a[@]}"Quando você precisa da posição (numerar, comparar com outro array, alterar o item).
Contadorfor ((i=0; i<${#a[@]}; i++))Só se o array não tem buracos. Prefira o anterior.

Missão: mude o laço para percorrer os índices ("${!compras[@]}") e mostrar a lista numerada a partir de 1: 1. arroz, 2. feijão, 3. café. Dica: $((i + 1)).

#!/usr/bin/env bash
compras=(arroz feijão café)
for item in "${compras[@]}"; do
  echo "- $item"
done

#!/usr/bin/env bash
compras=(arroz feijão café)
for i in "${!compras[@]}"; do
  echo "$((i + 1)). ${compras[i]}"
done

Array a partir de um comando ou arquivo

A tentação é usar a=($(comando)). Veja o que acontece com a lista de tarefas da Ana, que tem uma tarefa por linha:

$ cat Documentos/notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ tarefas=($(cat Documentos/notas.txt))
$ echo ${#tarefas[@]}
12                       « eram 4 tarefas!
$ declare -p tarefas
declare -a tarefas=([0]="Comprar" [1]="café" [2]="Ligar" [3]="para" [4]="o" [5]="João" [6]="Estudar" [7]="Bash" [8]="Fazer" [9]="backup" [10]="das" [11]="fotos")

A substituição de comando sem aspas é cortada em cada espaço, não em cada linha. E é pior: cada pedaço ainda passa pelos curingas. Uma linha com um * vira a lista de arquivos da pasta:

$ echo 'nota: 5 * 2' > conta.txt
$ itens=($(cat conta.txt))
$ declare -p itens
declare -a itens=([0]="nota:" [1]="5" [2]="Área de trabalho" [3]="conta.txt" [4]="Documentos" [5]="Downloads" [6]="frutas.txt" [7]="Imagens" [8]="Modelos" [9]="Música" [10]="Público" [11]="Vídeos" [12]="2")

O jeito certo de ler uma linha por item é o mapfile:

$ mapfile -t tarefas < Documentos/notas.txt
$ declare -p tarefas
declare -a tarefas=([0]="Comprar café" [1]="Ligar para o João" [2]="Estudar Bash" [3]="Fazer backup das fotos")

Ele tem uma aula só para ele: mapfile e readarray. Para dividir uma linha em palavras, use read -ra:

$ read -ra partes <<< "ana bruno carla"
$ declare -p partes
declare -a partes=([0]="ana" [1]="bruno" [2]="carla")

Uma linha do arquivo por itemmapfile -t a < arqa=($(cat arq))

Passar um array para uma função

Uma função recebe argumentos, não variáveis. O jeito mais simples é "espalhar" o array com "${a[@]}": cada item vira um argumento, e lá dentro a função lê "$@".

#!/usr/bin/env bash
listar() {
  local titulo=$1
  shift
  echo "$titulo ($# itens):"
  printf "  - %s\n" "$@"
}
cidades=("Porto Alegre" Recife Manaus)
listar "Cidades" "${cidades[@]}"

$ bash listar.sh
Cidades (3 itens):
  - Porto Alegre
  - Recife
  - Manaus
LinhaO que faz
local titulo=$1Guarda o primeiro argumento, o título.
shiftDescarta o $1. Agora "$@" tem só os itens do array.
printf " - %s\n" "$@"O printf repete o formato para cada argumento: um item por linha.
listar "Cidades" "${cidades[@]}"Chama a função com o título e os 3 itens (com aspas, "Porto Alegre" chega inteiro).

Esse jeito entrega uma cópia dos itens. Se a função precisa alterar o array de quem chamou, passe o nome e use uma referência (local -n, o nameref):

#!/usr/bin/env bash
acrescentar() {
  local -n lista=$1      # "lista" passa a ser outro nome para o array recebido
  lista+=("$2")
}
cidades=(Recife Manaus)
acrescentar cidades Salvador
declare -p cidades

$ bash ref.sh
declare -a cidades=([0]="Recife" [1]="Manaus" [2]="Salvador")

O local -n existe desde o bash 4.3. Os detalhes (e a armadilha de usar o mesmo nome dentro e fora) estão em eval, Indireção e nameref.

Uma expansão em todos os itens

Quase todas as operações de expansão de parâmetros funcionam com [@], e são aplicadas a cada item de uma vez, sem laço:

$ arqs=(relatorio notas backup)
$ echo "${arqs[@]/%/.txt}"
relatorio.txt notas.txt backup.txt         « /% com nada antes = acrescenta no fim
$ echo "${arqs[@]/#/old_}"
old_relatorio old_notas old_backup         « /# = acrescenta no começo
$ echo "${arqs[@]^^}"
RELATORIO NOTAS BACKUP                     « tudo maiúsculo
$ echo "${arqs[@]/o/0}"
relat0rio n0tas backup                     « troca o primeiro "o" de cada item
arqs[@]
Cada item do array, separadamente.
/%
"Troque no fim do item…" (% = fim, como em ${x%.txt}).
/
Separa o que procurar (aqui, nada) do que colocar.
.txt
…por ".txt". Trocar "nada no fim" por ".txt" = acrescentar.

Com aspas e [@], o resultado continua sendo uma palavra por item, então dá para usar num laço ou passar para um comando: cp "${arqs[@]/%/.txt}" backup/.

Missão: o laço mostra só os nomes. Sem mudar a linha que cria o array, faça o for percorrer os nomes já com .jpg no fim, usando ${fotos[@]/%/.jpg}.

#!/usr/bin/env bash
fotos=(ferias perfil viagem)
for f in "${fotos[@]}"; do
  echo "$f"
done

#!/usr/bin/env bash
fotos=(ferias perfil viagem)
for f in "${fotos[@]/%/.jpg}"; do
  echo "$f"
done

Ordenar um array

O Bash não tem um comando interno para ordenar. O caminho é: imprimir um item por linha, passar pelo sort e ler de volta com mapfile.

$ frutas=(uva banana maçã laranja)
$ mapfile -t ordenadas < <(printf '%s\n' "${frutas[@]}" | sort)
$ declare -p ordenadas
declare -a ordenadas=([0]="banana" [1]="laranja" [2]="maçã" [3]="uva")
printf '%s\n' "${frutas[@]}"
Um item por linha.
| sort
Ordena as linhas (use sort -n para números, sort -r para inverter).
<(…)
Substituição de processo: a saída vira um "arquivo" que o mapfile pode ler.
mapfile -t ordenadas <
Lê uma linha por item no novo array.

Para números, lembre do -n: sem ele, 100 vem antes de 9, porque a comparação é letra a letra.

$ nums=(10 9 100 2)
$ printf '%s\n' "${nums[@]}" | sort -n | tr '\n' ' '; echo
2 9 10 100

Quando não funciona

"erro de sintaxe próximo ao token inesperado `('" 
$ frutas = (a b)
bash: erro de sintaxe próximo ao token inesperado `('

O que aconteceu: espaços em volta do =. O Bash leu frutas como um comando, e parênteses no meio de argumentos são proibidos.

Como resolver: frutas=(a b), tudo junto.

Os itens ficaram com vírgula 
$ nums=(1, 2, 3)
$ declare -p nums
declare -a nums=([0]="1," [1]="2," [2]="3")

O que aconteceu: no Bash, quem separa os itens é o espaço. A vírgula virou parte do texto.

Como resolver: nums=(1 2 3).

Apareceu banana[1] em vez de maçã

O que aconteceu: faltaram as chaves: $frutas[1]. Confirme: o texto [1] aparece colado no resultado.

Como resolver: ${frutas[1]}.

O unset não apagou nada 
$ frutas=(banana maçã uva)
$ touch frutas1                  « um arquivo qualquer com esse nome na pasta
$ unset frutas[1]
$ declare -p frutas
declare -a frutas=([0]="banana" [1]="maçã" [2]="uva")      « a maçã continua lá

O que aconteceu: sem aspas, frutas[1] é um curinga: "frutas seguido de um caractere da lista [1]". Como existe um arquivo frutas1 na pasta, o Bash trocou o curinga pelo nome do arquivo e rodou unset frutas1, uma variável que nem existia. Sem esse arquivo, o comando funcionaria, o que torna o erro ainda mais traiçoeiro.

Como resolver: sempre unset 'frutas[1]', com aspas simples.

"subscrito de array incorreto" 
$ echo ${frutas[-10]}
bash: frutas: subscrito de array incorreto
                         « o echo ainda rodou, com o valor vazio

O que aconteceu: um índice negativo maior que o tamanho do array (só há 3 itens; -10 não aponta para lugar nenhum). Índices positivos inexistentes dão vazio em silêncio; negativos fora do array dão este aviso. Gravar num índice assim (frutas[-10]=x) também falha, com bash: frutas[-10]: subscrito de array incorreto.

Como resolver: confira o tamanho com ${#frutas[@]} antes, ou use índices positivos.

"Porto Alegre" virou duas cidades

O que aconteceu: faltaram as aspas em ${cidades[@]} (num for, num comando ou ao chamar uma função). Confirme com printf '[%s]\n' ${cidades[@]}.

Como resolver: "${cidades[@]}", sempre com aspas duplas. O ShellCheck avisa esse erro (SC2068).

O array tem mais itens do que linhas no arquivo

O que aconteceu: você usou a=($(cat arquivo)), que corta em espaços e expande curingas.

Como resolver: mapfile -t a < arquivo. Veja mapfile.

6. Qual é a melhor forma de colocar cada linha de notas.txt num item do array t?

Resumo

  • Crie com a=(x y "com espaço"); os índices começam em 0; leia com ${a[i]}, sempre com chaves.
  • "${a[@]}" (com aspas) é "um item por palavra" e é o que você quer quase sempre; "${a[*]}" junta tudo num texto.
  • ${#a[@]} conta, ${!a[@]} lista os índices, declare -p a mostra tudo.
  • a+=(novo) acrescenta; unset 'a[i]' remove e deixa buraco; percorra com "${!a[@]}" quando precisar da posição.
  • Nunca a=($(comando)): use mapfile -t. Para passar a uma função, "${a[@]}" (cópia) ou local -n (referência).
