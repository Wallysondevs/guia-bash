Bash Editar a Linha

Você digitou um comando comprido e percebeu um erro lá no começo. Segurar a seta ← até chegar lá funciona, mas é lento. O Bash tem dezenas de atalhos para andar, apagar e corrigir a linha num piscar de olhos. Nesta aula você aprende os que valem a pena decorar.

Você vai aprender
  • A pular para o começo e o fim da linha e andar de palavra em palavra.
  • A apagar uma palavra, o começo ou o fim da linha, e colar de volta o que apagou.
  • A desfazer, trocar letras e limpar a tela sem perder o que está digitando.
  • A diferença entre Ctrl+C, Ctrl+D e Ctrl+Z.
  • A editar a linha num editor de verdade (Ctrl+X Ctrl+E) e a ligar o modo vi.

Quem cuida da linha: a readline

Enquanto você digita, quem controla o cursor, as setas e os atalhos é uma biblioteca do projeto GNU chamada readline ("ler linha"). Ela vem embutida no Bash e também é usada por outros programas, como o python3 interativo e o gdb. Por isso, os mesmos atalhos funcionam em vários lugares.

Os atalhos padrão vieram do editor de texto Emacs: é o "modo emacs", ligado de fábrica. No fim da aula você vai ver o "modo vi", para quem prefere o vim.

Nos exemplos abaixo, o █ marca onde está o cursor.

No terminal simulado deste guia

O simulador entende ↑ ↓ (histórico), ← →, Tab, Ctrl+A/E/U/K/Y/L/C/D/R e Alt+B/F/D (a tabela no fim da aula diz quais). Os outros são do Bash de verdade: pratique-os no terminal do seu computador. Atenção ao Ctrl+W: no navegador ele costuma fechar a aba antes de a página recebê-lo; no simulador, prefira Ctrl+U.

Digitou um comando perigoso e se arrependeu antes do Enter? Ctrl+U (com o cursor no fim) limpa a linha sem executar nada. Ctrl+C também, como você vai ver adiante.

Colar o que você apagou: Ctrl+Y

Os atalhos que apagam pedaços (Ctrl+W, Ctrl+U, Ctrl+K, Alt+D) não jogam o texto fora: guardam numa área chamada kill ring ("anel do que foi cortado"). Ctrl+Y (yank, "puxar") cola de volta onde está o cursor. É o recortar-e-colar do terminal.

Um uso clássico: você começou a digitar um comando comprido e lembrou que precisa rodar outro antes.

PassoLinhaTecla
1cp Documentos/alunos.csv backup/alunos-15-10.csv█Ctrl+U (guarda a linha)
2█digita mkdir backup e Enter
3█Ctrl+Y
4cp Documentos/alunos.csv backup/alunos-15-10.csv█Enter

Depois de um Ctrl+Y, Alt+Y troca o texto colado pelo que foi cortado antes, girando o "anel".

Isto não é a área de transferência do sistema

O Ctrl+Y só conhece o que foi cortado dentro do Bash. Para copiar e colar com outros programas, use o menu do terminal ou Ctrl+Shift+C / Ctrl+Shift+V (no Linux) e Cmd+C / Cmd+V (no macOS). Ctrl+C sozinho, no terminal, não copia: ele interrompe.

Ctrl+C, Ctrl+D e Ctrl+Z

Esses três parecem parecidos e são muito diferentes. Os dois primeiros você usa todo dia; o terceiro pega muita gente de surpresa.

AtalhoDurante a digitaçãoCom um programa rodandoCódigo de saída
Ctrl+CDescarta a linha e mostra um prompt novoInterrompe o programa (manda o sinal SIGINT)130
Ctrl+DLinha vazia: fecha o shell. Com texto: apaga a letra sob o cursorAvisa "fim da entrada" a quem está lendo do teclado—
Ctrl+ZNadaPausa o programa e devolve o prompt (ele continua na memória)148

Veja os três numa sessão real. O sleep 100 fica parado 100 segundos sem fazer nada, ótimo para treinar:

$ sleep 100
^Z                                       « Ctrl+Z: pausou
[1]+  Parado                     sleep 100
$ jobs
[1]+  Parado                     sleep 100      « o sleep ainda existe, pausado
$ fg
sleep 100                                « fg (foreground) traz de volta e continua
^C                                       « Ctrl+C: interrompeu de vez
$ echo $?
130                                      « 130 = terminou por Ctrl+C

O ^Z e o ^C são o jeito do terminal mostrar que você apertou Ctrl+Z e Ctrl+C. O [1]+ Parado diz que o programa virou o "trabalho 1" e está pausado. Pausar e retomar programas é o assunto de Jobs.

E o Ctrl+D numa linha vazia:

$                                        « Ctrl+D com a linha vazia
exit                                     « o Bash encerra, como se você digitasse exit

Os números da coluna "código de saída" seguem uma regra: 128 + o número do sinal (SIGINT é 2, SIGTSTP é 20). Isso aparece em Código de Saída e trap e Sinais.

Editar a linha num editor: Ctrl+X Ctrl+E

Para um comando muito comprido (um for de várias linhas, um find cheio de opções), editar na linha é desconfortável. Ctrl+X Ctrl+E abre o que você digitou num editor de texto de verdade. Quando você salva e fecha o editor, o Bash executa o texto.

  1. Digite o começo do comando (ou nada) e aperte Ctrl+X Ctrl+E.
  2. O editor abre com a linha dentro. O editor escolhido é o da variável VISUAL ou EDITOR; sem elas, costuma ser o nano ou o vi.
  3. Edite à vontade, com várias linhas se quiser.
  4. Salve e saia (no nano: Ctrl+O, Enter, Ctrl+X). O Bash mostra o comando e o executa.

Para desistir, apague todo o texto no editor antes de salvar: um arquivo vazio não executa nada. O comando interno fc faz o mesmo com o último comando do histórico (veja Histórico).

Modo vi

Quem usa o editor vim pode preferir editar a linha do mesmo jeito. O comando set -o vi troca os atalhos:

set
Comando interno que liga e desliga opções do Bash.
-o
"Ligue a opção com este nome" (option).
vi
A opção: edição de linha no estilo do vi. set -o emacs volta ao padrão.
$ set -o | grep -E "^(vi|emacs)"
emacs          	on                       « o padrão
vi             	off
$ set -o vi
$ set -o | grep -E "^(vi|emacs)"
emacs          	off
vi             	on                       « agora é o modo vi
$ set -o emacs                           « de volta ao padrão

No modo vi, você começa digitando normalmente (modo de inserção). Esc passa para o modo de comando, onde h l andam, w b pulam palavras, 0 e $ vão ao começo e ao fim, x apaga uma letra, dw uma palavra, i e a voltam a inserir, k e j navegam no histórico e v abre o editor. Para deixar ligado sempre, coloque set -o vi no ~/.bashrc (Arquivos de Inicialização).

Descobrir e conferir os atalhos: bind

Os atalhos são configuráveis, e cada sistema pode ter alguns diferentes. O comando interno bind mostra o que está valendo. Com -q (query, "consultar") e o nome de uma ação, ele diz quais teclas a fazem:

$ bind -q unix-word-rubout
unix-word-rubout pode ser chamado via "\C-w".
$ bind -q yank
yank pode ser chamado via "\C-y".
$ bind -q undo
undo pode ser chamado via "\C-x\C-u", "\C-_".
$ bind -q edit-and-execute-command
edit-and-execute-command pode ser chamado via "\C-x\C-e".

Leia \C-w como Ctrl+W e \e (ou \M-) como Alt/Esc. Os nomes das ações (yank, undo…) são os do manual da readline; bind -P lista todos. Mudar atalhos é feito no arquivo ~/.inputrc.

Quando não funciona

O terminal "congelou" e não mostra o que eu digito

O que aconteceu: provavelmente você apertou Ctrl+S, que é um atalho antigo de "pausar a tela" (controle de fluxo). Tudo o que você digita fica guardado, mas não aparece.

Como resolver: aperte Ctrl+Q para soltar. O que você digitou durante a pausa aparece de uma vez. Para desligar esse comportamento, coloque stty -ixon no ~/.bashrc.

Alt+B ou Alt+F abre o menu do terminal

O que aconteceu: o programa de terminal usa Alt+letra para abrir os menus (Arquivo, Editar…) e "rouba" o atalho.

Como resolver: use Esc e depois a letra, ou Ctrl+←/→. Nas preferências do terminal, desligue os "atalhos de menu". No macOS, ative "Usar Option como tecla Meta".

Fechei o terminal sem querer

O que aconteceu: Ctrl+D numa linha vazia encerra o shell, e a janela fecha junto.

Como evitar: set -o ignoreeof faz o Bash ignorar o Ctrl+D e mostrar Use "exit" para sair do shell.. Coloque no ~/.bashrc se acontecer com frequência.

Apertei Ctrl+Z no lugar de Ctrl+C e o programa "sumiu" 
$ sleep 100
^Z
[1]+  Parado                     sleep 100

O que aconteceu: o programa não terminou: está pausado em segundo plano. Se você tentar sair do terminal, o Bash avisa que há trabalhos parados.

Como resolver: fg traz o programa de volta; aí use Ctrl+C. Ou kill %1 para encerrá-lo direto (Jobs).

Resumo

  • A edição da linha é feita pela readline, com atalhos do Emacs: Ctrl+A/E (começo/fim), Alt+B/F (palavras).
  • Ctrl+W, Ctrl+U e Ctrl+K recortam; Ctrl+Y cola; Ctrl+_ desfaz.
  • Ctrl+C interrompe, Ctrl+D fecha o shell (linha vazia), Ctrl+Z pausa.
  • Ctrl+X Ctrl+E edita a linha num editor; set -o vi liga o modo vi.
  • bind -q ação mostra quais teclas fazem cada ação.
