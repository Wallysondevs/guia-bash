Bash alias

Um alias (em inglês, "apelido") é um nome curto que o Bash troca por um comando mais comprido antes de executar. Com ele, ll vira ls -alF e docs vira cd ~/Documentos. É a forma mais simples de deixar o terminal com a sua cara, e também a mais limitada: nesta aula você vê o que ele faz bem e quando trocar por uma função.

Você vai aprender
  • Criar, listar e remover aliases (alias, unalias), com as aspas certas.
  • Por que um alias não aceita argumento "no meio" e como uma função resolve.
  • Por que aliases não funcionam em scripts (e o expand_aliases).
  • Como pular um alias: \comando, command e o caminho completo.
  • Onde guardar seus aliases para sempre (~/.bashrc, ~/.bash_aliases).

Você já usa aliases

A Ana nunca criou um alias, mas o .bashrc dela já trouxe cinco (veja arquivos de inicialização). O comando alias sozinho lista todos:

$ alias
alias grep='grep --color=auto'
alias l='ls -CF'
alias la='ls -A'
alias ll='ls -alF'
alias ls='ls --color=auto'

Cada linha está no formato em que o alias foi criado: alias nome='comando', em ordem alfabética. Repare em alias ls='ls --color=auto': quando a Ana digita ls, o Bash troca por ls --color=auto, e é por isso que as pastas aparecem coloridas. O alias tem o mesmo nome do comando, e o Bash não entra em loop: ele não troca de novo uma palavra que acabou de vir do mesmo alias.

Para ver um alias só, passe o nome; para saber o que um nome é, use type:

$ alias ll
alias ll='ls -alF'
$ type ll
ll está apelidada para `ls -alF'       « "apelidada" = é um alias

Criar um alias

A Ana vive entrando na pasta Documentos. Ela cria um atalho:

alias
O comando interno que cria (ou mostra) apelidos.
docs
O nome novo. Letras, números, _, - e até . valem; espaços e / não.
=
Grudado nos dois lados, sem espaço, como numa variável.
'cd ~/Documentos'
O texto que vai entrar no lugar de docs. Entre aspas, porque tem espaço.
$ alias docs='cd ~/Documentos'
$ docs

Nada apareceu, e está certo: o cd não escreve nada quando dá certo. O prompt, porém, mudou de pasta:

$ pwd
/home/ana/Documentos

O alias também não responde nada ao criar. O código de saída é 0 quando deu certo e 1 quando você pede um alias que não existe:

$ alias xyz
bash: alias: xyz: não encontrado
$ echo $?
1

O que acontece por baixo

Quando você aperta Enter, o Bash olha a primeira palavra de cada comando. Se ela é o nome de um alias, ele troca a palavra pelo texto do alias e só então continua lendo a linha. O resto do que você digitou fica onde estava, depois do texto do alias:

$ alias diga='echo Olá'
$ diga Ana e Bruno
Olá Ana e Bruno                « virou: echo Olá Ana e Bruno

Três consequências dessa regra:

  • Só a primeira palavra do comando é trocada. Em echo ll, o ll é só um texto.
  • Os argumentos sempre vão para o fim. Isso é ótimo para ll Documentos, e é exatamente o limite do alias (veja "Alias × função").
  • A troca acontece quando a linha é lida. Um alias criado numa linha só vale a partir da linha seguinte (veja "Quando não funciona").

Missão: crie o alias docs que entra na pasta ~/Documentos e use-o. Confira com pwd e com type docs.

As aspas no alias

Sem aspas, o alias para no primeiro espaço

$ alias hoje=date +%F
bash: alias: +%F: não encontrado
$ alias hoje
alias hoje='date'                « só o "date" entrou

Sem aspas, o Bash separou em duas palavras: hoje=date (criou o alias hoje = date) e +%F (tentou mostrar um alias chamado +%F, que não existe). Com aspas, o texto inteiro vira uma palavra só:

$ alias hoje='date +%F'
$ hoje
2026-10-15

Aspas simples × duplas

Aqui está uma armadilha. A Ana quer um alias que diga em que pasta ela está. Primeiro, com aspas duplas:

$ alias onde="echo Você está em $PWD"
$ alias onde
alias onde='echo Você está em /home/ana'     « o $PWD já foi trocado!
$ cd Documentos
$ onde
Você está em /home/ana                       « errado: estamos em Documentos

Aspas duplas deixam a variável ser trocada pelo valor (veja aspas). O $PWD foi trocado na hora de criar o alias, quando a Ana estava em /home/ana, e esse texto fixo ficou guardado. Com aspas simples, o $PWD é guardado como está e só é trocado quando o alias é usado:

$ alias onde='echo Você está em $PWD'
$ alias onde
alias onde='echo Você está em $PWD'          « guardou o $PWD, não o valor
$ cd Documentos
$ onde
Você está em /home/ana/Documentos
Regra prática

Use sempre aspas simples no alias. Se o comando tiver uma aspa simples dentro, troque por uma função, que é mais fácil de escrever do que escapar aspas.

Remover: unalias

unalias
Apaga um alias do shell atual (un = desfazer).
docs
O nome do alias, sem =.
$ unalias docs
$ docs
bash: docs: comando não encontrado
$ unalias docs
bash: unalias: docs: não encontrado       « já não existia

unalias -a apaga todos os aliases do shell atual. Nada disso mexe no .bashrc: ao abrir um terminal novo, os aliases do arquivo voltam. Para remover um alias "para sempre", apague a linha dele do arquivo.

Para mudar um alias, basta criá-lo de novo com o mesmo nome: o novo substitui o antigo, sem aviso.

$ alias ll='ls -lh'
$ alias ll
alias ll='ls -lh'

Pular um alias

Um alias com o mesmo nome de um comando "esconde" o comando original. Às vezes você quer o original. Exemplo clássico: muita gente cria alias rm='rm -i', para o rm pedir confirmação:

$ alias rm='rm -i'
$ touch teste.txt
$ rm teste.txt
rm: remover regular empty file 'teste.txt'? n      « a Ana respondeu n (não)
$ ls teste.txt
teste.txt

A pergunta (que saiu meio em inglês, por causa da tradução incompleta do rm) evitou a remoção. Mas, num momento em que ela tem certeza, a confirmação atrapalha. Uma barra invertida antes do nome desliga o alias só naquela vez:

$ \rm teste.txt
$ ls teste.txt
ls: não foi possível acessar 'teste.txt': Arquivo ou diretório inexistente

O type -a mostra tudo o que existe com um nome, na ordem em que o Bash procura. O primeiro da lista é o que roda:

$ type -a rm
rm está apelidada para `rm -i'     « 1º: o alias
rm é /usr/bin/rm                   « 2º: o programa
rm é /bin/rm                       « o mesmo programa, por outro caminho

$ \ls -d Doc*
Documentos
$ command ls -d Doc*
Documentos
$ /usr/bin/ls -d Doc*
Documentos

As três deram o mesmo resultado, só que sem o --color=auto do alias. A ordem completa em que o Bash procura um nome (alias, palavra-chave, função, comando interno, PATH) é o assunto de PATH e onde os comandos moram.

Não confie no rm -i

Quem se acostuma com o alias rm='rm -i' passa a digitar rm sem cuidado. Num servidor, no root ou num script, o alias não existe e o arquivo vai embora sem pergunta. A segurança está em conferir antes (veja apagar com segurança).

Alias × função: o argumento no meio

A Ana quer um atalho busca PALAVRA que procure a palavra, ignorando maiúsculas, no arquivo de frutas. Ela tenta com $1, como num script:

$ alias busca='grep -i "$1" frutas.txt'
$ busca BANANA
frutas.txt:banana
frutas.txt:maçã
frutas.txt:laranja
frutas.txt:banana
frutas.txt:uva
frutas.txt:maçã
frutas.txt:banana
grep: BANANA: Arquivo ou diretório inexistente

Deu tudo errado, e dá para entender lendo como o Bash montou o comando: o alias não tem $1 (o $1 do terminal está vazio) e o argumento foi para o fim. O comando que rodou foi grep -i "" frutas.txt BANANA: procurar "nada" (que casa com todas as linhas) em dois arquivos, frutas.txt e BANANA. Por isso cada linha veio com o nome do arquivo na frente, e o grep reclamou que o arquivo BANANA não existe.

Outro exemplo do mesmo problema, mais curto:

$ alias saud='echo "Olá, $1. Tudo bem?"'
$ saud Ana
Olá, . Tudo bem? Ana            « o Ana foi parar no fim

Quando o argumento precisa ir no meio, use uma função. Numa função, $1 é mesmo o primeiro argumento:

busca()
Define uma função chamada busca.
{ grep -i "$1" ~/frutas.txt; }
O corpo: o $1 é trocado pelo primeiro argumento. Repare no espaço depois de { e no ; antes de }.
$ unalias busca                « primeiro, apague o alias de mesmo nome
$ busca() { grep -i "$1" ~/frutas.txt; }
$ busca BANANA
banana
banana
banana

Por que apagar o alias antes? Porque, na linha de definição, a primeira palavra busca ainda era um alias e foi trocada. Sem o unalias, o Bash recusa com um erro de sintaxe (está em "Quando não funciona").

Um detalhe curioso: veja o corpo da função guardado pelo Bash.

$ type busca
busca é uma função
busca ()
{
    grep --color=auto -i "$1" ~/frutas.txt
}

O grep virou grep --color=auto: o alias do grep foi aplicado quando a função foi definida, não quando ela roda.

Qual usar?

AliasFunção
ArgumentosSó no fim, do jeito que vieramEm qualquer lugar: $1, $2, "$@"
Várias linhas, if, laçosNão (tudo numa linha, difícil de ler)Sim
Variáveis própriasNãoSim, com local
Em scriptsDesligado por padrãoFunciona sempre
Ideal paraTrocar um nome por um comando com opções fixas: ll, la, ..Todo o resto

O próprio manual do Bash diz: "para quase todos os fins, aliases foram superados por funções". Use alias para o simples; ao primeiro $1, mude para função.

Missão: um atalho que cria uma pasta e já entra nela precisa do nome duas vezes, então não dá para fazer com alias. Crie a função mkcd que rode mkdir -p "$1" && cd "$1". Depois entre em Documentos e use mkcd fotos.

Aliases não funcionam em scripts

A Ana escreve um script que cria e usa um alias:

#!/usr/bin/env bash
alias contar="wc -l"
contar frutas.txt

$ bash atalhos.sh
atalhos.sh: linha 3: contar: comando não encontrado
$ echo $?
127

O alias foi criado sem erro na linha 2, mas a linha 3 não o usou. O motivo é uma opção chamada expand_aliases ("expandir aliases"), que vem ligada no shell interativo e desligada nos scripts:

$ shopt expand_aliases
expand_aliases      	on
$ bash -c "shopt expand_aliases"
expand_aliases      	off

Dá para ligar no script com shopt -s expand_aliases (o -s é de set, ligar), antes de criar o alias:

#!/usr/bin/env bash
shopt -s expand_aliases
alias contar="wc -l"
contar frutas.txt

$ bash atalhos2.sh
7 frutas.txt

Funciona, mas quase nunca é a melhor escolha: em script, uma função ou o comando completo deixa o código mais claro. E lembre: mesmo com expand_aliases, o script não lê o seu .bashrc, então os aliases de lá (ll, la…) não existem nele:

$ cat usa-ll.sh
#!/usr/bin/env bash
ll Documentos
$ bash usa-ll.sh
usa-ll.sh: linha 2: ll: comando não encontrado

Missão: este script falha com "contar: comando não encontrado". Conserte de um dos dois jeitos: ligando a opção que permite aliases em script, ou trocando o alias por uma função contar(). Rode até aparecer 7 frutas.txt.

#!/usr/bin/env bash
cd ~
alias contar="wc -l"
contar frutas.txt

#!/usr/bin/env bash
cd ~
contar() { wc -l "$@"; }
contar frutas.txt

Guardar para sempre

Um alias criado no terminal some quando o terminal fecha. Para valer sempre, escreva a linha alias … num arquivo que o Bash lê ao abrir. Há dois lugares comuns:

1. No próprio ~/.bashrc

É onde estão os aliases que a Ana já tem. Acrescente no fim do arquivo (com um editor ou com >>, nunca com um > só, que apagaria o arquivo) e aplique com source ~/.bashrc. O passo a passo, e o que fazer se o arquivo quebrar, estão em arquivos de inicialização.

2. Num arquivo separado: ~/.bash_aliases

Quando a lista cresce, fica mais organizado guardar os aliases num arquivo só para eles. O .bashrc do Debian e do Ubuntu já vem com o trecho que carrega esse arquivo; o da Ana é uma versão curta e não tem, então ela acrescenta:

$ cat >> ~/.bashrc <<'FIM'
>
> # aliases pessoais ficam num arquivo separado
> if [ -f ~/.bash_aliases ]; then
>     . ~/.bash_aliases
> fi
> FIM
if [ -f ~/.bash_aliases ]
"Se o arquivo existir…" (-f = é um arquivo). Sem o teste, o .bashrc daria erro enquanto o arquivo não existisse.
. ~/.bash_aliases
…leia o arquivo aqui mesmo (o ponto é o source).

Agora cada alias novo vai para o arquivo próprio:

$ echo "alias ..='cd ..'" >> ~/.bash_aliases
$ echo "alias contar='wc -l'" >> ~/.bash_aliases
$ cat ~/.bash_aliases
alias ..='cd ..'
alias contar='wc -l'
$ source ~/.bashrc
$ alias
alias ..='cd ..'                  « os dois novos
alias contar='wc -l'
alias grep='grep --color=auto'
alias l='ls -CF'
alias la='ls -A'
alias ll='ls -alF'
alias ls='ls --color=auto'
$ contar frutas.txt
7 frutas.txt
Um alias que faz backup de si mesmo

Ao copiar seus aliases para outra máquina, leve o ~/.bash_aliases (e o trecho do .bashrc que o carrega). O projeto Seus Dotfiles mostra como manter esses arquivos versionados.

Quando não funciona

"alias: =: não encontrado" 
$ alias ll = 'ls -l'
alias ll='ls -alF'
bash: alias: =: não encontrado
bash: alias: ls -l: não encontrado

O que aconteceu: com espaços em volta do =, o Bash recebeu três palavras: ll, = e ls -l. Para cada uma ele tentou mostrar o alias com aquele nome: o ll existia (primeira linha), os outros não.

Como resolver: alias ll='ls -l', sem espaços em volta do =.

Criei o alias e usei na mesma linha: "comando não encontrado" 
$ alias oi='echo oi'; oi
bash: oi: comando não encontrado
$ oi
oi

O que aconteceu: o Bash troca os aliases quando lê a linha, antes de executar qualquer parte dela. Quando ele leu o oi do fim, o alias ainda não tinha rodado. Na linha seguinte, o alias já existia.

Como resolver: crie o alias numa linha e use nas próximas. O mesmo vale dentro de uma função ou de um bloco if: o alias criado lá dentro só vale para as linhas lidas depois do bloco inteiro.

"erro de sintaxe próximo ao token inesperado `('" ao criar uma função 
$ alias mkcd='mkdir -p "$1" && cd "$1"'
$ mkcd() { mkdir -p "$1" && cd "$1"; }
bash: erro de sintaxe próximo ao token inesperado `('

O que aconteceu: já existia um alias com o nome da função. Na linha de definição, mkcd foi trocado pelo texto do alias, e o Bash leu mkdir -p "$1" && cd "$1"() {…, que não faz sentido.

Como confirmar: type mkcd diz "está apelidada para…".

Como resolver: unalias mkcd e defina a função de novo. Se o alias vem do .bashrc, apague a linha lá também, senão o problema volta no próximo terminal. Outra saída é definir com a palavra function: function mkcd { …; }.

O alias funciona no terminal, mas não no script (ou no sudo) 
$ bash usa-ll.sh
usa-ll.sh: linha 2: ll: comando não encontrado

O que aconteceu: scripts não leem o .bashrc e têm expand_aliases desligado. Com sudo ll acontece algo parecido: o alias só é trocado na primeira palavra, que ali é o sudo, e o root não conhece o ll.

Como resolver: no script, escreva o comando completo (ls -alF) ou use uma função. Para o sudo, existe um truque: um alias que termina com espaço faz o Bash verificar também a palavra seguinte. Com alias sudo='sudo ' no .bashrc, sudo ll vira sudo ls -alF.

Apaguei o alias do .bashrc, mas ele continua

O que aconteceu: o shell aberto ainda tem o alias na memória. O source ~/.bashrc não apaga nada: ele só executa o que está no arquivo.

Como resolver: unalias nome no terminal aberto, ou abra um terminal novo (ou exec bash).

Resumo

  • alias nome='comando' cria (sem espaço no =, com aspas simples); alias lista; unalias remove.
  • O Bash troca só a primeira palavra, quando lê a linha, e os argumentos vão sempre para o fim.
  • Argumento no meio, várias linhas ou uso em script: escreva uma função.
  • Scripts não leem o .bashrc e têm expand_aliases desligado.
  • \comando pula o alias; command comando pula alias e função.
  • Para valer sempre: ~/.bashrc ou ~/.bash_aliases, e depois source ~/.bashrc.
