Bash case

Quando você precisa comparar um único valor com várias possibilidades ("a opção foi 1, 2 ou 3?", "o arquivo é .jpg, .pdf ou .mp3?"), uma escada de if/elif fica longa e repetitiva. O case ("caso", em inglês) faz isso de forma limpa: você escreve o valor uma vez e lista os padrões, um embaixo do outro.

Você vai aprender
  • A estrutura case … in … esac, com ) e ;;.
  • Padrões com curingas, várias opções com | e o padrão "todo o resto", *).
  • Os finais ;;, ;& e ;;&, e o shopt -s nocasematch.
  • Usos clássicos: menus, start|stop|restart, tipos de arquivo.
  • Quando usar case e quando usar if/elif.

O problema: muitos elif para o mesmo valor

Imagine um script que recebe uma ação. Com if, cada linha repete a variável e o teste:

if [[ $1 == start ]]; then
  echo "Iniciando"
elif [[ $1 == stop ]]; then
  echo "Parando"
elif [[ $1 == restart || $1 == reload ]]; then
  echo "Reiniciando"
else
  echo "Uso: ..."
fi

Com case, o valor aparece uma vez e as opções ficam alinhadas, como um cardápio.

A estrutura

case VALOR in
  PADRÃO1)
    comandos
    ;;
  PADRÃO2|PADRÃO3)
    comandos
    ;;
  *)
    comandos para todo o resto
    ;;
esac
case
Começa a escolha.
$fruta
O valor a examinar (pode ser variável, argumento, texto).
in
"Em": a seguir vêm os casos.
banana)
Um padrão, terminado por ). Se o valor casar com ele, os comandos depois do ) rodam.
echo "amarela"
Os comandos desse caso (um ou vários).
;;
Fim do caso: "pare aqui e vá para o esac".
esac
Fim do case. É case ao contrário, como fi é if ao contrário.
$ fruta=banana
$ case $fruta in
>   banana) echo "amarela" ;;
>   uva) echo "roxa" ;;
> esac
amarela

O Bash compara o valor com os padrões de cima para baixo e roda só o primeiro que casar. Se nenhum casar, nada acontece, e o código de saída é 0:

$ case $fruta in kiwi) echo "verde" ;; esac; echo "código: $?"
código: 0

Como no exemplo acima, um caso curto pode ficar numa linha só: padrão) comando ;;.

Exemplo clássico: start|stop|restart

Scripts que controlam serviços costumam receber uma ação como primeiro argumento. Este é o formato que você vai ver em muitos scripts de sistema:

#!/usr/bin/env bash
case $1 in
  start)
    echo "Iniciando o serviço..."
    ;;
  stop)
    echo "Parando o serviço..."
    ;;
  restart|reload)
    echo "Reiniciando o serviço..."
    ;;
  *)
    echo "Uso: $0 {start|stop|restart}" >&2
    exit 1
    ;;
esac
LinhaO que faz
2Examina o 1º argumento.
3–5Se for exatamente start: mostra a mensagem e para no ;;.
9restart|reload: a barra quer dizer "ou". Qualquer um dos dois cai aqui.
12*): o curinga * casa com qualquer coisa, inclusive vazio. Por estar por último, pega "todo o resto", como o else.
13–14Mostra o uso correto no canal de erros e sai com código 1. A mensagem {start|stop|restart} é só texto, uma convenção para "escolha um destes".
$ bash servico.sh start
Iniciando o serviço...
$ bash servico.sh reload
Reiniciando o serviço...
$ bash servico.sh xyz
Uso: servico.sh {start|stop|restart}
$ echo $?
1
$ bash servico.sh
Uso: servico.sh {start|stop|restart}       « sem argumento, $1 vazio também cai no *)

Padrões com curingas

Os padrões do case são os mesmos curingas dos nomes de arquivos (e do == em [[ ]]), mas aplicados ao texto, não aos arquivos da pasta:

PadrãoCasa comExemplo
*qualquer texto, até vazio*.jpg) → foto.jpg, .jpg
?exatamente um caractere??) → ab, 42
[abc]um caractere da lista[sS]) → s ou S
[a-z], [0-9]um caractere do intervalo[0-9]) → um dígito
a|ba ou bq|Q)
"texto"o texto literal (aspas desligam os curingas)"*") → só um asterisco
$ case 7 in [0-9]) echo "um dígito" ;; [0-9][0-9]) echo "dois dígitos" ;; esac
um dígito
$ case 42 in [0-9]) echo "um dígito" ;; [0-9][0-9]) echo "dois dígitos" ;; esac
dois dígitos
$ case foto.jpg in "*.jpg") echo "literal" ;; *.jpg) echo "padrão" ;; esac
padrão                « "*.jpg" entre aspas só casaria com o texto *.jpg
[1-12] não é "de 1 a 12" 
$ case 12 in [1-12]) echo "1 a 12?" ;; *) echo "não" ;; esac
não

Colchetes sempre representam um único caractere. [1-12] quer dizer "o caractere 1 a 1, ou o 2", e 12 tem dois caracteres. Para faixas de números, use if com (( )).

Tipos de arquivo pela extensão

#!/usr/bin/env bash
for arq in "$@"; do
  case $arq in
    *.jpg|*.jpeg|*.png) tipo="imagem" ;;
    *.mp3|*.ogg)        tipo="música" ;;
    *.pdf|*.odt)        tipo="documento" ;;
    *.zip|*.tar.gz)     tipo="compactado" ;;
    *)                  tipo="desconhecido" ;;
  esac
  echo "$arq: $tipo"
done

O for passa por cada argumento (ele é o assunto de for); para cada um, o case escolhe o tipo. Alinhar os comandos em coluna, como acima, deixa a tabela fácil de ler.

$ bash tipo.sh Downloads/* Imagens/* frutas.txt
Downloads/foto.jpg: imagem
Downloads/fotos-viagem.zip: compactado
Downloads/manual.pdf: documento
Downloads/musica.mp3: música
Downloads/ubuntu-26.04-desktop-amd64.iso: desconhecido
Imagens/ferias.jpg: imagem
Imagens/perfil.png: imagem
frutas.txt: desconhecido

Repare que o padrão casa com o valor inteiro, incluindo a pasta: *.jpg casa com Downloads/foto.jpg porque o * engole Downloads/foto (no case, o * passa por cima da /).

Respostas do usuário: sim ou não

Com colchetes, você aceita maiúsculas e minúsculas sem repetir cada combinação. O read (de Ler do Teclado) guarda o que a pessoa digitou:

#!/usr/bin/env bash
read -p "Continuar? (s/n) " resp
case $resp in
  [sS]|[sS][iI][mM]) echo "Continuando" ;;
  [nN]|[nN][aã][oO]) echo "Cancelado" ;;
  "")                echo "Você não respondeu" ;;
  *)                 echo "Resposta inválida: $resp" ;;
esac

$ bash resp.sh
Continuar? (s/n) SIM
Continuando
$ bash resp.sh
Continuar? (s/n) Não
Cancelado
$ bash resp.sh
Continuar? (s/n) talvez
Resposta inválida: talvez
$ bash resp.sh
Continuar? (s/n)
Você não respondeu        « só apertou Enter: o valor vazio casa com ""

Ignorar maiúsculas: shopt -s nocasematch

Escrever [sS][iI][mM] cansa. A opção nocasematch (no case match, "não diferencie a caixa") faz o case e o [[ == ]] ignorarem maiúsculas e minúsculas:

$ resp=SIM
$ case $resp in sim) echo "casou" ;; *) echo "não casou" ;; esac
não casou
$ shopt -s nocasematch
$ case $resp in sim) echo "casou" ;; *) echo "não casou" ;; esac
casou
$ [[ $resp == sim ]] && echo "também no [[ ]]"
também no [[ ]]
$ shopt -u nocasematch                    « -u desliga (unset)

A opção vale até ser desligada (ou até o script terminar). Outra saída é converter antes: case ${resp,,} in (minúsculas, veja Expansão de Parâmetros). Mais opções do shopt em Opções do Shell.

Missão: o script só aceita s ou sim em minúsculas, e a resposta SIM cai em "inválida". Faça ele aceitar qualquer combinação de maiúsculas e minúsculas, com shopt -s nocasematch ou com ${resp,,}.

#!/usr/bin/env bash
read -p "Continuar? (s/n) " resp
case $resp in
  s|sim) echo "Continuando" ;;
  n|não) echo "Cancelado" ;;
  *)     echo "Resposta inválida: $resp" ;;
esac

#!/usr/bin/env bash
shopt -s nocasematch
read -p "Continuar? (s/n) " resp
case $resp in
  s|sim) echo "Continuando" ;;
  n|não) echo "Cancelado" ;;
  *)     echo "Resposta inválida: $resp" ;;
esac

Um menu de opções

Juntando echo, read e case, você tem um menu simples:

#!/usr/bin/env bash
echo "1) Listar Documentos"
echo "2) Contar frutas"
echo "3) Ver a data"
echo "q) Sair"
read -p "Escolha: " op

case $op in
  1)   ls Documentos ;;
  2)   echo "A lista tem $(wc -l < frutas.txt) frutas" ;;
  3)   date +%d/%m/%Y ;;
  q|Q) echo "Até logo!" ;;
  *)   echo "Opção inválida: $op" ;;
esac

$ bash menu.sh
1) Listar Documentos
2) Contar frutas
3) Ver a data
q) Sair
Escolha: 2
A lista tem 7 frutas
$ bash menu.sh
1) Listar Documentos
2) Contar frutas
3) Ver a data
q) Sair
Escolha: 9
Opção inválida: 9

Para o menu voltar a aparecer depois de cada escolha, ele vai dentro de um laço while. O Bash também tem um comando pronto para menus, o select, visto em Menus e Cores.

Brinque: mude o valor da entrada e rode. Depois acrescente uma opção 4) que mostre o conteúdo de Documentos/notas.txt.

#!/usr/bin/env bash
echo "1) Listar Documentos"
echo "2) Contar frutas"
echo "3) Ver a data"
echo "q) Sair"
read -p "Escolha: " op

case $op in
  1)   ls Documentos ;;
  2)   echo "A lista tem $(wc -l < frutas.txt) frutas" ;;
  3)   date +%d/%m/%Y ;;
  q|Q) echo "Até logo!" ;;
  *)   echo "Opção inválida: $op" ;;
esac

Os três finais: ;; ;& ;;&

Quase sempre você vai usar ;;. Os outros dois existem para casos especiais bash 4.0+:

FinalDepois deste caso…Uso
;;…sai do case.O normal.
;&…roda também os comandos do próximo caso, sem testar o padrão dele ("cair", fall through).Níveis que acumulam.
;;&…continua testando os padrões seguintes, e roda os que casarem.Várias classificações para o mesmo valor.

;&: o nível 2 faz o que é do nível 2 e tudo o que é dos níveis abaixo:

$ nivel=2
$ case $nivel in
>   3) echo "- apagar logs antigos" ;&
>   2) echo "- compactar logs" ;&
>   1) echo "- listar logs" ;;
> esac
- compactar logs
- listar logs

;;&: o mesmo caractere passa por todos os testes:

$ c=a
$ case $c in
>   [a-z]) echo "letra minúscula" ;;&
>   [aeiou]) echo "vogal" ;;&
>   *) echo "um caractere qualquer" ;;
> esac
letra minúscula
vogal
um caractere qualquer

Esses dois finais não existem no Bash 3.2 do macOS nem no sh. Se precisar de portabilidade, repita os comandos ou use ifs separados.

case × if/elif

SituaçãoUsePor quê
Um valor, várias opções fixas (start, stop…)caseO valor aparece uma vez; as opções ficam alinhadas.
Padrões de texto (*.jpg, [sS]*)casePadrões são nativos; com | fica curto.
Faixas de números (nota >= 7)if/elifO case só compara texto com padrão.
Testes de arquivo (-f, -d)ifO case não roda comandos para decidir.
Condições sobre coisas diferentes ($1 e depois $idade)if/elifCada ramo pode testar algo diferente.
Testar se um comando deu certo (grep -q)ifSó o if olha códigos de saída.
Script que precisa rodar em shos doiscase é POSIX (sem ;&/;;&), e evita depender de [[ ]].

Quando não funciona

Esqueceu o ;; 
#!/usr/bin/env bash
case $1 in
  start) echo "Iniciando"
  stop)  echo "Parando" ;;
esac

$ bash c1.sh start
c1.sh: linha 4: erro de sintaxe próximo ao token inesperado `)'
c1.sh: linha 4: `  stop)  echo "Parando" ;;'

O que aconteceu: sem o ;;, o Bash achou que stop era mais um argumento do echo da linha 3, e o ) ficou sem sentido. O erro aponta para a linha seguinte à que tem o problema.

Como resolver: termine cada caso com ;;. (Só no último caso antes do esac o ;; é opcional, mas é bom costume pôr sempre.)

Esqueceu o ) 
$ bash c2.sh start
c2.sh: linha 3: erro de sintaxe próximo ao token inesperado `echo'
c2.sh: linha 3: `  start echo "Iniciando" ;;'

O que aconteceu: depois do padrão start o Bash esperava ) (ou |), e encontrou echo.

Como resolver: start) echo "Iniciando" ;;.

Esqueceu o esac 
#!/usr/bin/env bash
case $1 in
  start) echo "Iniciando" ;;
  stop)  echo "Parando" ;;

echo fim

$ bash c3.sh start
c3.sh: linha 6: erro de sintaxe próximo ao token inesperado `fim'
c3.sh: linha 6: `echo fim'

O que aconteceu: sem o esac, o Bash continuou dentro do case e leu echo como se fosse mais um padrão; depois dele esperava ) e encontrou fim. Se o case for a última coisa do arquivo, a mensagem muda para "fim inesperado do arquivo".

Como resolver: feche com esac.

Esqueceu o in 
$ bash c4.sh start
c4.sh: linha 3: erro de sintaxe próximo ao token inesperado `start'
c4.sh: linha 3: `  start) echo "Iniciando" ;;'

Como resolver: case $1 in, sempre com o in na mesma linha.

Sempre cai no *) (ou num caso errado)

O que aconteceu: causas comuns: o *) está antes dos outros casos (ele casa com tudo, então os de baixo nunca rodam); maiúsculas e minúsculas diferentes (SIM × sim); espaço no fim do valor ("sim "); padrão entre aspas, que desliga os curingas.

Como confirmar: mostre o valor entre colchetes antes do case: echo "[$resp]".

Como resolver: deixe o *) por último, use nocasematch ou ${resp,,}, e tire as aspas dos padrões que usam curingas.

Resumo

  • case VALOR in padrão) comandos ;; esac: compara um valor com padrões, de cima para baixo, e roda só o primeiro que casar.
  • | junta opções; *) no fim pega todo o resto; curingas (* ? [ ]) funcionam nos padrões.
  • ;; encerra o caso; ;& cai no próximo; ;;& continua testando (bash 4+).
  • shopt -s nocasematch ou ${var,,} para ignorar maiúsculas.
  • case para opções e padrões de texto; if para números, arquivos e códigos de saída.
