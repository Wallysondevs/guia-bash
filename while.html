Bash while e until

O for repete para cada item de uma lista que você já tem. O while repete enquanto uma condição for verdadeira, sem saber de antemão quantas voltas serão: enquanto a senha estiver errada, enquanto o usuário não escolher "Sair", enquanto o arquivo não aparecer. O until é o mesmo laço com a condição ao contrário: repete até ela ficar verdadeira.

Você vai aprender
  • Como o while decide se dá mais uma volta (o código de saída da condição).
  • A diferença entre while e until, e quando cada um lê melhor.
  • Contadores com [[ ]] e com while (( … )).
  • O padrão while true + break: senhas, menus que repetem e esperas.
  • Como parar um laço infinito com Ctrl+C, e como escolher entre while e for.

A ideia: repetir enquanto for verdade

Pense numa receita: "enquanto a água não ferver, espere". Você não sabe se vão ser 3 ou 8 minutos; você só sabe a condição de parada. É isso que o while (inglês para "enquanto") faz:

while CONDIÇÃO; do
  comandos
done

A condição é um comando qualquer. O Bash roda esse comando e olha o código de saída dele:

  • 0 (deu certo, "verdadeiro") → roda o corpo e volta a testar.
  • diferente de 0 ("falso") → o laço acaba e o script segue depois do done.

É a mesma regra do if. A diferença é que o if testa uma vez; o while testa de novo a cada volta.

Se a condição já começa falsa

O while testa antes de cada volta, inclusive da primeira. Se a condição já é falsa, o corpo não roda nem uma vez, e o código de saída do laço é 0:

$ x=10
$ while [[ $x -lt 3 ]]; do echo "x=$x"; done
$ while false; do echo "nunca"; done
$ echo $?
0                                    « nenhuma volta não é erro

Quando o corpo roda, o código de saída do while é o do último comando do corpo que rodou.

Contas na condição: while (( … ))

Quando a condição é uma comparação de números, os parênteses duplos (aritmética) leem mais naturalmente: dá para usar >, <=, == e escrever as variáveis sem $.

$ n=5
$ while (( n > 0 )); do echo -n "$n... "; ((n--)); done; echo "Fogo!"
5... 4... 3... 2... 1... Fogo!
(( n > 0 ))
Devolve 0 (verdadeiro) se a conta der verdadeiro, e 1 se der falso. Dentro de (( )), > é "maior que", não um redirecionamento.
((n--))
Diminui n em 1. É o mesmo que n=$((n - 1)).
echo -n
Escreve sem pular linha, para a contagem ficar lado a lado.
Condição com [[ ]]A mesma com (( ))
[[ $i -le 3 ]](( i <= 3 ))
[[ $n -gt 0 ]](( n > 0 ))
[[ $a -eq $b ]](( a == b ))
[[ $x -ne 0 ]](( x != 0 )) ou só (( x ))

Para números, prefira (( )). Para textos e arquivos (== "sim", -f arquivo), use [[ ]].

until: repetir até algo acontecer

until é inglês para "até que". Ele é o while com a condição invertida: roda o corpo enquanto a condição for falsa e para quando ela fica verdadeira.

$ i=1
$ until [[ $i -gt 3 ]]; do
>   echo "Volta $i"
>   ((i++))
> done
Volta 1
Volta 2
Volta 3

O resultado é igual ao primeiro exemplo: "até i passar de 3" é o mesmo que "enquanto i for no máximo 3". Os dois são sempre trocáveis:

untilO mesmo com while
until [[ $i -gt 3 ]]while [[ $i -le 3 ]]
until [[ -f pronto.txt ]]while [[ ! -f pronto.txt ]]
until (( saldo <= 0 ))while (( saldo > 0 ))

Use o que ler melhor em português. "Espere até o arquivo existir" pede until; "repita enquanto houver saldo" pede while. Um exemplo com until:

$ saldo=100
$ until (( saldo <= 0 )); do
>   echo "Saldo: $saldo"
>   (( saldo -= 40 ))
> done
Saldo: 100
Saldo: 60
Saldo: 20
$ echo "Saldo final: $saldo"
Saldo final: -20                     « o teste só acontece no começo de cada volta

Repare no -20: o laço não "vê" o saldo ficar negativo no meio da volta. Ele só confere na hora de começar a próxima. Se o saldo não pudesse ficar negativo, você teria que testar antes de descontar.

while true + break: quando a saída fica no meio

Às vezes a decisão de parar só pode ser tomada no meio do corpo, depois de ler algo. Por exemplo, pedir a senha: primeiro você lê, depois confere. Para isso existe o padrão "laço infinito com uma porta de saída":

#!/usr/bin/env bash
tentativas=0
while true; do
  read -rp "Senha: " senha
  ((tentativas++))
  if [[ $senha == "bash123" ]]; then
    echo "Entrou! ($tentativas tentativas)"
    break
  fi
  echo "Senha errada, tente de novo."
done
echo "Fim do script."
LinhaO que faz
while true; dotrue é um comando que não faz nada e sempre devolve 0. A condição nunca fica falsa: o laço só termina por dentro.
read -rp "Senha: " senhaMostra "Senha: " e guarda o que a pessoa digitar em senha (veja read).
((tentativas++))Conta mais uma tentativa.
if [[ $senha == "bash123" ]]Senha certa?
breakSai do laço na hora e pula para depois do done (veja break e continue).
echo "Senha errada…"Só chega aqui quem errou. Depois o done volta para o while true.
$ bash senha.sh

while :

Em scripts antigos você vai ver while :; do. O : é um comando que, como o true, não faz nada e devolve 0. Os dois funcionam igual; true é mais fácil de ler.

Um menu que repete

O mesmo padrão, com um case dentro, faz um menu que volta a aparecer depois de cada escolha, até a pessoa pedir para sair:

#!/usr/bin/env bash
while true; do
  echo "--- MENU ---"
  echo "1) Ver data"
  echo "2) Contar frutas"
  echo "3) Sair"
  read -rp "Escolha: " opcao
  case $opcao in
    1) date "+Hoje é %d/%m/%Y" ;;
    2) echo "frutas.txt tem $(wc -l < frutas.txt) linhas" ;;
    3) echo "Tchau!"; break ;;
    *) echo "Opção inválida: $opcao" ;;
  esac
done
$ bash menu.sh
--- MENU ---
1) Ver data
2) Contar frutas
3) Sair
Escolha: 2
frutas.txt tem 7 linhas
--- MENU ---                         « o laço voltou ao começo
1) Ver data
2) Contar frutas
3) Sair
Escolha: 9
Opção inválida: 9                    « o *) pega qualquer outra coisa
--- MENU ---
1) Ver data
2) Contar frutas
3) Sair
Escolha: 3
Tchau!                               « o break da opção 3 encerra o laço

Repare que o break dentro do case sai do laço while. O ;; é o que termina cada opção do case. Para menus numerados prontos, o Bash ainda tem o select (veja Menus e Cores).

Esperar algo acontecer

Um uso clássico do until é esperar: um arquivo ser criado por outro programa, um download terminar, um serviço responder. A receita é "teste; se ainda não, durma um pouco; teste de novo".

#!/usr/bin/env bash
echo "Esperando o arquivo pronto.txt..."
until [[ -f pronto.txt ]]; do
  sleep 1
done
echo "Chegou! Conteúdo: $(cat pronto.txt)"
until [[ -f pronto.txt ]]
"Até existir o arquivo comum pronto.txt." O teste -f está em Testes.
sleep 1
Espera 1 segundo antes de testar de novo. Não tire o sleep: sem ele, o laço testaria milhares de vezes por segundo e deixaria o processador a 100%.

A Ana roda o script num terminal. Ele fica parado esperando. Em outro terminal, ela cria o arquivo:

$ echo "backup ok" > pronto.txt

Em até um segundo, o primeiro terminal termina:

$ bash espera.sh
Esperando o arquivo pronto.txt...
Chegou! Conteúdo: backup ok

Esperar, mas não para sempre

E se o arquivo nunca aparecer? O script ficaria preso. Um script bem feito tem um limite de tempo:

#!/usr/bin/env bash
segundos=0
until [[ -f pronto.txt ]]; do
  if (( segundos >= 5 )); then
    echo "Desisti depois de $segundos segundos." >&2
    exit 1
  fi
  sleep 1
  ((segundos++))
done
echo "Chegou depois de $segundos segundos."
$ bash espera2.sh
Desisti depois de 5 segundos.        « ninguém criou o arquivo
$ echo $?
1                                    « o exit 1 avisa quem chamou que deu errado

O exit 1 encerra o script inteiro (não só o laço), com código 1. O >&2 manda a mensagem para a saída de erro (veja Redirecionamento).

Laço infinito e Ctrl+C

Um laço que nunca termina não é sempre um erro: um monitor que confere algo a cada minuto deve rodar até você mandar parar. Para interromper qualquer laço no terminal, aperte Ctrl+C:

$ while true; do echo "rodando..."; sleep 1; done
rodando...
rodando...
rodando...
^C                                   « a Ana apertou Ctrl+C
$ echo $?
130                                  « 128 + 2 (o sinal INT, "interromper")

O ^C é o jeito de o terminal mostrar que você apertou Ctrl+C. Isso manda o sinal INT (interrupt) para o que está rodando, e o Bash abandona o laço inteiro. O código 130 significa "terminado pelo sinal 2". Sinais e como reagir a eles num script estão em trap e Sinais.

O laço infinito por engano

O laço infinito acidental quase sempre é um contador que nunca muda: você esqueceu o ((i++)), ou mudou a variável errada. Se a tela começar a encher sozinha, Ctrl+C e confira se a condição consegue ficar falsa algum dia.

Quando não funciona

A tela não para de encher 
$ i=1
$ while [[ $i -le 3 ]]; do echo "Volta $i"; done
Volta 1
Volta 1
Volta 1
…
^C

O que aconteceu: o corpo não muda i, então a condição é verdadeira para sempre.

Como resolver: Ctrl+C, e acrescente o incremento: while [[ $i -le 3 ]]; do echo "Volta $i"; ((i++)); done. Quando o laço é uma contagem simples, for ((i=1; i<=3; i++)) evita esse erro.

"[: -le: esperava operador unário" 
$ unset k
$ while [ $k -le 3 ]; do echo $k; k=$((k+1)); done
bash: [: -le: esperava operador unário

O que aconteceu: a variável k não existia. Sem aspas, $k sumiu e o [ recebeu só -le 3, que não faz sentido. O teste falhou com código 2, e o laço nem começou.

Como resolver: inicialize o contador antes do laço (k=1). Usar [[ ]] ou (( )) também evita essa mensagem, porque eles tratam variável vazia sem quebrar.

"[[4: comando não encontrado" 
$ while [[$i -le 3]]; do echo oi; done
bash: [[4: comando não encontrado

O que aconteceu: faltaram os espaços depois de [[ e antes de ]]. O Bash juntou [[ com o valor de $i (4) e procurou um comando chamado [[4. Como o comando falhou, a condição é falsa e o laço não rodou.

Como resolver: while [[ $i -le 3 ]]; do, com espaço dos dois lados.

O laço não rodou nenhuma vez (e não apareceu nada)

O que aconteceu: a condição já era falsa no primeiro teste. Causas comuns: contador iniciado com o valor errado; while e until trocados; comparação ao contrário (-gt no lugar de -lt).

Como confirmar: rode a condição sozinha e veja o código: [[ $i -le 3 ]]; echo $?. Se der 1, ela é falsa agora. Ou rode o script com bash -x (veja Depurar) para ver cada teste.

Com set -e, o script morre no ((i++)) 
$ i=0
$ ((i++))
$ echo $?
1                                    « i++ devolve o valor ANTIGO (0), que conta como "falso"

O que aconteceu: (( )) devolve 1 quando o resultado da conta é 0. Em i++, o resultado é o valor de antes de somar. Com set -e (veja set -euo pipefail), esse 1 encerra o script.

Como resolver: use ((++i)), que devolve o valor novo, ou i=$((i + 1)).

Resumo

  • while COND repete enquanto a condição devolver 0; until COND repete até ela devolver 0.
  • A condição é testada antes de cada volta; se já começa falsa, o corpo não roda.
  • Num contador, prepare a variável antes e mude-a dentro do laço; para números, (( )) lê melhor.
  • while true + break serve quando a decisão de parar vem no meio (senhas, menus).
  • Para esperar algo, use until …; do sleep N; done, de preferência com limite de tempo.
  • Ctrl+C interrompe qualquer laço (código 130). Para listas, prefira o for; para linhas de arquivo, while read.
