Bash Arrays Associativos bash 4.0+

No array comum, cada item mora num número: 0, 1, 2… No array associativo, cada item mora num nome que você escolhe, a chave. É como uma agenda: você procura por "Recife" e encontra "PE", sem precisar saber em que posição está. Ele é perfeito para contar, agrupar e traduzir valores.

Você vai aprender
  • Por que declare -A é obrigatório, e o que acontece sem ele.
  • Como gravar, ler, listar chaves e valores, contar e remover.
  • Como testar se uma chave existe com [[ -v m[chave] ]].
  • Duas receitas clássicas: contar a frequência das frutas e agrupar os alunos por cidade.
  • Que a ordem das chaves não é garantida, e como copiar um array associativo.

Chave → valor

Em muitas linguagens isso se chama dicionário, mapa ou hash. A ideia é sempre a mesma: um "nome" leva a um "conteúdo".

  PE      →  Recife
  BA      →  Salvador
  AM      →  Manaus

O declare -A é obrigatório

Comece pelo erro mais comum. A Ana quer guardar a idade dos alunos e escreve direto, sem declarar:

$ idade[ana]=29
$ idade[bruno]=34
$ echo ${idade[ana]}
34                       « a idade da Ana virou a do Bruno?!
$ declare -p idade
declare -a idade=([0]="34")

Nenhuma mensagem de erro, e o resultado está errado. O declare -p mostra o que aconteceu: -a, um array indexado. Sem a declaração, o Bash achou que ana e bruno eram contas (o índice de um array comum é sempre um número) e calculou o valor de uma variável ana, que não existe, ou seja, 0. As duas idades foram gravadas no índice 0, e a segunda apagou a primeira.

Agora do jeito certo:

declare
Comando interno que cria variáveis com atributos especiais.
-A
"Associativo" (Associative). A maiúscula importa: -a minúsculo é o array indexado.
idade
O nome do array.
$ unset idade
$ declare -A idade
$ idade[ana]=29
$ idade[bruno]=34
$ idade[carla]=22
$ echo ${idade[bruno]}
34
$ declare -p idade
declare -A idade=([ana]="29" [bruno]="34" [carla]="22" )

O declare -p agora mostra -A e as chaves com nome. O espaço antes do ) no final é só o jeito do Bash imprimir associativos.

Não dá para "converter" depois 
$ idade[ana]=29
$ declare -A idade
bash: declare: idade: impossível converter array indexado para associativo

Se o nome já foi usado como array comum, apague antes com unset idade. Em scripts, faça o declare -A logo no começo, antes de qualquer uso.

Criar já com os valores

Você pode declarar e preencher numa linha. Cada item é [chave]=valor:

$ declare -A capital=([PE]=Recife [BA]=Salvador [AM]=Manaus)
$ echo "${capital[BA]}"
Salvador

Chaves com espaço precisam de aspas, tanto para gravar quanto para ler. Com uma variável como chave, use $:

$ declare -A m=(["Porto Alegre"]=RS [Recife]=PE)
$ echo "${m[Porto Alegre]}"
RS
$ k="Porto Alegre"; echo "${m[$k]}"
RS

Ler, alterar, acrescentar e remover

$ declare -A capital=([PE]=Recife [BA]=Salvador [AM]=Manaus)
$ capital[PE]=Olinda              « chave que já existe: troca o valor
$ echo ${capital[PE]}
Olinda
$ capital[SP]="São Paulo"         « chave nova: acrescenta
$ capital+=([RJ]="Rio de Janeiro")    « += também funciona, com [chave]=valor
$ unset 'capital[SP]'             « remove a chave SP (com aspas, como nos arrays)
$ declare -p capital
declare -A capital=([RJ]="Rio de Janeiro" [BA]="Salvador" [AM]="Manaus" [PE]="Olinda" )

Os comandos de gravar e remover não mostram nada; todos devolvem código 0. Para ler uma chave que não existe, o resultado é vazio, sem erro:

$ echo "[${capital[SP]}]"
[]

A pegadinha do $ na chave

No array comum, ${a[i]} funciona sem $ porque o índice é uma conta. No associativo, a chave é texto: sem $, você está pedindo a chave chamada literalmente "uf".

$ declare -A capital=([PE]=Recife [BA]=Salvador)
$ uf=PE
$ echo "[${capital[uf]}]"
[]                       « procurou a chave "uf"
$ echo "[${capital[$uf]}]"
[Recife]                 « procurou a chave "PE"

Todas as chaves, todos os valores, quantos

As mesmas formas dos arrays comuns, com uma mudança de sentido: ${!m[@]} agora devolve as chaves.

$ declare -A capital=([PE]=Recife [BA]=Salvador [AM]=Manaus)
$ echo "${!capital[@]}"
BA AM PE                 « as chaves (repare na ordem)
$ echo "${capital[@]}"
Salvador Manaus Recife   « os valores, na mesma ordem das chaves
$ echo ${#capital[@]}
3                        « quantas chaves

Percorrer: pelas chaves

O laço clássico percorre as chaves e, com cada uma, busca o valor:

$ for uf in "${!capital[@]}"; do echo "$uf: ${capital[$uf]}"; done

AM: Manaus

A ordem não é garantida

Você criou PE, BA, AM, e o Bash devolveu BA, AM, PE. O array associativo guarda as chaves numa tabela de busca rápida (uma tabela hash), que não lembra a ordem de entrada. A ordem pode mudar quando você acrescenta chaves, e pode ser diferente em outra versão do Bash. Nunca conte com ela.

Quando a ordem importa, ordene as chaves com sort:

$ for uf in $(printf '%s\n' "${!capital[@]}" | sort); do echo "$uf: ${capital[$uf]}"; done
AM: Manaus
BA: Salvador
PE: Recife

Esse $( ) sem aspas só é seguro porque as chaves são siglas, sem espaço. Com chaves que podem ter espaço, ordene a saída do laço inteiro, como nas receitas abaixo (done | sort).

Testar se uma chave existe: [[ -v m[chave] ]]

Ler uma chave inexistente dá vazio. Mas uma chave pode existir com valor vazio. Para saber se ela está lá, use o teste -v (de variable, "está definida?") do [[ ]]:

$ declare -A capital=([PE]=Recife [BA]=Salvador [AM]=Manaus)
$ [[ -v capital[PE] ]] && echo tem || echo "não tem"
tem
$ [[ -v capital[SP] ]] && echo tem || echo "não tem"
não tem
$ capital[SP]=""
$ [[ -v capital[SP] ]] && echo tem || echo "não tem"
tem                      « existe, mesmo vazia
$ [[ -n ${capital[SP]} ]] && echo tem || echo "vazio"
vazio                    « -n olha o valor, não a existência
[[
Abre o teste do Bash.
-v
"Esta variável (ou este item) está definida?"
capital[PE]
O item, sem $ e sem chaves: você passa o nome, não o valor.
]]
Fecha. O teste devolve 0 (sim) ou 1 (não), sem mostrar nada.

Se você só quer um valor padrão para chaves ausentes, a expansão :- resolve sem if:

$ echo "${capital[RJ]:-desconhecida}"
desconhecida

Missão: com o argumento 11, o script mostra DDD 11: e mais nada. Use um if [[ -v cidade[$ddd] ]] para mostrar DDD 11: desconhecido quando a chave não existir. Teste também com 81.

#!/usr/bin/env bash
declare -A cidade=([81]=Recife [71]=Salvador [92]=Manaus)
ddd=$1

#!/usr/bin/env bash
declare -A cidade=([81]=Recife [71]=Salvador [92]=Manaus)
ddd=$1
if [[ -v cidade[$ddd] ]]; then
  echo "DDD $ddd: ${cidade[$ddd]}"
else
  echo "DDD $ddd: desconhecido"
fi

Receita 1: contar a frequência das frutas

O frutas.txt da Ana tem uma fruta por linha, com repetições. Quantas vezes aparece cada uma? A ideia: a fruta é a chave, e o valor é um contador que sobe a cada aparição.

#!/usr/bin/env bash
declare -A contagem

while read -r fruta; do
  (( contagem[$fruta]++ ))
done < frutas.txt

for f in "${!contagem[@]}"; do
  echo "${contagem[$f]} $f"
done | sort -rn

$ bash frequencia.sh
3 banana
2 maçã
1 uva
1 laranja
$ echo $?
0
LinhaO que faz
declare -A contagemCria o array associativo vazio. Sem ela, todas as frutas iriam para o índice 0.
while read -r fruta; do … done < frutas.txtLê o arquivo linha a linha; cada linha vai para fruta.
(( contagem[$fruta]++ ))Soma 1 ao contador daquela fruta. Uma chave que ainda não existe vale 0 na conta, então a primeira aparição vira 1.
for f in "${!contagem[@]}"Percorre as frutas encontradas (as chaves).
echo "${contagem[$f]} $f"Mostra "quantidade fruta", com o número na frente para facilitar a ordenação.
done | sort -rnOrdena a saída do laço inteiro por número (-n), do maior para o menor (-r). Sem isso, a ordem seria a da tabela interna.

É a mesma resposta de sort frutas.txt | uniq -c | sort -rn, que você viu em pipes. A diferença: com o array, os números ficam dentro do script, prontos para outras contas (por exemplo, "avise se alguma fruta passar de 2").

(( x++ )) com set -e

Uma conta (( )) que resulta em 0 devolve código 1. O contagem[banana]++ da primeira vez vale 0 (o valor antes de somar), e um script com set -e pararia ali. Nesses scripts, use (( ++contagem[$fruta] )) (soma antes, vale 1) ou contagem[$fruta]=$(( ${contagem[$fruta]:-0} + 1 )).

Missão: complete o laço com a linha que soma 1 ao contador da fruta, para a saída mostrar banana: 3, laranja: 1, maçã: 2 e uva: 1.

declare -A contagem

  # some 1 ao contador desta fruta aqui
  :
done < frutas.txt

for f in "${!contagem[@]}"; do
  echo "$f: ${contagem[$f]}"
done | sort

Receita 2: agrupar os alunos por cidade

O Documentos/alunos.csv tem uma linha por aluno: nome,idade,cidade,nota. Para o exemplo ficar interessante, a Ana acrescenta dois alunos de cidades que já estão na lista:

$ printf '%s\n' "Fábio,31,Recife,8.0" "Gabi,25,Salvador,9.0" >> Documentos/alunos.csv
$ cat Documentos/alunos.csv
nome,idade,cidade,nota
Ana,29,Recife,9.5
Bruno,34,Curitiba,7.0
Carla,22,Salvador,8.5
Diego,41,Manaus,6.0
Elisa,27,Porto Alegre,10.0
Fábio,31,Recife,8.0
Gabi,25,Salvador,9.0

Agora, dois arrays associativos com a cidade como chave: um junta os nomes, o outro conta quantos alunos há em cada uma.

#!/usr/bin/env bash
declare -A alunos quantos

while IFS=, read -r nome idade cidade nota; do
  [[ $nome == nome ]] && continue        # pula o cabeçalho
  alunos[$cidade]+="$nome ($nota) "
  (( quantos[$cidade]++ ))
done < Documentos/alunos.csv

for c in "${!alunos[@]}"; do
  echo "$c [${quantos[$c]}]: ${alunos[$c]}"
done | sort

Porto Alegre [1]: Elisa (10.0)
Recife [2]: Ana (9.5) Fábio (8.0)
Salvador [2]: Carla (8.5) Gabi (9.0)

Copiar e inspecionar

Não existe "copiar com =" para arrays associativos. O jeito mais claro é percorrer as chaves:

$ declare -A capital=([PE]=Recife [BA]=Salvador [AM]=Manaus)
$ declare -A copia
$ for k in "${!capital[@]}"; do copia[$k]=${capital[$k]}; done
$ declare -p copia
declare -A copia=([BA]="Salvador" [AM]="Manaus" [PE]="Recife" )

O declare -p é seu melhor amigo para ver o conteúdo inteiro, com chaves e valores. Rodar declare -A sem nome lista todos os arrays associativos da sessão (inclusive dois do próprio Bash: BASH_ALIASES e BASH_CMDS).

Atalho bash 5.1+

A transformação ${m[@]@K} devolve os pares já no formato chave "valor". Com eval, ela copia numa linha: declare -A copia; eval "copia=(${capital[@]@K})". Funciona, mas o eval exige cuidado (veja eval e indireção); o laço acima é mais fácil de ler.

Arrays associativos em funções

Um declare -A dentro de uma função cria uma variável local, que some quando a função termina:

$ f() { declare -A tmp=([x]=1); }
$ f; declare -p tmp
bash: declare: tmp: não encontrado
$ g() { declare -gA glob=([x]=1); }
$ g; declare -p glob
declare -A glob=([x]="1" )

O -g (global) cria a variável fora da função. Para uma função receber um array associativo, passe o nome e use local -n, como na aula de arrays.

E no macOS?

O /bin/bash do macOS é a versão 3.2, de 2007, que não tem arrays associativos. Lá, o declare -A falha (saída ilustrativa, do Bash 3.2 em inglês):

$ declare -A capital
bash: declare: -A: invalid option
declare: usage: declare [-afFirtx] [-p] [name[=value] ...]

Como resolver: instale um Bash novo (por exemplo, pelo Homebrew) e use #!/usr/bin/env bash no script, para que ele ache o Bash novo no PATH. Num script que precisa rodar em qualquer lugar, confira a versão no começo:

if (( BASH_VERSINFO[0] < 4 )); then
  echo "Este script precisa do bash 4 ou mais novo." >&2
  exit 1
fi

Linux (Ubuntu, Debian, Fedora, Arch), WSL e Git Bash já vêm com Bash 5. Veja Bash em Cada Sistema.

Quando não funciona

Todas as chaves dão o mesmo valor 
$ idade[ana]=29
$ idade[bruno]=34
$ echo ${idade[ana]}
34

O que aconteceu: faltou o declare -A. O array virou indexado e todas as chaves de texto valem 0.

Como confirmar: declare -p idade mostra declare -a (minúsculo) e só [0].

Como resolver: unset idade; declare -A idade e grave de novo.

"impossível converter array indexado para associativo"

O que aconteceu: o nome já era um array comum quando você rodou declare -A.

Como resolver: unset nome antes do declare -A.

Não apareceu nada (a chave "existe" mas veio vazia)

O que aconteceu: provavelmente faltou o $ na chave: ${capital[uf]} procura a chave "uf". Ou a chave tem diferença de maiúsculas, espaço sobrando no fim (comum ao ler arquivos do Windows, com \r).

Como confirmar: declare -p capital mostra as chaves exatas; compare com printf '[%s]\n' "$uf".

Como resolver: ${capital[$uf]}, e limpe a chave antes de usar.

"subscrito de array incorreto" com chave vazia 
$ declare -A m
$ k=""; m[$k]=x
bash: m[$k]: subscrito de array incorreto

O que aconteceu: a chave não pode ser vazia. Geralmente é uma linha em branco no arquivo ou uma coluna faltando.

Como resolver: pule as linhas vazias: [[ -z $k ]] && continue.

"comando não encontrado" com o nome do item 
$ capital[BA]
bash: capital[BA]: comando não encontrado

O que aconteceu: sozinho na linha, o nome é tratado como comando. Para ver o valor, use echo "${capital[BA]}".

Resumo

  • Array associativo = chave (texto) → valor. Exige declare -A antes do primeiro uso; sem ele, as chaves viram 0 sem nenhum aviso.
  • Leia com "${m[$k]}" (com $ na chave em variável); "${!m[@]}" são as chaves, ${#m[@]} a quantidade.
  • A ordem das chaves não é garantida: ordene a saída com sort.
  • [[ -v m[$k] ]] testa se a chave existe; "${m[$k]:-padrão}" dá um valor padrão.
  • Contar: (( m[$k]++ )). Agrupar: m[$k]+="texto ". Exige bash 4.0+ (o bash 3.2 do macOS não tem).
