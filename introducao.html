Bash O que é o Bash

O Bash é o programa que entende o que você digita no terminal e manda o sistema fazer. Ele é, ao mesmo tempo, um jeito de conversar com o computador, um comando de cada vez, e uma linguagem de programação para escrever scripts. Nesta aula você vai entender de onde ele veio e o que ele faz com cada linha que você digita.

Você vai aprender
  • O que é um shell e onde ele fica entre você e o sistema.
  • A história do Bash: do Bourne shell ao "Bourne-Again SHell" do projeto GNU.
  • Os três passos que o Bash faz com cada linha: ler, expandir e executar.
  • A diferença entre Bash, sh, zsh, fish e PowerShell.
  • O que você vai conseguir fazer ao terminar este curso.

O que é um shell

O coração de um sistema operacional é o kernel (em inglês, "núcleo", como o caroço de uma fruta). É ele que fala com o disco, a memória, o teclado e a tela. Mas o kernel não conversa com pessoas: ele só recebe pedidos de outros programas.

O shell ("casca", em inglês) é a camada em volta desse núcleo. É um programa que recebe os seus pedidos em forma de texto, traduz para o que o sistema entende e mostra o resultado. O nome vem da imagem: o kernel é o miolo, o shell é a casca por onde você toca nele.

CamadaQuem éO que faz
VocêA pessoa no tecladoDigita wc -l frutas.txt e aperta Enter.
TerminalA janela (GNOME Terminal, Terminal do macOS, Windows Terminal…)Mostra as letras e entrega o que você digitou ao shell.
ShellO BashLê a linha, entende, prepara e manda executar o programa wc.
Programaswc, ls, grep…Fazem o trabalho: aqui, contar as linhas.

Terminal e shell parecem a mesma coisa, mas são programas diferentes: o terminal é a janela, o shell é quem entende os comandos. A próxima aula, Terminal, Shell e Console, separa bem esses nomes.

Um pouco de história

O Bash não surgiu do nada. Ele é o herdeiro de uma família de shells do sistema Unix, criado nos anos 1970:

AnoShellO que trouxe
1971Thompson shell (sh)O primeiro shell do Unix, de Ken Thompson. Só rodava comandos, quase sem programação.
1978C shell (csh)De Bill Joy. Inventou o histórico (!!) e os apelidos (alias), mas tinha uma sintaxe parecida com a linguagem C.
1979Bourne shell (sh)Escrito por Stephen Bourne, nos Bell Labs. Trouxe variáveis, if, for, while, case: virou uma linguagem de script de verdade.
1983Korn shell (ksh)De David Korn. Juntou o Bourne shell com as comodidades do C shell.
1989BashEscrito por Brian Fox para o projeto GNU. Compatível com o Bourne shell, com as melhores ideias do csh e do ksh.
1992POSIX shUma norma que define como um sh deve se comportar, para scripts rodarem em qualquer Unix.

Por que "Bourne-Again"?

Nos anos 1980, o projeto GNU, de Richard Stallman, estava construindo um sistema operacional inteiro feito de software livre (que qualquer um pode usar, estudar, mudar e distribuir). O Bourne shell pertencia à AT&T e não podia ser copiado livremente, então o GNU precisava do seu próprio shell. Brian Fox o escreveu, e a primeira versão pública saiu em junho de 1989. Desde o começo dos anos 1990, quem cuida do Bash é Chet Ramey.

O nome é um trocadilho: Bourne-Again SHell. Em inglês, born again é "nascido de novo". O Bash é o Bourne shell renascido, agora livre.

Quando o kernel Linux apareceu, em 1991, ele foi juntado às ferramentas GNU, e o Bash virou o shell padrão de quase todas as distribuições Linux. Por isso, até hoje, "aprender terminal" e "aprender Bash" são quase a mesma coisa.

O que o Bash faz com cada linha

Quando você aperta Enter, o Bash não entrega a linha ao programa do jeito que você digitou. Antes, ele faz um trabalho de preparação. Pense num garçom que anota o pedido "o de sempre para a mesa 3": antes de levar à cozinha, ele troca "o de sempre" pelo prato certo. O Bash faz igual.

  1. Lê a linha que você digitou, até o Enter. Se ela estiver incompleta (uma aspa aberta, por exemplo), ele pede o resto mostrando >.
  2. Separa em palavras, usando os espaços. A primeira palavra é o nome do comando; as outras são opções e argumentos.
  3. Expande: troca os "atalhos" pelo que eles representam. $USER vira ana, ~ vira /home/ana, *.txt vira a lista de arquivos que terminam em .txt.
  4. Executa: se o comando é interno do Bash (como echo e cd), ele mesmo faz; se é um programa (como wc), ele procura o arquivo do programa e manda o sistema rodá-lo.
  5. Espera e guarda o resultado: quando o comando termina, o Bash guarda o código de saída em $? e mostra o prompt de novo.

Vendo a expansão acontecer

Primeiro, três comandos com "atalhos". Repare que o echo não mostra $USER, *.txt nem ~: ele mostra o que o Bash colocou no lugar deles.

$ echo Olá, $USER
Olá, ana                                 « $USER virou o nome da usuária
$ echo Arquivos de texto: *.txt
Arquivos de texto: frutas.txt            « *.txt virou a lista de arquivos .txt
$ echo Pasta pessoal: ~
Pasta pessoal: /home/ana                 « ~ virou o caminho da pasta pessoal

Quem fez essas trocas não foi o echo: foi o Bash, antes de chamar o echo. Dá para provar. O comando set -x liga o "modo de rastreio": a partir dele, o Bash mostra cada comando depois das expansões, numa linha que começa com +.

set
Comando interno do Bash que liga e desliga opções do próprio shell.
-x
A opção xtrace ("rastrear a execução"): mostrar cada comando antes de rodá-lo, já expandido. set +x desliga.
$ set -x
$ echo Olá, $USER, você tem *.txt em ~
+ echo Olá, ana, você tem frutas.txt em /home/ana      « o que o echo realmente recebeu
Olá, ana, você tem frutas.txt em /home/ana             « o que o echo mostrou
$ set +x
+ set +x                                               « o próprio set +x ainda aparece no rastro

A linha com + é o comando como o Bash o entregou ao echo: sem $USER, sem *, sem ~. Essa ideia, "o shell prepara a linha antes de executar", explica a maioria das surpresas do Bash, e você vai reencontrá-la em Curingas, Aspas e A Ordem das Expansões. O set -x também é a ferramenta número um para achar erros em scripts (Depurar).

Missão: ligue o rastreio com set -x e rode echo *.txt. Compare a linha com + e a resposta. Depois desligue com set +x.

Comando interno ou programa?

No passo 4, o Bash decide quem vai trabalhar. Alguns comandos fazem parte do próprio Bash (os comandos internos, em inglês builtins); outros são programas separados, arquivos guardados no disco. O comando type -t conta o que cada nome é:

$ type -t echo wc for
builtin                            « echo: comando interno do Bash
file                               « wc: um programa, um arquivo no disco
keyword                            « for: palavra-chave da linguagem do Bash

Para você, que digita, a diferença quase não aparece. Mas ela explica por que man cd não funciona e help cd funciona (veja Obtendo Ajuda), e é o tema de Anatomia de um Comando e PATH.

Uma linguagem de comandos e de script

O Bash tem duas caras, e as duas usam exatamente a mesma linguagem:

  • Interativo: você digita um comando, ele responde, você digita outro. É o uso do dia a dia no terminal.
  • Script: você escreve os comandos num arquivo e o Bash executa o arquivo inteiro, do começo ao fim, sem você ficar digitando.

No terminal, a Ana pode repetir um comando para cada fruta com um laço for, tudo numa linha:

$ nome=Ana
$ for fruta in banana uva; do echo "$nome gosta de $fruta"; done
Ana gosta de banana
Ana gosta de uva

Os mesmos recursos vão para dentro de um arquivo. Este script conta as linhas de cada arquivo .txt da pasta:

#!/usr/bin/env bash
# conta.sh: quantas linhas tem cada arquivo .txt desta pasta
for arquivo in *.txt; do
  linhas=$(wc -l < "$arquivo")
  echo "$arquivo tem $linhas linhas"
done
LinhaO que faz
#!/usr/bin/env bashDiz ao sistema que este arquivo é um script do Bash.
# conta.sh: …Comentário: tudo depois de # é ignorado. Serve para pessoas.
for arquivo in *.txt; doPara cada arquivo .txt, guarda o nome em arquivo e roda o bloco.
linhas=$(wc -l < "$arquivo")Conta as linhas e guarda o número em linhas.
echo "…"Mostra o resultado.
doneFim do bloco que se repete.

Com uma cópia do notas.txt na pasta, a Ana roda o script:

$ cp Documentos/notas.txt .
$ bash conta.sh
frutas.txt tem 7 linhas
notas.txt tem 4 linhas

Tudo o que você aprender digitando no terminal serve para scripts, e vice-versa. O Nível 1 deste guia é o uso interativo; o Nível 2 começa em Seu Primeiro Script.

Bash × sh × zsh × fish × PowerShell

O Bash não é o único shell. Você vai esbarrar nestes nomes:

ShellOnde apareceParecido com o Bash?Bom saber
BashPadrão na maioria dos Linux; WSL; Git Bash—O shell deste guia. O mais usado em scripts e tutoriais.
sh (POSIX)/bin/sh de todo Unix. No Debian/Ubuntu é o dash; no Fedora, o próprio Bash em modo compatívelÉ um "subconjunto": o Bash entende tudo do sh, mas o sh não entende tudo do BashScripts com #!/bin/sh não podem usar recursos só do Bash, como [[ ]] e {1..3}. Veja POSIX sh e Bashismos.
zshPadrão do macOS desde 2019; popular com o Oh My ZshMuito: quase todo comando do dia a dia funciona igualDiferenças em detalhes (arrays começam em 1, curingas que não acham nada dão erro). Scripts com #!/usr/bin/env bash continuam rodando no Bash.
fishInstalado à parte, em qualquer sistemaPouco: sintaxe própria (set x 1, end)Muito amigável para digitar, com sugestões automáticas. Scripts de Bash não rodam nele.
PowerShellWindows (também existe para Linux e macOS)Não: outra famíliaOs comandos passam objetos, não texto (Get-ChildItem). Para Bash no Windows, use WSL ou Git Bash.

Veja na prática que o sh do Ubuntu (o dash) não entende um recurso que o Bash entende, as sequências com chaves:

$ bash -c "echo {1..3}"
1 2 3                              « o Bash expande a sequência
$ sh -c "echo {1..3}"
{1..3}                             « o sh (dash) não conhece {1..3}: mostra o texto como está
Por que aprender Bash e não outro?

Porque é o que você vai encontrar em servidores, contêineres, instaladores, tutoriais e scripts de outras pessoas. Mesmo quem usa zsh ou fish no dia a dia escreve scripts em Bash, porque ele está em todo lugar.

Quando não funciona

"comando não encontrado" ao tentar outro shell 
$ zsh
bash: zsh: comando não encontrado
$ echo $?
127                                « 127 = o Bash não achou nenhum comando com esse nome

O que aconteceu: a mensagem começa com bash: porque quem respondeu foi o Bash: ele procurou um programa chamado zsh e não achou. O zsh simplesmente não está instalado nesta máquina.

Como resolver: nada a resolver se você só queria conhecer. Para instalar outro shell, use o gerenciador de pacotes do seu sistema. Os códigos de saída, como o 127, têm aula própria: Código de Saída.

Um script funciona com bash e falha com sh 
$ sh -c "echo {1..3}"
{1..3}

O que aconteceu: o script usa um recurso do Bash, mas foi rodado por outro shell. Isso acontece com sh script.sh ou com um script que começa com #!/bin/sh.

Como resolver: rode com bash script.sh e comece o arquivo com #!/usr/bin/env bash. Detalhes em Formas de Executar.

O que você vai conseguir fazer

Ao terminar os três níveis e os projetos deste guia, você vai:

Resumo

  • O shell é a "casca" entre você e o kernel; o Bash é o shell mais usado.
  • Bash = Bourne-Again SHell: o Bourne shell (1979) renascido como software livre pelo projeto GNU, em 1989.
  • Com cada linha, o Bash lê, separa em palavras, expande ($USER, ~, *) e executa; set -x mostra o resultado da expansão.
  • A mesma linguagem serve para digitar no terminal e para escrever scripts.
  • sh é mais limitado, zsh é muito parecido, fish e PowerShell são outra coisa.
