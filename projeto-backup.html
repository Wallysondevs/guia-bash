Projeto Backup com Rotação

Backup é o script que todo mundo deveria ter e quase ninguém tem. Neste projeto você escreve um que compacta a pasta ~/Documentos num arquivo com a data no nome, guarda só os 5 mais recentes e, principalmente, falha do jeito certo: se algo der errado, ele para, apaga o arquivo pela metade, avisa na saída de erro e devolve um código diferente de 0. Um backup quebrado que diz "OK" é pior do que nenhum backup.

Ao terminar você terá
  • Um script backup.sh que cria ~/backups/documentos-2026-10-15_103012.tar.gz.
  • Rotação: só os 5 backups mais recentes ficam, os outros são apagados.
  • set -euo pipefail e um trap que limpa o arquivo incompleto quando algo falha.
  • Mensagens na saída de erro e só o caminho do backup na saída padrão, para outro script poder usá-lo.
  • Uma linha de agendamento para rodar todo dia sozinho.

Backup na mesma máquina é só meio backup

Para aprender, o destino aqui é ~/backups, no mesmo disco. Na vida real, mande a cópia para outro lugar: um HD externo, outro computador, a nuvem. Um disco que queima leva junto os dados e os backups que estavam nele.

As etapas

  1. Etapa 1 — Um .tar.gz com a data no nome

    O que vamos fazer e por quê: o tar (de tape archive, "arquivo de fita", do tempo em que backup ia para fita magnética) junta uma pasta inteira num arquivo só; com -z ele ainda compacta com gzip. A data no nome faz cada backup ter um nome diferente, e um nome que se ordena sozinho.

    #!/usr/bin/env bash
# backup.sh — versão 1: um .tar.gz com a data no nome
origem=~/Documentos
destino=~/backups
data=$(date +%F_%H%M%S)
nome=documentos-$data.tar.gz

mkdir -p "$destino"
tar -czf "$destino/$nome" -C "$(dirname "$origem")" "$(basename "$origem")"
echo "criado: $destino/$nome"

    A linha do date, parte por parte:

    $(
    Substituição de comando: roda o que está dentro e coloca a saída no lugar.
    date
    Mostra a data e a hora.
    +
    "A partir daqui vem um formato meu."
    %F
    Data completa no formato ano-mês-dia: 2026-10-15.
    _
    Um sublinhado literal (sem espaço, para o nome não precisar de aspas).
    %H%M%S
    Hora, minuto e segundo, com dois dígitos cada: 103012.

    E a linha do tar:

    tar
    O programa de arquivamento.
    -c
    create: criar um arquivo novo.
    -z
    Compactar com gzip (por isso o .gz).
    -f "$destino/$nome"
    file: o nome do arquivo a criar. O -f precisa vir por último no grupo -czf, porque o nome vem logo depois dele.
    -C "$(dirname "$origem")"
    Entra primeiro em /home/ana (o dirname tira o último pedaço do caminho)…
    "$(basename "$origem")"
    …e guarda Documentos. Assim os caminhos dentro do backup começam em Documentos/, e não em home/ana/Documentos/.

    A pasta inteira, com subpastas, cabe em 768 bytes (são arquivos de texto pequenos, e texto compacta muito bem). A ordem da listagem é a ordem em que o tar encontrou os arquivos no disco, não a alfabética.

    Confira o que importa: a restauração. Backup que nunca foi restaurado é só uma esperança. Extraia numa pasta de teste e compare com o original:

    O diff -r compara as duas árvores arquivo por arquivo e não escreve nada quando são iguais (código 0), então o && echo IGUAIS roda. Veja ; && ||.

  2. Etapa 2 — Rotação: manter só os 5 mais recentes

    O que vamos fazer e por quê: um backup por dia, sem limpeza, enche o disco. A rotação apaga os mais antigos e deixa só os N mais recentes. O truque: como o nome começa com AAAA-MM-DD_HHMMSS, a ordem alfabética é a ordem cronológica. E o curinga do Bash já devolve os nomes em ordem alfabética. Não precisamos do ls.

    manter=5                       # junto das outras variáveis, no começo

# depois do tar:
backups=("$destino"/documentos-*.tar.gz)
excesso=$(( ${#backups[@]} - manter ))
if (( excesso > 0 )); then
  for velho in "${backups[@]:0:excesso}"; do
    rm -f -- "$velho"
    echo "rotação: apagado ${velho##*/}"
  done
fi
    TrechoO que faz
    backups=("$destino"/documentos-*.tar.gz)Guarda num array todos os nomes que casam com o curinga, do mais antigo para o mais novo. Veja Arrays.
    ${#backups[@]}Quantos itens o array tem.
    excesso=$(( … - manter ))Quantos sobram além dos 5. Com 7 backups, excesso é 2.
    "${backups[@]:0:excesso}"Uma fatia do array: a partir da posição 0, pegue excesso itens. São os mais antigos.
    ${velho##*/}Só o nome do arquivo, sem a pasta, para a mensagem ficar curta.

    Para testar sem esperar seis dias, criamos seis "backups antigos" vazios com touch e as chaves {09..14}:

$ touch backups/documentos-2026-10-{09..14}_020000.tar.gz
$ ls backups

documentos-2026-10-10_020000.tar.gz  documentos-2026-10-13_020000.tar.gz
documentos-2026-10-11_020000.tar.gz  documentos-2026-10-14_020000.tar.gz
$ ./backup.sh
criado: /home/ana/backups/documentos-2026-10-15_103012.tar.gz

rotação: apagado documentos-2026-10-10_020000.tar.gz
$ ls backups

documentos-2026-10-12_020000.tar.gz  documentos-2026-10-15_103012.tar.gz

    Outras formas de fazer a rotação
    FormaComoQuando usar
    Pelo nome (a nossa)curinga + fatia do arrayQuando a data está no nome. Não chama programa nenhum e não se confunde com nomes estranhos.

  3. Etapa 3 — Parar no primeiro erro: set -euo pipefail

    O que vamos fazer e por quê: vamos provocar uma falha. Tiramos a permissão de leitura de um arquivo (chmod 000), como acontece com arquivos de outro usuário, e rodamos a versão 2:

    $ mkdir backups
$ touch backups/documentos-2026-10-{10..14}_020000.tar.gz
$ chmod 000 Documentos/notas.txt
$ ./backup.sh
tar: Documentos/notas.txt: Função open falhou: Permissão negada
tar: Saindo com status de falha em razão de erros anteriores
criado: /home/ana/backups/documentos-2026-10-15_103033.tar.gz      « mentira: está incompleto
rotação: apagado documentos-2026-10-10_020000.tar.gz               « e apagou um backup bom!
$ echo $?
0

    Veja o tamanho do estrago: o tar falhou, mas o script seguiu em frente, disse "criado", apagou um backup bom para dar lugar ao quebrado e ainda saiu com código 0 ("tudo certo"). Quem olhasse só o código jamais saberia. Por padrão, o Bash ignora erros e continua na próxima linha.

    A correção é uma linha logo depois do shebang:

    #!/usr/bin/env bash
# backup.sh — versão 3: para no primeiro erro
set -euo pipefail
    set
    Liga opções do shell.
    -e
    errexit: se um comando falhar (código diferente de 0), o script termina na hora, com o código desse comando.
    -u
    nounset: usar uma variável que não existe vira erro (pega erros de digitação como $destnio, que viraria texto vazio).
    -o pipefail
    Num pipe a | b, se o a falhar, o pipe todo falha (sem isso, só conta o último comando).
    $ ./backup.sh
tar: Documentos/notas.txt: Função open falhou: Permissão negada
tar: Saindo com status de falha em razão de erros anteriores
$ echo $?
2                                                       « o código do tar: 2 = erro fatal
$ ls backups
documentos-2026-10-10_020000.tar.gz  documentos-2026-10-13_020000.tar.gz
documentos-2026-10-11_020000.tar.gz  documentos-2026-10-14_020000.tar.gz
documentos-2026-10-12_020000.tar.gz  documentos-2026-10-15_103033.tar.gz

    Melhorou: nenhum "criado", nenhuma rotação, código 2. Mas olhe o ls: o arquivo incompleto documentos-2026-10-15_103033.tar.gz ficou lá, com cara de backup de verdade, e na próxima rotação vai contar como um dos 5. A etapa 4 resolve isso. O modo estrito tem armadilhas (o -e não vale dentro de if, por exemplo); a aula explica todas.

  4. Etapa 4 — Nome temporário e trap para limpar

    O que vamos fazer e por quê: duas ideias juntas. (1) O tar escreve num nome temporário que começa com ponto e termina em .parcial; só depois de terminar bem ele é renomeado para o nome final. Um backup pela metade nunca tem nome de backup. (2) Um trap … EXIT roda uma função de limpeza sempre que o script termina, inclusive quando o set -e o derruba no meio. Veja trap e Sinais.

    temp=""

limpar() {
  if [[ -n $temp && -e $temp ]]; then
    rm -f -- "$temp"
    echo "removido o arquivo incompleto ${temp##*/}"
  fi
}
trap limpar EXIT

mkdir -p "$destino"
temp=$destino/.$nome.parcial
tar -czf "$temp" -C "$(dirname "$origem")" "$(basename "$origem")"
mv -- "$temp" "$destino/$nome"
temp=""
echo "criado: $destino/$nome"
    TrechoPor quê
    temp="" no começoCom set -u, a função limpar não pode ler uma variável que nunca existiu. Começa vazia.
    trap limpar EXIT"Quando o script sair, por qualquer motivo, chame limpar." EXIT é um pseudo-sinal do Bash.
    [[ -n $temp && -e $temp ]]Só apaga se há um temporário e ele existe.
    .$nome.parcialO ponto no começo deixa o arquivo oculto, e o final .parcial não casa com documentos-*.tar.gz: a rotação nunca o conta.
    mv e depois temp=""Renomear dentro da mesma pasta é instantâneo e "tudo ou nada". Esvaziar temp depois avisa ao limpar que não há mais nada a apagar.
    $ chmod 000 Documentos/notas.txt
$ ./backup.sh
tar: Documentos/notas.txt: Função open falhou: Permissão negada
tar: Saindo com status de falha em razão de erros anteriores

$ echo $?
2
$ ls -A backups                                         « -A mostra até os ocultos: nada sobrou
documentos-2026-10-10_020000.tar.gz  documentos-2026-10-13_020000.tar.gz
documentos-2026-10-11_020000.tar.gz  documentos-2026-10-14_020000.tar.gz
documentos-2026-10-12_020000.tar.gz
$ chmod 644 Documentos/notas.txt                        « devolvemos a permissão

    Repare que o trap não muda o código de saída: o script ainda devolve o 2 do tar. E na execução que deu certo, o limpar também rodou, mas encontrou temp vazio e não fez nada.

  5. Etapa 5 — Mensagens para a saída de erro, resultado para a saída padrão

    O que vamos fazer e por quê: um bom programa de linha de comando separa as duas saídas. Na saída padrão (stdout, descritor 1) vai só o resultado: o caminho do backup criado. Na saída de erro (stderr, descritor 2) vão os avisos para o humano ("compactando…", "rotação…", erros). Assim outro script pode fazer arquivo=$(./backup.sh) e receber só o caminho. Aproveitamos para aceitar a origem e o destino como argumentos e checar se a origem existe.

    origem=${1:-$HOME/Documentos}
destino=${2:-$HOME/backups}

msg()   { printf 'backup: %s\n' "$*" >&2; }
falha() { msg "ERRO: $*"; exit 1; }

[[ -d $origem ]] || falha "a pasta '$origem' não existe"

msg "compactando $origem…"
# … tar, mv …
msg "criado ${nome} ($(du -h "$destino/$nome" | cut -f1))"
# … rotação, agora com msg "rotação: apagado …" …

echo "$destino/$nome"          # a ÚNICA linha que vai para a saída padrão
    TrechoO que faz
    ${1:-$HOME/Documentos}O primeiro argumento, ou ~/Documentos se não veio nenhum. Usamos $HOME em vez de ~ porque, se alguém escrever "${1:-~/Documentos}" entre aspas, o til não é expandido e vira o texto ~/Documentos; o $HOME funciona com ou sem aspas.
    msg() { printf 'backup: %s\n' "$*" >&2; }Toda mensagem leva o prefixo backup: (para saber de quem é, num log com vários programas) e vai para o descritor 2. Veja Redirecionamento.
    falha() { …; exit 1; }Mensagem de erro + código 1. Um exit dentro de uma função termina o script inteiro.
    [[ -d $origem ]] || falha …"A origem é uma pasta, senão falhe." Sem isso, o tar daria uma mensagem menos clara.
    du -h … | cut -f1O tamanho legível (4,0K); o cut -f1 fica só com a primeira coluna (o du separa com TAB).
    $ ./backup.sh
backup: compactando /home/ana/Documentos…
backup: criado documentos-2026-10-15_103057.tar.gz (4,0K)
backup: rotação: apagado documentos-2026-10-10_020000.tar.gz
/home/ana/backups/documentos-2026-10-15_103057.tar.gz      « a única linha no stdout
$ echo $?
0
$ arquivo=$(./backup.sh 2>/dev/null)                       « 2>/dev/null: joga fora as mensagens
$ echo "o backup novo é $arquivo"
o backup novo é /home/ana/backups/documentos-2026-10-15_103057.tar.gz
$ ./backup.sh ~/Documentoss
backup: ERRO: a pasta '/home/ana/Documentoss' não existe
$ echo $?
1
$ ./backup.sh > /dev/null                                  « só o stdout vai para o lixo
backup: compactando /home/ana/Documentos…
backup: criado documentos-2026-10-15_103057.tar.gz (4,0K)

    No terminal, as duas saídas aparecem misturadas e parecem iguais. A diferença surge quando você redireciona: 2>/dev/null some com as mensagens e deixa o resultado; > /dev/null faz o contrário. (No último comando, a segunda execução no mesmo segundo gerou o mesmo nome e não houve rotação.)

    Código de saídaSignificaQuem gera
    0Backup criado e rotação feita.O fim do script.
    1Erro de uso: a origem não existe.A função falha.
    2 (ou outro)O tar ou o mv falhou.O set -e, que repassa o código do comando que falhou.

  6. Etapa 6 — Agendar para rodar sozinho

    O que vamos fazer e por quê: backup que depende de você lembrar não é backup. O jeito clássico de rodar algo todo dia é o cron. Esta etapa é ilustrativa: o cron não existe no simulador nem no laboratório do guia, e a aula Agendar Scripts explica cron e os timers do systemd em detalhe.

    Primeiro, coloque o script num lugar fixo, por exemplo ~/.local/bin/backup.sh. Depois, crontab -e abre a sua tabela do cron num editor. Acrescente a linha:

    30 2 * * * $HOME/.local/bin/backup.sh >> $HOME/backup.log 2>&1
    30 2 * * *
    Minuto 30, hora 2, todo dia, todo mês, todo dia da semana: às 02:30.
    $HOME/.local/bin/backup.sh
    Caminho completo: o cron não usa o seu PATH nem o seu .bashrc.
    >> $HOME/backup.log
    Acrescenta a saída padrão (o caminho do backup) no log…
    2>&1
    …e manda a saída de erro (as mensagens backup: …) para o mesmo lugar. Sem isso, o cron tenta mandar as mensagens por e-mail local, que quase ninguém lê.
    $ crontab -l
30 2 * * * $HOME/.local/bin/backup.sh >> $HOME/backup.log 2>&1

    (Saída ilustrativa.) No dia seguinte, confira ~/backup.log e ls ~/backups. Se o computador estiver desligado às 02:30, o cron simplesmente pula aquele dia; os timers do systemd com Persistent=true não pulam. Os dois estão em Agendar Scripts.

    Funciona no terminal, mas não no cron

    O que aconteceu: no cron, o ambiente é mínimo: PATH=/usr/bin:/bin, sem as variáveis do seu .bashrc, e a pasta atual é a sua pasta pessoal. Como resolver: use caminhos completos no script, não dependa de aliases, e sempre redirecione a saída para um log (>> log 2>&1) para ver a mensagem de erro.

O script completo

Juntando as cinco etapas de código. Ele passa no ShellCheck sem avisos. Duas pequenas novidades: o nome do backup sai do nome da pasta em minúsculas (${nome,,}), para o script servir para qualquer pasta, e a rotação usa esse mesmo prefixo.

#!/usr/bin/env bash
# backup.sh — compacta uma pasta (padrão: ~/Documentos) num .tar.gz com data
# no nome, guardado em ~/backups, e mantém só os 5 backups mais recentes.
# Uso: backup.sh [ORIGEM] [DESTINO]
# Saída: o caminho do backup criado (stdout). Mensagens vão para stderr.
# Códigos: 0 = ok, 1 = erro de uso/origem, outro = falha do tar/mv.
set -euo pipefail

origem=${1:-$HOME/Documentos}
destino=${2:-$HOME/backups}
manter=5
data=$(date +%F_%H%M%S)
nome=$(basename "$origem")
nome=${nome,,}-$data.tar.gz
temp=""

msg()   { printf 'backup: %s\n' "$*" >&2; }
falha() { msg "ERRO: $*"; exit 1; }

limpar() {
  if [[ -n $temp && -e $temp ]]; then
    rm -f -- "$temp"
    msg "removido o arquivo incompleto ${temp##*/}"
  fi
}
trap limpar EXIT

[[ -d $origem ]] || falha "a pasta '$origem' não existe"
mkdir -p -- "$destino"

temp=$destino/.$nome.parcial
msg "compactando $origem…"
tar -czf "$temp" -C "$(dirname "$origem")" "$(basename "$origem")"
mv -- "$temp" "$destino/$nome"
temp=""
msg "criado ${nome} ($(du -h "$destino/$nome" | cut -f1))"

# Rotação: o curinga devolve os nomes em ordem alfabética, que aqui
# é também a ordem cronológica (a data AAAA-MM-DD está no nome).
prefixo=${nome%-"$data".tar.gz}
backups=("$destino/$prefixo"-*.tar.gz)
excesso=$(( ${#backups[@]} - manter ))
if (( excesso > 0 )); then
  for velho in "${backups[@]:0:excesso}"; do
    rm -f -- "$velho"
    msg "rotação: apagado ${velho##*/}"
  done
fi

echo "$destino/$nome"

$ shellcheck backup.sh
$ echo $?
0

Quando não funciona

tar: Removendo `/' inicial dos nomes dos membros

O que aconteceu: você trocou o -C … "$(basename …)" por tar -czf x.tar.gz /home/ana/Documentos. Não é erro: o tar só avisa que guardou os caminhos sem a / do começo (home/ana/Documentos/…), para que extrair nunca sobrescreva a pasta original por acidente. Com o -C, o aviso some e os caminhos ficam curtos.

variável não associada 
$ ./backup.sh ~/Nada
backup: ERRO: a pasta '/home/ana/Nada' não existe
./backup.sh: linha 20: temp: variável não associada
$ echo $?
1

O que aconteceu: o set -u encontrou o limpar lendo $temp antes de ela existir (por exemplo, a falha aconteceu antes da linha temp=… e você apagou o temp="" do começo). Como resolver: inicialize a variável no começo, ou use ${temp-} (vazio se não existir). Veja set -euo pipefail.

A rotação apagou backups que não devia

O que aconteceu: os nomes não se ordenam pela data. Com date +%d-%m-%Y (dia primeiro), 01-11-2026 vem antes de 15-10-2026 em ordem alfabética, e o backup de novembro seria tratado como o mais velho. Como resolver: use sempre ano-mês-dia (%F) em nomes de arquivo.

"Não apareceu nada" com ./backup.sh 2>/dev/null > /dev/null

Correto: as duas saídas foram descartadas. Confira o resultado pelo código, com echo $?, e pelo ls ~/backups.

Desafios extras

  • Compactação melhor: troque -z por -J (xz, arquivo .tar.xz, menor e mais lento) e ajuste a extensão e o curinga da rotação.
  • Excluir lixo: acrescente --exclude='*.tmp' --exclude='.cache' ao tar.
  • Opções de verdade: com getopts, aceite -k 10 (quantos manter) e -n (simular: mostrar o que a rotação apagaria).
  • Conferir o backup: depois do mv, rode tar -tzf "$destino/$nome" > /dev/null; se o arquivo estiver corrompido, o set -e derruba o script.
  • Backup incremental: pesquise tar --listed-incremental ou o rsync --link-dest, que só copia o que mudou.
  • Aviso de falha: no trap … EXIT, olhe o $? e, se for diferente de 0, mande uma notificação com notify-send "Backup falhou".

Resumo

  • tar -czf ARQ -C PAI PASTA cria o backup; tar -tzf lista; tar -xzf … -C destino restaura. Teste a restauração com diff -r.
  • Data no nome com %F_%H%M%S: nomes únicos que se ordenam sozinhos, e rotação com curinga + fatia de array.
  • set -euo pipefail faz o script parar no primeiro erro, com o código do comando que falhou.
  • Escreva num nome temporário, renomeie no fim e limpe com trap … EXIT.
  • Mensagens para >&2, resultado para a saída padrão, códigos de saída documentados.
  • Agende com cron ou timer do systemd, sempre com caminhos completos e um log.
