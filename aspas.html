Bash Aspas e Escapes

Antes de rodar qualquer comando, o Bash lê a linha que você digitou e decide o que é texto comum e o que é "especial": espaços, $, *, ~, !… As aspas e a barra invertida são a forma de dizer ao Bash "isto aqui é só texto, não mexa". Esta é a aula mais importante do Nível 1: metade dos erros de quem começa no Bash é aspa faltando ou aspa errada.

Você vai aprender
  • O que a barra invertida \, as aspas simples '…', as aspas duplas "…" e o $'…' protegem, e o que deixam passar.
  • Como lidar com nomes com espaço, como Área de trabalho.
  • Por que toda variável deve ser escrita como "$var".
  • Como colocar uma aspa simples dentro de aspas simples (e aspas duplas dentro de duplas).
  • O que fazer quando aparece o prompt >, o "event not found" ou o "número excessivo de argumentos".

Todos os exemplos acontecem na máquina fictícia notebook, na pasta da usuária ana. Você pode repetir cada um no terminal simulado das missões.

O problema: o Bash "mexe" no que você digita

Quando você aperta Enter, o Bash não entrega a linha inteira para o comando. Ele primeiro faz um trabalho de preparação:

  1. Separa a linha em palavras, cortando nos espaços. A primeira palavra é o comando; as outras são os argumentos.
  2. Troca as partes especiais: $HOME vira /home/ana, *.txt vira a lista de arquivos .txt, ~ vira a sua pasta pessoal…
  3. Só então chama o comando com as palavras prontas.

Na maior parte do tempo, isso é exatamente o que você quer. O problema aparece quando o texto tem um desses caracteres especiais por acaso. O exemplo clássico é a pasta Área de trabalho, que vem em todo Linux em português:

$ cd Área de trabalho
bash: cd: número excessivo de argumentos

Para você, isso é o nome de uma pasta. Para o Bash, são três palavras: Área, de e trabalho. O cd recebeu três argumentos, mas só sabe ir para um lugar, e reclamou. As aspas resolvem:

$ cd "Área de trabalho"
$ pwd
/home/ana/Área de trabalho          « funcionou: uma palavra só, com os espaços dentro

Raio-x: vendo as palavras que o comando recebe

Para entender aspas, você precisa ver como o Bash cortou a linha. Vamos usar um truque com o printf que será o nosso "raio-x" durante toda a aula:

printf
Comando que escreve texto seguindo um modelo (você vai estudá-lo em printf e echo).
'[%s]\n'
O modelo: %s é o lugar de uma palavra, [ ] são os colchetes em volta dela e \n pula a linha. O printf repete o modelo para cada argumento.
Área de trabalho
Os argumentos, do jeito que o Bash os entregar.
$ printf '[%s]\n' Área de trabalho
[Área]                     « três argumentos separados
[de]
[trabalho]
$ printf '[%s]\n' "Área de trabalho"
[Área de trabalho]         « um argumento só, com os espaços dentro

Cada par de colchetes é um argumento. Sempre que estiver em dúvida sobre aspas, troque o seu comando por printf '[%s]\n' e veja o que chegaria a ele.

Existem quatro formas de proteger texto. Vamos de uma em uma.

1. A barra invertida \: protege um caractere

A barra invertida (backslash, em inglês) é a forma mais simples: ela protege só o caractere que vem logo depois. Esse uso tem um nome técnico: escapar o caractere ("tirar o poder especial dele").

cd
O comando.
Área\ de\ trabalho
Cada \ (barra + espaço) vira um espaço comum, que não separa palavras. O resultado é um argumento só.
$ cd Área\ de\ trabalho
$ pwd
/home/ana/Área de trabalho

É isso que a tecla Tab escreve quando completa um nome com espaço (veja Completar com Tab). Funciona com qualquer caractere especial:

$ echo \$HOME
$HOME                      « o $ protegido não começa variável
$ echo \"oi\"
"oi"                       « as aspas protegidas aparecem
$ echo \\
\                          « para ter uma barra, escreva duas

Repare: a barra some na saída. Ela é uma instrução para o Bash, não parte do texto. Esse passo, em que o Bash retira as aspas e barras que já cumpriram o papel, se chama remoção de aspas e é o último da lista de expansões (veja A Ordem das Expansões).

Barra no fim da linha: continuar na próxima

Uma barra invertida como último caractere da linha protege o Enter. O Bash entende "o comando continua" e mostra o prompt de continuação >:

$ ls -l Documentos/notas.txt \
>   frutas.txt
-rw-rw-r-- 1 ana ana 69 out 14 17:40 Documentos/notas.txt
-rw-rw-r-- 1 ana ana 47 out 14 16:05 frutas.txt

O > não é digitado por você: é o Bash pedindo o resto do comando. Isso é muito usado em scripts para quebrar comandos compridos. Cuidado: nada pode vir depois da barra, nem um espaço.

Missão: entre na pasta Área de trabalho usando barras invertidas (sem aspas). Confira com pwd. Dica: digite cd Ár e aperte Tab para ver o que o Bash escreve.

2. Aspas simples '…': tudo é literal

Entre aspas simples, nada é especial. Nenhum caractere: nem espaço, nem $, nem *, nem \, nem !. O que você escreveu é exatamente o que o comando recebe, sem as aspas das pontas.

echo
Repete os argumentos na tela, separados por um espaço.
'
Abre as aspas simples: "a partir daqui, é tudo texto".
Olá, $nome
O texto. O $nome fica como está: não vira variável.
'
Fecha as aspas. Elas não aparecem na saída.
$ nome=Ana
$ echo 'Olá, $nome'
Olá, $nome                         « a variável NÃO foi trocada
$ echo 'Olá     mundo'
Olá     mundo                      « os espaços ficaram todos
$ echo Olá     mundo
Olá mundo                          « sem aspas: duas palavras, o echo junta com um espaço
$ echo '*.txt'
*.txt                              « o curinga não virou nome de arquivo
$ echo 'Hoje: $(whoami) em $(pwd)'
Hoje: $(whoami) em $(pwd)          « nenhum comando foi executado
$ echo 'C:\Users e \n'
C:\Users e \n                      « a barra também é só texto

Repare na terceira sessão: sem aspas, Olá mundo virou dois argumentos (Olá e mundo), e o echo sempre separa os argumentos com um espaço. Os espaços extras se perderam no corte das palavras, antes de o echo rodar.

Use aspas simples quando o texto deve chegar intacto: mensagens com $, padrões para o grep, programas para o awk e o sed, senhas de exemplo.

A única coisa que não cabe: outra aspa simples

Como a barra invertida não funciona dentro de aspas simples, não existe "aspa simples escapada" ali dentro. A primeira ' que aparecer fecha as aspas. Para escrever copo d'água há outras formas, que você vai ver na seção Uma aspa dentro da outra.

Missão: mostre na tela, exatamente, a frase O preço é $5. Tente primeiro echo O preço é $5 e veja o que acontece com o $5 (ele é uma variável especial, vazia aqui). Depois corrija.

3. Aspas duplas "…": agrupam, mas deixam o $ funcionar

As aspas duplas são as mais usadas. Elas protegem os espaços e os curingas (o texto continua sendo uma palavra só), mas deixam quatro caracteres com poder especial:

Dentro de "…"Continua funcionando?Exemplo
$Sim: variáveis, $( ) e $(( ))"Olá, $nome"
` (crase)Sim: executa o comando"Usuário: `whoami`"
\Só antes de $ ` " \ e do Enter"Custa \$5"
!Sim, no terminal (histórico). Em scripts, nãoveja a armadilha do !
espaço, * ? [ ~ { ' ; | & < > #Não: viram texto comum"*.txt", "copo d'água"
$ nome=Ana
$ echo "Olá, $nome"
Olá, Ana                                « a variável foi trocada pelo valor
$ echo "Pasta: $HOME e usuário: $USER"
Pasta: /home/ana e usuário: ana
$ echo "Hoje: $(whoami) em $(pwd)"
Hoje: ana em /home/ana                  « $( ) roda o comando e põe a resposta no lugar
$ echo "Crase: `whoami`"
Crase: ana                              « a forma antiga, com crases
$ echo "Olá     mundo"
Olá     mundo                           « espaços protegidos, como nas simples

Compare lado a lado o mesmo texto nos dois tipos de aspas:

$ echo 'Olá, $nome'
Olá, $nome
$ echo "Olá, $nome"
Olá, Ana

Essa é a diferença mais importante da aula: simples = nada muda; duplas = o $ funciona.

A barra invertida dentro das aspas duplas

Dentro de "…", a barra só é especial antes de cinco coisas: $, `, ", \ e a quebra de linha. Antes de qualquer outra letra, ela fica como está:

$ echo "Custa \$5"
Custa $5                         « \$ = um cifrão comum
$ echo "Ele disse \"oi\""
Ele disse "oi"                   « \" = aspa dupla dentro de aspas duplas
$ echo "Barra: \\ e \n e \a"
Barra: \ e \n e \a               « \\ virou uma barra; \n e \a ficaram como estavam
$ echo "C:\Users"
C:\Users
\n entre aspas duplas não pula linha

Muita gente espera que echo "a\nb" mostre duas linhas. No Bash, ele mostra a\nb. Para pular linha, use $'a\nb' (a próxima seção), printf 'a\nb\n' ou echo -e "a\nb". Veja a comparação em printf e echo.

Missão: a variável nome já vale Bruno. Mostre a frase Bruno disse "oi" para ana usando $nome e $USER (nada de digitar "Bruno" ou "ana"). As aspas em volta de oi devem aparecer na tela.

A armadilha do ! no terminal

No terminal (o shell interativo), o ! puxa comandos do histórico: !! é "o último comando", !ls é "o último comando que começou com ls". Isso se chama expansão de histórico e ela funciona até dentro de aspas duplas. O resultado surpreende:

$ echo "Olá!amigo"
bash: !amigo: event not found

O Bash leu !amigo como "o último comando que começou com amigo", não achou nenhum e cancelou a linha inteira. A mensagem vem em inglês mesmo: event not found = "evento não encontrado" (cada linha do histórico é um "evento"). O comando não rodou.

Pior ainda é quando o Bash acha o que procura:

$ ls Documentos
acesso.log  alunos.csv  notas.txt  projetos  relatorio.odt
$ echo "Ufa!!"
echo "Ufals Documentos"         « o Bash mostra a linha depois de trocar o !! pelo último comando
Ufals Documentos

Quando há expansão de histórico, o Bash sempre mostra a linha nova antes de executá-la. É o sinal de que um ! foi trocado.

O ! sozinho no fim do texto ou antes de um espaço não incomoda (echo "Bom dia!" funciona). Os problemas são ! seguido de letras, números ou outro !. Como resolver:

FormaExemploQuando usar
Aspas simplesecho 'Olá!amigo'O texto não tem variáveis. É a mais simples.
Só o ! em aspas simplesecho "Olá, $nome"'!'"amigo"O texto tem variáveis e exclamação.
Barra invertida, fora das aspasecho Uau\!\!Texto curto sem espaços.
Desligar a expansãoset +HVocê nunca usa !!. Vale até fechar o terminal; para ser permanente, coloque no ~/.bashrc (veja Arquivos de Inicialização).
$ echo 'Olá!amigo'
Olá!amigo
$ set +H
$ echo "Olá!amigo"
Olá!amigo                       « com a expansão de histórico desligada, funciona
Em scripts não existe esse problema

A expansão de histórico só vale no terminal. Dentro de um script, echo "Olá!amigo" funciona normalmente. Por isso o erro "event not found" aparece quando você testa um comando no terminal, mas não quando o mesmo comando está num script.

4. $'…': aspas com códigos de escape

Às vezes você quer o contrário: escrever caracteres "invisíveis", como uma quebra de linha ou um tab, dentro de um texto. A forma $'…' (um cifrão colado em aspas simples) funciona como as aspas simples, com uma diferença: a barra invertida volta a ter poder e entende os códigos de escape da linguagem C. Por isso o nome técnico é ANSI-C quoting.

$'
Abre: "texto literal, mas entenda os códigos com barra".
linha 1\nlinha 2
O \n (de new line) vira uma quebra de linha de verdade.
'
Fecha.
$ echo $'linha 1\nlinha 2'
linha 1
linha 2
$ echo $'col1\tcol2'
col1	col2                         « \t virou um tab
$ echo $'Ele disse: \'oi\''
Ele disse: 'oi'                  « \' = aspa simples, que nas aspas simples comuns é impossível
CódigoViraOrigem do nome
\nQuebra de linhanew line
\tTabtab
\\Uma barra invertida
\'Uma aspa simples
\"Uma aspa dupla
\eO caractere Escape, usado em cores (veja Menus e Cores)escape
\aO "bip" do terminalalert

O $'…' é muito útil para guardar textos com quebra de linha numa variável ou num arquivo:

$ echo $'pão\nleite' > lista.txt
$ cat lista.txt
pão
leite
Não confunda $'…' com "$…"

$'texto' é um tipo de aspas. "$texto" é uma variável chamada texto dentro de aspas duplas. Existe ainda $"…" (cifrão + aspas duplas), usado para traduzir mensagens de programas; você quase nunca vai precisar dele.

Misturando aspas na mesma palavra

Uma palavra do Bash pode ser feita de pedaços com aspas diferentes, desde que não haja espaço entre eles. O Bash cola os pedaços e depois tira as aspas:

$ printf '[%s]\n' "Ana""Bruno" "Ana" "Bruno"
[AnaBruno]                « pedaços colados = uma palavra
[Ana]                     « com espaço entre eles = palavras separadas
[Bruno]
$ printf '[%s]\n' "$USER"' mora em '"$HOME"
[ana mora em /home/ana]   « três pedaços: duplas, simples, duplas

Na segunda linha, a palavra tem três pedaços: "$USER" (a variável é trocada), ' mora em ' (texto literal, com os espaços) e "$HOME". Como não há espaço fora das aspas, é um argumento só.

Isso parece estranho no começo, mas é a chave para resolver dois problemas: misturar variáveis com texto que tem ! ou $, e colocar uma aspa simples dentro de aspas simples.

$ echo "Olá"'!'"amigo"
Olá!amigo
$ echo "Preço: R\$ 10" 'e mais $2'
Preço: R$ 10 e mais $2

Uma aspa dentro da outra

A Ana quer guardar o texto copo d'água numa variável. A aspa simples do meio é o problema. Sem nenhuma aspa, o Bash acha que você abriu aspas simples e ficou esperando o fechamento:

$ bebida=copo d'água
>                         « o Bash está esperando a aspa que fecha

Há quatro formas de resolver. Todas produzem o mesmo valor:

$ echo "copo d'água"
copo d'água               « 1. a aspa simples dentro de aspas duplas é comum
$ echo 'copo d'\''água'
copo d'água               « 2. fecha ', escapa \', abre ' de novo
$ echo 'copo d'"'"'água'
copo d'água               « 3. fecha ', põe "'", abre ' de novo
$ echo $'copo d\'água'
copo d'água               « 4. $'…' aceita \'

A forma 2 assusta, mas é só a mistura de aspas da seção anterior. Veja os pedaços:

'copo d'
Aspas simples com copo d. A aspa logo depois do d fecha as aspas.
\'
Fora de aspas, a barra protege uma aspa simples. Ela vira texto.
'água'
Abre aspas simples de novo, com água.

Os três pedaços estão colados, então formam uma palavra: copo d'água. A forma 3 é igual, só que a aspa do meio é protegida por aspas duplas ("'") em vez da barra.

Para o caso contrário, aspa dupla dentro de texto, use aspas simples por fora ou escape com \":

$ echo 'Ele disse "oi"'
Ele disse "oi"
$ echo "Ele disse \"oi\""
Ele disse "oi"
$ x=Bash
$ echo "Valor: '$x'"
Valor: 'Bash'             « a aspa simples dentro das duplas não impede a variável

Qual usar?

SituaçãoForma recomendada
Texto com ' e sem $ nem !"copo d'água"
Texto com ' e com $ que deve ficar literal'custa $5 no copo d'\''água' ou $'custa $5 no copo d\'água'
Texto com " e sem variáveis'Ele disse "oi"'
Texto com " e com variáveis"$nome disse \"oi\""
Texto que precisa de quebras de linha ou tabs$'a\nb'

Missão: crie a variável bebida com o valor copo d'água usando a forma 2 (aspas simples + \'). Confira com echo "$bebida". Se o Bash mostrar o prompt >, aperte Ctrl+C e tente de novo.

Aspas e nomes com espaço

Voltemos ao problema do começo. Todo nome com espaço precisa ser protegido, senão o Bash corta. Às vezes o resultado é um erro; às vezes é pior: o comando funciona, mas faz outra coisa.

$ mkdir Meus Projetos
$ ls
'Área de trabalho'   Downloads    Imagens   Modelos   Projetos   Vídeos
 Documentos          frutas.txt   Meus      Música    Público

Nenhum erro, mas foram criadas duas pastas: Meus e Projetos. O mkdir recebeu dois argumentos e fez o que pediram. O jeito certo:

$ rmdir Meus Projetos             « apaga as duas pastas vazias
$ mkdir "Meus Projetos"
$ touch "Copo d'água.txt" 'preço $5.txt'
$ ls
'Área de trabalho'   Downloads   'Meus Projetos'  'preço $5.txt'
"Copo d'água.txt"    frutas.txt   Modelos          Público
 Documentos          Imagens      Música           Vídeos

Repare como o ls mostra os nomes: ele coloca aspas nos que têm caracteres especiais, exatamente do jeito que você teria de digitá-los. 'Meus Projetos' com aspas simples; "Copo d'água.txt" com duplas, porque tem uma aspa simples dentro; 'preço $5.txt' com simples, por causa do $. Os nomes sem aspas ganham um espaço na frente só para ficarem alinhados. Essas aspas só aparecem quando o ls escreve na tela (veja Listar).

O mesmo vale para qualquer comando. Este grep procura um texto com espaço no arquivo de notas:

$ grep Ligar para Documentos/notas.txt
grep: para: Arquivo ou diretório inexistente           « "para" virou o nome de um arquivo!
Documentos/notas.txt:Ligar para o João
$ grep "Ligar para" Documentos/notas.txt
Ligar para o João

Sem aspas, o grep recebeu três argumentos: o padrão Ligar e dois arquivos, para e Documentos/notas.txt.

Missão: crie o arquivo Minhas notas.txt e a pasta Meus Projetos, cada um com um nome só (com o espaço dentro). Confira com ls: os dois devem aparecer entre aspas. Se criar pedaços soltos por engano, apague com rm ou rmdir.

Aspas e curingas (e o ~)

Os curingas só funcionam fora de aspas. Dentro de qualquer tipo de aspas, * é só um asterisco:

$ echo *.txt
frutas.txt                         « o Bash trocou o padrão pelos nomes que casam
$ echo "*.txt"
*.txt                              « entre aspas: texto comum
$ echo Documentos/*.csv
Documentos/alunos.csv
$ ls "Documentos/*.csv"
ls: não foi possível acessar 'Documentos/*.csv': Arquivo ou diretório inexistente
$ echo $?
2                                  « o ls procurou um arquivo chamado, literalmente, *.csv

Isso é útil quando um comando precisa receber o padrão como texto, para ele mesmo procurar. É o caso do find: em find . -name "*.txt", as aspas impedem o Bash de expandir o *, e o padrão chega inteiro ao find.

O til ~ também perde o poder entre aspas:

$ echo ~
/home/ana
$ echo "~"
~
$ cd "~/Documentos"
bash: cd: ~/Documentos: Arquivo ou diretório inexistente     « procurou uma pasta chamada "~"
$ cd ~/"Documentos" && pwd
/home/ana/Documentos                « o ~ fora das aspas, o resto dentro

Para caminhos com espaço a partir da pasta pessoal, deixe o ~ de fora: cd ~/"Área de trabalho". Ou use a variável: cd "$HOME/Área de trabalho".

Aspas em variáveis: "$var" sempre

Esta é a regra que mais evita bugs em scripts: quando usar uma variável, coloque-a entre aspas duplas. Veja por quê. A Ana guarda o nome da pasta numa variável:

$ pasta="Área de trabalho"
$ echo $pasta
Área de trabalho                « parece certo…
$ ls $pasta
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente
$ ls "$pasta"
$ touch "$pasta/lembrete.txt"
$ ls "$pasta"
lembrete.txt

As aspas da criação (pasta="Área de trabalho") guardaram o valor com os espaços. Mas, ao usar $pasta sem aspas, o Bash troca a variável pelo valor e corta de novo nos espaços. Esse corte depois da troca se chama separação de palavras (word splitting). O echo enganou: ele recebeu três palavras e as juntou com espaço, então pareceu certo.

E não são só os espaços. O valor da variável também passa pelos curingas:

$ frase="muitos     espaços   aqui"
$ echo $frase
muitos espaços aqui              « cortou nos espaços; o echo juntou com um só
$ echo "$frase"
muitos     espaços   aqui        « intacto
$ padrao="*.txt"
$ echo $padrao
frutas.txt                       « o * dentro da variável virou nome de arquivo!
$ echo "$padrao"
*.txt
EscritaO Bash fazResultado
$varTroca pelo valor → corta nos espaços → expande curingasZero, uma ou várias palavras. Imprevisível.
"$var"Troca pelo valor e paraSempre uma palavra, igual ao valor.
'$var'NadaO texto $var, literal.

Variável grudada em texto: ${var}

Dentro das aspas duplas, o nome da variável vai até onde houver letras, números e _. Se você quer colar texto logo depois, use chaves para marcar onde o nome acaba:

$ echo "$USERs"
                                 « procurou a variável USERs, que não existe: linha vazia
$ echo "${USER}s"
anas
Quando não precisa de aspas?

Em poucos lugares o Bash não corta a variável, como na criação de outra (copia=$pasta) e dentro de [[ ]]. Mas colocar as aspas ali não atrapalha. Por isso a regra prática é simples: na dúvida, "$var". Mais em Boas Práticas e no ShellCheck, que avisa quando falta aspa.

Missão: o script abaixo deveria listar a Área de trabalho, mas dá três erros. Clique em Rodar, leia os erros e corrija a terceira linha para aparecer lembrete.txt.

#!/usr/bin/env bash
pasta="Área de trabalho"
ls $pasta

#!/usr/bin/env bash
pasta="Área de trabalho"
ls "$pasta"

Rodando o script sem a correção, o Bash real mostra:

$ bash mostra.sh

Linha por linha: a linha 1 (o shebang) diz que o script é de Bash; a linha 2 guarda o nome com aspas, então o valor está certo; a linha 3 usa $pasta sem aspas, e é ali que o nome é cortado em três. Com ls "$pasta", a saída é lembrete.txt e o código de saída é 0.

Quando não funciona

Apareceu um > e o comando não roda 
$ echo It's ok
> fim
> ^C
$ echo $?
130

O que aconteceu: o apóstrofo de It's abriu aspas simples, e elas nunca foram fechadas. O Bash mostra o prompt de continuação > e fica esperando a aspa que fecha. Tudo o que você digitar (como o fim) entra no texto. O mesmo acontece com uma " sem par e com echo 'It\'s ok', porque a barra não funciona dentro de aspas simples.

Como resolver: aperte Ctrl+C para cancelar (o Bash mostra ^C e volta ao prompt normal; o código 130 indica "interrompido por Ctrl+C"). Depois digite de novo com as aspas certas: echo "It's ok". Se preferir, você também pode digitar a aspa que falta e apertar Enter, mas aí o texto já tem as linhas extras.

"número excessivo de argumentos" 
$ cd Área de trabalho
bash: cd: número excessivo de argumentos
$ echo $?
2

O que aconteceu: o nome tem espaços e foi cortado em várias palavras. O cd aceita só um destino.

Como confirmar: troque o comando por printf '[%s]\n' e veja quantos colchetes aparecem.

Como resolver: cd "Área de trabalho", cd 'Área de trabalho' ou cd Área\ de\ trabalho. Se o nome estiver numa variável: cd "$pasta".

"não foi possível acessar 'Área'" (vários erros, um por pedaço) 
$ ls -d Área de trabalho
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente

O que aconteceu: o mesmo problema, num comando que aceita vários argumentos. Em vez de reclamar da quantidade, ele tentou cada pedaço como um arquivo. Quando os erros citam pedaços de um nome, é sempre aspa faltando, quase sempre numa variável ($pasta em vez de "$pasta").

Como resolver: coloque o nome, ou a variável, entre aspas duplas.

"event not found" 
$ echo "Olá!amigo"
bash: !amigo: event not found

O que aconteceu: no terminal, ! seguido de texto busca um comando no histórico, mesmo entre aspas duplas. Nada foi executado.

Como resolver: use aspas simples ('Olá!amigo'), coloque só o ! em aspas simples ("Olá"'!'"amigo") ou desligue a expansão com set +H. Veja a armadilha do !.

A variável apareceu com o nome, e não com o valor 
$ nome=Ana
$ echo 'Olá, $nome'
Olá, $nome

O que aconteceu: não é erro: aspas simples desligam o $. O código de saída é 0, porque o echo fez exatamente o que recebeu.

Como resolver: troque por aspas duplas: echo "Olá, $nome".

Não apareceu nada (linha em branco) 
$ echo "$USERs"

O que aconteceu: o Bash procurou a variável USERs, que não existe. Variável inexistente vale vazio, e o echo mostrou uma linha vazia. Não há mensagem de erro e o código de saída é 0.

Como resolver: marque o fim do nome com chaves: echo "${USER}s". Para o Bash avisar quando você usa uma variável que não existe, veja set -u em set -euo pipefail.

Aspas "tortas" copiadas da internet 
$ cd “Documentos”
bash: cd: “Documentos”: Arquivo ou diretório inexistente
$ echo “Olá”
“Olá”

O que aconteceu: editores de texto, sites e aplicativos de mensagem trocam " por aspas curvas, “ ” e ‘ ’. Para o Bash, elas são letras comuns, não aspas. O cd procurou uma pasta cujo nome começa com “.

Como resolver: apague as aspas curvas e digite as retas do teclado (" e '). Ao copiar comandos, prefira o botão de copiar das páginas ou cole antes num editor de texto puro.

Resumo

  • O Bash corta a linha em palavras nos espaços e troca os caracteres especiais antes de rodar o comando. Aspas e barra invertida desligam isso.
  • \ protege um caractere; no fim da linha, continua o comando na próxima.
  • '…': tudo literal, inclusive $ e \. Não cabe outra ' dentro.
  • "…": uma palavra só, mas $, crase, \ e (no terminal) ! continuam funcionando.
  • $'…': literal, com códigos \n, \t, \'.
  • Pedaços com aspas diferentes, colados, formam uma palavra: 'copo d'\''água'.
  • Use variáveis sempre como "$var". Sem aspas, o valor é cortado nos espaços e passa pelos curingas.
  • Viu > do nada? Aspas abertas: Ctrl+C e digite de novo.
