Bash Personalizar o Prompt (PS1)

O texto ana@notebook:~$ que aparece antes de cada comando não é fixo: ele vem de uma variável chamada PS1. Mudando essa variável, você escolhe o que o prompt mostra (a pasta, a hora, o resultado do último comando, o ramo do git) e com que cores.

Você vai aprender
  • O que é o PS1 e os "escapes" que viram usuário, máquina, pasta, hora…
  • Como colocar cores com \[\e[…m\], e por que o \[ \] é obrigatório.
  • Como mostrar o código de saída do último comando e o ramo do git.
  • Para que servem PROMPT_COMMAND, PS0, PS2 e PS4.
  • Como deixar o prompt novo permanente no ~/.bashrc.

Se você ainda não sabe ler cada parte do prompt, veja antes Lendo o Prompt.

O prompt é uma variável

Peça para ver o valor do PS1 (Prompt String 1, "texto do prompt número 1"):

$ echo "$PS1"
\u@\h:\w\$

Esse é o valor que está no ~/.bashrc da Ana. Cada sequência que começa com contrabarra é um escape do prompt: o Bash troca por uma informação na hora de desenhar o prompt.

\u
O usuário (user): ana.
@
Texto comum, aparece como está.
\h
O nome da máquina (host), até o primeiro ponto: notebook.
:
Texto comum.
\w
A pasta atual (working directory), com ~ no lugar de /home/ana.
\$
$ para usuário comum, # para o root.
(espaço)
Um espaço no fim, para o comando não grudar no $.

Mudar na hora

Como é uma variável, basta atribuir outro valor. A mudança vale na hora, só neste terminal. Use aspas simples (o porquê vem daqui a pouco):

ana@notebook: ~
ana@notebook:~$ PS1='\W\$ '
~$ cd Documentos
Documentos$ PS1='[\t] \u:\w\$ '
[09:46:25] ana:~/Documentos$ PS1='\u@\h:\w\n\$ '
ana@notebook:~/Documentos
$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
ana@notebook:~/Documentos
$

O que aconteceu, linha por linha:

  1. PS1='\W\$ ': o prompt passou a mostrar só o nome da pasta atual (\W, maiúsculo), sem o caminho. Na pasta pessoal, o nome é ~.
  2. Depois do cd Documentos, o prompt virou Documentos$: ele é recalculado antes de cada comando.
  3. [\t] acrescentou a hora em que o prompt foi desenhado (o relógio do laboratório marcava 09:46).
  4. \n quebra a linha: informações em cima, o $ embaixo, e o comando começa sempre na mesma coluna.
Errou? Feche e abra o terminal

O PS1 mudado assim vale só para este terminal, até você fechá-lo. Se o prompt ficou estranho, abra um terminal novo (ou rode source ~/.bashrc) e tudo volta ao normal.

Missão: mude o PS1 para mostrar só o nome da pasta atual seguido de $ e um espaço ('\W\$ '). Depois entre em Documentos e veja o prompt mudar.

Testar sem trocar o prompt: ${PS1@P}

Dá para ver como um texto ficaria como prompt, sem mexer no seu. A transformação @P (de prompt) aplica os escapes a qualquer variável:

$ cd Documentos/projetos
$ p='\u@\h:\w\$ '
$ echo "${p@P}"
ana@notebook:~/Documentos/projetos$
$ p='\W | \t | \d | \A | \v'
$ echo "${p@P}"
projetos | 09:56:17 | sex out 16 | 09:56 | 5.3
$ p='linha 1\nlinha 2 \$ '
$ echo "${p@P}"
linha 1
linha 2 $

Assim você experimenta à vontade. O @P existe desde o bash 4.4; outras transformações (@Q, @U…) estão em Expansão de Parâmetros.

Não existe um escape para "código de saída": para isso usamos a variável $?, como você verá adiante.

Cores: \[\e[…m\]

Os terminais entendem "códigos de cor" (chamados de sequências ANSI): um caractere invisível ESC, seguido de [, números e a letra m. Tudo o que vem depois sai colorido, até outro código mudar a cor.

\[
"Começa um trecho invisível." Avisa o Bash que o que vem não ocupa espaço na tela.
\e
O caractere ESC (também se escreve \033).
[1;32m
O código: 1 = negrito, ; separa, 32 = verde, m fecha.
\]
"Fim do trecho invisível."
\u@\h
O texto que vai sair em verde.
\[\e[0m\]
0 = volta ao normal (reset). Sem ele, o resto da tela fica verde.

Um prompt completo, com usuário e máquina em verde e a pasta em azul (é o prompt colorido que o Ubuntu e o Debian vêm usando há anos):

PS1='\[\e[1;32m\]\u@\h\[\e[0m\]:\[\e[1;34m\]\w\[\e[0m\]\$ '

Veja o resultado no terminal (cores conferidas no laboratório com um terminal de verdade):

ana@notebook: ~/Documentos
[0] ~/Documentos$ PS1='\[\e[1;32m\]\u@\h\[\e[0m\]:\[\e[1;34m\]\w\[\e[0m\]\$ '
ana@notebook:~/Documentos$ cd
ana@notebook:~$

Por que o \[ \] é obrigatório

Para posicionar o cursor, o Bash precisa saber quantas colunas o prompt ocupa. Ele conta cada caractere do prompt pronto. Mas \e[1;32m não aparece na tela: são 7 caracteres que o terminal "come". Sem o \[ \], o Bash acha que o prompt é mais comprido do que é.

Enquanto você só digita comandos curtos, nada parece errado. O problema aparece ao editar:

  • um comando comprido não quebra para a linha de baixo no lugar certo e começa a escrever por cima do próprio prompt;
  • ao usar ↑ no histórico ou Home, o cursor para no lugar errado e sobram pedaços de comandos antigos na tela;
  • a linha "pula": o texto aparece deslocado algumas colunas.

O comando digitado continua certo (é só a tela que fica bagunçada), mas trabalhar assim é um tormento. A regra: todo código de cor no PS1 vai dentro de \[ e \]. Texto visível nunca vai dentro deles.

EscritaResultado
PS1='\e[32m\u\e[0m\$ 'Cor certa, mas a edição de linhas longas fica bagunçada.
PS1='\[\e[32m\]\u\[\e[0m\]\$ 'Correto.
PS1='\[\e[32m\u\]\[\e[0m\]\$ 'Errado ao contrário: o \u ficou dentro, o Bash acha que o prompt é mais curto.
Cores mais legíveis com variáveis

Um prompt colorido fica ilegível rápido. Guarde as cores em variáveis e monte o PS1 com elas:

verde='\[\e[1;32m\]'
azul='\[\e[1;34m\]'
normal='\[\e[0m\]'
PS1="${verde}\u@\h${normal}:${azul}\w${normal}\\$ "
unset verde azul normal

Aqui as aspas são duplas de propósito: queremos trocar ${verde} pelo valor agora. Por isso o \$ do fim virou \\$: dentro de aspas duplas, \\ vira uma contrabarra só, e o PS1 recebe \$. O tput é outra forma de obter as cores (veja Menus e Cores).

Mostrar o código de saída do último comando

O $? guarda o código do último comando. Colocando-o no PS1, você vê na hora se algo falhou, mesmo quando o comando não mostra mensagem nenhuma. Mas atenção às aspas:

ana@notebook: ~
ana@notebook:~$ false
ana@notebook:~$ PS1="[$?] \w\$ "
[1] ~$ true
[1] ~$ ls nada                        ← aspas duplas: o 1 ficou congelado
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
[1] ~$ PS1='[$?] \w\$ '
[0] ~$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
[2] ~$                                ← aspas simples: muda a cada comando
  • Com aspas duplas, o $? foi trocado pelo valor no momento da atribuição (1, do false). O PS1 ficou com o texto [1] fixo para sempre.
  • Com aspas simples, o PS1 guarda o texto $? e o Bash o expande cada vez que desenha o prompt. O ls nada devolveu 2 (arquivo não encontrado), e o prompt mostrou isso.

Essa é a regra geral: no PS1, variáveis e $( ) entre aspas simples são recalculados a cada prompt (o Bash faz isso porque a opção promptvars, de shopt, vem ligada).

Missão: crie um PS1 que mostre o código de saída entre colchetes, a pasta e o $ ('[$?] \w\$ ', com aspas simples). Depois rode ls nada e veja o número mudar.

Só quando falhar, e em vermelho

Um zero em todo prompt cansa. Uma função que monta o PS1 antes de cada prompt pode mostrar o código só quando ele não é zero, ou trocar a cor. Para rodar algo antes de cada prompt existe o PROMPT_COMMAND (próxima seção):

meu_prompt() {
  local codigo=$?                       # guarde o $? ANTES de qualquer outro comando
  local cor='\[\e[1;32m\]'              # verde
  (( codigo != 0 )) && cor='\[\e[1;31m\]'   # vermelho se falhou
  PS1="$cor[$codigo]\[\e[0m\] \u:\W\\$ "
}
PROMPT_COMMAND=meu_prompt
ana@notebook: ~
ana@notebook:~$ PROMPT_COMMAND=meu_prompt
[0] ana:~$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
[2] ana:~$ cd Documentos
[0] ana:Documentos$ false
[1] ana:Documentos$ true
[0] ana:Documentos$
LinhaO que faz
local codigo=$?Salva o código do último comando. Tem que ser a primeira linha: qualquer comando depois (até o local seguinte) troca o $?.
local cor='\[\e[1;32m\]'Começa com verde.
(( codigo != 0 )) && cor=…Se o código não é zero, troca para vermelho (31).
PS1="$cor[$codigo]…"Monta o PS1 com aspas duplas: aqui queremos os valores de agora, porque a função roda de novo antes de cada prompt.
PROMPT_COMMAND=meu_promptPede ao Bash para rodar a função antes de desenhar cada prompt.

PROMPT_COMMAND e PS0: antes e depois

O PROMPT_COMMAND guarda um comando que o Bash executa antes de mostrar cada prompt. O PS0 bash 4.4+ é um texto mostrado depois que você aperta Enter, antes de o comando rodar.

ana@notebook: ~
ana@notebook:~$ PS0='>> \t\n'
ana@notebook:~$ echo oi
>> 09:56:01                          ← PS0: depois do Enter
oi
ana@notebook:~$ PS0=
>> 09:56:01
ana@notebook:~$ PROMPT_COMMAND=(date)
sex 16 out 2026 09:56:01 -03         ← PROMPT_COMMAND: antes do prompt
ana@notebook:~$ echo um
um
sex 16 out 2026 09:56:01 -03
ana@notebook:~$ PROMPT_COMMAND+=('echo ---')
sex 16 out 2026 09:56:01 -03
---
ana@notebook:~$
  • O PS0 usa os mesmos escapes do PS1. Com \t, ele carimba a hora em que cada comando começou. Repare que o PS0= ainda mostrou o carimbo: a mudança só vale a partir do comando seguinte.
  • Desde o bash 5.1, o PROMPT_COMMAND pode ser um array: cada item é um comando, executados em ordem. Assim, programas diferentes (o seu .bashrc, ferramentas instaladas) acrescentam os seus com += sem apagar o dos outros. Em versões antigas, ele é um texto só: junte com ;.
Cuidado com o que roda no PROMPT_COMMAND

Ele roda a cada Enter. Um comando lento ali (consultar a rede, varrer pastas grandes) deixa o terminal inteiro lento. Mantenha-o leve.

O ramo do git no prompt

Quem usa git quer saber em que ramo (branch) está. O git traz uma função pronta, __git_ps1, que devolve o ramo da pasta atual (ou nada, fora de um repositório). Ela mora num arquivo que você carrega com source; o caminho varia:

SistemaArquivo com a __git_ps1
Debian / Ubuntu/usr/lib/git-core/git-sh-prompt (já carregado se o pacote bash-completion estiver ativo)
Fedora/usr/share/git-core/contrib/completion/git-prompt.sh
Arch/usr/share/git/completion/git-prompt.sh
macOS (git do Homebrew)$(brew --prefix)/etc/bash_completion.d/git-prompt.sh

Uma sessão no laboratório (que tem o git de um Ubuntu), criando um repositório de teste na pasta site:

ana@notebook: ~/site
ana@notebook:~$ source /usr/lib/git-core/git-sh-prompt
ana@notebook:~$ mkdir site && cd site
ana@notebook:~/site$ git init -q -b main
…
ana@notebook:~/site$ PS1='\u@\h:\w$(__git_ps1 " (%s)")\$ '
ana@notebook:~/site (main)$ echo oi > a.txt; git add a.txt; git commit -qm um
ana@notebook:~/site (main)$ git switch -qc teste
ana@notebook:~/site (teste)$ GIT_PS1_SHOWDIRTYSTATE=1
ana@notebook:~/site (teste)$ echo mais >> a.txt
ana@notebook:~/site (teste *)$ cd ..
ana@notebook:~$

(Encurtamos na linha …: ali a Ana configurou nome e e-mail no git, o que não interessa aqui.) Repare que o prompt ganhou (main) logo depois do PS1 novo, trocou para (teste) com o git switch, ganhou um * quando o arquivo mudou e sumiu ao sair da pasta.

$(__git_ps1 " (%s)")
Chama a função a cada prompt. O %s é trocado pelo nome do ramo; fora de um repositório, sai vazio.
' … '
Aspas simples, de novo: a substituição de comando precisa rodar a cada prompt, não uma vez só.
GIT_PS1_SHOWDIRTYSTATE=1
Opção da função: mostra * quando há alterações não salvas no git.

O git não faz parte do Bash: este é só um exemplo de como uma função externa entra no prompt. O simulador desta página não tem git.

PS4

No rastreamento de um script com bash -x, cada linha começa com o PS4. Colocar o número da linha ali ajuda muito a achar erros. Veja com este script de três linhas:

#!/usr/bin/env bash
nome=Ana
echo "Olá, $nome"

$ bash -x ola.sh
+ nome=Ana
+ echo 'Olá, Ana'
Olá, Ana
$ PS4='+ linha $LINENO: ' bash -x ola.sh     « PS4 só para este comando
+ linha 2: nome=Ana
+ linha 3: echo 'Olá, Ana'
Olá, Ana

O detalhe completo está em Depurar (set -x, bash -n).

Deixar permanente

Tudo o que você fez até aqui some ao fechar o terminal. Para valer sempre, o PS1 precisa estar no ~/.bashrc, que o Bash lê a cada terminal novo (veja Arquivos de Inicialização).

  1. Teste o prompt no terminal até gostar dele.
  2. Abra o ~/.bashrc num editor (nano ~/.bashrc) e procure a linha que começa com PS1=. No da Ana é PS1='\u@\h:\w\$ '.
  3. Troque essa linha pela sua (ou comente a antiga com # e escreva a nova embaixo). Se o seu .bashrc tiver vários PS1= (o do Ubuntu tem um bloco com color_prompt), vale o último que for executado.
  4. Recarregue: source ~/.bashrc, ou abra um terminal novo.

Sem editor, dá para acrescentar a linha no fim do arquivo com echo e >>. Repare no \\$: dentro das aspas duplas do echo, \\ vira uma contrabarra, e o arquivo recebe \$:

ana@notebook: ~
ana@notebook:~$ echo "PS1='[\t] \w\\$ '" >> ~/.bashrc
ana@notebook:~$ tail -n 1 ~/.bashrc
PS1='[\t] \w\$ '
ana@notebook:~$ source ~/.bashrc
[09:56:36] ~$

Como a linha nova ficou depois do PS1 original, é ela que vale. A partir de agora, todo terminal novo abre com esse prompt.

Missão: acrescente no fim do ~/.bashrc a linha PS1='[\t] \w\$ ' (como na sessão acima) e recarregue o arquivo com source ~/.bashrc. Confira com tail -n 1 ~/.bashrc.

Quando não funciona

O prompt mostra \u e \w literalmente

O que aconteceu: você colocou os escapes numa variável que não é prompt, ou usou echo para testar. Os escapes só valem dentro de PS0, PS1, PS2 e PS4 (e com ${var@P}).

Como resolver: teste com p='…'; echo "${p@P}" ou atribua direto ao PS1.

O código de saída (ou a hora feita com $(date)) não muda

O que aconteceu: o PS1 foi criado com aspas duplas, e o $? (ou o $(date)) foi trocado pelo valor uma vez só.

Como confirmar: echo "$PS1" mostra um número no lugar de $?.

Como resolver: use aspas simples: PS1='[$?] \w\$ '.

Linhas longas escrevem por cima do prompt; o histórico deixa lixo na tela

O que aconteceu: algum código de cor está fora de \[ \], e o Bash calcula errado o tamanho do prompt.

Como confirmar: echo "$PS1" e procure cada \e[: todos devem estar logo depois de um \[, e o m de cada código logo antes de um \].

Como resolver: envolva cada código: \[\e[1;32m\]. Para limpar a tela bagunçada agora, Ctrl+L.

Tudo ficou colorido depois do prompt

O que aconteceu: faltou o \[\e[0m\] no fim, que volta à cor normal. O que você digita e as saídas herdam a última cor.

Como resolver: termine cada trecho colorido com \[\e[0m\].

Mudei o .bashrc e nada mudou

O que aconteceu: o .bashrc só é lido quando o terminal abre; ou existe outro PS1= mais abaixo no arquivo, que sobrescreve o seu; ou o PROMPT_COMMAND está remontando o PS1 a cada prompt (como o meu_prompt acima).

Como confirmar: grep -n 'PS1=' ~/.bashrc mostra todas as atribuições; echo "$PROMPT_COMMAND" mostra se há algo rodando antes do prompt.

Como resolver: deixe a sua linha por último, rode source ~/.bashrc e, se precisar, unset PROMPT_COMMAND.

"__git_ps1: comando não encontrado" a cada prompt

O que aconteceu: o PS1 chama a função, mas o arquivo que a define não foi carregado (ou o caminho é outro na sua distro).

Como resolver: coloque o source do arquivo certo (tabela acima) antes do PS1 no ~/.bashrc.

Exercícios

1. Só o nome da pasta

Complete para o prompt mostrar apenas o nome da pasta atual (por exemplo, projetos$):

PS1='\$ '

2. Fechar a cor

Complete o fim do prompt, voltando à cor normal do jeito certo:

PS1='\[\e[1;34m\]\w\$ '

3. Hora no prompt

Complete para o prompt mostrar a hora no formato HH:MM:SS entre colchetes:

PS1='[] \w\$ '

4. A Ana escreveu PS1="[$?] \$ " e o número no prompt nunca muda. Por quê?

5. Para que serve o \[ \] em volta dos códigos de cor?

6. Qual variável define o começo das linhas mostradas pelo set -x?

Resumo

  • O prompt vem da variável PS1; escapes como \u \h \w \W \$ \t \n viram informações a cada prompt. Teste com echo "${p@P}".
  • Cores: \[\e[1;32m\] para começar e \[\e[0m\] para voltar ao normal. O \[ \] é obrigatório, senão a edição de linhas fica bagunçada.
  • Use aspas simples para que $? e $( ) (como __git_ps1) sejam recalculados a cada prompt.
  • PROMPT_COMMAND roda antes de cada prompt; PS0 aparece depois do Enter; PS2 é a continuação; PS4 é o do set -x.
  • Para ficar permanente, coloque o PS1 no fim do ~/.bashrc e rode source ~/.bashrc.
