Bash Criar, Copiar e Mover

Quatro comandos fazem quase todo o trabalho de organizar arquivos: mkdir cria pastas, touch cria arquivos vazios, cp copia e mv move ou renomeia. Eles não fazem parte do Bash: são programas separados. Mas o Bash trabalha antes deles, montando a lista de nomes que cada um recebe, e entender essa divisão de trabalho evita os erros mais comuns.

Você vai aprender
  • Criar pastas (inclusive várias e uma árvore inteira) com mkdir e arquivos com touch.
  • Copiar arquivos e pastas com cp, sem sobrescrever nada por engano (-i, --update=none, -u).
  • Por que renomear e mover são a mesma coisa para o mv.
  • Como o Bash ajuda: chaves {a,b}, curingas * e aspas em nomes com espaço.
  • Ler o código de saída (echo $?) e resolver os erros reais desses comandos.

Os exemplos acontecem na pasta pessoal da Ana (/home/ana, o ~), a mesma do simulador. Você pode repetir tudo nas caixas "Experimente".

Quem faz o quê: o Bash e o programa

Quando você digita mkdir aulas provas, acontecem duas etapas:

  1. O Bash lê a linha, separa as palavras nos espaços, expande chaves { }, curingas * e variáveis $x, e tira as aspas.
  2. Só então ele chama o programa mkdir, entregando a lista final de palavras: aulas e provas.

O mkdir nunca vê as chaves, os asteriscos nem as aspas que você digitou. Ele recebe só o resultado. Guarde isso: quase todo erro desta aula é uma diferença entre o que você quis dizer e a lista que o Bash montou. Para ver essa lista, troque o comando por echo, que apenas repete o que recebeu.

$ type mkdir cp mv touch
mkdir é /usr/bin/mkdir          « programas de verdade, em /usr/bin
cp é /usr/bin/cp
mv é /usr/bin/mv
touch é /usr/bin/touch

O type (veja Obtendo Ajuda) mostra que nenhum dos quatro é um comando interno do Bash: são programas do pacote GNU coreutils.

mkdir: criar uma pasta

mkdir vem de make directory, "criar diretório". Diretório é o nome técnico de pasta.

mkdir
O programa que cria pastas.
estudos
O argumento: o nome da pasta nova. Sem / no começo, ela é criada dentro da pasta atual.
$ mkdir estudos
$ ls
'Área de trabalho'   Downloads   frutas.txt   Modelos   Público
 Documentos          estudos     Imagens      Música    Vídeos      « "estudos" apareceu

O mkdir não respondeu nada. Nos programas do Linux, silêncio é sucesso: eles só falam quando dá errado ou quando você pede. Para ter certeza, além do ls, existe o código de saída, um número que todo comando devolve ao Bash e que fica guardado em $?:

$ mkdir estudos
mkdir: cannot create directory ‘estudos’: Arquivo existe
$ echo $?
1                                      « diferente de 0: deu errado

Na segunda vez a pasta já existia, e o código foi 1. Quando dá certo, o código é 0. A mensagem mistura inglês e português porque a tradução do coreutils ainda não está completa; você verá a mesma coisa no seu terminal. O $? tem uma aula própria: Código de Saída.

Pedindo para falar: -v

A opção -v (de verbose, "detalhado") faz o mkdir contar o que fez. Opções começam com hífen e mudam o comportamento do programa.

$ mkdir -v aulas
mkdir: foi criado o diretório 'aulas'

Várias pastas de uma vez

Cada palavra separada por espaço vira um argumento, e o mkdir cria uma pasta para cada um:

$ mkdir jan fev mar
$ ls
fev  jan  mar

Nome com espaço: o Bash separa antes

Como o Bash separa as palavras nos espaços, um nome com espaço vira dois argumentos:

$ mkdir Meus Projetos
$ ls
fev  jan  mar  Meus  Projetos          « duas pastas!

Para o Bash tratar o nome como uma palavra só, use aspas. Elas são lidas pelo Bash e removidas; o mkdir recebe Meus Projetos inteiro, sem aspas:

$ rmdir Meus Projetos                 « desfaz o engano (rmdir apaga pastas vazias)
$ mkdir "Meus Projetos"
$ ls
 fev   jan   mar  'Meus Projetos'

Agora o ls mostra o nome entre aspas simples: é o jeito dele dizer "isto é um nome só, com espaço". As aspas não fazem parte do nome. Você vai estudar todos os tipos de aspas em Aspas e Escapes.

Pastas dentro de pastas: -p

Sem opções, o mkdir só cria o último nível do caminho. Se uma pasta do meio não existe, ele recusa:

$ mkdir site/css
mkdir: cannot create directory ‘site/css’: Arquivo ou diretório inexistente
$ echo $?
1

A opção -p (de parents, "pais") cria todas as pastas que faltam no caminho, e não reclama se a pasta já existir:

mkdir
O programa.
-pv
Duas opções juntas: -p (cria os pais) e -v (conta o que fez). -pv é o mesmo que -p -v.
site/css
O caminho completo desejado.
$ mkdir -pv site/css
mkdir: foi criado o diretório 'site'
mkdir: foi criado o diretório 'site/css'
$ mkdir -p site/css
$ echo $?
0                                      « já existia, e mesmo assim é sucesso
Em scripts, prefira mkdir -p

Ele garante que a pasta exista, sem quebrar o script se ela já estiver lá. Isso deixa o script seguro para rodar duas vezes.

Uma árvore inteira com chaves

As chaves são uma expansão do Bash: loja/{src,docs} vira loja/src loja/docs antes de o programa rodar. Com o echo na frente, você vê exatamente a lista que o mkdir vai receber:

$ echo mkdir -p loja/{src,docs,testes/{unidade,integracao}}
mkdir -p loja/src loja/docs loja/testes/unidade loja/testes/integracao
$ mkdir -pv loja/{src,docs,testes/{unidade,integracao}}
mkdir: foi criado o diretório 'loja'
mkdir: foi criado o diretório 'loja/src'
mkdir: foi criado o diretório 'loja/docs'
mkdir: foi criado o diretório 'loja/testes'
mkdir: foi criado o diretório 'loja/testes/unidade'
mkdir: foi criado o diretório 'loja/testes/integracao'

Repare que as chaves podem ficar uma dentro da outra (testes/{unidade,integracao}). Para conferir a árvore, o find lista tudo o que há dentro de uma pasta:

$ find loja
loja
loja/testes
loja/testes/integracao
loja/testes/unidade
loja/src
loja/docs

As chaves funcionam com qualquer comando, e têm sua própria aula: Chaves {a,b} e {1..10}. Ali você aprende também as sequências, como aula{01..12}.

touch: criar arquivos vazios

touch quer dizer "tocar". A função original é atualizar a data de modificação de um arquivo ("tocar" nele). Se o arquivo não existe, ele cria um vazio, e por isso é o jeito mais comum de criar arquivos.

touch
O programa.
anotacoes.txt
O arquivo a criar, ou a "tocar" se já existir.
$ touch anotacoes.txt
$ echo $?
0
$ ls -l anotacoes.txt
-rw-rw-r-- 1 ana ana 0 out 15 10:30 anotacoes.txt      « tamanho 0: vazio

A coluna com o 0 é o tamanho em bytes. As colunas do ls -l são explicadas uma a uma em Listar (ls).

Vários arquivos, com chaves e com aspas

$ touch "lista de compras.txt" notas-aula.txt
$ touch capitulo{1..3}.md
$ ls
 capitulo1.md   fev                     mar
 capitulo2.md   jan                    'Meus Projetos'
 capitulo3.md  'lista de compras.txt'   notas-aula.txt

Três palavras para o Bash: o nome entre aspas (com espaços), notas-aula.txt e, na segunda linha, as três geradas por capitulo{1..3}.md.

O touch não apaga o conteúdo

Se o arquivo já existe, o touch só muda a data. O conteúdo fica intacto:

$ ls -l frutas.txt
-rw-rw-r-- 1 ana ana 47 out 14 16:05 frutas.txt
$ touch frutas.txt
$ ls -l frutas.txt
-rw-rw-r-- 1 ana ana 47 out 15 10:30 frutas.txt      « mesmo tamanho; só a data mudou
$ wc -l frutas.txt
7 frutas.txt                                         « as 7 linhas continuam lá

Com -d (de date) você escolhe a data. É útil para testar scripts que apagam "arquivos antigos":

$ touch -d "2026-01-01 08:00" antigo.log
$ ls -l antigo.log
-rw-rw-r-- 1 ana ana 0 jan  1  2026 antigo.log

Outras formas de criar um arquivo

O touch só cria arquivos vazios. Para já escrever algo, o próprio Bash cria o arquivo com um redirecionamento:

FormaO que fazCuidado
touch arq.txtCria vazio, ou só atualiza a dataNunca apaga conteúdo
echo "texto" > arq.txtCria com uma linhaApaga o que havia antes
echo "texto" >> arq.txtAcrescenta uma linha no fimSeguro: não apaga nada
> arq.txtCria vazio, ou esvazia um existenteApaga sem perguntar

O > e o >> são assunto de Redirecionamento.

Missão: com um único mkdir, crie a pasta curso contendo aulas, exercicios e provas. Depois, com um único touch, crie aula1.txt, aula2.txt e aula3.txt dentro de curso/aulas. Dica: teste antes com echo na frente; confira no fim com find curso.

cp: copiar arquivos

cp vem de copy, "copiar". Ele tem duas formas, e o que muda é o último argumento:

cp ORIGEM NOVO-NOME            « uma cópia, com outro nome
cp ORIGEM... PASTA/            « uma ou mais cópias dentro de uma pasta que já existe

Forma 1: cópia com outro nome

cp
O programa.
frutas.txt
A origem: o arquivo que já existe.
frutas-copia.txt
O destino: o nome da cópia. Se já existir um arquivo com esse nome, ele é substituído sem aviso.
$ cp frutas.txt frutas-copia.txt
$ echo $?
0
$ ls -l frutas.txt frutas-copia.txt
-rw-rw-r-- 1 ana ana 47 out 15 10:30 frutas-copia.txt   « a cópia ganha a data de agora
-rw-rw-r-- 1 ana ana 47 out 14 16:05 frutas.txt

A cópia tem o mesmo tamanho (47 bytes), mas a data é a do momento da cópia. Mais adiante, o -a muda isso.

Forma 2: copiar para dentro de uma pasta

Quando o último argumento é uma pasta que existe, as cópias vão para dentro dela, com o mesmo nome. A opção -v mostra cada cópia no formato 'origem' -> 'destino':

$ cp -v frutas.txt Documentos/notas.txt Imagens/
'frutas.txt' -> 'Imagens/frutas.txt'
'Documentos/notas.txt' -> 'Imagens/notas.txt'
Termine o nome da pasta com /

A barra no fim deixa claro que o destino é uma pasta. Se a pasta não existir, você recebe um erro em vez de um arquivo com o nome errado:

$ cp frutas.txt Docs/
cp: não foi possível criar arquivo comum 'Docs/': Não é um diretório
$ cp frutas.txt Docs
$ ls -l Docs
-rw-rw-r-- 1 ana ana 47 out 15 10:30 Docs            « sem a barra: virou um ARQUIVO chamado Docs

Copiar com curinga: quem expande é o Bash

O * quer dizer "qualquer sequência de caracteres". O Bash troca relatorio-*.txt pelos nomes que existem e casam com o padrão, em ordem alfabética, e o cp recebe a lista pronta:

$ touch relatorio-{jan,fev,mar}.txt
$ mkdir backup-2026
$ echo cp -v relatorio-*.txt backup-2026/
cp -v relatorio-fev.txt relatorio-jan.txt relatorio-mar.txt backup-2026/
$ cp -v relatorio-*.txt backup-2026/
'relatorio-fev.txt' -> 'backup-2026/relatorio-fev.txt'
'relatorio-jan.txt' -> 'backup-2026/relatorio-jan.txt'
'relatorio-mar.txt' -> 'backup-2026/relatorio-mar.txt'

Os curingas têm aula própria: Curingas (*, ?, [ ]).

O truque do backup: cp arquivo{,.bak}

Antes de editar um arquivo importante, faça uma cópia de segurança. Com chaves, você não precisa digitar o nome duas vezes: {,.bak} tem duas opções, "nada" e ".bak".

$ echo cp frutas.txt{,.bak}
cp frutas.txt frutas.txt.bak
$ cp -v frutas.txt{,.bak}
'frutas.txt' -> 'frutas.txt.bak'

Não sobrescrever por engano: -i, --update=none, -u

Por padrão, o cp substitui o destino em silêncio. Se Documentos/frutas.txt já existia com outro conteúdo, ele se perdeu. Três opções mudam isso:

-i: perguntar antes

-i vem de interactive. Antes de substituir, o cp pergunta. Responda s (sim) para substituir; qualquer outra coisa mantém o arquivo antigo.

$ cp -i frutas.txt Documentos/
cp: sobrescrever 'Documentos/frutas.txt'? n
$ echo $?
1                                       « recusou: código 1

--update=none: nunca sobrescrever

Para pular, sem perguntar, os arquivos que já existem no destino, use --update=none. A forma curta antiga, -n (no-clobber, "não destruir"), ainda funciona, mas o coreutils atual avisa que ela pode mudar:

$ cp -n frutas.txt Documentos/
cp: warning: behavior of -n is non-portable and may change in future; use --update=none instead
$ cp --update=none frutas.txt Documentos/
$ echo $?
0                                       « nada copiado, sem aviso, e não é erro

-u: só se a origem for mais nova

-u (de update, "atualizar") copia apenas quando o destino não existe ou é mais antigo que a origem. É o jeito simples de "sincronizar" uma cópia:

$ cp -uv frutas.txt Documentos/         « nada aparece: a cópia já estava em dia
$ touch frutas.txt
$ cp -uv frutas.txt Documentos/
'frutas.txt' -> 'Documentos/frutas.txt' « agora a origem é mais nova

Copiar pastas: -r e -a

Sem opção, o cp se recusa a copiar uma pasta:

$ cp Documentos/projetos backup
cp: -r não especificado; omitindo o diretório 'Documentos/projetos'
$ echo $?
1

-r (de recursive, "recursivo") copia a pasta com tudo o que há dentro, nível por nível:

$ cp -rv Documentos/projetos copia2
'Documentos/projetos' -> 'copia2'
'Documentos/projetos/site' -> 'copia2/site'
'Documentos/projetos/site/index.html' -> 'copia2/site/index.html'
'Documentos/projetos/site/style.css' -> 'copia2/site/style.css'
'Documentos/projetos/backup.sh' -> 'copia2/backup.sh'
A segunda vez é diferente da primeira

Se o destino não existe, a cópia ganha o nome do destino. Se ele já existe, a pasta é copiada para dentro dele. Rodar o mesmo comando duas vezes cria uma pasta a mais:

$ cp -r Documentos/projetos backup
$ ls backup
backup.sh  site
$ cp -r Documentos/projetos backup
$ ls backup
backup.sh  projetos  site                « apareceu backup/projetos!

Para copiar só o conteúdo de uma pasta para outra que já existe, use origem/. (o ponto é "esta pasta"): cp -r Documentos/projetos/. backup/.

-a: a cópia fiel

-a (de archive, "arquivar") copia recursivamente e preserva datas, permissões e links. Use para backups, quando a data original importa:

$ cp Documentos/notas.txt n1.txt
$ cp -a Documentos/notas.txt n2.txt
$ ls -l n1.txt n2.txt
-rw-rw-r-- 1 ana ana 69 out 15 10:30 n1.txt     « cp comum: data de agora
-rw-rw-r-- 1 ana ana 69 out 14 17:40 n2.txt     « cp -a: data original

Missão: faça uma cópia fiel (com as datas originais) da pasta Documentos/projetos com o nome projetos-backup, na sua pasta pessoal. Confira com ls -l projetos-backup. Cuidado: se rodar duas vezes, aparece projetos-backup/projetos e a missão não conta.

mv: mover e renomear

mv vem de move, "mover". Para o sistema, renomear é mover um arquivo para um nome novo. Por isso não existe um comando "rename" básico: o mv faz as duas coisas, com as mesmas duas formas do cp.

Renomear

mv
O programa.
lista.txt
O nome atual.
compras.txt
O nome novo. Como não é uma pasta existente, o mv entende "renomear".
$ cp frutas.txt lista.txt
$ mv lista.txt compras.txt
$ echo $?
0
$ ls lista.txt compras.txt
ls: não foi possível acessar 'lista.txt': Arquivo ou diretório inexistente
compras.txt                             « o nome antigo sumiu, o novo existe

Renomear com chaves funciona como o backup: notas{.txt,.md} vira notas.txt notas.md.

$ echo mv notas{.txt,.md}
mv notas.txt notas.md
$ mv -v notas{.txt,.md}
renomeado 'notas.txt' -> 'notas.md'

Mover para uma pasta

Quando o último argumento é uma pasta que existe, os arquivos vão para dentro dela:

$ mkdir fotos
$ mv -v Downloads/foto.jpg Imagens/ferias.jpg fotos/
renomeado 'Downloads/foto.jpg' -> 'fotos/foto.jpg'
renomeado 'Imagens/ferias.jpg' -> 'fotos/ferias.jpg'

O -v do mv diz "renomeado" mesmo quando o arquivo mudou de pasta, porque, para ele, é a mesma operação.

Pastas não precisam de -r

Ao contrário do cp, o mv move ou renomeia uma pasta inteira sem opção nenhuma. Ele não copia nada: só muda o endereço.

$ mv fotos imagens-viagem               « renomeia a pasta
$ mv -v imagens-viagem Imagens/          « move a pasta para dentro de Imagens
renomeado 'imagens-viagem' -> 'Imagens/imagens-viagem'
O mv também sobrescreve em silêncio

Se o destino já existe, o arquivo antigo é substituído e se perde, com código 0:

$ echo "versão nova" > a.txt
$ echo "versão velha importante" > b.txt
$ mv a.txt b.txt
$ echo $?
0
$ cat b.txt
versão nova                            « a "versão velha importante" acabou

Use mv -i (pergunta) ou mv -n (nunca sobrescreve) quando não tiver certeza. No mv, o -n não gera aviso.

$ mv -i frutas.txt Documentos/
mv: sobrescrever 'Documentos/frutas.txt'? n
$ echo $?
1

Quando não funciona

"Arquivo existe" 
$ mkdir estudos
mkdir: cannot create directory ‘estudos’: Arquivo existe

O que aconteceu: já existe uma pasta, ou um arquivo, com esse nome.

Como confirmar: ls -ld estudos. Se a linha começa com d, é uma pasta; com -, é um arquivo.

Como resolver: se você só queria garantir que a pasta exista, use mkdir -p estudos. Se é um arquivo, escolha outro nome.

"Arquivo ou diretório inexistente" no mkdir ou no touch 
$ mkdir projetos/2026/janeiro
mkdir: cannot create directory ‘projetos/2026/janeiro’: Arquivo ou diretório inexistente
$ touch semnada/a.txt
touch: não foi possível tocar 'semnada/a.txt': Arquivo ou diretório inexistente

O que aconteceu: uma pasta do meio do caminho não existe. O touch nunca cria pastas.

Como resolver: crie o caminho antes com mkdir -p projetos/2026, ou de uma vez: mkdir -p projetos/2026/janeiro.

"Não é um diretório" 
$ mkdir frutas.txt/x
mkdir: cannot create directory ‘frutas.txt/x’: Não é um diretório

O que aconteceu: uma parte do caminho é um arquivo, e arquivos não podem conter nada.

Como resolver: confira o caminho com ls -ld frutas.txt e corrija o nome.

"Permissão negada" 
$ mkdir trancada/x
mkdir: cannot create directory ‘trancada/x’: Permissão negada
$ touch trancada/a.txt
touch: não foi possível tocar 'trancada/a.txt': Permissão negada

O que aconteceu: você não tem permissão de escrita naquela pasta. Fora da sua pasta pessoal (por exemplo, em /etc ou /usr), quase tudo é do administrador, e a mensagem é a mesma.

Como confirmar: ls -ld trancada mostra as permissões (dr-xr-xr-x: sem w, sem escrita).

Como resolver: trabalhe dentro da sua pasta pessoal. Para pastas do sistema, é preciso ser administrador, o que foge desta aula.

"-r não especificado; omitindo o diretório" 
$ cp Documentos/projetos backup
cp: -r não especificado; omitindo o diretório 'Documentos/projetos'

O que aconteceu: a origem é uma pasta, e o cp só copia pastas com -r (ou -a).

Como resolver: cp -r Documentos/projetos backup.

"alvo '…': Arquivo ou diretório inexistente": o nome com espaço 
$ cp frutas.txt Área de trabalho/
cp: alvo 'trabalho/': Arquivo ou diretório inexistente

O que aconteceu: sem aspas, o Bash entregou quatro argumentos ao cp: frutas.txt, Área, de e trabalho/. Com mais de uma origem, o último argumento tem que ser uma pasta, e trabalho/ não existe.

Como confirmar: echo cp frutas.txt Área de trabalho/ mostra as palavras separadas.

Como resolver: aspas em volta do nome: cp frutas.txt "Área de trabalho/". A tecla Tab completa e já coloca as barras no lugar (veja Completar com Tab).

"falta o operando arquivo de destino" 
$ cp frutas.txt
cp: falta o operando arquivo de destino após 'frutas.txt'
Tente "cp --help" para mais informações.

O que aconteceu: o cp (e o mv) precisa de pelo menos dois nomes: origem e destino. Às vezes você digitou os dois, mas uma variável vazia ou um curinga que não casou com nada sumiu com um deles.

Como resolver: informe o destino. Para "copiar para a pasta atual", o destino é .: cp Documentos/notas.txt .

Outros recados do cp e do mv 
$ cp naoexiste.txt x.txt
cp: não foi possível obter estado de 'naoexiste.txt': Arquivo ou diretório inexistente
$ cp frutas.txt frutas.txt
cp: 'frutas.txt' e 'frutas.txt' são o mesmo arquivo
$ mv Documentos Documentos/projetos/
mv: não é possível mover 'Documentos' para um subdiretório de si mesmo, 'Documentos/projetos/Documentos'

"Obter estado" é a tradução de stat, ler as informações do arquivo: a origem não existe (confira o nome com ls ou use Tab). Os outros dois são pedidos impossíveis: copiar um arquivo sobre ele mesmo e colocar uma pasta dentro dela própria.

Não apareceu nada… deu certo?

O que aconteceu: esses quatro programas ficam em silêncio quando funcionam. Isso também vale para cp -u e cp --update=none quando eles decidem não copiar.

Como confirmar: echo $? logo depois (0 = sucesso), ou repita com -v para ver o que foi feito.

4. A Ana digitou mkdir Fotos de Família. O que aconteceu?

Resumo

  • mkdir cria pastas; -p cria o caminho inteiro e não falha se já existir.
  • touch cria arquivos vazios e nunca apaga conteúdo.
  • cp origem destino copia; pastas exigem -r (ou -a, que preserva datas).
  • mv renomeia e move; pastas não precisam de opção.
  • cp e mv sobrescrevem em silêncio: use -i ou --update=none na dúvida.
  • Chaves, curingas e aspas são do Bash, que monta a lista de nomes antes do programa rodar. Teste com echo.
  • Silêncio é sucesso; confirme com echo $?.
