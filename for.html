Bash for

O for repete um bloco de comandos uma vez para cada item de uma lista: cada nome, cada arquivo, cada número. É o laço que você mais vai usar em scripts, porque quase toda tarefa repetitiva ("faça isto com todas as fotos") cabe nele.

Você vai aprender
  • A forma for x in lista; do … done, parte por parte, e como escrevê-la numa linha só.
  • Como percorrer arquivos com curingas, e o que acontece quando nenhum arquivo combina (nullglob).
  • Como contar com {1..10}, com for ((i=0; i<5; i++)) e com seq.
  • Como percorrer os argumentos do script com "$@".
  • Por que for linha in $(cat arquivo) e for f in $(ls) quebram nomes com espaço, e como renomear arquivos em lote com segurança.

O problema: fazer a mesma coisa várias vezes

A Ana quer cumprimentar três amigos. Sem laço, ela escreve três comandos quase iguais:

echo "Olá, Ana!"
echo "Olá, Bruno!"
echo "Olá, Carla!"

Funciona, mas e se fossem 300 nomes? Ou 300 fotos para renomear? Repare que só uma parte muda (o nome). O for deixa você escrever o comando uma vez, com uma variável no lugar da parte que muda, e o Bash repete para cada item.

A forma mais simples: for x in lista

for VARIÁVEL in ITEM1 ITEM2 ITEM3; do
  comandos que usam $VARIÁVEL
done

Os nomes vêm do inglês: for = "para (cada)", in = "em", do = "faça" e done = "feito". Lido em voz alta: "para cada fruta em maçã, banana e uva, faça… feito".

$ for fruta in maçã banana uva; do
>   echo "Eu gosto de $fruta"
> done
Eu gosto de maçã           « 1ª volta: fruta=maçã
Eu gosto de banana         « 2ª volta: fruta=banana
Eu gosto de uva            « 3ª volta: fruta=uva
$ echo $?
0                          « o laço terminou bem
for
Palavra que abre o laço.
fruta
O nome da variável que recebe um item a cada volta. Sem $ aqui: você está dando nome a ela, não lendo o valor.
in maçã banana uva
A lista. São três palavras, separadas por espaço, então serão três voltas.
; do
Fim da lista e começo do corpo. O ; é necessário porque o do está na mesma linha da lista.
echo "Eu gosto de $fruta"
O corpo: o que se repete. Aqui você usa $fruta, com $, para ler o valor da vez.
done
Fim do corpo. O Bash volta para o for, pega o próximo item e repete. Quando os itens acabam, segue para o que vem depois do done.

Enquanto você digita no terminal, o Bash mostra > no começo das linhas: é o prompt de continuação, avisando que o for ainda não foi fechado. Você não digita esse sinal. Só quando aparece o done o laço inteiro roda.

O que o for devolve

O código de saída de um for é o do último comando que rodou dentro dele. Se a lista estiver vazia e o corpo não rodar nenhuma vez, o código é 0. E a variável continua existindo depois do laço, com o último valor:

$ echo "$fruta"
uva                        « ficou com o valor da última volta

Tudo numa linha

Para laços curtos no terminal, escreva tudo numa linha. A regra é: antes de do e antes de done vai um ; (ou uma quebra de linha).

$ for fruta in maçã banana uva; do echo "Eu gosto de $fruta"; done
Eu gosto de maçã
Eu gosto de banana
Eu gosto de uva
OndeEm várias linhasNuma linha
Entre a lista e o doquebra de linha (ou ; do na mesma linha);
Entre um comando e outro do corpoquebra de linha;
Entre o último comando e o donequebra de linha;

Quando você aperta a seta para cima depois de um for de várias linhas, o histórico mostra exatamente essa versão de uma linha. É assim que o Bash guarda o laço.

Missão: use um for para cumprimentar Ana, Bruno, Carla e Diego, um por linha, no formato Olá, Nome!. Clique em Rodar.

#!/usr/bin/env bash
# troque estas linhas por um for
echo "Olá, Ana!"
echo "Olá, Bruno!"

#!/usr/bin/env bash
for nome in Ana Bruno Carla Diego; do
  echo "Olá, $nome!"
done

Percorrer arquivos com curingas

O uso mais comum do for é "para cada arquivo". Em vez de escrever os nomes, você usa um curinga (veja Curingas). O Bash troca o curinga pela lista de arquivos que combinam, em ordem alfabética, antes de o laço começar.

$ cd Documentos
$ for arq in *; do
>   echo "Encontrei: $arq"
> done
Encontrei: acesso.log
Encontrei: alunos.csv
Encontrei: notas.txt
Encontrei: projetos            « pastas também entram no *
Encontrei: relatorio.odt

Você pode colocar vários curingas na lista, e usar o arquivo da vez em qualquer comando:

$ for arq in *.csv *.txt; do
>   echo "$arq tem $(wc -l < "$arq") linhas"
> done
alunos.csv tem 6 linhas          « primeiro tudo que combinou com *.csv…
notas.txt tem 4 linhas           « …depois tudo que combinou com *.txt
*.csv *.txt
Dois curingas. O Bash expande cada um e junta as listas: alunos.csv notas.txt.
"$arq"
O arquivo da vez, entre aspas. Se o nome tiver espaço, as aspas mantêm o nome inteiro como uma coisa só.
$(wc -l < "$arq")
Roda wc -l com o arquivo como entrada e coloca o número no texto (veja Substituição de Comando).
Curingas são seguros com espaços

Quando o Bash expande *.jpg, cada nome vira um item inteiro da lista, mesmo que tenha espaço. O perigo aparece depois, se você usar $arq sem aspas dentro do corpo. Regra de ouro: for f in *.jpg sem aspas no curinga, e "$f" com aspas no corpo.

E quando nenhum arquivo combina?

A pasta Documentos não tem nenhum vídeo. Veja o que acontece:

$ for video in *.mp4; do
>   echo "Achei o vídeo: $video"
> done
Achei o vídeo: *.mp4           « o laço rodou uma vez, com o próprio texto "*.mp4"

Quando um curinga não combina com nada, o Bash deixa o texto do jeito que está. O laço roda uma vez, com a variável valendo *.mp4. Num script que apaga ou move arquivos, isso vira um erro do tipo mv: não foi possível obter estado de '*.mp4'. Há duas soluções.

Solução 1: ligar o nullglob. Com essa opção, um curinga sem resultado vira nada, e o laço simplesmente não roda:

$ shopt -s nullglob
$ for video in *.mp4; do
>   echo "Achei o vídeo: $video"
> done
$ echo $?
0                              « nenhuma volta, nenhuma mensagem, código 0
$ shopt -u nullglob            « desliga de novo
shopt
Liga e desliga opções do Bash (shell options). Veja Opções do Shell.
-s
Liga (set). O -u desliga (unset).
nullglob
"Curinga sem resultado vira nulo." Em scripts, ligue no começo e esqueça.

Solução 2: conferir se o arquivo existe. Funciona sem mexer em opções, e também em outros shells:

$ cd ~/Downloads
$ for f in *.mp4; do
>   [[ -e $f ]] || continue
>   echo "Vídeo: $f"
> done
$ echo "status: $?"
status: 0

O [[ -e $f ]] testa se o arquivo existe (Testes); se não existir, o continue pula para a próxima volta (break e continue). Como *.mp4 não é um arquivo de verdade, o corpo é pulado.

Contar com chaves: {1..10}

A expansão de chaves (veja Chaves) gera sequências. Dentro de um for, vira o jeito mais curto de "repetir N vezes":

$ for i in {1..5}; do echo "Volta $i"; done
Volta 1
Volta 2
Volta 3
Volta 4
Volta 5
$ for i in {10..0..5}; do echo -n "$i "; done; echo
10 5 0                         « de 10 até 0, de 5 em 5
$ for n in {01..03}; do echo "foto-$n.jpg"; done
foto-01.jpg                    « o zero à esquerda é mantido
foto-02.jpg
foto-03.jpg
{1..5}
Início .. fim. Vira 1 2 3 4 5.
{10..0..5}
Um terceiro número é o passo. Pode contar para trás.
{01..03}
Com zero à esquerda, todos os números ficam com a mesma largura.
echo -n
Escreve sem pular linha, para os números ficarem lado a lado. O echo final só pula a linha.

A pegadinha: chaves não aceitam variáveis

$ fim=5
$ for i in {1..$fim}; do echo "Volta $i"; done
Volta {1..5}                   « uma volta só, com o texto literal!

As chaves são expandidas antes das variáveis (veja A Ordem das Expansões). Quando o Bash olha {1..$fim}, ainda não sabe que $fim vale 5, então não reconhece uma sequência e deixa o texto como está. Quando o limite está numa variável, use o for no estilo C, logo abaixo, ou o seq.

O for estilo C: for (( ; ; ))

Quem vem de C, Java ou JavaScript conhece este formato. Em vez de uma lista, você dá três instruções de conta, separadas por ;:

for (( INÍCIO; CONDIÇÃO; PASSO )); do
  comandos
done
$ for ((i = 0; i < 5; i++)); do echo "i vale $i"; done
i vale 0
i vale 1
i vale 2
i vale 3
i vale 4                       « 5 não entra: a condição é i < 5
(( … ))
Parênteses duplos: lá dentro vale a aritmética do Bash (veja Contas). Não precisa de $ antes das variáveis, e espaços são livres.
i = 0
Início: roda uma vez, antes da primeira volta.
i < 5
Condição: testada antes de cada volta. Enquanto for verdadeira, o corpo roda; quando ficar falsa, o laço acaba.
i++
Passo: roda no fim de cada volta. i++ soma 1 a i.

A ordem real é: início → condição → corpo → passo → condição → corpo → passo… até a condição falhar. O passo pode ser qualquer conta, e você pode controlar duas variáveis de uma vez, separando com vírgula:

$ for ((i = 10; i > 0; i -= 3)); do echo -n "$i "; done; echo
10 7 4 1                       « tira 3 a cada volta; -2 já não passa em i > 0
$ for ((i = 1, j = 10; i <= 3; i++, j--)); do echo "$i e $j"; done
1 e 10
2 e 9
3 e 8

E, diferente das chaves, aqui a variável funciona como limite:

$ for ((i = 1; i <= fim; i++)); do echo "Volta $i"; done
Volta 1
Volta 2
Volta 3
Volta 4
Volta 5

Missão: o script recebe um número como argumento. Complete-o com um for ((…)) que mostre a tabuada desse número de 1 a 10, no formato 7 x 1 = 7. Dica: a conta é $((n * i)).

#!/usr/bin/env bash
n=$1
# escreva o for aqui

#!/usr/bin/env bash
n=$1
for ((i = 1; i <= 10; i++)); do
  echo "$n x $i = $((n * i))"
done

Percorrer os argumentos do script: "$@"

Um script recebe argumentos em $1, $2… (veja Argumentos). Para tratar todos, não importa quantos sejam, use "$@" como lista:

#!/usr/bin/env bash
echo "Recebi $# nomes."
for nome in "$@"; do
  echo "Olá, $nome!"
done
$ bash saudar.sh Ana "Bruno Lima" Carla
Recebi 3 nomes.
Olá, Ana!
Olá, Bruno Lima!               « as aspas de "$@" mantêm "Bruno Lima" inteiro
Olá, Carla!
$ bash saudar.sh
Recebi 0 nomes.                « nenhum argumento: o laço não roda nenhuma vez

Agora veja o mesmo script com $@ sem aspas (for nome in $@; do):

$ bash saudar.sh Ana "Bruno Lima" Carla
Recebi 3 nomes.                « o script recebeu 3 argumentos…
Olá, Ana!
Olá, Bruno!                    « …mas o for quebrou o segundo em dois
Olá, Lima!
Olá, Carla!

Sem aspas, o Bash separa de novo cada argumento nos espaços. Escreva sempre "$@", com aspas. Existe ainda um atalho: for nome; do, sem o in, percorre "$@" automaticamente.

$ set -- Ana "Bruno Lima"      « set -- define $1 e $2 no terminal, para testar
$ for nome; do echo "Olá, $nome"; done
Olá, Ana
Olá, Bruno Lima

Percorrer a saída de um comando (e o erro clássico)

Você pode usar a saída de um comando como lista, com $( ). Para extrair só os nomes dos alunos (a primeira coluna do alunos.csv, com cut — veja grep, sed, awk e cia.):

$ cd ~/Documentos
$ for nome in $(cut -d, -f1 alunos.csv); do echo "Aluno: $nome"; done
Aluno: nome                    « o cabeçalho também veio
Aluno: Ana
Aluno: Bruno
Aluno: Carla
Aluno: Diego
Aluno: Elisa

Funcionou porque cada nome é uma palavra só. Mas o for não percorre linhas: ele percorre palavras. A saída de $( ) sem aspas é cortada em todo espaço, tab e quebra de linha. Veja o que acontece com a linha da Elisa, que mora em Porto Alegre:

$ for linha in $(cat alunos.csv); do echo "Linha: $linha"; done
Linha: nome,idade,cidade,nota
Linha: Ana,29,Recife,9.5
Linha: Bruno,34,Curitiba,7.0
Linha: Carla,22,Salvador,8.5
Linha: Diego,41,Manaus,6.0
Linha: Elisa,27,Porto          « a linha foi cortada no espaço…
Linha: Alegre,10.0             « …e virou duas "linhas"
$ for linha in $(cat notas.txt); do echo "[$linha]"; done
[Comprar]                      « cada palavra virou uma volta
[café]
[Ligar]
[para]
…
Para ler linhas, não use for

for linha in $(cat arquivo) é um dos erros mais comuns em scripts. Além de cortar nos espaços, ele também expande curingas que estiverem no texto (uma linha com * vira a lista de arquivos da pasta). O jeito certo de ler um arquivo linha por linha é while IFS= read -r linha, explicado em Ler Arquivos Linha a Linha.

O mesmo vale para for f in $(ls): a saída do ls é texto, e nomes com espaço se partem. Para arquivos, use sempre o curinga:

$ cd ~/fotos
$ for f in $(ls); do echo "$f"; done
aniversario.jpg
festa                          « errado: um arquivo virou dois
junina.jpg
praia.jpg
$ for f in *; do echo "$f"; done
aniversario.jpg
festa junina.jpg               « certo
praia.jpg

Renomear arquivos em lote

Agora juntamos tudo numa tarefa real. A Ana tem uma pasta fotos com arquivos .jpg, um deles com espaço no nome, e quer trocar a extensão para .jpeg.

$ cd ~/fotos
$ ls
 aniversario.jpg  'festa junina.jpg'   praia.jpg     « o ls mostra entre aspas o nome com espaço

Passo 1: ensaie com echo

Antes de mover qualquer coisa, coloque echo na frente do mv. Assim o laço só mostra os comandos que rodaria:

$ for f in *.jpg; do echo mv "$f" "${f%.jpg}.jpeg"; done
mv aniversario.jpg aniversario.jpeg
mv festa junina.jpg festa junina.jpeg          « o echo não mostra as aspas, mas elas estão lá
mv praia.jpg praia.jpeg
for f in *.jpg
Para cada arquivo terminado em .jpg.
echo mv
Ensaio: mostra o comando em vez de executá-lo. Tire o echo quando a lista estiver certa.
"$f"
O nome atual, entre aspas.
"${f%.jpg}.jpeg"
${f%.jpg} é o nome sem o .jpg do final (festa junina); depois colamos .jpeg. Essa forma de "cortar o fim" é explicada em Expansão de Parâmetros.

Passo 2: o erro de esquecer as aspas

Veja o que acontece se a Ana rodar a versão sem aspas:

$ for f in *.jpg; do mv $f ${f%.jpg}.jpeg; done
mv: alvo 'junina.jpeg': Arquivo ou diretório inexistente
$ ls
 aniversario.jpeg  'festa junina.jpg'   praia.jpeg    « duas renomeadas, uma ficou para trás

Sem aspas, mv $f ${f%.jpg}.jpeg virou mv festa junina.jpg festa junina.jpeg: quatro argumentos. Com mais de dois, o mv entende "mova os três primeiros para dentro da pasta junina.jpeg", que não existe. Por sorte deu erro; com outros nomes, poderia ter movido arquivos para o lugar errado.

Passo 3: a versão certa

$ for f in *.jpg; do mv "$f" "${f%.jpg}.jpeg"; done
$ ls
 aniversario.jpeg  'festa junina.jpeg'   praia.jpeg    « todas renomeadas

Nenhuma mensagem: o mv não fala nada quando dá certo. E repare que, na segunda vez, o *.jpg só pegou o arquivo que tinha sobrado. Os outros já eram .jpeg.

Nome que começa com hífen

Se um arquivo se chamar -foto.jpg, o mv acha que é uma opção. Para scripts à prova disso, escreva mv -- "$f" "${f%.jpg}.jpeg": o -- avisa que acabaram as opções.

Missão: na pasta relatorios há três arquivos .txt, um deles com espaço no nome. Com um único for, troque a extensão de todos para .bak. Ensaie primeiro com echo mv; confira com ls.

O comando seq

O seq (de sequence) é um programa que imprime números, um por linha. Ele existe fora do Bash e aceita variáveis, já que é um comando comum:

$ seq 5
1
2
3
4
5
$ seq 2 5                      « início e fim
2
3
4
5
$ seq 0 10 30                  « início, passo, fim (o passo fica no meio!)
0
10
20
30
$ seq -w 8 11                  « -w: mesma largura, com zeros
08
09
10
11
$ seq -s ' ' 1 5               « -s: separador entre os números
1 2 3 4 5

Dentro de um for:

$ for i in $(seq 1 3); do echo "Volta $i"; done
Volta 1
Volta 2
Volta 3

Aqui o $( ) sem aspas não atrapalha, porque números não têm espaço. Repare também que o seq respeita o idioma do sistema: com LANG=pt_BR.UTF-8, números quebrados saem com vírgula.

$ seq 0.5 0.5 2
0,5                            « vírgula, por causa do idioma pt_BR
1,0
1,5
2,0

Hoje o seq é menos necessário: {1..10} e for ((…)) fazem o mesmo sem chamar um programa externo. Ele ainda é útil para passos quebrados (0.5) e no sh (que não tem chaves nem (( ))).

Quando não funciona

"erro de sintaxe próximo ao token inesperado `done'" 
$ for x in 1 2 3 do echo $x; done
bash: erro de sintaxe próximo ao token inesperado `done'

O que aconteceu: faltou o ; antes do do. O Bash achou que do, echo e $x eram mais itens da lista, e depois do ; esperava um do, mas encontrou done.

Como resolver: for x in 1 2 3; do echo $x; done. Se a mensagem fala do token `echo', quem faltou foi o próprio do:

$ for i in 1 2 3; echo $i; done
bash: erro de sintaxe próximo ao token inesperado `echo'
"não é um identificador válido" 
$ for $i in 1 2 3; do echo $i; done
bash: `$i': não é um identificador válido

O que aconteceu: no for, você dá nome à variável, então ela vai sem $. O $ só aparece quando você lê o valor, dentro do corpo.

Como resolver: for i in 1 2 3; do echo $i; done.

O terminal ficou mostrando > e não roda 
$ for i in 1 2 3; do echo $i done
> done
1 done
2 done
3 done

O que aconteceu: faltou o ; antes do done. Sem ele, done virou só uma palavra para o echo, e o Bash ficou esperando o done de verdade (o > é o prompt de continuação). Quando a Ana digitou done na linha seguinte, o laço rodou, imprimindo "done" a cada volta.

Como resolver: se estiver preso no > e não souber o que falta, aperte Ctrl+C para cancelar e digite de novo com ; done.

"fim inesperado do arquivo" num script 
$ bash semdone.sh
semdone.sh: linha 4: erro de sintaxe: fim inesperado do arquivo do comando `for' na linha 2

O que aconteceu: o for da linha 2 nunca foi fechado. O Bash leu o arquivo até o fim (a "linha 4" é depois da última) procurando o done.

Como resolver: confira se cada for … do tem o seu done. Indentar o corpo (2 espaços) ajuda a enxergar onde cada laço termina. bash -n script.sh confere a sintaxe sem rodar (veja Depurar).

O laço rodou uma vez só, com o texto literal 
$ for i in 1..5; do echo $i; done
1..5
$ cd ~/Imagens
$ for f in "*.jpg"; do echo "$f"; done
*.jpg

O que aconteceu: no primeiro, faltaram as chaves: o certo é {1..5}. No segundo, as aspas em volta do curinga desligaram o *, e a lista virou o texto *.jpg. O mesmo sintoma aparece com {1..$n} e quando o curinga não encontra arquivos (sem nullglob).

Como resolver: {1..5} com chaves; for f in *.jpg sem aspas no curinga; for ((i=1; i<=n; i++)) quando o limite é variável; shopt -s nullglob para pastas que podem estar vazias.

Um nome com espaço virou dois

O que aconteceu: a lista veio de $(ls) ou $(cat …), ou você usou $f / $@ sem aspas. Veja as sessões acima com festa junina.jpg e Porto Alegre.

Como resolver: arquivos → curinga; linhas → while read; argumentos → "$@"; dentro do corpo → sempre "$f".

Resumo

  • for x in lista; do … done roda o corpo uma vez para cada item; a variável vai sem $ no for e com $ no corpo.
  • Para arquivos, use curingas (for f in *.jpg) e "$f" com aspas; ligue shopt -s nullglob para pastas sem arquivos.
  • Para contar: {1..10} (números fixos), for ((i=0; i<n; i++)) (limite variável) ou seq.
  • for arg in "$@" percorre os argumentos, mantendo os que têm espaço.
  • O for percorre palavras: nunca use $(cat arquivo) nem $(ls). Para linhas, use while IFS= read -r.
  • Antes de mover ou apagar em lote, ensaie com echo.
