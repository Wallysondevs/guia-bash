Bash Argumentos

Quando você digita cp foto.jpg Imagens, o cp recebe dois argumentos: o que copiar e para onde. Seus scripts podem receber argumentos do mesmo jeito. É isso que transforma um script que faz sempre a mesma coisa num comando de verdade, que trabalha com o arquivo, a pasta ou o nome que você passar.

Você vai aprender
  • Onde os argumentos chegam: $1, $2… ${10}, e o que são $0 e $#.
  • A diferença entre "$@", "$*" e $@ sem aspas, e por que "$@" é quase sempre a resposta.
  • Como andar pela lista com shift e percorrer todos os argumentos.
  • Como dar um valor padrão e como exigir um argumento, com mensagem de uso e código de saída 2.

Conceito: a fila de argumentos

Tudo o que você escreve depois do nome do script, separado por espaços, vira um argumento. O Bash guarda cada um numa variável numerada, na ordem em que chegaram. Elas se chamam parâmetros posicionais, porque o nome é a posição.

  $ ./args.sh   banana   maçã   uva
      │           │        │      │
      $0          $1       $2     $3          $# = 3  (quantos)

Para ver isso acontecendo, um script que só mostra o que recebeu:

#!/usr/bin/env bash
echo "Nome do script: $0"
echo "Quantos argumentos: $#"
echo "Primeiro: $1"
echo "Segundo:  $2"
echo "Terceiro: $3"
$0
Como o script foi chamado (o "argumento zero"). Veja mais em Formas de Executar.
$#
Quantos argumentos chegaram. Pense no # como "número de".
$1 $2 $3
O primeiro, o segundo e o terceiro argumento.
$ ./args.sh banana maçã
Nome do script: ./args.sh
Quantos argumentos: 2
Primeiro: banana
Segundo:  maçã
Terceiro:                        « não veio terceiro: $3 está vazio, sem erro
$ ./args.sh
Nome do script: ./args.sh
Quantos argumentos: 0            « nenhum argumento
Primeiro:
Segundo:
Terceiro:

Repare que pedir um argumento que não veio não dá erro: a variável simplesmente está vazia. Isso é perigoso (imagine rm -r "$1"/ com $1 vazio), e mais adiante você vai aprender a exigir o argumento.

Espaços separam argumentos; aspas juntam

$ ./args.sh Área de trabalho

Primeiro: Área
Segundo:  de
Terceiro: trabalho
$ ./args.sh 'Área de trabalho' Documentos

Primeiro: Área de trabalho
Segundo:  Documentos
Terceiro:
$ ./args.sh '' x
Nome do script: ./args.sh
Quantos argumentos: 2            « um texto vazio entre aspas também conta
Primeiro:
Segundo:  x
Terceiro:

Quem separa as palavras é o seu shell, antes de o script começar. O script recebe a lista pronta. Mais sobre aspas em Aspas e Escapes.

Do décimo em diante: ${10}

Com um dígito só, $1 a $9 funcionam direto. A partir do décimo, use chaves. Sem elas, o Bash lê $10 como $1 seguido do texto 0:

#!/usr/bin/env bash
echo "nono: $9"
echo "décimo errado: $10"
echo "décimo certo:  ${10}"

$ ./dez.sh a b c d e f g h i j
nono: i
décimo errado: a0                « $1 (a) + o texto "0"
décimo certo:  j

Todos de uma vez: "$@", "$*" e $@

Muitas vezes você quer todos os argumentos, sem saber quantos são: para repassar a outro comando ou para percorrer um por um. O Bash tem duas variáveis para isso, $@ e $*, e elas se comportam de um jeito diferente com e sem aspas. Esta é a parte mais importante da aula.

#!/usr/bin/env bash
echo "--- com \"\$@\" ---"
for a in "$@"; do echo "[$a]"; done
echo "--- com \"\$*\" ---"
for a in "$*"; do echo "[$a]"; done
echo "--- com \$@ sem aspas ---"
for a in $@; do echo "[$a]"; done

Cada for mostra cada item entre colchetes, para você ver onde um termina e o outro começa (o for tem aula própria em for). Vamos passar dois argumentos, sendo que o primeiro tem espaços:

$ ./mostra.sh 'Área de trabalho' Downloads
--- com "$@" ---
[Área de trabalho]               « 2 itens, exatamente como chegaram
[Downloads]
--- com "$*" ---
[Área de trabalho Downloads]     « 1 item: tudo colado num texto só
--- com $@ sem aspas ---
[Área]                           « 4 itens: o nome foi picado nos espaços
[de]
[trabalho]
[Downloads]
FormaViraQuando usar
"$@"Um item para cada argumento, intacto: "Área de trabalho" "Downloads"Quase sempre. Para percorrer e para repassar os argumentos a outro comando.
"$*"Um texto só, com os argumentos separados por espaço: "Área de trabalho Downloads"Para mostrar tudo numa mensagem: echo "Recebi: $*".
$@ ou $* sem aspasPicado em cada espaço (e curingas como * são expandidos)Praticamente nunca. É fonte de bugs.
Curiosidade: o separador do "$*"

"$*" junta os argumentos com o primeiro caractere da variável IFS, que normalmente é o espaço. Com IFS=, no script, echo "Com vírgulas: $*" mostra Com vírgulas: maçã,uva,banana.

Na prática: o bug do $@ sem aspas

Um script que diz quantos itens tem cada pasta. A versão certa usa "$@", e também coloca "$pasta" entre aspas:

#!/usr/bin/env bash
# conta.sh — diz quantos itens tem cada pasta recebida
for pasta in "$@"; do
  echo "$pasta: $(ls "$pasta" | wc -l) itens"
done

$ ./conta.sh Documentos 'Área de trabalho' Imagens
Documentos: 5 itens
Área de trabalho: 0 itens
Imagens: 2 itens
$ ./conta-errado.sh Documentos 'Área de trabalho' Imagens     « igual, mas com $@ sem aspas
Documentos: 5 itens
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
Área: 0 itens
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
de: 0 itens
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente
trabalho: 0 itens
Imagens: 2 itens

Sem aspas, Área de trabalho virou três "pastas" que não existem. Com nomes de pastas de verdade (que muitas vezes têm espaço), é o tipo de erro que só aparece no dia em que importa.

Missão: rode o script como está e veja os erros. Depois corrija o for para que Área de trabalho seja tratada como uma pasta só.

#!/usr/bin/env bash
# conta.sh — diz quantos itens tem cada pasta recebida
for pasta in $@; do
  echo "$pasta: $(ls "$pasta" | wc -l) itens"
done

#!/usr/bin/env bash
# conta.sh — diz quantos itens tem cada pasta recebida
for pasta in "$@"; do
  echo "$pasta: $(ls "$pasta" | wc -l) itens"
done

Andar pela fila: shift

shift ("deslocar") tira o primeiro argumento da fila e puxa todos uma posição para a frente: o $2 vira $1, o $3 vira $2, e o $# diminui. O antigo $1 some (se você precisar dele, guarde numa variável antes).

shift
Descarta o primeiro argumento.
2
Opcional: quantos descartar de uma vez. Sem número, é 1.
#!/usr/bin/env bash
echo "Antes:  \$#=$#  \$1=$1  todos: $*"
shift
echo "Depois: \$#=$#  \$1=$1  todos: $*"
shift 2
echo "Depois do shift 2: \$#=$#  \$1=$1  todos: $*"

$ ./fila.sh a b c d e
Antes:  $#=5  $1=a  todos: a b c d e
Depois: $#=4  $1=b  todos: b c d e           « o "a" saiu, todos andaram uma casa
Depois do shift 2: $#=2  $1=d  todos: d e    « "b" e "c" saíram

E se não houver argumentos suficientes? O shift não mexe em nada e devolve o código 1, sem mensagem:

$ ./pula.sh a
Tenho 1 argumentos: a
Código do shift 2: 1                « falhou: só havia 1 para tirar 2
Agora tenho 1: a                     « nada mudou

Um uso típico: o primeiro argumento é especial (por exemplo, a pasta de destino), e o resto é uma lista. Guarde o primeiro, dê shift, e o "$@" passa a ser só a lista.

#!/usr/bin/env bash
# copiar-para.sh DESTINO ARQUIVO...
destino=$1
shift
cp -- "$@" "$destino"

O -- no cp avisa "acabaram as opções": assim, um arquivo chamado -r não é confundido com uma opção.

Você também pode criar argumentos no terminal: set --

No terminal, set -- a b c define $1, $2 e $3 do seu shell. É ótimo para testar sem criar um script:

$ set -- maçã uva
$ echo "$# argumentos: $1 e $2"
2 argumentos: maçã e uva
$ shift
$ echo "$# argumento: $1"
1 argumento: uva

Percorrer todos os argumentos

Duas formas, e as duas estão certas.

Forma 1: for arg

O for sem a parte in … percorre os argumentos automaticamente. for arg é o mesmo que for arg in "$@":

#!/usr/bin/env bash
for arg; do
  echo "recebi: $arg"
done

Forma 2: while (( $# )) + shift

Enquanto ainda houver argumentos ($# diferente de zero), trate o $1 e dê shift. É a base de quem processa opções na mão.

#!/usr/bin/env bash
n=1
while (( $# )); do
  echo "$n: $1"
  shift
  (( n++ ))
done
echo "Sobrou: $# argumentos"
while
"Enquanto…" (aula em while e until).
(( $# ))
Conta aritmética: é verdadeira quando $# não é zero.
shift
Sem ele, o $# nunca diminui e o laço não termina.
$ ./lista.sh maçã 'pão de queijo' café
1: maçã
2: pão de queijo
3: café
Sobrou: 0 argumentos             « o while consumiu a fila toda
FormaQuando usar
for arg; do …; doneFazer a mesma coisa com cada argumento. A lista continua intacta depois.
while (( $# )); do …; shift; doneQuando um argumento pode "comer" o seguinte (como -o arquivo) ou quando você quer parar no meio.

Para opções no estilo -v, -o arquivo, o Bash tem uma ferramenta própria: Opções com getopts.

Valor padrão: ${1:-padrão}

Às vezes o argumento é opcional: se a pessoa não passar, use um valor razoável.

${1
O primeiro argumento…
:-
…mas, se ele não veio ou está vazio, use…
visitante}
…este valor.
#!/usr/bin/env bash
nome=${1:-visitante}
echo "Olá, $nome!"

$ ./saudar.sh
Olá, visitante!
$ ./saudar.sh Bruno
Olá, Bruno!
$ ./saudar.sh ''
Olá, visitante!                  « vazio também conta como "não veio"

É uma das formas de Expansão de Parâmetros, que tem muitas outras.

Exigir um argumento

Se o script não faz sentido sem o argumento (o arquivo a copiar, a pasta a limpar), ele deve parar logo, avisando o que faltou. Duas formas.

Forma 1, curta: ${1:?mensagem}

#!/usr/bin/env bash
origem=${1:?informe o arquivo de origem}
echo "Copiando $origem..."

$ ./copia.sh
./copia.sh: linha 2: 1: informe o arquivo de origem
$ echo $?
1
$ ./copia.sh frutas.txt
Copiando frutas.txt...

Sem o argumento, o Bash mostra a mensagem na saída de erro, com o nome do script, a linha e o parâmetro (1), e encerra o script com código 1. É prático, mas a mensagem é técnica.

Forma 2, amigável: if + mensagem de uso + exit 2

Programas bem-educados respondem a um uso errado com uma mensagem de uso (usage): como chamar o programa e um exemplo. Três regras: a mensagem vai para a saída de erro (>&2), usa $0 para mostrar o nome do script, e o script sai com código 2, a convenção para "uso incorreto" (é o que o ls e o grep fazem).

#!/usr/bin/env bash
# backup.sh — copia arquivos para a pasta backup/
if (( $# < 1 )); then
  echo "Uso: $0 ARQUIVO..." >&2
  echo "Exemplo: $0 frutas.txt Documentos/notas.txt" >&2
  exit 2
fi
mkdir -p backup
for arq in "$@"; do
  cp -- "$arq" backup/ && echo "copiado: $arq"
done
LinhaO que faz
if (( $# < 1 )); thenSe chegaram menos de 1 argumento… (if; (( )) compara números).
echo "Uso: $0 ARQUIVO..." >&2Mostra como usar. >&2 manda para a saída de erro (Redirecionamento). ARQUIVO... é a convenção para "um ou mais arquivos".
exit 2Encerra o script com código 2 (Código de Saída).
for arq in "$@"Para cada arquivo recebido…
cp -- "$arq" backup/ && echo ……copia e, se deu certo, avisa.
$ ./backup.sh
Uso: ./backup.sh ARQUIVO...
Exemplo: ./backup.sh frutas.txt Documentos/notas.txt
$ echo $?
2                                 « 2 = foi usado do jeito errado
$ ./backup.sh 2>/dev/null
$                                 « a mensagem foi para o canal de erro, por isso sumiu
$ ./backup.sh frutas.txt nada.txt
copiado: frutas.txt
cp: não foi possível obter estado de 'nada.txt': Arquivo ou diretório inexistente
$ echo $?
1                                 « o último comando (o cp de nada.txt) falhou

O último resultado mostra uma regra útil: sem exit no fim, o código do script é o do último comando que rodou.

Missão: o script cumprimenta o nome recebido. Faça com que, sem argumento, ele mostre Uso: saudar.sh NOME na saída de erro e saia com o código 2. Rode com o campo de argumentos vazio. Depois teste com um nome.

Quando não funciona

Um nome com espaço virou vários argumentos 
$ ./args.sh Área de trabalho
…
Quantos argumentos: 3

O que aconteceu: sem aspas, o seu shell separou o nome em três palavras antes de chamar o script.

Como resolver: quem chama põe aspas: ./args.sh 'Área de trabalho'. Dentro do script, use sempre "$1", "$@", "$arq" entre aspas, senão o nome é picado de novo lá dentro.

"ls: não foi possível acessar 'Área'" 
$ ./conta-errado.sh 'Área de trabalho'
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente

O que aconteceu: o argumento chegou certo, mas o script usou $@ (ou $1) sem aspas, e o nome foi picado nos espaços.

Como resolver: troque $@ por "$@" e $1 por "$1". O ShellCheck aponta esse erro automaticamente (aviso SC2068).

$10 mostra o primeiro argumento com um 0 no fim 
$ ./dez.sh a b c d e f g h i j
…
décimo errado: a0

Como resolver: do décimo em diante, use chaves: ${10}, ${11}.

Não apareceu nada no lugar do argumento 
$ ./args.sh
…
Primeiro:

O que aconteceu: o argumento não foi passado, e um parâmetro que não existe vale texto vazio, sem erro. Também acontece depois de shift, que já tirou aquele argumento da fila.

Como confirmar: mostre o $#. Como resolver: dê um padrão com ${1:-padrão} ou exija o argumento com a mensagem de uso.

O while (( $# )) nunca termina

O que aconteceu: faltou o shift dentro do laço. O $# nunca diminui, e o mesmo $1 é tratado para sempre.

Como resolver: Ctrl+C para parar; acrescente shift antes do done.

Resumo

  • Os argumentos chegam em $1, $2… (${10} em diante com chaves); $# diz quantos e $0 é o nome do script.
  • Use "$@" (com aspas) para percorrer ou repassar todos; "$*" só para mostrar numa mensagem; $@ sem aspas, nunca.
  • shift tira o primeiro da fila; for arg e while (( $# )) percorrem todos.
  • ${1:-padrão} dá um valor padrão; ${1:?msg} exige o argumento.
  • Mensagem de uso: para a saída de erro (>&2), com $0, e exit 2.
