Projeto Seus Dotfiles

Dotfiles ("arquivos de ponto") são os arquivos de configuração que moram na sua pasta pessoal com nome começando por ponto: .bashrc, .inputrc, .gitconfig. Com o tempo, o .bashrc vira uma gaveta bagunçada de 300 linhas que ninguém tem coragem de mexer. Neste projeto você o reorganiza em módulos pequenos, acrescenta funções e um prompt que valem a pena, guarda tudo num repositório git e escreve um instalador que deixa qualquer computador novo do seu jeito em um comando.

Ao terminar você terá
  • Uma pasta ~/dotfiles versionada com git, com bashrc, bashrc.d/*.sh, inputrc e instalar.sh.
  • Um ~/.bashrc de 20 linhas que só carrega os módulos, num laço.
  • As funções mkcd, up N e extrair, e um prompt colorido que mostra o código de saída quando algo falha.
  • Um histórico grande, sem repetições, com data e compartilhado entre terminais.
  • Um instalar.sh que cria os links simbólicos e guarda um backup do que já existia.

Antes de mexer no seu .bashrc de verdade

Um erro no .bashrc aparece em todo terminal novo. Faça uma cópia (cp ~/.bashrc ~/.bashrc.original) e mantenha um terminal aberto enquanto testa: se o novo quebrar, você conserta pelo antigo. Para testar sem abrir janelas, use bash -i (um shell interativo novo, que lê o .bashrc) e saia com exit.

Antes de programar: a organização

A ideia central: os arquivos de verdade ficam em ~/dotfiles (uma pasta comum, versionada com git), e os lugares onde o Bash os procura (~/.bashrc, ~/.inputrc) viram links simbólicos (atalhos) para lá. Editar ~/.bashrc é editar ~/dotfiles/bashrc, e o git vê a mudança.

As etapas

  1. Etapa 1 — Um .bashrc que carrega os módulos num laço

    O que vamos fazer e por quê: o novo bashrc não configura nada sozinho: ele só garante que o shell é interativo e carrega, em ordem, cada .sh da pasta ~/.bashrc.d.

    # ~/.bashrc — só carrega os módulos de ~/.bashrc.d
# (este arquivo vive em ~/dotfiles/bashrc; ~/.bashrc é um link para ele)

# Shell não interativo (scp, bash -c, scripts): não faz nada
case $- in
  *i*) ;;
  *) return ;;
esac

# Carrega cada módulo, em ordem alfabética (por isso os números no nome)
for modulo in ~/.bashrc.d/*.sh; do
  # shellcheck source=/dev/null
  [[ -r $modulo ]] && source "$modulo"
done
unset modulo

# Configurações só desta máquina (fora do git)
if [[ -r ~/.bashrc.local ]]; then
  # shellcheck source=/dev/null
  source ~/.bashrc.local
fi
    TrechoO que faz
    case $- in *i*) ;; *) return ;; esac$- lista as opções do shell; se não tem i (interativo), para de ler o arquivo. Programas como o scp abrem shells não interativos que podem ler o .bashrc, e qualquer texto impresso aqui os quebraria. É o mesmo teste do .bashrc original do Ubuntu. Veja Arquivos de Inicialização.
    for modulo in ~/.bashrc.d/*.shOs módulos, em ordem alfabética: 10-…, 20-…, 30-…. Deixar espaço entre os números (10, 20) permite encaixar um 15-… depois.

  2. Etapa 2 — Aliases e funções que valem a pena

    O que vamos fazer e por quê: os aliases que a Ana já tinha vão para 20-aliases.sh, com alguns novos. E três funções para tarefas que todo mundo faz várias vezes por dia. Por que funções e não aliases? Um alias só troca um texto pelo outro; uma função recebe argumentos, tem if, laço e código de saída. Veja alias e Funções.

    # Apelidos
alias ls='ls --color=auto'
alias ll='ls -alF'
alias la='ls -A'
alias grep='grep --color=auto'
alias ..='cd ..'
alias ...='cd ../..'
alias rm='rm -I'                   # pergunta antes de apagar mais de 3 arquivos
alias df='df -h'
alias du='du -h'

    Destaques: .. e ... sobem pastas; rm -I (i maiúsculo) pergunta uma vez só quando você apaga mais de três arquivos ou uma pasta inteira, sem ser chato como o -i; df e du passam a mostrar tamanhos legíveis.

    # Funções úteis

# mkcd PASTA — cria a pasta (e as do meio) e entra nela
mkcd() {
  if (( $# != 1 )); then
    echo "uso: mkcd PASTA" >&2
    return 2
  fi
  mkdir -p -- "$1" && cd -- "$1" || return
}

# up [N] — sobe N pastas (padrão: 1)
up() {
  local n=${1:-1} caminho=
  if [[ ! $n =~ ^[0-9]+$ ]]; then
    echo "uso: up [N]" >&2
    return 2
  fi
  while (( n-- > 0 )); do
    caminho+=../
  done
  cd -- "${caminho:-.}" || return
}

# extrair ARQUIVO... — descompacta conforme a extensão
extrair() {
  local arq status=0
  if (( $# == 0 )); then
    echo "uso: extrair ARQUIVO..." >&2
    return 2
  fi
  for arq in "$@"; do
    if [[ ! -f $arq ]]; then
      echo "extrair: '$arq' não é um arquivo" >&2
      status=1
      continue
    fi
    case ${arq,,} in
      *.tar.gz|*.tgz)   tar -xzf "$arq" ;;
      *.tar.xz|*.txz)   tar -xJf "$arq" ;;
      *.tar.bz2|*.tbz2) tar -xjf "$arq" ;;
      *.tar)            tar -xf "$arq" ;;
      *.zip)            unzip -q "$arq" ;;
      *.gz)             gunzip -k "$arq" ;;
      *.xz)             unxz -k "$arq" ;;
      *.bz2)            bunzip2 -k "$arq" ;;
      *.7z)             7z x "$arq" ;;
      *)                echo "extrair: não sei abrir '$arq'" >&2; false ;;
    esac || status=1
  done
  return "$status"
}

  3. Etapa 3 — Um prompt com cor e o código de saída

    O que vamos fazer e por quê: quando um comando falha sem mensagem (como o grep que não acha nada), você só descobre com echo $?. Um prompt que mostra o código quando ele não é 0 avisa sozinho. O truque: a variável PROMPT_COMMAND guarda um comando que o Bash roda logo antes de mostrar cada prompt; nele, montamos o PS1 do zero. Veja Personalizar o Prompt.

    # Prompt: usuário@máquina:pasta, em cores, e o código de saída quando não for 0
__prompt() {
  local codigo=$?                  # TEM que ser a primeira linha
  local verde='\[\e[32m\]' azul='\[\e[34m\]' vermelho='\[\e[31m\]' normal='\[\e[0m\]'
  PS1="${verde}\u@\h${normal}:${azul}\w${normal}"
  if (( codigo != 0 )); then
    PS1+=" ${vermelho}[${codigo}]${normal}"
  fi
  PS1+='\$ '
}
PROMPT_COMMAND="__prompt${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
    local codigo=$?
    Guarda o código do comando que você acabou de rodar. Tem que ser a primeira coisa da função: qualquer comando antes trocaria o $?.
    \[ … \]
    Envolve as sequências de cor para o Bash saber que elas não ocupam espaço na tela. Sem isso, linhas compridas se embaralham ao editar.
    \e[32m
    Verde (31 vermelho, 34 azul, 0 volta ao normal). As mesmas sequências do jogo.
    \u@\h … \w … \$
    Usuário, máquina, pasta atual e $ (ou # para o root).
    PROMPT_COMMAND="__prompt${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
    Põe __prompt na frente do que já existia, separado por ;. O ${X:+…} só acrescenta o ; … se já havia algo. Assim os módulos não apagam o trabalho uns dos outros.

    Num terminal novo, depois de instalado (as cores não aparecem aqui; o prompt real é verde, azul e vermelho):

    ana@notebook:~$ false
ana@notebook:~ [1]$ ls nada                     « o false devolveu 1

ana@notebook:~ [2]$ mkcd projetos/novo          « o ls devolveu 2
ana@notebook:~/projetos/novo$ up 2              « deu certo: o código some
ana@notebook:~$ up x
uso: up [N]
ana@notebook:~ [2]$
    A ordem no PROMPT_COMMAND importa

    O módulo de histórico (etapa 4, arquivo 10-…) é carregado antes e põe history -a no PROMPT_COMMAND. O de prompt (40-…) põe __prompt na frente. Resultado: __prompt; history -a. Se fosse ao contrário, o __prompt veria o $? do history -a (sempre 0) e nunca mostraria erro. No Bash 5.1 ou mais novo, PROMPT_COMMAND também pode ser um array (PROMPT_COMMAND+=(history -a)). bash 5.1+

    Missão: sem função nenhuma, dá para pôr o código no prompt: mude o PS1 para começar com [$?] (use aspas simples, para o $? ser lido a cada prompt e não uma vez só). Depois rode false e veja o prompt.

  4. Etapa 4 — Um histórico que não esquece

    O que vamos fazer e por quê: o padrão do Bash guarda pouco (500 a 2000 comandos), guarda repetidos e, com dois terminais abertos, o último a fechar apaga o histórico do outro. Veja Histórico.

    # Histórico: maior, sem repetições, com data, salvo a cada comando
HISTCONTROL=ignoreboth:erasedups   # ignora repetidos e linhas que começam com espaço
HISTSIZE=10000                     # comandos na memória
HISTFILESIZE=20000                 # linhas no ~/.bash_history
HISTTIMEFORMAT='%F %T  '           # data e hora no comando history
HISTIGNORE='ls:ll:history:exit'    # comandos que nem vale a pena guardar
shopt -s histappend                # acrescenta ao arquivo em vez de sobrescrever
shopt -s cmdhist                   # comando de várias linhas vira uma entrada só
PROMPT_COMMAND="history -a${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
    ConfiguraçãoEfeito
    HISTCONTROL=ignoreboth:erasedupsignoreboth = ignorespace (comando começado com espaço não é guardado: útil para senhas) + ignoredups (repetido em seguida não é guardado). erasedups apaga cópias antigas de um comando repetido.
    HISTSIZE / HISTFILESIZEQuantos comandos ficam na memória do terminal / no arquivo ~/.bash_history.
    HISTTIMEFORMAT='%F %T 'O comando history passa a mostrar data e hora (formato do date).
    HISTIGNORE='ls:ll:history:exit'Comandos que não vale a pena guardar (só se forem exatamente isso).
    shopt -s histappendAo fechar, acrescenta ao arquivo em vez de sobrescrever.
    PROMPT_COMMAND="history -a…"Grava cada comando no arquivo assim que ele termina (-a = append). Um terminal novo já enxerga o que você digitou no outro.

    Bônus: a busca com ↑ pelo começo, no inputrc

    O ~/.inputrc configura o readline, a biblioteca que faz a edição de linha do Bash. Esta é a configuração preferida de muita gente: digite git e aperte ↑ para ver só os comandos anteriores que começam com git. Veja Atalhos do Teclado.

"\e[B": history-search-forward

set show-all-if-ambiguous on       # um Tab só já mostra as opções

"\e[A": history-search-backward
"\e[6~": history-search-forward

    O \e[A é o código que o terminal manda para a seta para cima (e \e[B, para baixo). As linhas \e[5~ e \e[6~ (Page Up e Page Down) vieram do /etc/inputrc do sistema, incluído na primeira linha. O $include é importante: sem ele, você perderia as configurações do sistema.

    Missão: no terminal, configure o HISTCONTROL para ignorar espaços e repetidos e apagar duplicatas antigas, e ligue a opção histappend.

  6. Etapa 6 — O instalar.sh: links simbólicos com backup

    O que vamos fazer e por quê: num computador novo, o roteiro será: git clone … ~/dotfiles e ~/dotfiles/instalar.sh. O instalador troca cada arquivo de configuração por um link para a pasta dotfiles, e nunca apaga nada: o que existia ganha um nome de backup. E pode rodar de novo sem estragar nada (idempotente).

    #!/usr/bin/env bash
# instalar.sh — liga os arquivos de ~/dotfiles nos lugares certos.
# O que já existir é guardado com o sufixo .backup-DATA, nunca apagado.
# Pode rodar quantas vezes quiser.
set -euo pipefail

pasta=$(cd -- "$(dirname -- "$0")" && pwd)    # onde este script está
data=$(date +%F_%H%M%S)

# linkar ORIGEM DESTINO — faz DESTINO apontar para ORIGEM
linkar() {
  local origem=$pasta/$1 destino=$2
  if [[ -L $destino && $destino -ef $origem ]]; then
    echo "ok:      $destino (já aponta para $origem)"
    return
  fi
  if [[ -e $destino || -L $destino ]]; then
    mv -- "$destino" "$destino.backup-$data"
    echo "backup:  $destino -> $destino.backup-$data"
  fi
  ln -s -- "$origem" "$destino"
  echo "link:    $destino -> $origem"
}

linkar bashrc    ~/.bashrc
linkar bashrc.d  ~/.bashrc.d
linkar inputrc   ~/.inputrc

echo "Pronto. Abra um terminal novo (ou rode: source ~/.bashrc)."
    TrechoO que faz
    pasta=$(cd -- "$(dirname -- "$0")" && pwd)O caminho absoluto da pasta do próprio script, de onde quer que ele seja chamado. Os links precisam de caminho absoluto: um link relativo é resolvido a partir da pasta do link.
    [[ -L $destino && $destino -ef $origem ]]-L = "é um link simbólico"; -ef = "é o mesmo arquivo" (mesmo dispositivo e inode, seguindo links). Já está certo: não faz nada.
    [[ -e $destino || -L $destino ]]Existe alguma coisa ali? O -L pega também um link "quebrado", que aponta para algo que não existe (o -e segue o link e diria "não existe").
    mv … "$destino.backup-$data"Guarda o antigo com a data no nome.
    ln -s -- "$origem" "$destino"Cria o link simbólico (-s): primeiro para onde aponta, depois onde fica. Veja Criar, Copiar e Mover.

    #!/usr/bin/env bash
set -euo pipefail
pasta=~/dotfiles
data=$(date +%F_%H%M%S)

linkar() {
  local origem=$pasta/$1 destino=$2
  if [[ -e $destino || -L $destino ]]; then
    mv -- "$destino" "$destino.backup-$data"
    echo "backup:  $destino -> $destino.backup-$data"
  fi
  ln -s -- "$origem" "$destino"

Num computador novo

$ git clone https://github.com/SEU-USUARIO/dotfiles.git ~/dotfiles
$ ~/dotfiles/instalar.sh
$ exec bash                       « troca o shell atual por um novo, já com tudo carregado

(Saída do git clone omitida: depende do seu repositório.) O exec bash é mais limpo que source ~/.bashrc: o source roda os módulos de novo por cima do que já estava carregado, e o PROMPT_COMMAND, por exemplo, ficaria com __prompt duas vezes.

Quando não funciona

Nada mudou no terminal novo

O que aconteceu: o terminal abre um shell de login (comum no macOS e em conexões SSH), que lê o ~/.bash_profile ou o ~/.profile, e não o ~/.bashrc. Como confirmar: shopt -q login_shell && echo login. Como resolver: no ~/.bash_profile, acrescente [[ -r ~/.bashrc ]] && source ~/.bashrc. Veja Arquivos de Inicialização.

O terminal abre e fecha na hora

O que aconteceu: um módulo tem exit ou set -e (num .bashrc, o set -e derruba o terminal no primeiro comando que falhar). Como resolver: abra um terminal sem configuração (bash --norc, ou o modo de recuperação do emulador de terminal), conserte ou renomeie o módulo para .off. Nunca use set -e em arquivos carregados com source pelo shell interativo.

O prompt nunca mostra o código de erro

O que aconteceu: algum comando roda antes do __prompt no PROMPT_COMMAND e "zera" o $?. Como confirmar: echo "$PROMPT_COMMAND"; o __prompt precisa ser o primeiro.

Linhas compridas se sobrepõem ao editar

O que aconteceu: faltou o \[ … \] em volta de alguma sequência de cor do PS1, e o Bash calcula errado o tamanho do prompt. Veja Personalizar o Prompt.

ln: falha ao criar link simbólico '.inputrc': Arquivo existe

O que aconteceu: o ln -s não sobrescreve. É o caso que a função linkar resolve com o backup. Evite ln -sf num instalador: o -f apagaria o arquivo antigo sem backup.

Desafios extras

  • Mais dotfiles: leve também o ~/.gitconfig, o ~/.vimrc ou ~/.config/… (crie a pasta pai com mkdir -p antes do link).
  • Desinstalar: um desinstalar.sh que apaga os links e devolve o backup mais recente de cada arquivo.
  • Modo simulação: instalar.sh -n mostra o que faria, como no organizador.
  • Git no prompt: mostre o ramo atual com git branch --show-current 2>/dev/null no __prompt (ou use o __git_ps1 que vem com o git).
  • Medir: time bash -ic exit mostra quanto o seu .bashrc demora. Acima de 0,2 s você sente; descubra o módulo culpado.

Resumo

  • Arquivos de verdade em ~/dotfiles (com git); nos lugares de costume, links simbólicos.
  • .bashrc mínimo: teste de interativo + laço for m in ~/.bashrc.d/*.sh; do source "$m"; done.
  • Funções (mkcd, up, extrair) quando precisa de argumentos ou de mudar a pasta do terminal; aliases para o resto.
  • PROMPT_COMMAND + local codigo=$? na primeira linha = prompt que mostra erros.
  • Histórico: ignoreboth:erasedups, tamanhos grandes, histappend e history -a.
  • Instalador idempotente, que faz backup em vez de apagar.
