Projeto Jogo da Adivinhação

O computador pensa num número e você tenta adivinhar; a cada palpite ele diz "maior" ou "menor". É o "olá, mundo" dos jogos, e um ótimo treino: em seis etapas você usa números aleatórios, leitura do teclado, laços, decisões, validação com expressão regular, menus, arquivos e cores. E descobre por que todo dado digitado pelo usuário precisa ser conferido: a versão sem validação pode ser vencida digitando uma palavra.

Ao terminar você terá
  • Um jogo adivinha.sh com três níveis (1–10, 1–100, 1–1000) escolhidos num menu.
  • Validação do palpite: só números, dentro do intervalo, sem cair na armadilha do 08.
  • Um recorde por nível guardado em ~/.adivinha_recordes.
  • Cores que aparecem no terminal e somem quando a saída vai para um arquivo.

Tempo estimado45 min
Pré-requisitosLer do Teclado (read), while e until, if, elif, else, Contas. Ajudam: Regex com [[ =~ ]] e Menus e Cores.

  2. Etapa 2 — Repetir até acertar e contar as tentativas

    O que vamos fazer e por quê: um palpite só não é jogo. Um laço while true repete "pergunta e compara" para sempre, até um break no acerto. Um contador guarda quantas tentativas foram.

    #!/usr/bin/env bash

while true; do
  read -rp "Seu palpite: " palpite
  tentativas=$(( tentativas + 1 ))

    echo "O número é MAIOR que $palpite."
  elif (( palpite > secreto )); then
    echo "O número é MENOR que $palpite."
  else
    echo "Acertou! Era $secreto. Você usou $tentativas tentativa(s)."
    break
  fi
done

    Três defeitos de uma vez, todos por confiar no que foi digitado:

    • abc: dentro de (( )), uma palavra é tratada como nome de variável. Não existe variável abc, então ela vale 0.
    • 08: na aritmética do Bash, um número que começa com 0 é octal (base 8), e 8 não existe em octal. O (( )) dá erro, devolve "falso", o elif também, e o else declara vitória.
    • secreto: o pior. palpite vale o texto secreto, que na aritmética é a variável secreto: o jogo compara o número com ele mesmo. É uma pequena injeção de código, o mesmo tipo de falha que derruba sistemas de verdade.

  5. Etapa 5 — Guardar o recorde num arquivo

    O que vamos fazer e por quê: variáveis morrem quando o script termina. Para o recorde sobreviver, ele vai para um arquivo. O formato é o mais simples possível, uma linha nível=tentativas por nível, que dá para ler e escrever com o próprio Bash. Dentro do script, os recordes ficam num array associativo indexado pelo nível.

  6. Etapa 6 — Cores (só quando faz sentido) e saída com Ctrl+D

    O que vamos fazer e por quê: verde para o acerto, amarelo para as dicas, vermelho para erros. Cores no terminal são sequências de escape: caracteres invisíveis que começam com o caractere ESC (\e) e que o terminal interpreta. O cuidado: se a saída for para um arquivo ou um pipe, essas sequências viram lixo (^[[32m). Então só ligamos as cores quando a saída é um terminal.

    # Cores só quando a saída é um terminal e o usuário não pediu NO_COLOR
if [[ -t 1 && -z ${NO_COLOR-} ]]; then
  verde=$'\e[32m' amarelo=$'\e[33m' vermelho=$'\e[31m' normal=$'\e[0m'
else
  verde='' amarelo='' vermelho='' normal=''
fi

  # no laço, as mensagens ganham cor:
  echo "${verde}Acertou! Era $secreto. Você usou $tentativas tentativa(s).${normal}"

  # e o read trata o Ctrl+D (fim da entrada):
  read -rp "Seu palpite: " palpite || { echo; echo "Desistiu? O número era $secreto."; exit 1; }
    TrechoO que faz
    [[ -t 1 ]]"O descritor 1 (a saída padrão) é um terminal?" Falso em ./adivinha.sh > log ou ./adivinha.sh | tee log.
    ${NO_COLOR-}NO_COLOR é uma convenção (no-color.org): quem a define não quer cores em programa nenhum.
    $'\e[32m'Aspas $'…' transformam \e no caractere ESC de verdade. [32m = verde, [33m = amarelo, [31m = vermelho, [0m = volta ao normal. Veja Aspas e Escapes.

Quando não funciona

valor muito grande para esta base de numeração

O que aconteceu: um número com zero na frente (08, 09) entrou numa conta e foi lido como octal. Acontece muito com horas e datas (date +%H às 8h dá 08). Como resolver: $(( 10#$x )). Veja Contas.

A regex aceita tudo (ou nada)

O que aconteceu: a regex foi escrita entre aspas (=~ "^[0-9]+$"), e aí ela é comparada como texto literal; ou faltou o ^/$, e 12abc passa. Como resolver: regex sem aspas, ou numa variável: re='^[0-9]+$'; [[ $x =~ $re ]]. Veja Regex com [[ =~ ]].

O jogo não para de perguntar, mesmo com Ctrl+D

O que aconteceu: o read falha no fim da entrada, mas o laço while true não olha para isso. Como resolver: read … || exit, como na etapa 6. Para sair agora, Ctrl+C.

O número é sempre o mesmo

O que aconteceu: a variável ADIVINHA_SEMENTE ficou exportada no seu terminal (export ADIVINHA_SEMENTE=7). Como confirmar: declare -p ADIVINHA_SEMENTE. Como resolver: unset ADIVINHA_SEMENTE.

Aparece ^[[32m no arquivo de log

O que aconteceu: as cores foram ligadas sem o teste [[ -t 1 ]] e a saída foi para um arquivo. Como resolver: o teste da etapa 6, ou rode com NO_COLOR=1 ./adivinha.sh.

Desafios extras

  • Limite de tentativas: 4 no fácil, 7 no médio, 10 no difícil. Esgotou, perdeu.
  • Esquentando/esfriando: em vez de "maior/menor", diga "quente" quando a diferença for menor que 5% do máximo. Dica: dif=$(( palpite > secreto ? palpite - secreto : secreto - palpite )).
  • Placar com nomes: pergunte o nome do jogador e guarde nível=tentativas=nome.
  • Inverta os papéis: você pensa no número e o script adivinha com busca binária, perguntando "maior, menor ou acertou?".
  • Melhor sorteio: troque RANDOM por SRANDOM (32 bits, não aceita semente) quando não houver ADIVINHA_SEMENTE. bash 5.1+

Resumo

  • $(( RANDOM % N + 1 )) sorteia de 1 a N; RANDOM=semente torna o sorteio repetível para testes.
  • while true + break para o laço principal; continue para descartar uma entrada.
  • Nunca faça conta com o que foi digitado sem validar: [[ $x =~ ^[0-9]+$ ]] e 10#$x.
  • select + case fazem um menu com repetição automática; PS3 é a pergunta.
  • Estado que precisa sobreviver vai para um arquivo simples, lido com IFS='=' read.
  • Cores só com [[ -t 1 ]] e respeitando NO_COLOR.
