Bash Terminal, Shell e Console

"Abra o terminal", "rode no shell", "digite no console", "olhe o prompt": tutoriais usam essas palavras como se fossem a mesma coisa. Não são. Nesta aula você vai separar cada uma, descobrir qual shell está usando e ver como trocar o shell padrão.

Você vai aprender
  • A diferença entre terminal, shell, console, TTY e prompt.
  • Qual programa de terminal abrir no Linux, no macOS e no Windows.
  • Três formas de descobrir qual shell você está usando: echo $0, echo $SHELL e ps -p $$.
  • A ideia de shell de login e shell interativo.
  • Como trocar o shell padrão com chsh.

Cinco nomes, cinco coisas

Pense num telefonema. O aparelho só leva a sua voz e traz a resposta: ele não entende nada. Quem entende é a pessoa do outro lado da linha. No computador é igual: o terminal é o aparelho e o shell é quem atende.

NomeO que éExemplo
Terminal (ou emulador de terminal)O programa com a janela onde você digita. Ele desenha as letras, as cores e entrega o que você digitou ao shell.GNOME Terminal, Konsole, Terminal do macOS, Windows Terminal
ShellO programa que entende os comandos e manda executar. Roda "dentro" do terminal.Bash, zsh, fish, sh
ConsoleO terminal "de verdade" do computador, em tela cheia, sem interface gráfica. Hoje também se usa "console" como sinônimo de terminal.A tela preta que aparece com Ctrl+Alt+F3 no Linux
TTYDe teletypewriter, "teletipo": as máquinas de escrever ligadas a computadores nos anos 1970. Hoje é o nome do dispositivo que liga terminal e shell./dev/pts/0, /dev/tty3
PromptO texto que o shell mostra quando está pronto para o próximo comando.ana@notebook:~$

Então, quando você abre o "Terminal", na verdade abre dois programas: o terminal (a janela) e, dentro dele, um shell (quase sempre o Bash). Se você trocar o shell, a janela continua a mesma. Se trocar o programa de terminal, o Bash continua o mesmo.

O TTY da sua janela

Cada janela de terminal recebe um dispositivo próprio. O comando tty mostra qual é:

$ tty
/dev/pts/0                         « pts = pseudoterminal; 0 = a primeira janela aberta

"Pseudo" porque não existe uma máquina de escrever ligada ao computador: é um programa (o terminal) fingindo ser uma. Nos consoles de tela cheia do Linux, o nome seria /dev/tty3, /dev/tty4… O tty é um programa do GNU coreutils; o terminal simulado deste guia não o conhece.

Qual shell eu estou usando?

Antes de seguir um tutorial, vale confirmar que o shell é mesmo o Bash. Há três jeitos, e cada um responde uma pergunta um pouco diferente.

Forma 1: echo $0

echo
Mostra na tela o que receber.
$0
Variável especial: o nome do programa que está rodando agora. Num terminal, é o nome do shell.
$ echo $0
bash                               « o shell desta janela é o Bash

Em alguns sistemas a resposta é -bash, com um hífen na frente. O hífen é a marca de um shell de login (veja abaixo). Também é Bash. No zsh, a resposta seria zsh (ou -zsh).

Forma 2: echo $SHELL

$ echo $SHELL
/bin/bash                          « o shell PADRÃO da usuária, não necessariamente o atual

Cuidado: a variável SHELL não diz qual shell está rodando agora. Ela diz qual é o shell padrão da usuária, aquele que o sistema abre quando ela entra. Se a Ana rodar outro shell dentro do Bash, $SHELL continua dizendo /bin/bash. Veja, usando o sh para rodar dois comandos:

$ sh -c 'echo $0; echo $SHELL'
sh                                 « $0: quem está rodando é o sh
/bin/bash                          « $SHELL: o padrão da Ana continua sendo o Bash

Forma 3: ps -p $$

A forma mais confiável é perguntar ao sistema qual programa está rodando com o número deste shell.

ps
De process status: lista processos (programas em execução).
-p
Mostra só o processo com este número (PID, de process ID).
$$
Variável especial: o PID do shell atual.
$ ps -p $$
    PID TTY          TIME CMD
   3001 pts/0    00:00:00 bash     « CMD: o nome do programa; TTY: a janela dele

Leia as colunas: PID é o número do processo (no seu computador será outro), TTY é o mesmo /dev/pts/0 que o tty mostrou, TIME é quanto tempo de processador ele já usou e CMD é o programa: bash.

Qual usar?

ComandoRespondeMelhor quando…

Shell dentro de shell

O Bash é um programa como outro qualquer, então você pode abrir um Bash dentro do Bash. A variável SHLVL (de shell level, "nível do shell") conta quantos estão empilhados:

$ echo $SHLVL
1                                  « o primeiro shell da janela
$ bash                             « abre um Bash dentro do Bash (o prompt é igual!)
$ echo $SHLVL
2                                  « agora estamos um nível abaixo
$ exit
exit                               « sai do Bash de dentro e volta ao primeiro
$ echo $SHLVL
1

Repare que nada no prompt avisa que você entrou num segundo shell. Por isso, se um exit não fechar a janela, provavelmente havia um shell dentro do outro. O exit e o atalho Ctrl+D encerram o shell atual; veja Primeiros Comandos.

Shell de login e shell interativo

O Bash pode ser aberto de jeitos diferentes, e isso muda quais arquivos de configuração ele lê ao começar. Por enquanto, guarde só a ideia:

TipoO que éQuando acontece
InterativoConversa com você: mostra prompt e espera comandos.Toda janela de terminal.
Não interativoSó executa e termina, sem prompt.Quando roda um script (bash script.sh).
De loginO primeiro shell de uma sessão, aberto quando você "entra" no sistema.Console de tela cheia, conexão por SSH, o Terminal do macOS.
Não de loginAberto quando você já estava dentro.Uma janela nova do terminal no Linux, um bash digitado.

Dá para perguntar ao próprio Bash. O comando shopt mostra a opção login_shell, e a variável $- lista as opções ligadas; se tiver a letra i, o shell é interativo:

$ shopt login_shell
login_shell         	off          « esta janela não é shell de login
$ echo $-
himBHs                             « tem "i": é interativo
$ bash -l -c "shopt login_shell"
login_shell         	on           « -l pede um shell de login

Por que isso importa? Porque um shell de login lê o ~/.profile (ou ~/.bash_profile) e um interativo comum lê o ~/.bashrc. É a explicação clássica para "coloquei no .bashrc e não funcionou pelo SSH". Os detalhes estão em Arquivos de Inicialização.

Trocar o shell padrão: chsh

O shell padrão de cada usuário fica anotado no arquivo /etc/passwd, no último campo da linha:

$ grep ana /etc/passwd
ana:x:1000:1000:Ana,,,:/home/ana:/bin/bash     « o último campo é o shell padrão

Só podem ser escolhidos os shells listados em /etc/shells:

$ cat /etc/shells
# /etc/shells: valid login shells
/bin/sh
/usr/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/usr/bin/dash
/usr/bin/screen

Para trocar, use chsh (de change shell, "trocar o shell"). O exemplo abaixo é ilustrativo: ele pede a sua senha e só funciona se o zsh estiver instalado. O terminal simulado não tem chsh.

chsh
Troca o shell padrão do usuário (grava no /etc/passwd).
-s
De shell: o caminho do novo shell vem a seguir.
/usr/bin/zsh
O shell escolhido. Precisa estar em /etc/shells.
$ chsh -s /usr/bin/zsh
Senha:                             « a sua senha; nada aparece enquanto você digita
$ echo $SHELL
/bin/bash                          « ainda o antigo: a troca vale para o próximo login

A mudança só aparece quando você sair da sessão e entrar de novo. Para voltar ao Bash: chsh -s /bin/bash. No macOS, o mesmo comando troca o zsh pelo Bash; a aula Bash em Cada Sistema mostra como usar um Bash novo do Homebrew.

Não precisa trocar o shell padrão para usar o Bash

Para experimentar, basta digitar bash dentro do shell atual (e exit para voltar). Para scripts, o que vale é a primeira linha do arquivo (#!/usr/bin/env bash), e não o seu shell padrão.

Quando não funciona

echo $SHELL diz bash, mas os comandos não se comportam como no guia 
$ echo $SHELL
/bin/bash
$ echo $0
sh

O que aconteceu: o shell padrão é o Bash, mas o que está rodando agora é outro (aqui, o sh). Uma pista: no sh o prompt costuma ser só $ , sem ana@notebook:~ (o guia desenha todos os prompts do mesmo jeito). $SHELL não muda quando você abre outro shell.

Como confirmar: ps -p $$ mostra o programa de verdade na coluna CMD.

Como resolver: digite exit para voltar ao shell anterior, ou bash para abrir um Bash.

echo $BASH_VERSION não mostra nada 
$ echo $BASH_VERSION

$ echo $?
0                                  « o echo funcionou: só não havia nada para mostrar

O que aconteceu: o echo mostrou uma linha vazia porque a variável não existe. Ela só existe dentro do Bash, então você está em outro shell (por exemplo, o zsh do macOS ou o sh). Repare que o código de saída é 0: para o echo, mostrar uma linha vazia não é erro.

Como resolver: digite bash para entrar no Bash e repita.

"is an invalid shell" no chsh

Mensagem ilustrativa (o texto exato muda de sistema para sistema):

$ chsh -s /usr/bin/fish
chsh: /usr/bin/fish is an invalid shell

O que aconteceu: o caminho não está em /etc/shells, ou o programa nem está instalado.

Como resolver: confira o caminho certo com type -a fish e se ele está em cat /etc/shells. Instalar pelo gerenciador de pacotes costuma acrescentar o shell à lista sozinho.

Digitei exit e a janela não fechou 
$ exit
exit
$                                  « ainda há um prompt

O que aconteceu: havia um shell dentro de outro (você digitou bash antes). O exit fechou o de dentro.

Como confirmar: echo $SHLVL maior que 1 indica shells empilhados.

Resumo

  • Terminal = a janela; shell = quem entende os comandos; console = o terminal de tela cheia; TTY = o dispositivo que liga os dois; prompt = o aviso de "pode digitar".
  • echo $0 mostra o shell atual, echo $SHELL o shell padrão, ps -p $$ o processo de verdade.
  • Shells podem ficar um dentro do outro; exit fecha só o de dentro.
  • Shell de login e interativo leem arquivos de configuração diferentes (Inicialização).
  • chsh -s troca o shell padrão, que precisa estar em /etc/shells.
