Bash Here-docs e Here-strings

Um here-doc ("documento aqui") é um bloco de texto escrito dentro do próprio script e entregue como entrada a um comando. Com ele, um script cria arquivos de configuração, páginas HTML e mensagens de ajuda de várias linhas sem um echo por linha. A here-string é a versão de uma linha só.

Você vai aprender
  • Como funciona o <<FIM e por que ele troca variáveis pelo valor.
  • A diferença entre <<FIM, <<'FIM' (literal) e <<-FIM (tira tabs).
  • Como gerar arquivos de configuração e HTML, e escrever a ajuda de um script numa função.
  • A here-string <<< e o truque read a b <<< "$linha".
  • O aviso "here-document … delimitado pelo fim do arquivo" e como resolver.

O problema: muitas linhas de texto

Imagine um script que precisa criar um arquivo de configuração com quatro linhas. Com echo, fica assim:

echo "# Configuração da loja" > app.conf
echo "nome=loja" >> app.conf
echo "porta=8080" >> app.conf
echo "log=/home/ana/logs/loja.log" >> app.conf

Funciona, mas é repetitivo, e basta trocar um >> por > para apagar o que veio antes. Com um here-doc, você escreve o texto do jeito que ele vai ficar:

cat > app.conf <<FIM
# Configuração da loja
nome=loja
porta=8080
log=/home/ana/logs/loja.log
FIM

A forma básica: <<FIM

O here-doc é um redirecionamento de entrada: em vez de o comando ler do teclado ou de um arquivo, ele lê as linhas que vêm logo abaixo, até encontrar a palavra que marca o fim.

comando <<DELIMITADOR
linhas de texto
…
DELIMITADOR
cat
O comando que recebe o texto. O cat só repete o que recebe, então o texto aparece na tela (ou vai para um arquivo, com >).
<<
"A entrada são as próximas linhas". Um < lê de um arquivo; dois, do próprio script.
FIM
O delimitador: a palavra que encerra o bloco. O nome é livre. EOF (end of file) é o mais comum nos tutoriais; aqui usamos FIM.
linhas do meio
O conteúdo, entregue ao comando como se fosse um arquivo.
FIM (sozinho)
A linha que fecha. Precisa ter só o delimitador: nada antes, nada depois, nem espaço.

No terminal, o Bash mostra o prompt de continuação > enquanto espera o FIM (você não digita esse sinal):

$ cat <<FIM
> Usuária: $USER
> Pasta: $PWD
> FIM
Usuária: ana                        « $USER foi trocado pelo valor
Pasta: /home/ana

Repare: as variáveis foram expandidas. Um here-doc com o delimitador sem aspas funciona como um texto entre aspas duplas: troca $variável, $(comando) e $((conta)).

$ cat <<FIM
> Dois mais dois: $((2 + 2))
> FIM
Dois mais dois: 4

Mandar para um arquivo

O > arquivo fica na primeira linha, junto do comando. É lá que estão todos os redirecionamentos do comando:

$ cat <<FIM > lembrete.txt
> Comprar pão
> Pagar a luz
> FIM
$ cat lembrete.txt
Comprar pão
Pagar a luz

cat > lembrete.txt <<FIM é igual: a ordem dos redirecionamentos na linha não importa aqui. Use >> para acrescentar no fim de um arquivo que já existe.

Gerar um arquivo de configuração

Este é o uso mais comum em scripts. O script abaixo cria o app.conf usando variáveis, a data do dia e um argumento opcional.

#!/usr/bin/env bash
app=loja
porta=${1:-8080}
cat > app.conf <<FIM
# Gerado por $0 em $(date +%d/%m/%Y)
nome=$app
porta=$porta
log=$HOME/logs/$app.log
FIM
echo "app.conf criado ($porta)"

$ bash gerar-config.sh 9000
app.conf criado (9000)
$ cat app.conf
# Gerado por gerar-config.sh em 15/10/2026
nome=loja
porta=9000
log=/home/ana/logs/loja.log
LinhaO que faz
3${1:-8080}: o primeiro argumento, ou 8080 se não houver (veja Expansão de Parâmetros).
4Abre o here-doc e manda tudo para app.conf, substituindo o que existia.
5$0 é o nome do script; $(date …) roda o date e cola o resultado (a data em que você rodar).
6–8Cada $variável vira seu valor. $HOME virou /home/ana.
9FIM sozinho fecha o bloco. O script continua na linha 10.

Texto literal: <<'FIM'

Às vezes você quer o texto exatamente como está, com os $ intactos. Por exemplo, para gerar outro script, ou mostrar um exemplo de código. Basta colocar o delimitador entre aspas, na primeira linha:

#!/usr/bin/env bash
nome=Ana
cat <<'FIM'
Olá, $nome!
Hoje é $(date +%A).
FIM

$ bash literal.sh
Olá, $nome!                          « nada foi trocado
Hoje é $(date +%A).

Compare com a mesma coisa sem as aspas, e com uma barra antes de um $ que deve ficar:

#!/usr/bin/env bash
nome=Ana
cat <<FIM
Olá, $nome!
Hoje é $(date +%A).
O script custa \$ 0,00 e mora em $HOME.
FIM

$ bash carta.sh
Olá, Ana!
Hoje é quinta.
O script custa $ 0,00 e mora em /home/ana.   « o \$ virou um $ comum
AberturaExpande $var, $( ), $(( ))?Use quando…
<<FIMSim (como aspas duplas). \$ mantém um $.O texto tem valores do script (configurações, relatórios).
<<'FIM' ou <<"FIM"Não, nada (como aspas simples).O texto é código, ou tem muitos $ e crases.

Basta qualquer aspas em qualquer parte do delimitador ('FIM', "FIM", até \FIM) para o bloco ficar literal. A linha que fecha é sempre só FIM, sem aspas.

Indentar sem estragar: <<-FIM

Dentro de um if ou de uma função, você quer recuar o código. Mas no here-doc comum, o recuo vira parte do texto, e o FIM recuado não fecha o bloco. A forma <<- (com hífen) remove tabs do começo de cada linha, inclusive da linha do FIM.

#!/usr/bin/env bash
if true; then
	cat <<-FIM
		linha com dois tabs
	linha com um tab
	FIM
fi
echo "fim do script"

Você não enxerga a diferença entre tab e espaço. O cat -A mostra cada tab como ^I e o fim de cada linha como $:

$ cat -A tabs.sh
#!/usr/bin/env bash$
if true; then$
^Icat <<-FIM$
^I^Ilinha com dois tabs$
^Ilinha com um tab$
^IFIM$
fi$
echo "fim do script"$
$ bash tabs.sh
linha com dois tabs                  « todos os tabs do começo saíram
linha com um tab
fim do script
Só tabs, nunca espaços

O <<- remove apenas o caractere tab. Muitos editores trocam o tab por espaços quando você aperta a tecla Tab; aí o FIM recuado não é reconhecido e o here-doc engole o resto do script (veja "Quando não funciona"). Se o seu editor usa espaços, deixe o conteúdo e o FIM encostados na margem esquerda, com <<FIM normal.

Gerar HTML

Um here-doc pode ter um $( ) com um laço dentro. Este script gera uma página com a lista de alunos do alunos.csv:

#!/usr/bin/env bash
titulo="Turma de Bash"
total=$(tail -n +2 Documentos/alunos.csv | wc -l)
cat > turma.html <<FIM
<!doctype html>
<html lang="pt-BR">
<head><meta charset="utf-8"><title>$titulo</title></head>
<body>
  <h1>$titulo</h1>
  <p>$total alunos matriculados.</p>
  <ul>
$(tail -n +2 Documentos/alunos.csv | while IFS=, read -r nome _ cidade _; do
    printf '    <li>%s (%s)</li>\n' "$nome" "$cidade"
  done)
  </ul>
</body>
</html>
FIM
echo "turma.html gerada"

$ bash pagina.sh
turma.html gerada
$ cat turma.html
<!doctype html>
<html lang="pt-BR">
<head><meta charset="utf-8"><title>Turma de Bash</title></head>
<body>
  <h1>Turma de Bash</h1>
  <p>5 alunos matriculados.</p>
  <ul>
    <li>Ana (Recife)</li>
    <li>Bruno (Curitiba)</li>
    <li>Carla (Salvador)</li>
    <li>Diego (Manaus)</li>
    <li>Elisa (Porto Alegre)</li>
  </ul>
</body>
</html>

O que acontece nas linhas 12 a 14: o $( ) roda um laço que lê o CSV (o _ é um nome de variável para os campos que não interessam) e imprime um <li> por aluno com o printf. O resultado é colado no lugar, dentro do here-doc. A leitura com while read é explicada em Ler Arquivos Linha a Linha.

Here-doc dentro de uma função: a ajuda do script

Todo script com opções deve mostrar como se usa. Uma função com um here-doc deixa a ajuda legível e fácil de manter:

#!/usr/bin/env bash
uso() {
  cat <<FIM
Uso: ${0##*/} [-v] ARQUIVO...

Conta as linhas de cada ARQUIVO.
  -v   mostra detalhes
  -h   mostra esta ajuda
FIM
}
if [[ $# -eq 0 ]]; then
  uso >&2
  exit 1
fi

$ bash ajuda.sh
Uso: ajuda.sh [-v] ARQUIVO...

Conta as linhas de cada ARQUIVO.
  -v   mostra detalhes
  -h   mostra esta ajuda
$ echo $?
1                                    « saiu com erro: faltou o ARQUIVO
uso() { … }
Uma função chamada uso. O here-doc fica dentro dela, mas o texto e o FIM ficam na margem esquerda (sem <<-, o recuo entraria no texto).
${0##*/}
O nome do script sem a pasta: se você rodar bash ~/bin/ajuda.sh, aparece só ajuda.sh.
uso >&2
Manda a ajuda para a saída de erro, porque aqui ela aparece por causa de um uso errado.

Here-doc para outros comandos

Qualquer comando que lê a entrada padrão aceita um here-doc. Alguns exemplos que funcionam na máquina da Ana:

$ wc -l <<FIM
> um
> dois
> três
> FIM
3
$ cat <<FIM | sort
> uva
> banana
> maçã
> FIM
banana
maçã
uva

No segundo exemplo, o here-doc é a entrada do cat, e o | sort fica na primeira linha também. Um here-doc também alimenta um laço while read:

$ while read -r fruta qtd; do
>   echo "$fruta: $qtd"
> done <<FIM
> banana 3
> maçã 2
> FIM
banana: 3
maçã: 2

Exemplos do mundo real (ilustrativos)

Os três exemplos abaixo precisam de rede, de um servidor de e-mail ou de senha de administrador, então não rodam no laboratório nem no simulador. Eles mostram o mesmo padrão em ação:

# 1. Enviar um e-mail (precisa de um programa mail configurado)
mail -s "Backup de $(date +%d/%m)" ana@exemplo.com <<FIM
O backup terminou às $(date +%H:%M).
Arquivos copiados: $total
FIM

# 2. Rodar vários comandos em outro computador pelo ssh
#    (aspas no FIM: as variáveis são do servidor, não daqui)
ssh ana@servidor <<'FIM'
cd /var/www
du -sh .
df -h /
FIM

# 3. Gravar um arquivo do sistema como root
#    (o "> /etc/…" não funcionaria: veja redirecionamento.html)
sudo tee /etc/minha-app.conf > /dev/null <<FIM
porta=8080
FIM

No exemplo do ssh, as aspas em 'FIM' são importantes: sem elas, o seu computador trocaria as variáveis e os $( ) antes de enviar o texto ao servidor.

Guardar um here-doc numa variável

Duas formas:

$ msg=$(cat <<'FIM'
> um
> dois
> FIM
> )
$ echo "$msg"
um
dois
$ read -r -d '' texto <<'FIM'
> linha A
> linha B
> FIM
$ echo $?
1                                    « "erro", mas a variável foi preenchida
$ echo "$texto"
linha A
linha B

O read -d '' lê até achar um caractere nulo, que nunca vem; por isso termina com código 1 ao chegar no fim do texto. Isso é normal, mas cuidado com set -e (veja set -euo pipefail): ali, esse 1 encerraria o script. A forma com $(cat …) não tem esse problema.

Here-string: <<<

Quando o texto é uma linha só (ou está numa variável), use a here-string ("texto aqui"): três sinais de menor e o texto logo depois.

tr a-z A-Z
Um comando que lê a entrada padrão (aqui, troca minúsculas por maiúsculas).
<<<
"A entrada é este texto".
"ola mundo"
O texto. Use aspas: é uma palavra só para o Bash. Pode ser "$variável".
$ tr a-z A-Z <<< "ola mundo"
OLA MUNDO
$ bc <<< "9.5 + 7.0 + 8.5"
25.0
$ texto="erro: disco cheio"
$ grep -q erro <<< "$texto" && echo "achei um erro"
achei um erro

É o mesmo que echo "$texto" | grep -q erro, sem criar um pipe. Um detalhe: a here-string acrescenta uma quebra de linha no fim.

$ wc -c <<< "abc"
4                                    « a, b, c e o \n
$ printf '%s' "abc" | wc -c
3

O truque mais útil: read com here-string

A here-string é a forma certa de separar uma linha em variáveis:

$ linha="Ana 29 Recife"
$ read nome idade cidade <<< "$linha"
$ echo "$nome / $idade / $cidade"
Ana / 29 / Recife
$ IFS=, read -r nome idade cidade nota <<< "Bruno,34,Curitiba,7.0"
$ echo "$nome tem nota $nota"
Bruno tem nota 7.0

Por que não echo "$linha" | read nome? Porque cada lado de um pipe roda num subshell: o read preenche as variáveis lá dentro, e elas somem quando o pipe acaba.

$ echo "Ana" | read n; echo "[$n]"
[]                                   « vazio: o read rodou num subshell
$ read n <<< "Ana"; echo "[$n]"
[Ana]

Esse mesmo problema aparece com cmd | while read; ele é explicado com calma em Ler Arquivos Linha a Linha.

Missão: use read com uma here-string para separar a linha Carla,22,Salvador,8.5 nas variáveis nome idade cidade nota (o separador é a vírgula). Confira com echo "$cidade".

Quando não funciona

"aviso: here-document na linha N delimitado pelo fim do arquivo (desejava `FIM')" 
#!/usr/bin/env bash
cat <<FIM
linha 1
linha 2
FIM 
echo "depois"

$ bash espaco-fim.sh
espaco-fim.sh: linha 6: aviso: here-document na linha 2 delimitado pelo fim do arquivo (desejava `FIM')
linha 1
linha 2
FIM                                  « o FIM virou texto…
echo "depois"                        « …e o resto do script também
$ echo $?
0

O que aconteceu: a linha 5 tem um espaço invisível depois de FIM. Para o Bash, FIM não é FIM, então ele seguiu procurando até o fim do arquivo e usou tudo como texto. É só um aviso: o script "funciona" e sai com 0, mas o echo "depois" nunca rodou.

Como confirmar: cat -A espaco-fim.sh mostra FIM $ (espaço antes do $ do fim da linha). Outras causas: FIM recuado com espaços, escrito diferente (fim, FIM;) ou o arquivo salvo no Windows (aparece FIM^M$).

Como resolver: deixe a linha de fechamento com só o delimitador, encostado na margem (ou recuado só com tabs, se usar <<-).

"erro de sintaxe: fim inesperado do arquivo" 
$ bash espacos.sh
espacos.sh: linha 7: aviso: here-document na linha 3 delimitado pelo fim do arquivo (desejava `FIM')
espacos.sh: linha 8: erro de sintaxe: fim inesperado do arquivo do comando `if' na linha 2
$ echo $?
2

O que aconteceu: o here-doc estava dentro de um if, com <<-FIM, mas recuado com espaços. O FIM não foi reconhecido, o here-doc engoliu o fi, e o if ficou sem fechar. Agora o script nem roda.

Como resolver: recue com tabs de verdade (confira com cat -A: devem aparecer ^I), ou tire o recuo do conteúdo e do FIM.

O terminal ficou mostrando > e não sai

Você abriu um here-doc no terminal e o Bash está esperando o delimitador. Digite a linha com só FIM (ou o nome que você usou) e Enter. Para desistir, aperte Ctrl+C. Se apertar Ctrl+D, o here-doc termina ali com o aviso bash: aviso: here-document na linha 8 delimitado pelo fim do arquivo (desejava `FIM').

As variáveis apareceram como $nome

O que aconteceu: o delimitador estava entre aspas (<<'FIM' ou <<"FIM"), o que desliga as expansões. Ao contrário: se um $ sumiu ou virou outra coisa, o delimitador estava sem aspas; escape com \$ ou use 'FIM'.

Resumo

  • cmd <<FIM … FIM entrega várias linhas como entrada; os redirecionamentos e pipes ficam na primeira linha.
  • Sem aspas no delimitador, expande variáveis e $( ); com 'FIM', o texto é literal.
  • <<-FIM remove tabs (não espaços) do começo das linhas.
  • A linha de fechamento tem só o delimitador. Um espaço a mais gera "delimitado pelo fim do arquivo (desejava `FIM')".
  • <<< "$var" passa uma linha como entrada; read a b <<< "$linha" separa campos sem perder as variáveis.
