Projeto Relatório de Logs

Todo servidor web anota cada visita num log de acesso: quem pediu (o IP), quando, qual página e o que o servidor respondeu (o código HTTP). Ler isso linha por linha é impossível quando são milhares. Neste projeto você escreve um script que transforma o log num relatório: quantos acessos, de quem, quais páginas, quais erros, em que horários. E faz a mesma conta de dois jeitos, em Bash puro e com awk/sort/uniq, para saber quando usar cada um.

Ao terminar você terá
  • Um script relatorio.sh que lê ~/Documentos/acesso.log (ou outro log) e mostra tabelas com quantidade, porcentagem e uma barra.
  • A opção -c para gerar CSV (abre em qualquer planilha) e -t N para o "top N" de páginas.
  • A opção -g N, que inventa um log de teste com N linhas, para você testar com volume.
  • Uma comparação medida entre Bash puro e awk.

Antes de programar: como é uma linha do log

O arquivo ~/Documentos/acesso.log tem 6 linhas neste formato (é uma versão simplificada do Common Log Format, o formato do Apache e do nginx):

$ head -1 Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200

Separando pelos espaços, como o read e o awk fazem, cada linha tem 8 campos:

CampoExemploO que é
1192.168.0.10O IP de quem acessou.
2 e 3- -Identidade e usuário (quase sempre vazios, viram -).
4[15/Oct/2026:09:01:12]Data e hora, entre colchetes. A hora começa na posição 13.
5"GETO método (GET = pedir uma página; POST = enviar um formulário), com a aspa grudada.
6/A página pedida.
7HTTP/1.1"A versão do protocolo.
8200O código de resposta: 200 = OK, 304 = não mudou, 403 = proibido, 404 = não encontrado, 500 = erro do servidor.

As etapas

  1. Etapa 1 — Ler cada linha em campos

    O que vamos fazer e por quê: o while read lê uma linha por volta e, se você der vários nomes, divide a linha entre eles. É a base de tudo: depois que cada campo tem um nome, contar é fácil.

    #!/usr/bin/env bash
# relatorio.sh — versão 1: ler cada linha em campos
log=${1:-$HOME/Documentos/acesso.log}
total=0
while read -r ip _ _ data _ pagina _ codigo; do
  total=$(( total + 1 ))
  echo "ip=$ip hora=${data:13:8} pagina=$pagina codigo=$codigo"
done < "$log"
echo "total: $total acessos"
    while read -r
    Lê uma linha por volta; o -r não deixa a barra invertida ser interpretada. Veja Ler Arquivos Linha a Linha.
    ip _ _ data _ pagina _ codigo
    Um nome por campo. O _ é uma variável "lixeira" para os campos que não interessam. O último nome recebe todo o resto da linha (aqui só há o código).
    done < "$log"
    O arquivo entra pela entrada padrão do laço inteiro (e não do read sozinho, que leria só a primeira linha para sempre).
    ${data:13:8}
    Fatia de texto: a partir da posição 13 (contando do 0), 8 caracteres: 09:01:12. Veja Manipular Strings.

  2. Etapa 2 — Contar por IP com um array associativo

    O que vamos fazer e por quê: uma variável por código funciona na missão anterior, mas não para IPs: não sabemos de antemão quais vão aparecer. Um array associativo cria uma "gaveta" para cada IP novo na hora em que ele aparece. Veja Arrays Associativos.

    #!/usr/bin/env bash
# relatorio.sh — versão 2: contar por IP
set -euo pipefail
log=${1:-$HOME/Documentos/acesso.log}
declare -A por_ip
total=0
while read -r ip _ _ data _ pagina _ codigo; do
  (( ++total ))
  por_ip[$ip]=$(( ${por_ip[$ip]:-0} + 1 ))
done < "$log"
echo "total: $total acessos"
for ip in "${!por_ip[@]}"; do
  echo "${por_ip[$ip]} $ip"
done | sort -rn
    TrechoO que faz
    set -euo pipefailO modo estrito do projeto de backup. Aqui ele vai nos ensinar uma armadilha (veja abaixo). Veja set -euo pipefail.
    declare -A por_ipCria o array associativo (índice = texto).
    (( ++total ))Soma 1. Com ++ antes, o resultado é o valor novo (1, 2, 3…), nunca 0, então o set -e não o confunde com uma falha.
    por_ip[$ip]=$(( ${por_ip[$ip]:-0} + 1 ))"O valor atual (ou 0, se a gaveta ainda não existe) mais 1."
    for ip in "${!por_ip[@]}"Percorre as chaves (os IPs). O ! pede as chaves em vez dos valores.
    done | sort -rnA saída do laço inteiro passa pelo sort: -n numérico, -r do maior para o menor. O Bash conta; o sort ordena.
    $ ./relatorio.sh
total: 6 acessos
3 192.168.0.10
2 192.168.0.23
1 192.168.0.57
$ echo $?
0
    "por_ip: variável não associada" com (( por_ip[$ip]++ ))

    A forma mais curta de contar seria (( por_ip[$ip]++ )). Com o modo estrito, ela quebra:

    $ ./relatorio.sh
./relatorio.sh: linha 9: por_ip: variável não associada
$ echo $?
1

    O que aconteceu: o set -u proíbe ler uma posição que não existe, e na primeira vez a gaveta do IP não existe. (Com ++por_ip[$ip] acontece o mesmo.) Sem o -u, o (( x++ )) ainda teria outro problema com o -e: ele devolve o valor antigo, 0 na primeira vez, e (( 0 )) é "falso", o que derruba o script. Como resolver: a forma com ${…:-0} funciona em qualquer modo. Veja set -euo pipefail.

  3. Etapa 3 — Todas as contagens numa passada só

    O que vamos fazer e por quê: com o mesmo laço contamos quatro coisas ao mesmo tempo: IP, código, página e hora. Ler o arquivo uma vez só é o que deixa o script rápido. E, para não repetir o laço de impressão quatro vezes, uma função recebe o nome do array.

    #!/usr/bin/env bash
# relatorio.sh — versão 3: todas as contagens
set -euo pipefail
log=${1:-$HOME/Documentos/acesso.log}
top=5
declare -A por_ip por_codigo por_pagina por_hora
total=0
while read -r ip _ _ data _ pagina _ codigo; do
  (( ++total ))
  por_ip[$ip]=$(( ${por_ip[$ip]:-0} + 1 ))
  por_codigo[$codigo]=$(( ${por_codigo[$codigo]:-0} + 1 ))
  por_pagina[$pagina]=$(( ${por_pagina[$pagina]:-0} + 1 ))
  por_hora[${data:13:2}h]=$(( ${por_hora[${data:13:2}h]:-0} + 1 ))
done < "$log"

# imprime "quantidade chave" de um array associativo (nome em $1)
listar() {
  local -n arr=$1
  local k
  for k in "${!arr[@]}"; do
    printf '%d %s\n' "${arr[$k]}" "$k"
  done
}

echo "== $total acessos =="
echo "-- por IP";     listar por_ip     | sort -k1,1nr -k2
echo "-- por código"; listar por_codigo | sort -k2
echo "-- páginas";    listar por_pagina | sort -k1,1nr -k2 | head -n "$top"
echo "-- por hora";   listar por_hora   | sort -k2
    TrechoO que faz
    declare -A por_ip por_codigo …Quatro arrays associativos numa linha.
    por_hora[${data:13:2}h]A chave é a hora, 09, com um h colado: 09h.
    local -n arr=$1Um nameref: arr passa a ser um apelido do array cujo nome veio em $1. listar por_ip faz arr = por_ip. Veja eval, Indireção e nameref. bash 4.3+
    sort -k1,1nr -k2Ordena pela coluna 1 numérica decrescente; no empate, pela coluna 2 (o nome), em ordem alfabética. Sem o desempate, a ordem dos empatados mudaria de uma execução para outra.
    sort -k2Códigos e horas ficam melhores em ordem da chave (200, 403, 404; 08h, 09h…).
    head -n "$top"Só as primeiras $top linhas: o "top 5".

  4. Etapa 4 — Saída formatada com printf

    O que vamos fazer e por quê: "3 192.168.0.10" serve para o computador, mas um relatório para gente precisa de colunas alinhadas, porcentagem e, de preferência, algo visual. Uma função tabela lê as linhas "quantidade chave" e desenha cada uma assim:

      192.168.0.10          3  50%  ##############################

    Os quatro truques de printf e de aritmética que ela usa, testados um por um:

    $ printf "%-16s %5d\n" 192.168.0.10 3
192.168.0.10         3
$ printf "%3d%%\n" 17
 17%
$ total=6 qtd=1; echo $(( qtd * 100 / total )) $(( (qtd * 100 + total / 2) / total ))
16 17
$ printf -v barra "%*s" 5 ""; echo "[$barra]" "[${barra// /#}]"
[     ] [#####]
    TruqueO que faz
    %-16sTexto em 16 colunas, alinhado à esquerda (o -). Sem o -, à direita. Veja printf.
    %5dNúmero inteiro em 5 colunas, alinhado à direita: as unidades ficam umas embaixo das outras.
    %%Um % de verdade (sozinho, ele iniciaria um formato).
    (qtd * 100 + total / 2) / totalO Bash só faz contas com inteiros e trunca: 100/6 = 16,67 vira 16. Somar metade do divisor antes de dividir faz arredondar: 17. Veja Contas.
    printf -v barra '%*s' N ''Guarda em barra (o -v) um texto vazio alinhado em N colunas, isto é, N espaços. O * pega a largura do argumento seguinte.
    ${barra// /#}Troca todos os espaços por #. Veja Expansão de Parâmetros.

    A função completa. Ela guarda as linhas num array (com mapfile) porque precisa passar por elas duas vezes: a primeira para achar o maior valor, que vira a barra cheia de 30 #; a segunda para imprimir.

    # lê linhas "quantidade chave" e mostra como tabela (ou CSV, com -c)
tabela() {
  local titulo=$1 linha qtd chave maior=1 barra
  local -a linhas
  mapfile -t linhas
  if (( csv )); then
    for linha in "${linhas[@]}"; do
      printf '%s,%s,%d\n' "$titulo" "${linha#* }" "${linha%% *}"
    done
    return
  fi
  for linha in "${linhas[@]}"; do
    qtd=${linha%% *}
    if (( qtd > maior )); then maior=$qtd; fi
  done
  printf '\n%s\n' "$titulo"
  for linha in "${linhas[@]}"; do
    qtd=${linha%% *}
    chave=${linha#* }
    printf -v barra '%*s' $(( qtd * 30 / maior )) ''
    printf '  %-16s %6d %3d%%  %s\n' "$chave" "$qtd" \
      $(( (qtd * 100 + total / 2) / total )) "${barra// /#}"
  done
}
    mapfile -t linhas
    Lê a entrada padrão inteira para o array linhas, uma linha por item, sem o \n (-t). Veja mapfile.
    ${linha%% *}
    Apaga do primeiro espaço até o fim: sobra a quantidade.
    ${linha#* }
    Apaga do começo até o primeiro espaço: sobra a chave (mesmo que ela tenha espaços).
    if (( qtd > maior )); then …; fi
    Guarda o maior valor. Usamos if, e não (( … )) && maior=…, porque com set -e um && falso na última linha de uma função faz a função "falhar".

  5. Etapa 5 — Um log grande para testar, e a comparação com awk

    O que vamos fazer e por quê: 6 linhas não testam nada. Logs de verdade têm milhares de linhas, e só com volume aparecem as perguntas importantes: o script aguenta? Quanto demora? Em vez de procurar um log real, o script vai inventar um, sorteando IPs, páginas, códigos e horários.

    gerar() {
  local n=$1 i ip pagina codigo metodo
  local ips=(192.168.0.10 192.168.0.23 192.168.0.57 10.0.0.5 10.0.0.8 172.16.4.2)
  local paginas=(/ / / /contato /fotos /blog /blog/bash /login /admin /favicon.ico)
  local codigos=(200 200 200 200 200 200 304 404 403 500)
  local horas=(08 09 09 10 10 10 11 11 12 14 14 15 15 15 16 16 17 18 19 20)
  RANDOM=42                              # semente fixa: o mesmo log sempre
  for (( i = 0; i < n; i++ )); do
    ip=${ips[RANDOM % ${#ips[@]}]}
    pagina=${paginas[RANDOM % ${#paginas[@]}]}
    codigo=${codigos[RANDOM % ${#codigos[@]}]}
    metodo=GET
    if [[ $pagina == /login ]]; then metodo=POST; fi
    printf '%s - - [15/Oct/2026:%s:%02d:%02d] "%s %s HTTP/1.1" %s\n' \
      "$ip" "${horas[RANDOM % ${#horas[@]}]}" $(( RANDOM % 60 )) $(( RANDOM % 60 )) \
      "$metodo" "$pagina" "$codigo"
  done | sort -k4,4
}

    Os três dão o mesmo resultado, mas o awk foi uns 50 vezes mais rápido que o laço em Bash. O motivo: o while read do Bash lê o arquivo quase caractere por caractere e interpreta cada linha do laço de novo a cada volta; o awk é um programa compilado feito exatamente para "ler linhas, separar campos, contar". O comando do awk, por partes:

    awk '…' grande.log
    Roda o programa entre aspas simples para cada linha do arquivo.
    { n[$1]++ }
    Para cada linha: some 1 no array n, na posição do campo 1 (o IP). No awk, uma posição nova já vale 0, sem precisar de :-0.
    END { … }
    Roda uma vez, depois da última linha.
    for (ip in n) print n[ip], ip

#!/usr/bin/env bash
# relatorio.sh — relatório de um log de acesso de servidor web.
# Uso: relatorio.sh [-c] [-t N] [ARQUIVO]   (padrão: ~/Documentos/acesso.log)
#      relatorio.sh -g N > teste.log        gera um log de teste com N linhas
#   -c    saída em CSV (secao,chave,quantidade)
#   -t N  quantas páginas mostrar no "mais acessadas" (padrão: 5)
set -euo pipefail

csv=0
top=5
gerar_linhas=0

uso() {
  echo "uso: ${0##*/} [-c] [-t N] [ARQUIVO] | ${0##*/} -g N" >&2
  exit 2
}

gerar() {
  local n=$1 i ip pagina codigo metodo
  local ips=(192.168.0.10 192.168.0.23 192.168.0.57 10.0.0.5 10.0.0.8 172.16.4.2)
  local paginas=(/ / / /contato /fotos /blog /blog/bash /login /admin /favicon.ico)
  local codigos=(200 200 200 200 200 200 304 404 403 500)
  local horas=(08 09 09 10 10 10 11 11 12 14 14 15 15 15 16 16 17 18 19 20)
  RANDOM=42                              # semente fixa: o mesmo log sempre
  for (( i = 0; i < n; i++ )); do
    ip=${ips[RANDOM % ${#ips[@]}]}
    pagina=${paginas[RANDOM % ${#paginas[@]}]}
    codigo=${codigos[RANDOM % ${#codigos[@]}]}
    metodo=GET
    if [[ $pagina == /login ]]; then metodo=POST; fi
    printf '%s - - [15/Oct/2026:%s:%02d:%02d] "%s %s HTTP/1.1" %s\n' \
      "$ip" "${horas[RANDOM % ${#horas[@]}]}" $(( RANDOM % 60 )) $(( RANDOM % 60 )) \
      "$metodo" "$pagina" "$codigo"
  done | sort -k4,4
}

# lê linhas "quantidade chave" e mostra como tabela (ou CSV, com -c)
tabela() {
  local titulo=$1 linha qtd chave maior=1 barra
  local -a linhas
  mapfile -t linhas
  if (( csv )); then
    for linha in "${linhas[@]}"; do
      printf '%s,%s,%d\n' "$titulo" "${linha#* }" "${linha%% *}"
    done
    return
  fi
  for linha in "${linhas[@]}"; do
    qtd=${linha%% *}
    if (( qtd > maior )); then maior=$qtd; fi
  done
  printf '\n%s\n' "$titulo"
  for linha in "${linhas[@]}"; do
    qtd=${linha%% *}
    chave=${linha#* }
    printf -v barra '%*s' $(( qtd * 30 / maior )) ''
    printf '  %-16s %6d %3d%%  %s\n' "$chave" "$qtd" \
      $(( (qtd * 100 + total / 2) / total )) "${barra// /#}"
  done
}

Quando não funciona

As colunas saem trocadas (pagina=HTTP/1.1")

O que aconteceu: o número de nomes no read não bate com o formato do log. Logs reais do Apache e do nginx têm mais campos (tamanho da resposta, navegador…). Como confirmar: head -1 seu.log | tr ' ' '\n' | cat -n numera os campos. Como resolver: ajuste os nomes (ou os $N do awk) para o seu formato.

Só aparece a primeira linha, para sempre

O que aconteceu: o < "$log" foi parar no read (while read … < "$log"; do): a cada volta o arquivo é aberto de novo e a primeira linha é lida outra vez. Como resolver: o redirecionamento vai no done. Interrompa com Ctrl+C.

Os totais somem depois do laço

O que aconteceu: você escreveu cat "$log" | while read …. Cada parte de um pipe roda num subshell, e as variáveis criadas lá dentro morrem com ele. Como resolver: while …; done < "$log" (como no script) ou shopt -s lastpipe. Veja Subshells e Grupos.

A última linha do log não é contada

O que aconteceu: o arquivo não termina com quebra de linha, e o read devolve "falha" na última linha incompleta. Como resolver: while read -r … || [[ -n $ip ]]; do. Veja Ler Arquivos Linha a Linha.

sort: opção inválida -- 'k' ou ordem estranha no macOS

O sort do macOS (BSD) aceita -k1,1nr, mas a ordem alfabética depende do LANG. Para resultados iguais em qualquer máquina, use LC_ALL=C sort … (ordem por byte).

Desafios extras

  • Só os erros: uma opção -e que considera apenas códigos 4xx e 5xx ([[ $codigo == [45]* ]] || continue).
  • Turbo: troque o laço while read por um único awk que imprime as quatro contagens com um prefixo (print "ip", n, $1…), e leia o resultado com while read secao qtd chave. Meça com time num log de 100 mil linhas.
  • Log real: adapte para o formato completo do Apache, com o tamanho da resposta, e some os bytes enviados por página.
  • HTML: uma opção -H que gera uma página com uma <table> usando um here-doc.
  • Suspeitos: liste os IPs com mais de 3 respostas 403 (alguém tentando entrar no /admin?).

Resumo

  • while read -r a _ b …; do …; done < arquivo separa cada linha em campos nomeados.
  • Um array associativo conta "por chave"; ${a[$k]:-0} + 1 funciona até com set -u.
  • O Bash conta, o sort ordena, o head corta o top N.
  • printf com %-16s, %5d e %% monta tabelas; (a*100 + t/2)/t arredonda.
  • RANDOM=semente gera dados de teste repetíveis.
  • Para arquivos grandes, awk ganha de longe; para perguntas rápidas, cut | sort | uniq -c.
