Bash grep, sed, awk e cia.

O Bash sabe decidir e repetir, mas quem faz o trabalho pesado com texto são pequenos programas: grep procura, cut recorta, sort ordena, sed troca, awk calcula. Esta aula mostra cada um com os arquivos da Ana e, principalmente, como usá-los dentro de um script: guardando o resultado numa variável, decidindo pelo código de saída e encadeando com pipes.

Você vai aprender
  • grep e o seu código de saída (0, 1 e 2), para usar com if.
  • Recortar, ordenar e contar: cut, sort, uniq, wc, tr.
  • sed para trocar e apagar linhas, e o cuidado com sed -i.
  • awk para colunas e contas: somar e tirar a média das notas do alunos.csv (e a armadilha da vírgula).
  • tee, column e quando o próprio Bash basta, sem ferramenta nenhuma.

A ideia: filtros ligados por pipes

Todas essas ferramentas são filtros: leem texto (de um arquivo ou da entrada padrão), fazem uma coisa só e escrevem o resultado na saída. Ligadas por pipes, resolvem perguntas inteiras. Exemplo: "quais IPs mais acessaram o site da Ana?"

$ cut -d' ' -f1 acesso.log | sort | uniq -c | sort -rn
      3 192.168.0.10
      2 192.168.0.23
      1 192.168.0.57

Quatro programas, cada um com uma tarefa: o cut pega a primeira coluna (o IP), o sort junta os iguais, o uniq -c conta os repetidos e o último sort -rn põe o maior primeiro. Ao fim da aula, você vai montar essa linha sozinho.

Os exemplos rodam dentro da pasta Documentos da Ana. Os arquivos que vamos usar:

$ cat acesso.log

192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200
$ cat alunos.csv

Carla,22,Salvador,8.5

Cada linha do acesso.log é um pedido feito ao site: o IP de quem pediu, a data, o pedido (GET /admin) e, no fim, o código de resposta (200 = ok, 403 = proibido, 404 = não encontrado). O alunos.csv é uma planilha em texto: campos separados por vírgula, com cabeçalho.

grep: procurar linhas

O grep mostra as linhas que contêm um padrão. O nome vem de um comando do antigo editor ed: g/re/p, "global, regular expression, print".

grep
O comando.
404
O padrão a procurar (uma expressão regular; aqui, um texto simples).
acesso.log
Onde procurar. Sem arquivo, o grep lê a entrada padrão (de um pipe).
$ grep 404 acesso.log
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
$ grep -n 403 acesso.log
3:192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403   « -n: número da linha
$ grep -v 200 acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403   « -v: as que NÃO têm 200
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404

Maiúsculas e palavras inteiras: -i e -w

$ grep -i ana alunos.csv
Ana,29,Recife,9.5
Diego,41,Manaus,6.0                « "Manaus" tem "ana" dentro!
$ grep -w Ana alunos.csv
Ana,29,Recife,9.5                  « -w: só a palavra inteira

O -i (ignore case) ignora maiúsculas e minúsculas. O -w (word) exige que o padrão seja uma palavra inteira, não um pedaço de outra. Em scripts, o -w evita muitos falsos positivos.

Vários padrões e só o pedaço: -E e -o

$ grep -E '403|404' acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
$ grep -oE '[0-9]{3}$' acesso.log | sort | uniq -c
      4 200
      1 403
      1 404
-E
Expressão regular estendida: | (ou), +, {3}, ( ) funcionam sem barra. Sem -E, '403|404' procuraria o texto "403|404" literal.
-o
Mostra só o pedaço que casou (only matching), um por linha, em vez da linha inteira.
[0-9]{3}$
Três dígitos no fim da linha ($ = fim). As regex são explicadas em Regex com [[ =~ ]].

No script: -q, -c e o código de saída

Dentro de um script você raramente quer as linhas na tela. Você quer uma resposta: "tem ou não tem?", "quantas?". O grep responde pelo código de saída:

$ grep -q 404 acesso.log; echo $?
0                                  « achou
$ grep -q 500 acesso.log; echo $?
1                                  « não achou (não é erro!)
$ grep -q 404 nada.log; echo $?
grep: nada.log: Arquivo ou diretório inexistente
2                                  « erro de verdade
$ grep -c 404 acesso.log
1                                  « -c: quantas linhas casaram
CódigoSignificado
0Achou pelo menos uma linha.
1Não achou nenhuma.
2Erro: arquivo inexistente, sem permissão, regex inválida.

O -q (quiet, "quieto") não mostra nada e para na primeira linha encontrada. É feito para o if:

$ if grep -qw Bruno alunos.csv; then echo "Bruno está na turma"; fi
Bruno está na turma

Repare: não se escreve if [ grep … ]. O if já testa o código de saída de qualquer comando (veja if, elif, else).

E o -c (count) serve para guardar um número numa variável:

#!/usr/bin/env bash
log=Documentos/acesso.log
total=$(wc -l < "$log")
ok=$(grep -c ' 200$' "$log")
echo "Total: $total acessos"
echo "Com sucesso (200): $ok"

$ bash ok.sh
Total: 6 acessos
Com sucesso (200): 4
grep -c que não acha nada devolve 1 
$ grep -c 500 acesso.log; echo $?
0
1

Ele imprime 0, mas o código de saída é 1 ("não achei"). Num script com set -e (veja set -euo pipefail), isso encerra o script. Escreva n=$(grep -c 500 "$log" || true) quando zero for um resultado normal.

Missão: complete a linha do erros para contar quantas linhas do log terminam com 403 ou 404. Dica: grep -c com -E e o padrão ' (403|404)$'. Rode até aparecer Com erro (403/404): 2.

#!/usr/bin/env bash

cut: recortar colunas

O cut pega pedaços de cada linha: campos separados por um caractere, ou posições.

-d,
O separador (delimiter) é a vírgula. Para espaço: -d' '. Sem -d, o separador é o tab.
-f1,4
Os campos (fields) 1 e 4. Também vale -f2- (do 2 ao fim) e -f1-3.
$ cut -d, -f1,4 alunos.csv
nome,nota
Ana,9.5
Bruno,7.0
Carla,8.5
Diego,6.0
Elisa,10.0
$ cut -d' ' -f1 acesso.log
192.168.0.10
192.168.0.23
192.168.0.10
192.168.0.57
192.168.0.10
192.168.0.23

Limitações: o cut aceita um caractere como separador, e cada espaço conta (dois espaços seguidos criam um campo vazio). Para colunas separadas por "vários espaços", use awk. E o -c (caracteres) do GNU cut conta bytes, o que quebra letras acentuadas:

$ cut -c1-3 frutas.txt
ban
ma�                                « o "ç" tem 2 bytes e foi cortado ao meio
lar
…

(Saída encurtada.) Para cortar texto com acento, use a expansão ${var:0:3}, que conta letras (veja Expansão de Parâmetros).

sort e uniq: ordenar e contar

$ sort frutas.txt
banana
banana
banana
laranja
maçã
maçã
uva
$ sort frutas.txt | uniq
banana
laranja
maçã
uva
$ sort frutas.txt | uniq -c | sort -rn
      3 banana
      2 maçã
      1 uva
      1 laranja

O uniq só junta linhas iguais vizinhas. Por isso ele quase sempre vem depois de um sort. Com -c (count), ele mostra quantas vezes cada linha apareceu.

Opção do sortO que faz
-nOrdem numérica (sem ela, "10" vem antes de "9", como num dicionário).
-rOrdem inversa (reverse): maior primeiro.
-t,O separador de campos é a vírgula.
-k4Ordenar pelo campo 4 (key).
-uTira as repetidas (como sort | uniq).
$ tail -n +2 alunos.csv | sort -t, -k4 -rn
Elisa,27,Porto Alegre,10.0
Ana,29,Recife,9.5
Carla,22,Salvador,8.5
Bruno,34,Curitiba,7.0
Diego,41,Manaus,6.0
$ tail -n +2 alunos.csv | sort -t, -k2 -n | head -n 1
Carla,22,Salvador,8.5              « a mais nova

O tail -n +2 pula o cabeçalho, para ele não se misturar com os dados.

sort -n e números com ponto, em português

No locale pt_BR, o ponto é o separador de milhar. Então, para o sort -n, 9.25 vale 925:

$ printf '9.5\n10.0\n9.25\n' | sort -n
9.5
10.0
9.25                               « 925 > 100 > 95
$ printf '9.5\n10.0\n9.25\n' | LC_ALL=C sort -n
9.25
9.5
10.0

As notas do alunos.csv só saíram certas porque todas têm uma casa decimal. Em scripts que ordenam números com ponto, use LC_ALL=C sort -n. O mesmo assunto aparece no printf.

wc: contar

O wc (word count) conta linhas, palavras e bytes.

$ wc acesso.log
  6  48 389 acesso.log             « linhas, palavras, bytes, nome
$ wc -l alunos.csv
6 alunos.csv
$ wc -l < alunos.csv
6                                  « só o número: ideal para variáveis
$ wc -w notas.txt
12 notas.txt

Em scripts, use wc -l < arquivo: com o <, o wc não sabe o nome do arquivo e mostra só o número, pronto para n=$(wc -l < arquivo). E lembre: o alunos.csv tem 6 linhas, mas 5 alunos (uma é o cabeçalho). -c conta bytes; -m conta caracteres (letras acentuadas usam mais de um byte).

tr: trocar ou apagar caracteres

O tr (translate) troca caracteres um por um. Ele só lê da entrada padrão: não aceita nome de arquivo.

$ tr ',' ';' < alunos.csv
nome;idade;cidade;nota
Ana;29;Recife;9.5
…
$ echo "Olá   mundo   bash" | tr -s ' '
Olá mundo bash                     « -s: espremeu os espaços repetidos
$ echo "R$ 1.234,56" | tr -d 'R$ .'
1234,56                            « -d: apagou R, $, espaço e ponto

(A primeira saída foi encurtada.) Cuidado com acentos: os intervalos a-z e A-Z só cobrem as letras sem acento, e o GNU tr trabalha byte a byte:

$ echo "maçã" | tr a-z A-Z
MAçã                               « ç e ã ficaram minúsculos

Para maiúsculas com acento, use o próprio Bash: ${texto^^} (veja Expansão de Parâmetros).

sed: trocar e apagar linhas

O sed (stream editor, "editor de fluxo") edita o texto enquanto ele passa, linha por linha, sem abrir um editor. O comando mais usado é o s, de substitute:

s
Substituir.
/,/
O que procurar (uma regex), entre barras.
;/
Pelo que trocar.
g
global: todas as ocorrências da linha. Sem o g, só a primeira.
$ sed 's/,/;/' alunos.csv | head -n 2
nome;idade,cidade,nota             « só a primeira vírgula de cada linha
Ana;29,Recife,9.5
$ sed 's/,/;/g' alunos.csv | head -n 2
nome;idade;cidade;nota             « com g: todas
Ana;29;Recife;9.5

Apagar e mostrar linhas

$ sed '1d' alunos.csv
Ana,29,Recife,9.5                  « 1d: apagou a linha 1 (o cabeçalho)
Bruno,34,Curitiba,7.0
Carla,22,Salvador,8.5
Diego,41,Manaus,6.0
Elisa,27,Porto Alegre,10.0
$ sed -n '2,3p' alunos.csv
Ana,29,Recife,9.5                  « -n + p: mostra só as linhas 2 a 3
Bruno,34,Curitiba,7.0
$ sed -n '/Bruno/p' alunos.csv
Bruno,34,Curitiba,7.0

Um endereço pode ser um número (1), um intervalo (2,3), $ (a última linha) ou uma regex entre barras (/^#/, linhas que começam com #). sed '/^#/d' config apaga os comentários de um arquivo de configuração.

Regex estendida: -E

$ sed -E 's/^([^,]*),([^,]*)/\2 anos: \1/' alunos.csv
idade anos: nome,cidade,nota
29 anos: Ana,Recife,9.5
…

(Saída encurtada.) Com -E, os parênteses capturam pedaços: \1 é o que casou no primeiro par (o nome), \2 no segundo (a idade). [^,]* quer dizer "qualquer coisa que não seja vírgula".

Editar o arquivo de verdade: -i

Até aqui o sed só mostrou o resultado; o arquivo ficou igual. O -i (in place) grava a mudança no próprio arquivo, sem perguntar e sem desfazer. Pratique numa cópia:

$ cp notas.txt notas-copia.txt
$ sed -i 's/café/chá/' notas-copia.txt
$ cat notas-copia.txt
Comprar chá
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ sed -i.bak 's/João/Maria/' notas-copia.txt
$ ls notas-copia*
notas-copia.txt
notas-copia.txt.bak                « -i.bak guardou o original
$ diff notas-copia.txt.bak notas-copia.txt
2c2
< Ligar para o João
---
> Ligar para o Maria
Cuidados com sed -i
  • Teste sempre sem -i primeiro, olhe a saída e só então acrescente o -i.
  • Prefira -i.bak: ele guarda uma cópia do original. Sem o .bak, o erro é para sempre.
  • No macOS (BSD sed), o -i exige um argumento: sed -i '' 's/a/b/' arq. A forma -i.bak funciona nos dois.
  • Nunca faça sed 's/a/b/' arq > arq: o > esvazia o arquivo antes de o sed ler (veja Redirecionamento).

awk: colunas e contas

O awk (iniciais dos criadores: Aho, Weinberger e Kernighan) é quase uma linguagem. Ele lê cada linha, separa em campos $1, $2… e executa um programa curto para cada uma. É a ferramenta certa quando você precisa de colunas e contas ao mesmo tempo.

awk 'padrão { ação }' arquivo
-F,
O separador de campos é a vírgula (field separator). Sem -F, o separador é "um ou mais espaços ou tabs", o que já resolve o acesso.log.
'…'
O programa awk, sempre entre aspas simples, senão o Bash trocaria o $1 pelo argumento do script.
NR > 1
O padrão: só as linhas em que o número da linha (number of record) é maior que 1, ou seja, pula o cabeçalho.
{ print $1, $4 }
A ação: mostrar os campos 1 e 4, separados por espaço (é o que a vírgula faz no print).
$ awk -F, 'NR > 1 { print $1, $4 }' alunos.csv
Ana 9.5
Bruno 7.0
Carla 8.5
Diego 6.0
Elisa 10.0
$ awk -F, '$3 == "Recife"' alunos.csv
Ana,29,Recife,9.5                  « só padrão, sem ação: mostra a linha
$ awk '{ print $NF }' acesso.log | sort | uniq -c
      4 200
      1 403
      1 404

NF é o número de campos da linha (number of fields), então $NF é o último campo: o código de resposta.

Somar e tirar a média das notas

Aqui o awk brilha: ele tem variáveis e faz contas com decimais (o Bash só faz com inteiros). Mas, na máquina da Ana, a primeira tentativa dá errado:

$ awk -F, 'NR > 1 { soma += $4; n++ } END { print "Média:", soma / n }' alunos.csv
Média: 8                           « errado! a média é 8,2

O que aconteceu: o awk da máquina da Ana (e do Debian e do Ubuntu) é o mawk, que segue o idioma do sistema. Em pt_BR, o separador decimal é a vírgula, então ele leu 9.5 como 9, 8.5 como 8… A soma deu 40 em vez de 41. A correção é a mesma do printf: números no formato "C" (com ponto).

$ LC_NUMERIC=C awk -F, 'NR > 1 { soma += $4; n++ } END { printf "Média: %.2f\n", soma / n }' alunos.csv
Média: 8.20
LC_NUMERIC=C
Só para este comando: números com ponto (veja printf e echo).
soma += $4
Para cada aluno, acrescenta a nota à variável soma. No awk, variáveis não precisam ser criadas: começam valendo 0.
n++
Conta quantos alunos foram somados.
END { … }
Um bloco que roda uma vez, depois da última linha. Existe também BEGIN { … }, que roda antes da primeira.
printf "Média: %.2f\n", soma / n
O printf do awk funciona como o do Bash, com os argumentos separados por vírgula.

Com o mesmo cuidado, o awk filtra por número e monta tabelas:

$ LC_NUMERIC=C awk -F, 'NR > 1 && $4 >= 8 { print $1 }' alunos.csv
Ana
Carla
Elisa
$ LC_NUMERIC=C awk -F, 'NR > 1 { printf "%-8s %5.1f\n", $1, $4 }' alunos.csv
Ana        9.5
Bruno      7.0
Carla      8.5
Diego      6.0
Elisa     10.0
mawk × gawk

Existem várias versões do awk. Debian e Ubuntu instalam o mawk; Fedora, Arch e openSUSE, o gawk (GNU awk); o macOS, o awk do BSD. Tudo o que esta aula mostra funciona em todos. Já funções como gensub(), asort() e a variável IGNORECASE são só do gawk:

$ awk 'BEGIN { print gensub(/a/, "A", "g", "banana") }'
awk: line 2: function gensub never defined

Use gsub() (que existe em todos) ou instale o gawk e chame gawk pelo nome. Outra diferença: o gawk, por padrão, sempre lê números com ponto, então o problema da média acima não acontece nele. Escreva LC_NUMERIC=C mesmo assim: o seu script vai funcionar nos dois.

tee e column

O tee é um "T" de encanamento: grava a entrada num arquivo e deixa ela seguir para a tela (ou para o próximo pipe). Útil para guardar um log do que o script mostra.

$ grep 404 acesso.log | tee erros-404.txt
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404   « na tela…
$ cat erros-404.txt
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404   « …e no arquivo
$ echo "nova linha" | tee -a erros-404.txt > /dev/null
$ wc -l erros-404.txt
2 erros-404.txt

tee -a acrescenta em vez de substituir (append). O > /dev/null no fim descarta a cópia da tela quando você só quer gravar.

O column -t alinha colunas automaticamente. Com -s, ele separa na vírgula:

$ column -t -s, alunos.csv
nome   idade  cidade        nota
Ana    29     Recife        9.5
Bruno  34     Curitiba      7.0
Carla  22     Salvador      8.5
Diego  41     Manaus        6.0
Elisa  27     Porto Alegre  10.0

É o jeito mais rápido de ver um CSV. Quando você precisa controlar a largura e o alinhamento de cada coluna, use o printf.

Tudo junto num script

Um relatório do acesso.log usando várias ferramentas, cada uma no que faz melhor:

#!/usr/bin/env bash
# Relatório rápido do acesso.log
export LC_NUMERIC=C
log=Documentos/acesso.log

if ! grep -q 'HTTP' "$log"; then
  echo "O arquivo $log não parece um log de acesso." >&2
  exit 1
fi

total=$(wc -l < "$log")
erros=$(grep -cE ' (403|404)$' "$log")
printf 'Acessos: %d (com erro: %d)\n' "$total" "$erros"

echo "Por IP:"
cut -d' ' -f1 "$log" | sort | uniq -c | sort -rn | awk '{ printf "  %-14s %s\n", $2, $1 }'

echo "Páginas com erro:"
awk '$NF >= 400 { print "  " $6 " (" $NF ")" }' "$log"

$ bash relatorio.sh
Acessos: 6 (com erro: 2)
Por IP:
  192.168.0.10   3
  192.168.0.23   2
  192.168.0.57   1
Páginas com erro:
  /admin (403)
  /fotos (404)
LinhasO que fazem
3Números no formato com ponto para todos os comandos do script.
6–9grep -q no if: confere o arquivo antes de começar. O ! inverte ("se não achou").
11–12Números guardados em variáveis com $( ): wc -l < e grep -c.
16O ranking de IPs; o awk no fim troca a ordem das colunas e alinha.
19O awk filtra pelo último campo ($NF >= 400) e mostra a página (campo 6).

Quando o próprio Bash basta

Cada ferramenta é um programa novo que o sistema precisa iniciar. Para uma variável, o Bash resolve sozinho com as expansões de parâmetro, mais rápido e sem problemas de acento. Dentro de um laço que roda mil vezes, a diferença é grande.

$ arquivo="relatorio.odt"
$ echo "${arquivo%.odt}.pdf"
relatorio.pdf                      « em vez de: echo "$arquivo" | sed 's/\.odt$/.pdf/'
$ linha="Ana,29,Recife,9.5"
$ echo "${linha%%,*}"
Ana                                « em vez de: echo "$linha" | cut -d, -f1

Quando não funciona

O grep com | não acha nada 
$ grep 'Ana|Bruno' alunos.csv; echo $?
1

O que aconteceu: sem -E, o | é um caractere comum; o grep procurou o texto "Ana|Bruno".

Como resolver: grep -E 'Ana|Bruno' alunos.csv.

A média ou a soma do awk deu um número "redondo" e errado

O que aconteceu: o mawk, em português, leu 9.5 como 9 (veja a seção da média). Um filtro como $4 >= 8 também falha: sem LC_NUMERIC=C, a Elisa (10.0) não aparece, porque o valor deixa de parecer número e é comparado como texto ("10.0" vem antes de "8" no dicionário).

Como resolver: LC_NUMERIC=C awk …, ou export LC_NUMERIC=C no começo do script.

awk imprimiu linhas vazias 
$ awk -F, '{ print $5 }' alunos.csv | head -n 2

O que aconteceu: não existe campo 5. Confira quantos campos há com awk -F, '{ print NF }' arquivo. Outra causa comum: esquecer o -F,, e aí a linha inteira é o campo 1.

O cut devolveu a linha inteira 
$ cut -f1 alunos.csv | head -n 2
nome,idade,cidade,nota
Ana,29,Recife,9.5

O que aconteceu: sem -d, o cut procura tabs. Linhas sem o separador saem inteiras.

Como resolver: cut -d, -f1 alunos.csv.

"sed: não foi possível ler …" 
$ sed -i 's/x/y/' nada.txt
sed: não foi possível ler nada.txt: Arquivo ou diretório inexistente

O que aconteceu: o arquivo não existe na pasta atual. Confira com pwd e ls. Num script, use caminhos a partir de uma variável e teste antes: [[ -f $arq ]] || exit 1.

O $1 do awk virou outra coisa

O que aconteceu: o programa estava entre aspas duplas (awk "{ print $1 }"). O Bash trocou $1 pelo primeiro argumento do script (ou por nada) antes de o awk rodar.

Como resolver: programas awk sempre entre aspas simples. Para passar um valor do Bash, use -v: awk -v min="$minimo" '$4 >= min'.

Resumo

  • grep procura; no script, use -q no if e -c para contar. Código 0 = achou, 1 = não achou, 2 = erro.
  • cut recorta campos com um separador; sort | uniq -c | sort -rn faz rankings; wc -l < arq dá só o número.
  • sed 's/a/b/g' troca, sed '1d' apaga; teste sem -i e prefira -i.bak.
  • awk -F, lida com colunas e contas; em pt_BR, use LC_NUMERIC=C para números com ponto. Evite recursos só do gawk.
  • tee grava e mostra, column -t alinha. Para uma variável só, prefira as expansões do próprio Bash.
