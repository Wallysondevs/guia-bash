Bash Variáveis: o Básico

Uma variável é um nome que guarda um valor. Você guarda uma vez (nome=Ana) e usa quantas vezes quiser ($nome). Variáveis estão em todo lugar no Bash: a sua pasta pessoal, o seu usuário e a lista de pastas onde os comandos moram já estão guardados em variáveis, antes mesmo de você digitar qualquer coisa.

Você vai aprender
  • Criar uma variável com nome=valor e por que não pode haver espaços em volta do =.
  • Usar o valor com $nome e ${nome}, e quando as chaves são obrigatórias.
  • As variáveis prontas: HOME USER PWD SHELL PATH LANG RANDOM.
  • O que acontece com uma variável que não existe, e como apagar uma com unset.
  • Como ver todas as variáveis com set e env.

A ideia: uma etiqueta numa caixa

Pense numa caixa com uma etiqueta. A etiqueta é o nome (cidade); o que está dentro é o valor (Recife). Quando você quer o conteúdo, não precisa lembrar o que pôs lá: basta pedir pela etiqueta.

No terminal isso economiza digitação e evita erros. No script, é o que permite o mesmo código funcionar para pessoas, arquivos e pastas diferentes: muda o valor, o resto fica igual.

Criar uma variável: nome=valor

Para criar (os programadores dizem atribuir), escreva o nome, o sinal de igual e o valor, tudo colado:

nome
O nome da variável. Você escolhe.
=
"Guarde em…". Sem espaço antes nem depois.
Ana
O valor guardado. Para o Bash, é sempre texto.
$ nome=Ana
$ echo $?
0                       « deu certo, mesmo sem mostrar nada

A atribuição é silenciosa: não aparece nada na tela. O código de saída 0 confirma que deu certo (veja Código de Saída).

Regras para o nome

  • Pode ter letras sem acento (a-z, A-Z), números e o sublinhado _.
  • Não pode começar com número.
  • Não pode ter hífen, ponto, espaço nem acento.
  • Maiúsculas e minúsculas são diferentes: nome, Nome e NOME são três variáveis.

Quando o nome é inválido, o Bash não entende a linha como atribuição. Ele acha que é o nome de um comando, procura, não acha e reclama:

$ meu_nome=Ana
$ echo $meu_nome
Ana
$ 1nome=x
bash: 1nome=x: comando não encontrado
$ nome-completo=x
bash: nome-completo=x: comando não encontrado

Mudar o valor

Atribuir de novo troca o valor. O antigo é perdido:

$ total=10
$ total=20
$ echo $total
20

Valores com espaço: use aspas

O espaço separa as partes de um comando. Para guardar um valor com espaço, coloque-o entre aspas:

$ nome="Ana Souza"
$ echo "$nome"
Ana Souza

Sem aspas, nome=Ana Souza dá erro. Você vai ver por quê na seção Quando não funciona.

Usar o valor: $nome

Para usar o valor, escreva um cifrão $ antes do nome. O Bash troca $nome pelo valor antes de rodar o comando. Isso se chama expansão de parâmetro: é a mesma ideia das chaves e dos curingas. O comando nunca vê o $nome; ele recebe o texto já trocado.

$ nome=Ana
$ echo $nome
Ana
$ echo "Olá, $nome!"
Olá, Ana!
você digita:     echo "Olá, $nome!"
o Bash troca:    echo "Olá, Ana!"
o echo recebe:   Olá, Ana!

Variáveis podem aparecer em qualquer parte do comando, e em qualquer comando, não só no echo:

$ pasta=Documentos
$ ls "$pasta"
acesso.log
alunos.csv
notas.txt
projetos
relatorio.odt
$ echo "Caminho: $HOME/Documentos"
Caminho: /home/ana/Documentos

Aspas duplas × aspas simples

Dentro de aspas duplas, o $ continua funcionando. Dentro de aspas simples, tudo é literal, e o $nome sai como está:

$ nome="Ana Souza"
$ echo "Arquivo de $nome"
Arquivo de Ana Souza          « duplas: o Bash trocou
$ echo '$nome'
$nome                         « simples: o Bash não mexeu

A aula Aspas e Escapes mostra em detalhe o que cada tipo de aspas protege.

Por que "$nome" com aspas, sempre

Sem aspas, depois de trocar a variável o Bash ainda separa o valor em palavras nos espaços (e procura curingas nele). Com aspas, o valor chega inteiro ao comando. Veja a diferença com o nome da pasta Área de trabalho:

$ arq="Área de trabalho"
$ ls $arq
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente
$ ls "$arq"
$ echo $?
0                             « a pasta existe e está vazia

Sem aspas, o ls recebeu três nomes. Com aspas, recebeu um só, o certo. Os espaços extras também somem sem aspas:

$ frase="  muitos    espaços   aqui  "
$ echo $frase
muitos espaços aqui
$ echo "$frase"
  muitos    espaços   aqui
Regra prática

Escreva "$variavel", com aspas duplas, sempre que for usar uma variável. Você só tira as aspas quando quer, de propósito, que o valor seja quebrado em palavras, e isso é raro.

Missão: crie a variável cidade com o valor Porto Alegre (cuidado com o espaço!). Depois use-a num echo para mostrar Moro em Porto Alegre.

Chaves no nome: ${nome}

$nome e ${nome} são a mesma coisa. As chaves só marcam onde o nome termina. Elas são obrigatórias quando, logo depois do nome, vem uma letra, um número ou um _, porque esses caracteres poderiam fazer parte do nome.

$ fruta=maçã
$ echo "Duas $frutas"
Duas                          « o Bash procurou a variável "frutas", que não existe
$ echo "Duas ${fruta}s"
Duas maçãs                    « as chaves dizem: o nome é só "fruta"
$
"Troque pelo valor de…"
{fruta}
…a variável fruta. As chaves fecham o nome aqui.
s
Texto comum, colado logo depois do valor.

O sublinhado engana muita gente, porque ele pode fazer parte de nomes. Já o hífen e o ponto não podem, então ali o nome termina sozinho:

$ arquivo=relatorio
$ echo "$arquivo_2026.txt"
.txt                          « procurou "arquivo_2026": vazia
$ echo "${arquivo}_2026.txt"
relatorio_2026.txt
$ echo "$arquivo-2026.txt"
relatorio-2026.txt            « o hífen não entra em nomes: funcionou sem chaves

As chaves também abrem a porta para muitos truques, como ${#nome} (quantas letras tem o valor) e ${nome:-padrão}. Eles estão em Expansão de Parâmetros.

$ echo "$nome tem ${#nome} letras"
Ana Souza tem 9 letras        « o espaço também conta

Missão: a variável arquivo já existe e vale relatorio. Mostre na tela relatorio_2026.txt usando a variável. Primeiro tente echo "$arquivo_2026.txt" e veja o que sai; depois corrija com chaves.

Variável que não existe = vazia

Usar uma variável que nunca foi criada não dá erro. O Bash troca por nada, e o comando segue em frente. Os colchetes abaixo são só para você enxergar o vazio:

$ echo "[$cidade]"
[]
$ echo $?
0                             « nenhum aviso, nenhum erro
$ cidade=Recife
$ echo "[$cidade]"
[Recife]

Isso é cômodo, mas perigoso: um erro de digitação no nome ($cidde) vira texto vazio sem nenhum aviso. Em scripts, a opção set -u transforma isso em erro; ela aparece em Apagar com Segurança e em set -euo pipefail.

Apagar uma variável: unset

unset (de "des-definir") remove a variável. Depois disso ela volta a ser vazia:

unset
Comando interno do Bash que apaga variáveis.
cidade
O nome da variável, sem $. Com $, o Bash trocaria pelo valor e o unset tentaria apagar uma variável chamada Recife.
$ unset cidade
$ echo "[$cidade]"
[]

Existe ou está vazia? declare -p

Como as duas situações aparecem iguais no echo, use declare -p (de print) para ver a variável de verdade. Ele mostra a definição, ou reclama se ela não existe:

$ nome=Ana
$ declare -p nome
declare -- nome="Ana"
$ unset nome
$ declare -p nome
bash: declare: nome: não encontrado
$ echo $?
1

Variáveis que já vêm prontas

Quando o Bash começa, várias variáveis já estão criadas, pelo sistema ou pelo próprio Bash. Por convenção, elas têm nomes em MAIÚSCULAS:

$ echo $HOME
/home/ana
$ echo $USER
ana
$ echo $PWD
/home/ana
$ cd Documentos
$ echo $PWD
/home/ana/Documentos          « o Bash atualiza o PWD a cada cd
$ cd
$ echo $SHELL
/bin/bash
$ echo $LANG
pt_BR.UTF-8
$ echo $RANDOM
32099
$ echo $RANDOM
10174                         « um número novo a cada uso

O RANDOM devolve um número sorteado entre 0 e 32767; no seu terminal os números serão outros.

VariávelO que guardaNa máquina da Ana
HOMESua pasta pessoal. É para onde cd sem nada e o ~ levam./home/ana
USERSeu nome de usuário.ana
PWDA pasta atual (print working directory). Veja Navegar.muda a cada cd
SHELLO shell padrão da conta (não necessariamente o que está rodando agora)./bin/bash
PATHA lista de pastas onde o Bash procura os comandos, separadas por :./usr/local/sbin:…:/bin
LANGIdioma e codificação. É por ele que as mensagens saem em português.pt_BR.UTF-8
RANDOMUm número aleatório de 0 a 32767, novo a cada leitura.muda sempre

O PATH merece uma olhada:

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Quando você digita ls, o Bash procura um arquivo chamado ls em cada uma dessas pastas, da esquerda para a direita. No seu computador o PATH provavelmente é mais longo. A aula PATH e Onde os Comandos Moram explica tudo; outras variáveis especiais estão em Variáveis Especiais.

Juntando as prontas com as suas:

$ echo "Você é $USER e está em $PWD"
Você é ana e está em /home/ana

Maiúsculas × minúsculas: a convenção

O Bash diferencia maiúsculas de minúsculas, então estas são três variáveis independentes:

$ nome=ana
$ NOME=Carla
$ echo "$nome $NOME"
ana Carla
$ echo "[$Nome]"
[]                            « Nome nunca foi criada

A convenção é:

  • MAIÚSCULAS para as variáveis do sistema e do Bash (HOME, PATH, USER…) e para as que você exporta para outros programas.
  • minúsculas para as suas, no terminal e nos scripts (nome, total, pasta_destino).

Seguir isso evita sobrescrever sem querer uma variável importante. Veja o que acontece se a Ana resolve chamar a pasta dos scripts dela de PATH:

$ PATH=/home/ana/scripts
$ ls
bash: ls: comando não encontrado
$ echo $?
127

Ela trocou a lista de pastas onde os comandos moram. Agora o Bash não acha mais o ls. A mudança vale só para este terminal: feche-o e abra outro, e tudo volta ao normal. Com o nome pasta, minúsculo, nada disso aconteceria.

Ver todas as variáveis: set e env

Há duas listas, e elas são diferentes:

set
Sem argumentos, mostra todas as variáveis do shell atual, inclusive as que você criou (e também as funções). Vem em ordem alfabética.
env
Mostra só as variáveis de ambiente, as que serão passadas para os programas que você rodar.

As listas são longas, então usamos head para ver o começo e grep para procurar uma (veja Pipes):

$ nome=Ana
$ set | head -n 3
BASH=/usr/bin/bash
BASHOPTS=checkwinsize:cmdhist:complete_fullquote:expand_aliases:extquote:force_fignore:globasciiranges:globskipdots:histappend:hostcomplete:interactive_comments:patsub_replacement:progcomp:promptvars:sourcepath
BASH_ALIASES=()
$ set | grep '^nome='
nome=Ana                      « a sua variável está no set…
$ env | head -n 5
SHELL=/bin/bash
LANGUAGE=pt_BR:pt:en
EDITOR=nano
PWD=/home/ana
LOGNAME=ana
$ env | grep '^nome='
$ echo $?
1                             « …mas não está no env (o grep não achou)

Por que a sua nome não aparece no env? Porque uma variável criada com nome=Ana existe só dentro deste shell. Um programa chamado a partir dele, mesmo outro Bash, não a recebe:

$ bash -c 'echo "[$nome]"'
[]

Para passar uma variável adiante existe o export, assunto de Variáveis, Escopo e export. Para ver uma variável só, printenv HOME (do ambiente) ou declare -p nome (qualquer uma) são mais diretos.

Missão: o script deveria mostrar Olá, Ana! Você tem 29 anos., mas mostra uma mensagem de erro e Olá, !. Corrija a linha 2 e clique em Rodar.

#!/usr/bin/env bash

#!/usr/bin/env bash
nome=Ana
idade=29
echo "Olá, $nome! Você tem $idade anos."

Rodando o script com o erro, a saída é esta. Repare que, em script, o Bash acrescenta o nome do arquivo e a linha:

$ bash saudacao.sh
saudacao.sh: linha 2: nome: comando não encontrado
Olá, ! Você tem 29 anos.
$ echo $?
0                             « o script seguiu em frente e terminou "bem"

Quando não funciona

"nome: comando não encontrado" 
$ nome = Ana
bash: nome: comando não encontrado
$ echo $?
127

O que aconteceu: com espaços, a linha virou três palavras: nome, = e Ana. A primeira palavra de um comando é o nome do programa, então o Bash procurou um programa chamado nome, passando = e Ana como argumentos. O código 127 significa "comando não encontrado".

Como resolver: tudo colado: nome=Ana. Em outras linguagens os espaços são permitidos; no Bash, não.

"Ana: comando não encontrado" 
$ nome= Ana
bash: Ana: comando não encontrado
$ echo "[$nome]"
[]

O que aconteceu: com espaço só depois do =, o Bash entende nome= (valor vazio) e depois o comando Ana. Uma atribuição colada antes de um comando vale só para aquele comando, por isso nome nem ficou criada.

Como resolver: nome=Ana.

"Souza: comando não encontrado" 
$ nome=Ana Souza
bash: Souza: comando não encontrado

O que aconteceu: o espaço separou o valor. O Bash entendeu "rode o comando Souza com nome valendo Ana". Como no caso anterior, a variável não foi guardada (se ela já existia, continua com o valor antigo).

Como resolver: aspas em volta do valor: nome="Ana Souza".

"Ana=Bruno: comando não encontrado" 
$ nome=Ana
$ $nome=Bruno
bash: Ana=Bruno: comando não encontrado

O que aconteceu: o $ serve para ler a variável. Aqui o Bash trocou $nome por Ana e a linha virou Ana=Bruno, que não é uma atribuição feita por você: é texto gerado, e o Bash tenta rodá-lo como comando.

Como resolver: para guardar, escreva o nome sem $: nome=Bruno. Regra: sem $ para guardar, com $ para usar.

Não apareceu nada (ou só um pedaço) 
$ echo "Duas $frutas"
Duas
$ echo "$arquivo_2026.txt"
.txt

O que aconteceu: o Bash procurou variáveis que não existem (frutas e arquivo_2026) e, como sempre, trocou por vazio sem avisar. Pode ser erro de digitação ou letras grudadas no nome.

Como confirmar: declare -p frutas responde "não encontrado".

Como resolver: confira a grafia (maiúsculas contam!) e use chaves para separar o nome do texto seguinte: "${fruta}s", "${arquivo}_2026.txt".

O valor com espaços virou vários argumentos 
$ arq="Área de trabalho"
$ ls $arq
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente

O que aconteceu: sem aspas, o valor foi quebrado nos espaços depois da troca.

Como resolver: ls "$arq". Sempre "$variavel".

Apareceu um > e o terminal "travou" 
$ echo "Nome:
>

O que aconteceu: faltou fechar as aspas. O > é o prompt de continuação do Bash: ele está esperando o resto do texto.

Como resolver: digite a aspa que falta e Enter, ou cancele com Ctrl+C e digite de novo. Mais detalhes em Aspas e Escapes.

"ls: comando não encontrado" depois de criar uma variável 
$ PATH=/home/ana/scripts
$ ls
bash: ls: comando não encontrado

O que aconteceu: você sobrescreveu uma variável do sistema, o PATH.

Como resolver: feche este terminal e abra outro. Use nomes minúsculos para as suas variáveis.

Resumo

  • Crie com nome=valor, tudo colado; valores com espaço vão entre aspas.
  • Sem $ para guardar, com $ para usar. O Bash troca $nome pelo valor antes de rodar o comando.
  • Use "$nome" com aspas duplas; aspas simples deixam $nome literal.
  • ${nome} marca onde o nome termina: "${fruta}s", "${arquivo}_2026".
  • Variável que não existe vira vazio, sem erro. unset apaga; declare -p confere.
  • Prontas: HOME USER PWD SHELL PATH LANG RANDOM. Suas variáveis em minúsculas, para não estragar as do sistema.
  • set lista todas; env, só as de ambiente. Para passar adiante, export.
