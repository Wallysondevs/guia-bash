Bash read

Argumentos são passados antes de o script começar. Às vezes, porém, o script precisa perguntar no meio do caminho: o nome do usuário, uma senha, "tem certeza?". O comando read ("ler") para o script, espera você digitar uma linha e guarda o que foi digitado numa variável.

Você vai aprender
  • Como fazer uma pergunta e guardar a resposta: read -p "Pergunta: " variavel.
  • Por que usar sempre o -r, e quando usar IFS=.
  • As opções do dia a dia: -s (senha), -n 1 (uma tecla), -t (tempo limite), -a (lista).
  • Como ler de um arquivo, e por que echo "x" | read v deixa v vazia.
  • Como fazer a confirmação "Tem certeza? [s/N]".

A forma mais simples

read
Comando interno do Bash: espera uma linha da entrada (o teclado, normalmente).
nome
A variável onde a linha vai ser guardada. Sem $: aqui você está dando o nome da variável, não usando o valor dela.
$ read nome
Ana                              « você digita e aperta Enter
$ echo "Olá, $nome"
Olá, Ana

Depois do read nome, o cursor fica parado numa linha vazia, sem prompt. O Bash está esperando. Você digita Ana, aperta Enter, e o texto (sem o Enter) vai para a variável nome.

Fazendo a pergunta: -p

Um cursor piscando sem explicação confunde quem usa o script. A opção -p (prompt) mostra um texto antes de esperar. Termine o texto com um espaço, para a resposta não grudar na pergunta.

read
O comando.
-p "Qual é a sua cidade? "
A pergunta, mostrada na mesma linha da resposta.
cidade
A variável que recebe a resposta.
$ read -p "Qual é a sua cidade? " cidade
Qual é a sua cidade? Recife
$ echo "Você mora em $cidade"
Você mora em Recife

Num script, perguntas em sequência ficam assim:

#!/usr/bin/env bash
read -rp "Nome: " nome
read -rp "Idade: " idade
echo "Cadastro: $nome, $idade anos."

$ ./cadastro.sh
Nome: Ana Souza
Idade: 29
Cadastro: Ana Souza, 29 anos.

O -rp é -r e -p juntos (o p tem que ser o último, porque o texto vem logo depois dele). O -r é o assunto da próxima seção.

Missão: o script só pergunta o nome. Acrescente uma pergunta Idade: guardando a resposta em idade, e faça a última linha mostrar Cadastro: Carla, 22 anos. (as respostas Carla e 22 já estão no campo de entrada).

#!/usr/bin/env bash
read -rp "Nome: " nome
echo "Cadastro: $nome."

#!/usr/bin/env bash
read -rp "Nome: " nome
read -rp "Idade: " idade
echo "Cadastro: $nome, $idade anos."

Use sempre -r

Sem o -r, o read trata a barra invertida \ como um caractere especial (de "escape") e a remove. Isso estraga caminhos do Windows, expressões regulares e qualquer texto com \:

$ cat caminho.txt
C:\Users\ana\novo
$ read linha < caminho.txt
$ echo "$linha"
C:Usersananovo                   « as barras sumiram
$ read -r linha < caminho.txt
$ echo "$linha"
C:\Users\ana\novo                « com -r, o texto chega intacto

O -r vem de raw, "cru": a linha chega exatamente como foi digitada. Não há quase nenhum caso em que você queira o comportamento sem -r; por isso, a regra é simples: escreva sempre read -r. O ShellCheck avisa quando falta (SC2162). Nos exemplos de terminal acima, com nomes simples, tanto faz; em scripts, nunca esqueça.

(O < caminho.txt faz o read ler a primeira linha do arquivo em vez do teclado. Mais sobre isso adiante.)

Vários nomes: read a b resto

Com mais de uma variável, o read divide a linha em palavras (nos espaços) e distribui: uma palavra para cada nome, e tudo o que sobrar vai para o último.

$ read a b resto
um dois três quatro cinco
$ echo "a=[$a] b=[$b] resto=[$resto]"
a=[um] b=[dois] resto=[três quatro cinco]

Os colchetes só servem para você ver onde cada valor começa e termina. Se vierem menos palavras que nomes, as variáveis que sobrarem ficam vazias.

Mudando o separador: IFS=,

Quem decide onde dividir é a variável IFS (Internal Field Separator, "separador interno de campos"), que normalmente vale espaço, tab e quebra de linha. Escrita na frente do comando, ela muda só para aquele read. Assim dá para ler uma linha do alunos.csv, que separa os campos com vírgula:

$ sed -n 2p Documentos/alunos.csv
Ana,29,Recife,9.5
$ IFS=, read -r nome idade cidade nota < <(sed -n 2p Documentos/alunos.csv)
$ echo "$nome tem $idade anos e mora em $cidade"
Ana tem 29 anos e mora em Recife
IFS=,
Para este comando, o separador é a vírgula.
read -r
Lê uma linha, sem mexer nas barras.
nome idade cidade nota
Quatro variáveis, uma por campo.
< <(sed -n 2p …)
A entrada vem da saída do sed, que mostra só a linha 2 (substituição de processo; por que não um pipe, você vê mais abaixo).

Preservar os espaços: IFS= read -r

Com uma variável só, o read ainda apara os espaços do começo e do fim da linha. Na maioria das vezes isso ajuda (a pessoa digitou um espaço sem querer). Quando você quer a linha exatamente como é, esvazie o IFS:

$ printf '   Estudar Bash   \n' > recuo.txt
$ read -r linha < recuo.txt
$ echo "[$linha]"
[Estudar Bash]                   « espaços das pontas removidos
$ IFS= read -r linha < recuo.txt
$ echo "[$linha]"
[   Estudar Bash   ]             « linha intacta

IFS= read -r linha é a forma "linha intacta" que você vai usar para ler arquivos linha a linha, em Ler Arquivos Linha a Linha (com while).

Sem nome nenhum: REPLY

Se você não der nome de variável, o read guarda a linha em REPLY ("resposta"), sem aparar os espaços:

$ read
texto livre
$ echo "REPLY=$REPLY"
REPLY=texto livre

Prefira sempre dar um nome: o script fica mais fácil de ler.

Opções do dia a dia

Senha: -s

-s (silent, "silencioso") não mostra o que é digitado. Repare num detalhe: como o Enter também não aparece, o próximo texto gruda na pergunta.

$ read -sp "Senha: " senha
Senha: ana@notebook:~$ echo                    « o prompt grudou: o Enter não foi mostrado
                                 « o echo vazio só pula uma linha
$ echo "A senha tem ${#senha} letras"
A senha tem 10 letras

Por isso, em scripts, coloque um echo logo depois: read -rsp "Senha: " senha; echo. (${#senha} é o tamanho do texto, de Expansão de Parâmetros.)

Senha em variável não é cofre

O -s só evita que alguém veja por cima do seu ombro. A senha fica em texto puro na memória do script. Nunca a mostre com echo, nem a passe como argumento para outro programa (argumentos aparecem para qualquer usuário no ps).

Uma tecla só: -n 1

-n 1 ("n caracteres") volta assim que uma tecla é apertada, sem esperar o Enter. Ótimo para "aperte uma tecla" e menus. Aqui também o prompt gruda, porque não houve Enter:

$ read -n 1 -p "Continuar? [s/n] " resp
Continuar? [s/n] sana@notebook:~$ echo "resp=$resp"      « o "s" e o próximo prompt ficaram na mesma linha
resp=s

Em scripts: read -rn 1 -p "Continuar? [s/n] " resp; echo.

Tempo limite: -t

-t 3 (timeout) espera no máximo 3 segundos. Se ninguém responder, o read desiste e devolve um código de saída maior que 128 (142 no Linux). Junto com || (que roda o segundo comando se o primeiro falhar), vira um valor padrão:

$ read -t 3 -p "Seu nome (3 s): " nome || nome=anônimo
Seu nome (3 s): ana@notebook:~$ echo "Olá, $nome"           « ninguém respondeu em 3 segundos
Olá, anônimo
$ read -t 3 -p "Rápido: " x
Rápido: ana@notebook:~$ echo $?
142                                         « 142 = tempo esgotado

Se a pessoa responder a tempo, o código é 0. O operador || é explicado em ; && ||, e os códigos em Código de Saída.

Uma lista: -a

-a (array) guarda cada palavra numa posição de uma lista, começando do 0:

$ read -ra frutas <<< "banana maçã uva"
$ echo "${frutas[1]}"
maçã                             « a posição 0 é banana, a 1 é maçã
$ echo "${#frutas[@]} frutas"
3 frutas

O <<< (here-string) entrega o texto como se fosse digitado; veja Here-docs e Here-strings. Arrays têm aula própria em Arrays.

É esse código que permite usar o read como condição de um while, para ler um arquivo inteiro: assunto de Ler Arquivos Linha a Linha.

Ler de um arquivo ou de outro comando

O read lê da entrada padrão. Com <, a entrada passa a ser um arquivo, e o read pega a primeira linha:

$ read -r < Documentos/notas.txt
$ echo "$REPLY"
Comprar café

A pegadinha: echo "Bruno" | read quem

O natural seria mandar o texto por um pipe. Parece funcionar, mas a variável fica vazia:

$ echo "Bruno" | read quem
$ echo "quem=[$quem]"
quem=[]                          « vazia!

Por quê? Cada lado de um pipe roda num subshell, uma cópia separada do shell. O read rodou na cópia, guardou Bruno na variável da cópia, e a cópia terminou levando a variável junto. É a mesma história do cd dentro de um script, em Formas de Executar. Os detalhes estão em Subshells e Grupos.

Três formas de resolver:

$ read -r quem <<< "Bruno"
$ echo "quem=[$quem]"
quem=[Bruno]                                   « here-string: sem pipe, sem subshell
$ head -n 1 Documentos/alunos.csv | { read -r cab; echo "Dentro: $cab"; }
Dentro: nome,idade,cidade,nota                « usar a variável dentro do mesmo grupo { }
FormaExemploQuando usar
Here-string <<<read -r v <<< "$texto"O texto já está numa variável ou é curto.
Substituição de processo < <( )read -r v < <(comando)O texto vem de um comando, e você quer a variável depois.
Grupo { } no fim do pipecomando | { read -r v; echo "$v"; }Você só precisa da variável ali dentro.

Missão: rode echo "Bruno" | read quem e confira que echo "$quem" não mostra nada. Depois use o read de um jeito que deixe quem valendo Bruno no seu shell.

Confirmação: "Tem certeza? [s/N]"

Antes de algo que não tem volta (apagar, sobrescrever), um bom script pergunta. A convenção [s/N] diz duas coisas: as respostas possíveis são "s" e "n", e a letra maiúscula é o padrão, o que acontece se a pessoa só apertar Enter. Para ações perigosas, o padrão é sempre "não".

#!/usr/bin/env bash
# apagar.sh — pede confirmação antes de apagar
arquivo=${1:?informe o arquivo}
read -rp "Apagar \"$arquivo\"? Tem certeza? [s/N] " resp
case $resp in
  [sS] | [sS][iI][mM])
    rm -- "$arquivo" && echo "Apagado."
    ;;
  *)
    echo "Nada foi apagado."
    ;;
esac

Missão: o script só aceita s como confirmação. A resposta no campo de entrada é sim, e ele diz "Cancelado". Mude o case para aceitar também S, sim e Sim.

#!/usr/bin/env bash
read -rp "Continuar? [s/N] " resp
case $resp in
  s) echo "Confirmado." ;;
  *) echo "Cancelado." ;;
esac

#!/usr/bin/env bash

  [sS] | [sS][iI][mM]) echo "Confirmado." ;;
  *) echo "Cancelado." ;;
esac

Quando não funciona

A variável ficou vazia depois de … | read v 
$ echo "Bruno" | read quem
$ echo "quem=[$quem]"
quem=[]

O que aconteceu: o read rodou num subshell, do outro lado do pipe.

Como resolver: read -r quem <<< "Bruno" ou read -r quem < <(comando).

As barras invertidas sumiram 
$ read linha < caminho.txt
$ echo "$linha"
C:Usersananovo

Como resolver: faltou o -r. Use read -r.

O prompt grudou na pergunta 
$ read -sp "Senha: " senha
Senha: ana@notebook:~$

O que aconteceu: com -s, -n ou quando o tempo do -t acaba, nenhuma quebra de linha é mostrada.

Como resolver: coloque um echo logo depois do read.

O script "travou" e não mostrou nada

O que aconteceu: provavelmente ele está parado num read sem -p, esperando você digitar. Ou a pergunta existe, mas a entrada do script vem de um pipe ou arquivo: nesse caso o read não mostra o texto do -p (ele só aparece quando a entrada é um terminal):

$ printf "Bruno\n34\n" | ./cadastro.sh
Cadastro: Bruno, 34 anos.        « as perguntas "Nome:" e "Idade:" não apareceram

Como resolver: digite a resposta e aperte Enter, ou Ctrl+C para cancelar. No script, use sempre -p com uma pergunta clara.

"Arquivo ou diretório inexistente" no read … < arquivo 
$ read -r < notas.txt
bash: notas.txt: Arquivo ou diretório inexistente

O que aconteceu: o arquivo não está na pasta atual (o notas.txt da Ana fica em Documentos). Quem reclama é o shell, ao abrir o arquivo, antes do read rodar.

Como resolver: use o caminho certo: read -r < Documentos/notas.txt.

Resumo

  • read -rp "Pergunta: " var pergunta e guarda a resposta. Use sempre o -r.
  • Com vários nomes, cada um recebe uma palavra e o último leva o resto; IFS=, muda o separador; IFS= read -r preserva a linha intacta.
  • -s para senha, -n 1 para uma tecla, -t para tempo limite (código > 128), -a para array. Depois de -s e -n, um echo.
  • read v < arquivo lê a primeira linha; … | read v perde a variável (subshell): use <<< ou < <( ).
  • Confirmação: read -rp "… [s/N] " r + case, com "não" como padrão.
