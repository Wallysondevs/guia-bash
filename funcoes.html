Bash Funções

Uma função é um pedaço de script com nome. Você escreve os comandos uma vez, dá um nome a eles e, daí em diante, usa esse nome como se fosse um comando novo. Funções evitam repetição, deixam o script legível e são a base de qualquer script com mais de uma página.

Você vai aprender
  • As duas formas de criar uma função e como chamá-la.
  • Como passar argumentos para a função ($1, $#, $@) e por que eles não são os do script.
  • Por que a função precisa ser definida antes de ser usada.
  • Como ver, listar e apagar funções (type, declare -f, unset -f) e guardar as suas no .bashrc.
  • Como organizar um script com main "$@" e reaproveitar funções com source.

Por que funções?

Imagine uma receita de bolo que, em três lugares diferentes, diz "bata 3 ovos com 2 xícaras de açúcar por 5 minutos até ficar fofo". Seria mais fácil escrever uma vez, no topo, "massa básica: bata 3 ovos…", e depois só dizer "faça a massa básica". Se você mudar a quantidade de açúcar, muda num lugar só.

Uma função é isso: um nome para um conjunto de passos. Ela traz três vantagens:

  • Não repetir: o mesmo trecho usado 5 vezes vira 1 definição e 5 chamadas.
  • Ler melhor: faz_backup diz mais do que 12 linhas de cp e tar.
  • Consertar num lugar só: um erro corrigido na função vale para todas as chamadas.

Criar e chamar uma função

A forma mais comum (e a que funciona em qualquer shell POSIX) é o nome seguido de () e de um bloco entre chaves:

nome() {
  comandos
}
ola
O nome da função. Use letras, números e _; não comece com número. Evite nomes de comandos que já existem (ls, test…).
()
Os parênteses dizem "isto é uma definição de função". Eles ficam sempre vazios: no Bash, os argumentos não são declarados aqui.
{
Abre o corpo. Precisa de um espaço (ou quebra de linha) depois dele.
echo "…"
Os comandos da função. Pode ser quantos você quiser.
}
Fecha o corpo. Precisa estar numa linha nova, ou depois de um ;.
$ ola() {
>   echo "Olá! Hoje é dia de estudar Bash."
> }
$ ola
Olá! Hoje é dia de estudar Bash.
$ ola
Olá! Hoje é dia de estudar Bash.

O que aconteceu:

  • Ao definir a função (as três primeiras linhas), nada aparece. O Bash só guardou a receita na memória. Os > são o prompt de continuação: o Bash espera o }.
  • Para chamar, digite só o nome, como qualquer comando. Sem parênteses.
  • Cada chamada roda o corpo de novo.
$ ola
Olá! Hoje é dia de estudar Bash.
$ echo $?
0                « o código de saída da função é o do último comando dela (o echo deu certo)

A outra forma: a palavra function

O Bash também aceita a palavra-chave function antes do nome. Aí os parênteses são opcionais:

$ function tchau {
>   echo "Até mais!"
> }
$ tchau
Até mais!
$ function oi() { echo "oi, $1"; }
$ oi Ana
oi, Ana                « a mistura function + () também funciona

Repare na última definição, numa linha só: { echo "oi, $1"; }. O ; antes do } é obrigatório quando tudo fica na mesma linha.

FormaFunciona emQual usar?
nome() { … }Bash, zsh, dash, sh do macOS, qualquer shell POSIXPrefira esta. É a mais comum e a mais portável.
function nome { … }Bash, zsh, ksh (não no sh/dash)Válida, aparece em muitos scripts. Não traz vantagem no Bash.
function nome() { … }Bash e zshMistura das duas; evite (não é POSIX nem ksh).

Passar argumentos para a função

Você passa argumentos para uma função do mesmo jeito que para um comando: separados por espaço, depois do nome. Lá dentro, eles chegam como $1, $2…, exatamente como os argumentos de um script.

$ saudacao() {
>   echo "Olá, $1! Você passou $# argumento(s)."
> }
$ saudacao Ana
Olá, Ana! Você passou 1 argumento(s).
$ saudacao "Ana Maria" Bruno
Olá, Ana Maria! Você passou 2 argumento(s).     « as aspas fizeram "Ana Maria" ser um só
$ saudacao
Olá, ! Você passou 0 argumento(s).              « sem argumento, $1 fica vazio (não é erro)
$1, $2, …
O primeiro, o segundo… argumento desta chamada.
$#
Quantos argumentos a função recebeu (# lembra "número").
$@
Todos os argumentos. Use sempre "$@", com aspas, para repassá-los sem quebrar os que têm espaço.
$0
Não muda: continua sendo o nome do script (ou bash, no terminal). O nome da função fica em FUNCNAME (veja local, return e saída).

O $1 da função não é o $1 do script

Esta é a confusão mais comum. Quando a função é chamada, o Bash troca temporariamente os parâmetros posicionais pelos argumentos da chamada. Quando ela termina, os do script voltam.

#!/usr/bin/env bash
mostra() {
  echo "  dentro: \$1=$1  \$#=$#  \$@=$@"
}
echo "fora:   \$1=$1  \$#=$#  \$@=$@"
mostra laranja
mostra "$@"
echo "fora de novo: \$1=$1"

O \$ (com barra) imprime o cifrão literalmente, para servir de rótulo; o $1 sem barra mostra o valor.

$ bash args.sh banana uva
fora:   $1=banana  $#=2  $@=banana uva
  dentro: $1=laranja  $#=1  $@=laranja         « a função só vê o que recebeu na chamada
  dentro: $1=banana  $#=2  $@=banana uva       « mostra "$@" repassou os argumentos do script
fora de novo: $1=banana                        « os do script voltaram
Regra prática

Se a função precisa de um argumento do script, passe-o na chamada (mostra "$1", ou todos com mostra "$@"). Funções que recebem tudo por argumento são mais fáceis de testar e reaproveitar.

Missão: o script já chama mostra_aluno duas vezes, mas a função ainda não existe (rode e veja o erro "comando não encontrado"). Crie a função acima das chamadas para que ela mostre Ana tem 29 anos e Bruno tem 34 anos, usando $1 e $2.

#!/usr/bin/env bash
# Crie aqui a função mostra_aluno


mostra_aluno Ana 29
mostra_aluno Bruno 34

#!/usr/bin/env bash
mostra_aluno() {
  echo "$1 tem $2 anos"
}

mostra_aluno Ana 29
mostra_aluno Bruno 34

Definir antes de usar

O Bash lê e executa o script de cima para baixo, linha por linha. A definição de uma função é um comando como outro qualquer: só depois que ela é executada a função passa a existir. Chamar antes dá erro:

#!/usr/bin/env bash
saudacao Ana

saudacao() {
  echo "Olá, $1!"
}

saudacao Bruno

$ bash antes.sh
antes.sh: linha 2: saudacao: comando não encontrado    « na linha 2 a função ainda não existia
Olá, Bruno!                                           « na linha 8, já existia
$ echo $?
0

Repare que o script não parou no erro: o Bash avisou e seguiu para a próxima linha. E o código de saída final é 0, porque o último comando deu certo. Para scripts que devem parar no primeiro erro, veja set -euo pipefail.

Dentro de uma função, porém, você pode chamar outra que está definida mais abaixo no arquivo, desde que a chamada só aconteça depois que as duas foram definidas. É isso que o padrão main (mais abaixo) aproveita.

Funções no terminal e no .bashrc

Funções não são só para scripts. As que você define no terminal ficam valendo até fechar a janela. Um exemplo útil: criar uma pasta e já entrar nela.

$ mkcd() { mkdir -p "$1" && cd "$1"; }
$ mkcd projetos/novo
$ pwd
/home/ana/projetos/novo         « a função mudou a pasta do seu terminal
mkdir -p "$1"
Cria a pasta (e as pastas do caminho, se faltarem).
&&
Só continua se o mkdir deu certo (veja ; && ||).
cd "$1"
Entra na pasta. Como a função roda no seu shell, o cd vale para o terminal.

Isso não funciona como script, e o motivo é importante: um script roda num processo filho, que tem a própria pasta atual. O cd muda a pasta do filho, que termina logo em seguida:

#!/usr/bin/env bash
mkdir -p "$1" && cd "$1"
pwd

$ bash mkcd.sh projetos/teste
/home/ana/projetos/teste        « dentro do script, mudou…
$ pwd
/home/ana                       « …mas o seu terminal continua onde estava

Para não perder a função ao fechar o terminal, coloque-a no fim do ~/.bashrc (o arquivo que o Bash lê ao abrir cada terminal; veja arquivos de inicialização):

# cria uma pasta e entra nela
mkcd() {
  mkdir -p "$1" && cd "$1"
}

Os terminais novos já vão ter a função. No terminal que está aberto, recarregue o arquivo com source:

$ source ~/.bashrc
$ mkcd projetos/blog
$ pwd
/home/ana/projetos/blog
Função ou alias?

Um alias só troca uma palavra por outra (alias ll='ls -l'). Ele não sabe usar argumentos no meio, nem ter if. Assim que você precisar de $1 ou de mais de um comando, use uma função.

Missão: crie no terminal a função mkcd, que cria uma pasta e entra nela, e use-a para criar e entrar em projetos/blog. Confira com pwd.

Organizar um script com main "$@"

Quando o script cresce, uma organização muito usada é: todas as funções em cima, uma função main com o "roteiro" do script, e uma única linha solta no fim que chama main. O script abaixo resume o arquivo de alunos da Ana:

#!/usr/bin/env bash
# relatorio.sh — resumo de um arquivo CSV de alunos

cabecalho() {
  echo "=== Relatório de $1 ==="
}

conta_alunos() {
  local total
  total=$(wc -l < "$1")
  echo "Alunos: $(( total - 1 ))"
}

mostra_cidades() {
  echo "Cidades:"
  cut -d, -f3 "$1" | tail -n +2 | sort | sed "s/^/  - /"
}

main() {
  local arquivo=${1:-Documentos/alunos.csv}
  if [[ ! -f $arquivo ]]; then
    echo "Arquivo não encontrado: $arquivo" >&2
    exit 1
  fi
  cabecalho "$arquivo"
  conta_alunos "$arquivo"
  mostra_cidades "$arquivo"
}

main "$@"
ParteO que faz
cabecalhoMostra o título com o nome do arquivo recebido em $1.
conta_alunosConta as linhas com wc -l e desconta 1 (o cabeçalho). local faz a variável total existir só dentro da função (explicado em local, return e saída).
mostra_cidadesPega a 3ª coluna (cut), tira o cabeçalho (tail -n +2), ordena e põe " - " no começo de cada linha (sed). Ferramentas de grep, sed, awk e cia.
mainO roteiro: escolhe o arquivo (o 1º argumento ou, se não houver, o padrão — veja ${1:-padrão}), confere se existe e chama as outras funções na ordem.
main "$@"A única linha "solta". Entrega a main todos os argumentos do script.
$ bash relatorio.sh
=== Relatório de Documentos/alunos.csv ===
Alunos: 5
Cidades:
  - Curitiba
  - Manaus
  - Porto Alegre
  - Recife
  - Salvador
$ bash relatorio.sh turma2.csv
Arquivo não encontrado: turma2.csv
$ echo $?
1                         « o exit 1 da main virou o código de saída do script

Vantagens deste formato:

  • Quem abre o arquivo lê main e entende o script inteiro em 5 linhas.
  • A ordem das funções deixa de importar: quando main "$@" roda, na última linha, todas já foram definidas.
  • Se o arquivo for cortado no meio de um download, o Bash não roda metade do script: sem a última linha, nada acontece.

Uma biblioteca de funções com source

Quando várias scripts usam as mesmas funções (mostrar mensagens, pedir confirmação), guarde-as num arquivo separado e carregue-o com source (ou o atalho .). O source executa o arquivo no shell atual, então as funções definidas lá passam a existir no script.

# lib/util.sh — funções reaproveitáveis (não é para rodar sozinho)

msg() {
  echo "[$(date +%H:%M)] $*"
}

erro() {
  echo "ERRO: $*" >&2
}

confirma() {
  local resposta
  read -r -p "$1 [s/N] " resposta
  [[ $resposta == [sS] ]]
}

#!/usr/bin/env bash
source "$(dirname "$0")/lib/util.sh"

msg "Iniciando backup"
if cp Documentos/notas.txt Documentos/notas.bak; then
  msg "Cópia feita: Documentos/notas.bak"
else
  erro "não consegui copiar"
fi
source
"Leia e execute este arquivo aqui mesmo". Não cria processo filho; tudo o que o arquivo define fica no script.
"$(dirname "$0")"
A pasta onde o script está ($0 é o caminho do script; dirname tira o nome do arquivo). Assim a biblioteca é achada mesmo que o script seja rodado de outra pasta.
/lib/util.sh
O caminho da biblioteca, relativo à pasta do script.
msg, erro
Usadas como se fossem comandos, porque o source já as definiu. O $* junta todos os argumentos num texto só.
$ bash backup-notas.sh
[10:30] Iniciando backup
[10:30] Cópia feita: Documentos/notas.bak

A biblioteca não tem #! nem permissão de execução: ela não é para ser rodada, só carregada. A função confirma não foi usada neste script, mas está lá para os próximos. Repare também que ela devolve "sim/não" pelo código de saída do [[ ]], e por isso pode ir direto num if confirma "Apagar?"; then; o assunto da próxima aula, local, return e saída.

Quando não funciona

"comando não encontrado" com uma função que existe 
$ bash antes.sh
antes.sh: linha 2: saudacao: comando não encontrado

O que aconteceu: a função foi chamada antes da linha que a define. Ou, se ela fica num arquivo separado, o source falhou. Ou você está num terminal novo, e a função tinha sido definida só no anterior.

Como confirmar: type saudacao ou declare -F mostram se ela existe agora.

Como resolver: mova as definições para o topo (ou use o padrão main "$@"). No terminal, coloque a função no ~/.bashrc.

"erro de sintaxe próximo ao token inesperado" ao chamar 
$ saudacao("Ana")
bash: erro de sintaxe próximo ao token inesperado `"Ana"'

O que aconteceu: o hábito de outras linguagens. No Bash, função se chama como comando: sem parênteses e sem vírgulas. nome( só aparece na definição.

Como resolver: saudacao "Ana". Para dois argumentos: saudacao "Ana" 29, e não saudacao("Ana", 29).

Erro de sintaxe na definição: o espaço depois do { 
$ ola(){echo oi;}
bash: erro de sintaxe próximo ao token inesperado `{echo'

O que aconteceu: o { é uma palavra reservada e precisa estar separado. Colado em echo, o Bash leu a palavra {echo.

Como resolver: ola() { echo oi; }, com espaço depois do { e ; antes do }.

"fim inesperado do arquivo": faltou o ; antes do } 
#!/usr/bin/env bash
ola() { echo "oi" }
ola

$ bash semponto.sh
semponto.sh: linha 4: erro de sintaxe: fim inesperado do arquivo do comando `{' na linha 2
$ echo $?
2

O que aconteceu: sem ;, o } virou só mais um argumento do echo. O Bash continuou procurando o } de verdade até o fim do arquivo. Repare que o erro aponta a linha 4 (o fim), mas diz onde o bloco abriu: "na linha 2". No terminal, o sintoma é o prompt > esperando mais texto; aperte Ctrl+C.

Como resolver: ola() { echo "oi"; }, ou feche a chave numa linha própria.

"Falha de segmentação": a função chama a si mesma sem querer 
#!/usr/bin/env bash
ls() {
  echo "Listando $1:"
  ls "$1"
}
ls Imagens

$ bash rec.sh
Listando Imagens:
Listando Imagens:
Listando Imagens:
…                                « milhares de linhas iguais (encurtado)
Falha de segmentação     (imagem do núcleo gravada) bash rec.sh
$ echo $?
139

O que aconteceu: a função se chama ls. Lá dentro, ls "$1" não chama o programa ls: chama a própria função, que chama de novo, sem fim, até a memória do Bash estourar. O código 139 é 128 + 11 (o sinal SIGSEGV).

Como resolver: dentro da função, use command ls "$1": o command pula funções e aliases e chama o comando de verdade. Melhor ainda: dê um nome que não seja de comando (lista). Para se proteger, FUNCNEST=100 limita o aninhamento e troca o travamento pela mensagem ls: excedido o nível máximo de aninhamento de avaliação (100).

A biblioteca não é achada quando rodo de outra pasta 
$ bash ../quebrado.sh
../quebrado.sh: linha 2: lib/util.sh: Arquivo ou diretório inexistente
../quebrado.sh: linha 3: msg: comando não encontrado

O que aconteceu: o script usou source lib/util.sh. Um caminho relativo é procurado a partir da pasta atual (~/Documentos), e não da pasta do script.

Como resolver: monte o caminho a partir do script: source "$(dirname "$0")/lib/util.sh", como no backup-notas.sh.

Resumo

  • Defina com nome() { …; } (ou function nome { …; }) e chame com nome arg1 arg2, sem parênteses.
  • Dentro da função, $1, $# e $@ são os argumentos da chamada, não os do script. Repasse com "$@".
  • O Bash lê de cima para baixo: defina antes de chamar, ou use main "$@" na última linha.
  • Funções do terminal somem ao fechar; guarde-as no ~/.bashrc. Funções podem mudar a pasta e as variáveis do seu shell; scripts não.
  • type, declare -f/-F e unset -f mostram, listam e apagam funções. source carrega uma biblioteca.
