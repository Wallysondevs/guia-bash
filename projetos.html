Bash Como Usar os Projetos

As aulas ensinam um recurso de cada vez. Nos projetos você junta tudo para construir um script que resolve um problema de verdade: arrumar a pasta de downloads, fazer backup, ler um log, criar um jogo, uma ferramenta de linha de comando completa e a sua própria configuração do terminal. Cada projeto é construído em etapas, e em cada etapa o script cresce um pouco.

Você vai aprender
  • O que cada projeto constrói e quais aulas ele pratica.
  • Como uma página de projeto está organizada (etapas, sessões, missões, script completo).
  • Onde rodar: no simulador do guia ou no seu computador, e o que muda.
  • Como testar scripts que mexem em arquivos sem arriscar os seus.

Como aproveitar melhor
  • Digite o código em vez de copiar. É mais lento, e é exatamente por isso que você aprende: os erros de digitação viram treino de leitura de mensagens de erro.
  • Rode cada versão antes de passar para a próxima e compare a saída com a da página.
  • Faça as missões antes de olhar a solução. Se travar, releia a tabela da etapa: a resposta quase sempre está nela.
  • Quando terminar, faça pelo menos um desafio extra. É o primeiro código que vai ser só seu.

Onde rodar: simulador ou seu computador?

As caixas "Experimente" rodam no simulador do guia: um Bash escrito em JavaScript, dentro da página, com uma máquina fictícia (a da Ana, com Downloads, Documentos, acesso.log…). Nada do que você faz nele toca o seu computador. As sessões de terminal das páginas (os quadros pretos com $) foram gravadas no Bash 5.3 de verdade, numa máquina igual à da Ana.

Por isso algumas etapas não têm caixa no simulador e são só para o seu computador: o tar do backup, o shellcheck e a instalação da ferramenta, o git dos dotfiles. A página sempre avisa.

Preparar o seu computador

Você precisa de um Bash 4.0 ou mais novo (o ideal é o 5.x) e de um editor de texto. Confira:

$ bash --version | head -1
GNU bash, versão 5.3.9(1)-release (x86_64-pc-linux-gnu)

No Linux, você já tem. No macOS, o /bin/bash é o 3.2, antigo demais (sem arrays associativos, sem ${x,,}): instale um novo com brew install bash. No Windows, use o WSL. Detalhes em Bash em Cada Sistema. Os projetos de backup e da ferramenta também usam o shellcheck; ele está nos repositórios de quase toda distribuição (sudo apt install shellcheck no Debian e Ubuntu, sudo dnf install ShellCheck no Fedora, sudo pacman -S shellcheck no Arch, brew install shellcheck no macOS).

Uma pasta só para os projetos

Crie uma pasta e trabalhe sempre dentro dela:

$ mkdir -p ~/projetos-bash
$ cd ~/projetos-bash
$ pwd
/home/ana/projetos-bash

Missão: crie a pasta ~/projetos-bash com uma subpasta teste/Downloads dentro (num comando só, com mkdir -p) e entre em ~/projetos-bash.

Quando não funciona

A saída no meu computador é diferente da página

O que aconteceu: o mais comum é a língua: com o sistema em inglês, as mensagens de erro saem em inglês (No such file or directory em vez de Arquivo ou diretório inexistente). Outras diferenças: a data e a hora, a ordem dos arquivos (depende do LANG) e programas que não são os do GNU (no macOS, sed -i e date têm outras opções). Como confirmar: echo $LANG e bash --version.

Permissão negada ao rodar ./script.sh 
$ ./organizar.sh
bash: ./organizar.sh: Permissão negada

O que aconteceu: falta a permissão de execução. Como resolver: chmod +x organizar.sh, ou rode com bash organizar.sh. Veja Formas de Executar.

declare: -A: opção inválida, ${x,,}: substituição incorreta

O que aconteceu: você está rodando um Bash 3.2 (o /bin/bash do macOS). Como resolver: instale um Bash novo e use o shebang #!/usr/bin/env bash, que pega o primeiro bash do PATH. Veja Bash em Cada Sistema.

A caixa "Experimente" não reconhece um comando

O que aconteceu: o simulador não tem todos os programas (veja a tabela acima). Quando a página mostra um comando só num quadro de sessão, sem caixa, é porque ele precisa do seu computador.
