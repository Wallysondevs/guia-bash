Bash local, return e Saída

Em outras linguagens, uma função "devolve um valor" com return. No Bash não é bem assim: o return devolve só um código de saída, de 0 a 255. Para devolver um texto ou um número de verdade, a função escreve na saída e quem chamou captura. Nesta aula você vai entender essas duas "saídas" e como proteger as variáveis da função com local.

Você vai aprender
  • Por que toda variável de função é global, a menos que você use local (e o "escopo dinâmico" do Bash).
  • O que o return N realmente devolve e por que só vai de 0 a 255.
  • As formas de devolver um valor: echo + $( ), variável global, printf -v e declare -n.
  • A pegadinha do local var=$(comando), que esconde erros.
  • Recursão (uma função que chama a si mesma) e a variável FUNCNAME.

Esta aula continua Funções. Se você ainda não sabe criar e chamar uma função, comece por lá.

O problema: a função mexeu na minha variável

No Bash, uma variável criada dentro de uma função é, por padrão, global: vale para o script inteiro. Isso surpreende quem vem de outras linguagens.

$ nome=Ana
$ troca() {
>   nome=Bruno
>   cidade=Recife
> }
$ troca
$ echo "$nome mora em $cidade"
Bruno mora em Recife          « a função trocou "nome" e criou "cidade" do lado de fora

Num script pequeno, isso parece prático. Num script grande, é uma armadilha: uma função auxiliar que usa uma variável i ou total estraga o i ou o total de quem a chamou.

local: variáveis que só existem na função

$ nome=Ana
$ troca_local() {
>   local nome=Carla
>   echo "dentro: $nome"
> }
$ troca_local
dentro: Carla
$ echo "fora: $nome"
fora: Ana                     « o "nome" de fora ficou intacto
local
"Esta variável pertence a esta função." Ela nasce quando a função começa e some quando ela termina.
nome
Pode ter o mesmo nome de uma variável de fora: a local "esconde" a de fora enquanto a função roda.
=Carla
O valor inicial (opcional: local nome cria a variável vazia).

Você pode declarar várias de uma vez: local soma=0 n i. E o local só funciona dentro de funções:

$ local x=1
bash: local: somente pode ser usado em uma função
Regra de ouro

Toda variável que só a função usa deve ser local, inclusive o contador de um for (local i). Só deixe global o que a função quer mudar de propósito.

Escopo dinâmico: a função chamada enxerga o local de quem chamou

Aqui o Bash é diferente de Python, JavaScript ou C. Uma variável local não é visível só "no texto" da função: ela é visível em todas as funções que forem chamadas a partir dela, enquanto ela estiver rodando. Isso se chama escopo dinâmico.

#!/usr/bin/env bash
cor=azul                 # global

mostra_cor() {
  echo "  mostra_cor vê: $cor"
}

pinta() {
  local cor=vermelho     # local de pinta
  mostra_cor             # quem será que mostra_cor vê?
}

echo "chamando mostra_cor direto:"
mostra_cor
echo "chamando pinta:"
pinta
echo "depois: $cor"

$ bash escopo.sh
chamando mostra_cor direto:
  mostra_cor vê: azul
chamando pinta:
  mostra_cor vê: vermelho      « mostra_cor enxergou o local de pinta!
depois: azul                   « fora de tudo, a global continua azul

A mesma mostra_cor, sem mudar uma letra, mostrou valores diferentes. O que decide não é onde ela foi escrita, e sim quem a chamou: o Bash procura a variável na função atual, depois em quem a chamou, depois em quem chamou essa… e por último nas globais.

Na prática: uma função pode até alterar o local de quem a chamou. Por isso, mesmo dentro de funções auxiliares, declare as suas variáveis com local.

return: um código de saída, não um valor

Todo comando termina com um código de saída: 0 = deu certo, outro número = algo falhou. Uma função é um comando, e o return diz qual código ela devolve.

$ tem_arquivo() {
>   [[ -f $1 ]]
> }
$ tem_arquivo frutas.txt; echo $?
0                              « existe: "verdadeiro"
$ tem_arquivo nada.txt; echo $?
1                              « não existe: "falso"
$ if tem_arquivo frutas.txt; then echo "existe"; fi
existe

Esta função nem tem return: sem ele, a função devolve o código do último comando que rodou (aqui, o [[ ]]). Isso a torna perfeita para usar direto num if, como os testes do Bash.

return
Sai da função na hora. Sem número, devolve o código do último comando executado.
return 0
"Sucesso", "sim", "verdadeiro".
return 1
"Falha", "não", "falso". Outros números (2, 3…) podem indicar tipos diferentes de falha.

Por que só 0–255?

O código de saída é guardado pelo sistema em 1 byte (8 bits), e um byte vai de 0 a 255. Números fora disso "dão a volta":

#!/usr/bin/env bash
soma() {
  return $(( $1 + $2 ))
}
soma 2 3;     echo "2 + 3 = $?"
soma 200 100; echo "200 + 100 = $?"

$ bash soma.sh
2 + 3 = 5
200 + 100 = 44                 « 300 não cabe em 1 byte: 300 - 256 = 44
$ f() { return 300; }
$ f; echo $?
44
$ f() { return -1; }
$ f; echo $?
255                            « -1 também dá a volta
$ f() { return abc; }
$ f; echo $?
bash: return: abc: requer argumento numérico
2
Nunca use return para devolver um resultado

Ele parece funcionar com números pequenos e quebra sem aviso com números grandes, negativos, com vírgula ou com texto. Use return só para dizer se deu certo. Para devolver o resultado, veja a próxima seção.

Missão: a função pode_votar deve devolver o código 0 (sim) quando a idade em $1 for 16 ou mais, e 1 (não) caso contrário. Hoje ela sempre devolve 1. Corrija e rode: 16 e 40 devem poder votar.

#!/usr/bin/env bash
pode_votar() {
  return 1     # troque esta linha
}
for idade in 15 16 40; do
  if pode_votar "$idade"; then
    echo "$idade anos: pode votar"
  else
    echo "$idade anos: não pode"
  fi
done

#!/usr/bin/env bash
pode_votar() {
  if (( $1 >= 16 )); then
    return 0
  fi
  return 1
}
for idade in 15 16 40; do
  if pode_votar "$idade"; then
    echo "$idade anos: pode votar"
  else
    echo "$idade anos: não pode"
  fi
done

Devolver um valor: echo + $( )

A forma mais comum: a função escreve o resultado na saída, e quem chama captura essa saída com a substituição de comando $( ).

$ dobro() {
>   echo $(( $1 * 2 ))
> }
$ resultado=$(dobro 21)
$ echo "O dobro é $resultado"
O dobro é 42
echo $(( $1 * 2 ))
A função "devolve" escrevendo o resultado na saída padrão.
$(dobro 21)
Roda a função e é trocado por tudo o que ela escreveu (sem a quebra de linha final).
resultado=
Guarda o texto capturado numa variável.

Funciona com qualquer coisa: números grandes, negativos, texto, várias linhas. É a forma "natural" do shell, a mesma usada com comandos (hoje=$(date +%F)).

Cuidado: tudo o que a função escreve é capturado

#!/usr/bin/env bash
media() {
  echo "Calculando..."
  echo $(( ($1 + $2) / 2 ))
}
m=$(media 8 6)
echo "Média: $m"

$ bash media.sh
Média: Calculando...
7                              « a mensagem entrou junto no resultado

A mensagem "Calculando..." era para a pessoa, não para a variável. Mande mensagens para a saída de erro com >&2: o $( ) só captura a saída padrão (veja redirecionamento).

#!/usr/bin/env bash
media() {
  echo "Calculando..." >&2
  echo $(( ($1 + $2) / 2 ))
}
m=$(media 8 6)
echo "Média: $m"

$ bash media2.sh
Calculando...                  « foi para a tela pelo canal 2
Média: 7                       « só o número ficou na variável

Missão: complete a função media para que ela some todos os argumentos (use for n in "$@") e mostre com echo a média inteira (soma dividida por $#). Use local para as variáveis da função. Com 8 6 10, o resultado deve ser Média: 8.

#!/usr/bin/env bash
media() {
  echo 0     # troque por: some os argumentos e mostre a média
}
m=$(media 8 6 10)
echo "Média: $m"

#!/usr/bin/env bash
media() {
  local soma=0 n
  for n in "$@"; do
    soma=$(( soma + n ))
  done
  echo $(( soma / $# ))
}
m=$(media 8 6 10)
echo "Média: $m"

Outras formas de devolver um valor

1. Uma variável global

A função grava o resultado numa variável combinada (por convenção, em MAIÚSCULAS para chamar atenção), e quem chamou lê depois:

#!/usr/bin/env bash
conta_linhas() {
  TOTAL=$(wc -l < "$1")
}
conta_linhas frutas.txt
echo "frutas.txt tem $TOTAL linhas"

$ bash global.sh
frutas.txt tem 7 linhas

É mais rápido que $( ) (não cria um processo extra) e permite devolver várias coisas de uma vez. A desvantagem: quem lê a chamada conta_linhas frutas.txt não vê que ela cria TOTAL.

E atenção: dentro de $( ), a função não consegue mudar variáveis globais. O $( ) roda num subshell, uma cópia do shell que é jogada fora no fim:

#!/usr/bin/env bash
chamadas=0
proximo() {
  chamadas=$(( chamadas + 1 ))
  echo "$chamadas"
}
n=$(proximo)
n=$(proximo)
echo "n=$n, chamadas=$chamadas"
proximo > /dev/null
proximo > /dev/null
echo "chamadas=$chamadas"

$ bash contador.sh
n=1, chamadas=0               « as duas chamadas com $( ) mudaram só a cópia
chamadas=2                    « chamadas diretas mudam a variável de verdade

2. printf -v: gravar na variável que quem chamou escolheu

Quem chama passa o nome da variável; a função grava nela com printf -v (o -v manda o resultado para a variável em vez da tela; veja printf).

#!/usr/bin/env bash
maiusculas() {
  printf -v "$1" "%s" "${2^^}"
}
maiusculas nome "ana maria"
echo "$nome"

$ bash maiusc.sh
ANA MARIA
maiusculas nome "ana maria"
1º argumento: o nome da variável que vai receber o resultado (sem $). 2º: o texto.
printf -v "$1"
"Grave na variável cujo nome está em $1" (aqui, nome).
"%s" "${2^^}"
O formato e o valor: o 2º argumento em maiúsculas (^^, veja expansão de parâmetros).

3. declare -n (nameref): um apelido para a variável de quem chamou bash 4.3+

Com local -n (ou declare -n), uma variável da função vira um apelido de outra. Tudo o que você faz com o apelido acontece na original. É a forma de uma função receber e alterar um array:

#!/usr/bin/env bash
dobra_lista() {
  local -n lista=$1      # lista vira um "apelido" da variável cujo nome veio em $1
  local i
  for i in "${!lista[@]}"; do
    lista[i]=$(( lista[i] * 2 ))
  done
}
numeros=(1 5 10)
dobra_lista numeros
echo "${numeros[@]}"

$ bash nameref.sh
2 10 20                        « o array "numeros" de fora foi alterado

O nameref tem suas pegadinhas (por exemplo, se quem chama usar uma variável com o mesmo nome do apelido, o Bash avisa referência circular de nome). O assunto é aprofundado em eval, indireção e nameref. O macOS, com Bash 3.2, não tem nameref; lá use printf -v.

Uma função pode usar duas formas ao mesmo tempo: escrever o resultado com echo e devolver um código com return. Por exemplo, if linha=$(busca Ana); then … testa o código e guarda o texto.

A pegadinha: local var=$(comando) esconde o erro

Juntar o local e a atribuição numa linha só parece inofensivo. Mas o código de saída que sobra é o do local (que sempre dá certo), não o do comando:

#!/usr/bin/env bash
pega() {
  local linha=$(grep Natal Documentos/alunos.csv)
  echo "código do grep: $?"
}
pega_certo() {
  local linha
  linha=$(grep Natal Documentos/alunos.csv)
  echo "código do grep: $?"
}
pega
pega_certo

$ bash pegadinha.sh
código do grep: 0              « mentira! o grep não achou "Natal"; esse 0 é do local
código do grep: 1              « separado: agora o $? é mesmo do grep
local linha=$(grep …)
Uma linha só: o $? é o do comando local, que conseguiu criar a variável. O erro do grep se perde.
local linha
Primeiro declara a variável (vazia)…
linha=$(grep …)
…depois atribui. Uma atribuição simples devolve o código do $( ).

O mesmo vale para export var=$(…), declare var=$(…) e readonly var=$(…). Isso importa ainda mais com set -e, que não percebe o erro escondido. O ShellCheck avisa (é o alerta SC2155).

Recursão: a função que chama a si mesma

Uma função pode chamar a si mesma, desde que haja um caso de parada. O exemplo clássico é o fatorial: 5! = 5 × 4 × 3 × 2 × 1, ou seja, 5! = 5 × 4!.

#!/usr/bin/env bash
fatorial() {
  local n=$1
  if (( n <= 1 )); then
    echo 1
    return
  fi
  local anterior
  anterior=$(fatorial $(( n - 1 )))
  echo $(( n * anterior ))
}
for n in 0 1 5 10 20; do
  echo "$n! = $(fatorial $n)"
done
LinhaO que faz
local n=$1Cada chamada tem o seu n. Sem local, as chamadas de dentro estragariam o n das de fora.
if (( n <= 1 )); then echo 1; return; fiO caso de parada: 0! e 1! valem 1. Sem ele, a função se chamaria para sempre.
anterior=$(fatorial $(( n - 1 )))A chamada a si mesma, com um número menor. Cada chamada espera a de baixo responder.
echo $(( n * anterior ))Devolve n × (n−1)!.
$ bash fatorial.sh
0! = 1
1! = 1
5! = 120
10! = 3628800
20! = 2432902008176640000      « o maior que cabe nos inteiros de 64 bits do Bash

Recursão em Bash é boa para aprender e para percorrer pastas, mas é lenta (cada $( ) cria um processo). Para contas, um laço resolve melhor. E sem caso de parada, ela termina em "Falha de segmentação", como no exemplo do ls recursivo.

FUNCNAME: quem sou eu e quem me chamou

O Bash mantém um array chamado FUNCNAME com a "pilha" de funções em execução: ${FUNCNAME[0]} é a função atual, ${FUNCNAME[1]} é quem a chamou, e assim por diante. Muito útil em mensagens de log e de erro:

#!/usr/bin/env bash
log() {
  echo "[${FUNCNAME[1]}] $*"
}
erro() {
  echo "ERRO em ${FUNCNAME[1]} (chamada por ${FUNCNAME[2]}): $*" >&2
}
instala() {
  log "começando"
  erro "pacote não encontrado"
  echo "  pilha completa: ${FUNCNAME[*]}"
}
main() {
  log "início"
  instala
}
main "$@"

$ bash nomes.sh
[main] início
[instala] começando
ERRO em instala (chamada por main): pacote não encontrado
  pilha completa: instala main main
${FUNCNAME[0]}
A própria função (dentro de log, seria "log").
${FUNCNAME[1]}
Quem chamou a função atual. Por isso log mostra o nome de quem pediu o log.
${FUNCNAME[*]}
A pilha inteira, da atual até o começo.

Por que "main" aparece duas vezes na pilha? O primeiro é a nossa função main. O último é o nome que o Bash dá ao corpo do script, fora de qualquer função; ele sempre aparece no fim da pilha quando o código vem de um script. No terminal, fora de função, FUNCNAME fica vazio.

Quando não funciona

O resultado veio errado: 44 em vez de 300 
$ bash soma.sh
2 + 3 = 5
200 + 100 = 44

O que aconteceu: a função "devolveu" o valor com return, que só guarda de 0 a 255.

Como resolver: troque return $(( … )) por echo $(( … )) e chame com r=$(soma 200 100).

"requer argumento numérico" 
$ f() { return abc; }
$ f; echo $?
bash: return: abc: requer argumento numérico
2

O que aconteceu: tentou devolver um texto com return. Também acontece com return $resultado quando resultado tem vírgula ou texto.

Como resolver: echo "$resultado" + $( ).

A variável capturada tem lixo (mensagens) junto 
$ bash media.sh
Média: Calculando...
7

O que aconteceu: o $( ) captura toda a saída padrão da função, inclusive mensagens e a saída dos comandos que ela roda (um cp -v, um grep sem -q…).

Como resolver: mensagens com >&2; comandos cuja saída não interessa com >/dev/null; deixe na saída padrão só o resultado.

A variável global não mudou 
$ bash contador.sh
n=1, chamadas=0

O que aconteceu: a função foi chamada dentro de $( ) (ou num pipe, f | outro), que roda num subshell. As mudanças ficam na cópia.

Como resolver: escolha uma forma: ou a função devolve por echo (e você usa $( )), ou devolve por variável (e você a chama direto, sem $( )).

"local: somente pode ser usado em uma função" 
$ local x=1
bash: local: somente pode ser usado em uma função

O que aconteceu: o local foi usado fora de uma função (no terminal ou no corpo principal do script). Lá ele não faz sentido: tudo já é global.

Como resolver: tire o local (uma atribuição simples basta) ou mova o código para dentro de uma função (como a main).

O erro do comando sumiu ($? sempre 0)

Você escreveu local x=$(comando) e testou $?. Veja a pegadinha acima: declare em uma linha e atribua em outra.

Resumo

  • Sem local, toda variável de função é global. Com local, ela vale na função e nas que ela chamar (escopo dinâmico).
  • return N devolve um código de saída (0–255), ótimo para if. Sem número, vale o código do último comando.
  • Para devolver um valor: echo + v=$(f) (padrão); mensagens vão para >&2.
  • Alternativas: variável global, printf -v "$1" e local -n. Funções dentro de $( ) não mudam variáveis de fora.
  • Escreva local x e x=$(cmd) em linhas separadas. Recursão precisa de caso de parada; FUNCNAME diz quem chamou quem.
