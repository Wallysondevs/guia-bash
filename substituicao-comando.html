Bash Substituição de Comando $( )

Você já sabe que date +%F mostra a data de hoje. Mas e se você quiser usar essa data no nome de um arquivo, ou guardar numa variável? A substituição de comando roda um comando e coloca a saída dele no meio de outro comando, como se você tivesse digitado o resultado.

Você vai aprender
  • Usar $(comando) para guardar a saída de um comando numa variável ou usar dentro de outro comando.
  • Por que preferir $( ) às crases ` `.
  • Por que pôr aspas em volta ("$(…)") e o que acontece com as quebras de linha.
  • Qual é o código de saída de var=$(cmd), e o atalho $(< arquivo).
  • O custo de cada $( ) e quando ele importa.

O problema: a saída vai para a tela, e eu queria guardar

$ date +%F
2026-10-15
$ hoje=date +%F
bash: +%F: comando não encontrado

A segunda linha não funcionou: hoje=date virou uma atribuição temporária e o Bash tentou rodar +%F como comando. O que você quer é "rode date +%F e guarde o que ele mostraria". É exatamente isso que $( ) faz.

A forma básica: $(comando)

hoje=
Atribuição: a variável vai receber o que vem depois.
$(
"Rode o comando que está aqui dentro…"
date +%F
…este comando. Ele roda primeiro, numa cópia do shell.
)
"…e coloque aqui o que ele imprimiu."
$ hoje=$(date +%F)
$ echo "Hoje é $hoje"
Hoje é 2026-10-15

O date não mostrou nada na tela: a saída dele foi capturada e virou o valor de hoje. Você não precisa de variável: o $( ) pode ir direto no meio do texto.

$ echo "Você está em $(pwd)"
Você está em /home/ana
$ echo "Há $(ls Downloads | wc -l) arquivos em Downloads"
Há 5 arquivos em Downloads

No segundo exemplo, dentro do $( ) há um pipe inteiro: ls Downloads lista os arquivos (um por linha, porque a saída não é a tela) e wc -l conta as linhas. O resultado, 5, entra no lugar.

A ordem das coisas

  echo "Há $(ls Downloads | wc -l) arquivos"
            └──────────┬─────────┘
  1º  o Bash roda  ls Downloads | wc -l   →  imprime "5"
  2º  troca o $( ) pelo texto             →  echo "Há 5 arquivos"
  3º  roda o echo                         →  Há 5 arquivos

Missão: guarde na variável qtd quantas linhas tem o arquivo frutas.txt, usando $( ). Dica: wc -l < frutas.txt mostra só o número. Confira com echo "$qtd".

Crases: a forma antiga

Antes do $( ), a substituição de comando era feita com crases (o acento grave, `). Ela ainda funciona e aparece em muitos scripts e tutoriais antigos:

$ echo "Usuário: `whoami`"
Usuário: ana

O resultado é o mesmo. Então por que todo mundo recomenda $( )? Veja o que acontece quando um comando precisa de outro dentro dele (aninhar). Vamos mostrar só o nome da pasta atual: pwd dá o caminho, e basename pega a última parte.

$ echo "Pasta: $(basename "$(pwd)")"
Pasta: ana
$ echo "Pasta: `basename \`pwd\``"
Pasta: ana                       « funciona, mas as crases de dentro precisam de \
$ echo `echo `echo quebrou``
echo quebrou                     « sem as barras, o Bash fechou na crase errada

Com crases, o Bash não sabe se uma crase abre ou fecha: ele sempre fecha na próxima. No último exemplo, ele entendeu `echo ` (vazio) + echo quebrou + `` (vazio). Com $( ), abrir e fechar são símbolos diferentes, então você pode aninhar quantos níveis quiser:

$ echo "$(echo "$(echo "três níveis")")"
três níveis

Repare também nas aspas: dentro de $( ) você pode usar aspas normalmente, mesmo que o $( ) esteja dentro de outras aspas. Cada $( ) começa um "mundo novo" de aspas.

$(comando)`comando`
AninharDireto: $(a $(b))Precisa escapar: `a \`b\``
LegibilidadeFácil de ver onde começa e terminaA crase se confunde com aspas simples '
Barra invertida dentroFunciona como foraTem regras especiais (\$, \\, \`)
Onde funcionaBash, zsh, dash, qualquer sh POSIXEm todos, inclusive shells muito antigos
Qual usar?Sempre, em código novoSó para entender scripts antigos

O ShellCheck avisa quando encontra crases (aviso SC2006) e sugere trocar por $( ).

Aspas em volta: "$(…)"

O resultado de $( ) passa pelas mesmas etapas que $variavel: se estiver sem aspas, ele é quebrado em palavras nos espaços e quebras de linha, e os curingas são expandidos. Veja com a lista de frutas, uma por linha:

$ lista=$(cat frutas.txt)
$ echo $lista
banana maçã laranja banana uva maçã banana      « sem aspas: as linhas viraram palavras
$ echo "$lista"
banana
maçã
laranja
banana
uva
maçã
banana                                          « com aspas: as quebras de linha ficam

A variável lista guardou as quebras de linha direitinho. Quem as "perdeu" foi o echo $lista sem aspas: o Bash separou o valor em 7 palavras e o echo as imprimiu separadas por espaço.

O problema fica sério com nomes que têm espaço:

$ p=$(echo "Área de trabalho")
$ ls -d $p
ls: não foi possível acessar 'Área': Arquivo ou diretório inexistente
ls: não foi possível acessar 'de': Arquivo ou diretório inexistente
ls: não foi possível acessar 'trabalho': Arquivo ou diretório inexistente
$ ls -d "$p"
Área de trabalho

Regra: use aspas em volta de $( ) e da variável que guarda o resultado, sempre que for usá-los como argumento. Na atribuição (var=$(cmd)), as aspas são opcionais, porque o Bash não separa palavras ali. Mais sobre isso em Aspas e Escapes.

As quebras de linha do final somem

Quase todo comando termina a saída com uma quebra de linha. O $( ) remove todas as quebras de linha do final (só do final). É por isso que hoje=$(date +%F) não guarda um "enter" junto com a data.

$ x=$(printf 'a\nb\n\n\n')
$ echo "[$x]"
[a
b]                       « a quebra do meio ficou; as três do fim sumiram

Na maioria das vezes, isso é exatamente o que você quer. Só preste atenção se precisar guardar um arquivo byte a byte (aí, use outras técnicas, vistas em mapfile).

O código de saída de var=$(cmd)

Uma atribuição com $( ) devolve o código de saída do comando de dentro. Assim você captura a saída e ainda sabe se deu certo:

$ saida=$(ls nada)
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente   « o erro não foi capturado!
$ echo "código: $?"
código: 2                « o código do ls chegou até aqui
$ echo "[$saida]"
[]                       « a variável ficou vazia

Duas coisas para notar:

  1. $( ) captura só a saída padrão (canal 1). A mensagem de erro (canal 2) continua indo para a tela. Para capturar as duas, junte com 2>&1 (veja Redirecionamento): 
    $ saida=$(ls nada 2>&1)
$ echo "[$saida]"
[ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente]
  2. Como a atribuição devolve o código do comando, ela pode ir direto num if (assunto de if, elif, else): 
    $ if total=$(grep -c Ana Documentos/alunos.csv); then echo "achei $total"; fi
achei 1
A exceção: local, export e declare

Em export x=$(cmd) ou local x=$(cmd), o código de saída é o do export/local (que quase sempre dá certo), não o do cmd. Se o código importa, separe em duas linhas: local x e depois x=$(cmd). Isso volta em local, return e Saída.

Ler um arquivo inteiro: $(< arquivo)

$(cat arquivo) é tão comum que o Bash tem um atalho: $(< arquivo). Ele faz o mesmo, mas sem chamar o programa cat, então é mais rápido.

$ conteudo=$(< Documentos/notas.txt)
$ echo "$conteudo"
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos

Se o arquivo não existir, a mensagem é do próprio Bash e o código é 1:

$ arquivo=$(< naoexiste.txt)
bash: naoexiste.txt: Arquivo ou diretório inexistente
$ echo $?
1

Não confunda com $(wc -l < frutas.txt): ali o < é um redirecionamento comum para o wc. O atalho é só quando o < arquivo está sozinho dentro dos parênteses.

Exemplos do dia a dia

Data no nome do backup

$ cp Documentos/notas.txt "notas-$(date +%F).txt"
$ ls notas-*
notas-2026-10-15.txt
$ tar czf "backup-$(date +%Y%m%d).tar.gz" Documentos
$ ls backup-*
backup-20261015.tar.gz

O formato %F (ano-mês-dia) é ótimo para nomes de arquivo, porque a ordem alfabética coincide com a ordem das datas. Os formatos do date estão em man date.

Missão: faça uma cópia de Documentos/notas.txt na sua pasta pessoal com a data de hoje no nome, no formato notas-ANO-MÊS-DIA.txt, usando $(date +%F). Confira com ls.

Contar arquivos

$ qtd=$(ls Documentos | wc -l)
$ echo "Documentos tem $qtd itens"
Documentos tem 5 itens

Nome do script e da pasta

Em scripts, é comum mostrar só o nome do script nas mensagens: echo "Uso: $(basename "$0") ARQUIVO". Lembre que o mesmo resultado sai sem processo extra com ${0##*/} (veja Expansão de Parâmetros).

Missão: o script recebe o nome de uma pasta. Troque o ??? para que ele mostre quantos itens há nela, usando $( ) com ls e wc -l. Com Downloads, a saída deve ser Downloads tem 5 arquivos.

#!/usr/bin/env bash
pasta=${1:-.}
echo "$pasta tem ??? arquivos"

#!/usr/bin/env bash
pasta=${1:-.}
qtd=$(ls "$pasta" | wc -l)
echo "$pasta tem $qtd arquivos"

O custo: cada $( ) é um subshell

Para rodar o comando de dentro, o Bash cria uma cópia de si mesmo (um subshell). Duas consequências:

1. O que acontece lá dentro fica lá dentro. Um cd ou uma variável alterada dentro do $( ) não afeta o seu shell, como o script filho de Variáveis:

$ pasta=$(cd Documentos; pwd)
$ echo "$pasta"
/home/ana/Documentos
$ pwd
/home/ana                « o cd aconteceu só na cópia
$ n=1
$ x=$(n=99; echo "dentro: $n")
$ echo "$x / fora: $n"
dentro: 99 / fora: 1

2. Criar uma cópia leva tempo. Uma vez não faz diferença; dentro de um laço que roda milhares de vezes, sim. Compare 500 voltas (o comando time mede quanto demorou; o for é a próxima unidade):

$ time for i in {1..500}; do x=$(echo oi); done

real	0m0,304s
user	0m0,170s
sys	0m0,166s
$ time for i in {1..500}; do x=oi; done

real	0m0,001s
user	0m0,001s
sys	0m0,000s

Os números variam de máquina para máquina, mas a proporção é parecida: centenas de vezes mais lento. Por isso, quando existe uma forma sem $( ), prefira-a dentro de laços: ${arq##*/} em vez de $(basename "$arq"), $((a + b)) em vez de $(expr $a + $b), $(< arq) em vez de $(cat arq).

Novidade do Bash 5.3: ${ comando; }

O Bash 5.3 trouxe uma substituição de comando que roda no shell atual, sem criar a cópia: ${ comando; } (com espaço depois da chave e ; antes de fechar). Ela é mais rápida e as variáveis alteradas dentro dela continuam alteradas depois. Como só existe no 5.3+, ela é explicada em Novidades do Bash 5.

Quando não funciona

"comando não encontrado" com o nome da variável 
$ nome=Ana
$ echo $(nome)
bash: nome: comando não encontrado

O que aconteceu: parênteses são para comandos. O Bash tentou rodar um programa chamado nome.

Como resolver: para variáveis, use chaves: ${nome} ou $nome. Para contas, parênteses duplos: $((…)).

O comando de dentro não existe 
$ v=$(dataa)
bash: dataa: comando não encontrado
$ echo "[$v] $?"
[] 127

O que aconteceu: erro de digitação dentro do $( ). A variável ficou vazia e o código 127 quer dizer "comando não encontrado".

Como resolver: teste o comando sozinho primeiro (date +%F) e só depois coloque dentro do $( ).

"EOF inesperado enquanto procurava por `)'" 
#!/usr/bin/env bash
hoje=$(date +%F
echo "Backup de $hoje"

$ bash data.sh
data.sh: linha 4: encontrado EOF inesperado enquanto procurava por `)' correspondente
$ echo $?
2

O que aconteceu: faltou fechar o $( da linha 2, e o Bash leu até o fim do arquivo (EOF, end of file) procurando o ). A linha indicada (4) é depois da última, não a do erro. Nenhuma linha do script rodou: o código 2 indica erro de sintaxe. No terminal, o mesmo erro aparece como o prompt > esperando o resto (saia com Ctrl+C).

Como resolver: procure um $( sem par. bash -n data.sh confere a sintaxe sem rodar (veja Depurar).

Espaço em volta do = 
$ hoje = $(date +%F)
bash: hoje: comando não encontrado

Como resolver: sem espaços: hoje=$(date +%F).

O erro apareceu na tela e a variável ficou vazia

O que aconteceu: o comando escreveu no canal de erro, que o $( ) não captura.

Como resolver: confira o código com echo $? logo depois. Se quiser a mensagem na variável, use var=$(cmd 2>&1); se quiser escondê-la, var=$(cmd 2>/dev/null).

Resumo

  • $(comando) roda o comando e põe a saída dele no lugar; use para guardar em variável ou montar textos e nomes.
  • Prefira $( ) às crases: aninha sem escapes e é mais legível.
  • Use aspas: "$(…)". As quebras de linha do final são removidas.
  • var=$(cmd) devolve o código de saída do cmd; só a saída padrão é capturada (use 2>&1 para os erros).
  • $(< arq) lê um arquivo sem cat. Cada $( ) cria um subshell: o que muda lá dentro não volta, e em laços isso custa tempo.
