Bash Variáveis, Escopo e export

Em Variáveis: o Básico você criou nome=Ana e leu com $nome. Agora vamos responder às perguntas que aparecem quando você começa a escrever scripts: quem enxerga uma variável, por que um script não consegue mudar o seu terminal, e como dar "superpoderes" a uma variável com declare.

Você vai aprender
  • A diferença entre variável de shell e variável de ambiente, e o papel do export.
  • Como listar o ambiente com env e printenv, e como passar uma variável para um único comando (VAR=valor comando).
  • Por que um script filho nunca altera as variáveis do terminal pai, e o que fazer quando você quer isso.
  • Os atributos do declare (-i -r -x -l -u -p), o readonly e o unset.
  • Quais nomes são válidos e quais são as variáveis especiais mais usadas.

O problema: o filho não sabe o que o pai sabe

Todo programa que você roda no terminal é um processo filho do Bash. Pense numa casa: o Bash é a mãe, e cada comando é um filho que ela manda fazer uma tarefa. A mãe tem anotações num caderno (as variáveis). Quando o filho sai, ele não leva o caderno inteiro: leva só uma cópia das folhas que a mãe marcou como "pode levar".

Essas folhas marcadas são o ambiente (environment). Marcar uma folha é o que o comando export faz.

TipoQuem enxergaComo criarExemplo
Variável de shellSó o próprio Bash onde foi criadanome=valorcidade=Recife
Variável de ambienteO Bash e todos os programas que ele abrir depoisexport nome=valorHOME, PATH, LANG

A prova com bash -c

Para ver isso acontecendo, vamos usar um "filho" de teste: bash -c '…' abre outro Bash, roda o texto entre aspas e fecha. As aspas são simples de propósito: assim quem troca $cidade pelo valor é o Bash filho, não o seu (as aspas simples impedem a troca no pai).

bash
Abre um novo Bash, filho do atual.
-c
"Rode este comando e saia" (de command).
'echo "No filho: [$cidade]"'
O comando que o filho vai rodar. Os colchetes não têm função especial: estão aí só para você ver quando o valor está vazio.
$ cidade=Recife
$ echo "$cidade"
Recife                                « o próprio Bash enxerga
$ bash -c 'echo "No filho: [$cidade]"'
No filho: []                          « o filho NÃO enxerga: colchetes vazios
$ export cidade
$ bash -c 'echo "No filho: [$cidade]"'
No filho: [Recife]                    « depois do export, o filho recebe uma cópia

O que aconteceu, linha a linha:

  1. cidade=Recife criou uma variável de shell. Ela existe, mas fica "em casa".
  2. O primeiro bash -c mostrou []: para o filho, $cidade não existe, e uma variável que não existe vale texto vazio. Repare que não houve erro: o Bash não avisa.
  3. export cidade não mostrou nada. Ele só marcou a variável para ir junto com os filhos. O código de saída é 0 (deu certo).
  4. O segundo bash -c já recebeu Recife.

As formas do export

export
"Exportar": colocar no ambiente dos próximos filhos.
cor=verde
Você pode criar e exportar na mesma linha. Sem o =valor, exporta uma variável que já existe.
$ export cor=verde
$ bash -c 'echo "cor no filho: $cor"'
cor no filho: verde
$ declare -p cor
declare -x cor="verde"                « o -x quer dizer "exportada"

O comando declare -p (de print) mostra a variável e os atributos dela. Compare: uma variável comum aparece com -- (nenhum atributo), e uma exportada aparece com -x:

$ fruta=uva
$ declare -p fruta
declare -- fruta="uva"                « -- = sem atributos: variável de shell

Para "desexportar" sem apagar, use export -n. A variável continua existindo, mas volta a ser só de shell:

$ export -n cidade
$ declare -p cidade
declare -- cidade="Recife"
Exportar uma vez basta

Depois do export, se você mudar o valor (cidade=Natal), a variável continua exportada. Não precisa repetir o export. Muita gente escreve variáveis de ambiente em MAIÚSCULAS (EDITOR, JAVA_HOME) e as suas, de script, em minúsculas. É só convenção, mas ajuda a não sobrescrever uma variável do sistema sem querer.

Missão: crie a variável cor com o valor verde e rode bash -c 'echo $cor': nada aparece. Agora use export e rode o bash -c de novo até o filho mostrar verde.

Ver o ambiente: env e printenv

Dois programas mostram as variáveis de ambiente (só as exportadas):

env
Sem argumentos, lista o ambiente inteiro, uma variável por linha, no formato NOME=valor.
printenv NOME
Mostra só o valor de uma variável. Sem o nome, faz o mesmo que env.
$ env | head -n 5
SHELL=/bin/bash
LANGUAGE=pt_BR:pt:en
EDITOR=nano
PWD=/home/ana
LOGNAME=ana
$ printenv HOME
/home/ana
$ export cidade
$ printenv cidade
Recife
$ env | grep cidade
cidade=Recife

Cortamos o env com head -n 5 (as 5 primeiras linhas). A lista completa muda de máquina para máquina. Para procurar uma variável, o jeito mais prático é env | grep NOME (o | é um pipe).

Quando o printenv não mostra nada

Se a variável não existe ou não foi exportada, o printenv fica calado. A diferença aparece no código de saída:

$ fruta=uva
$ printenv fruta
$ echo $?
1                                     « 1 = não achei (fruta é só de shell)
$ printenv naoexiste
$ echo $?
1

env, set e declare -p: quem mostra o quê

ComandoMostraQuando usar
env / printenvSó as variáveis de ambiente (exportadas)Saber o que um programa vai receber.
printenv NOMEO valor de uma variável de ambienteConferir uma variável, com código de saída útil em scripts.

Na máquina da Ana, env | wc -l deu 14 linhas e set | wc -l deu 49: o set mostra bem mais, porque inclui as variáveis que ficam só no shell.

Uma variável só para um comando: VAR=valor comando

Às vezes você quer mudar uma variável só para um comando, sem mexer no terminal. Basta escrever a atribuição antes do comando, na mesma linha, separada por espaço.

LANG=C
Atribuição temporária: vale só para o comando desta linha. C é o idioma "neutro", em inglês.
ls nada
O comando que recebe a variável no ambiente dele.
$ ls nada
ls: não foi possível acessar 'nada': Arquivo ou diretório inexistente
$ LANG=C ls nada
ls: cannot access 'nada': No such file or directory     « só este comando falou inglês
$ echo "$LANG"
pt_BR.UTF-8                                             « o terminal continua em português

Isso é muito útil para pesquisar uma mensagem de erro na internet: a versão em inglês tem muito mais resultados. Outro exemplo, com uma variável nossa:

$ nome=Bruno bash -c 'echo "Filho vê: $nome"'
Filho vê: Bruno
$ echo "Pai vê: [$nome]"
Pai vê: []                            « no terminal, nome nem chegou a existir

O programa env também sabe fazer isso: env cor=azul comando é o mesmo que cor=azul comando. A forma sem env é a mais comum no Bash.

Não funciona com o echo $VAR na mesma linha

nome=Bruno echo "$nome" mostra vazio. Por quê? O $nome é trocado pelo valor antes de o comando rodar, quando nome ainda não existe. A atribuição temporária vai para o ambiente do comando, e o echo não lê o ambiente: ele só imprime o que recebeu. Por isso os exemplos acima usam bash -c '…' com aspas simples.

Escopo: o script filho não altera o pai

Esta é a regra que mais confunde quem começa: um script rodado com bash script.sh ou ./script.sh é um processo filho. Ele recebe uma cópia do ambiente, pode mudar a cópia à vontade, e quando termina a cópia é jogada fora. O terminal (o pai) nunca vê as mudanças, nem com export.

Vamos provar com este script:

echo "No script, antes: cidade=[$cidade]"
cidade=Manaus
export cidade
echo "No script, depois: cidade=[$cidade]"
LinhaO que faz
1Mostra o valor que o script recebeu ao começar.
2Muda o valor dentro do script.
3Exporta. Isso só afeta os filhos do script, não o pai dele.
4Mostra o valor novo.
$ cidade=Recife
$ bash muda.sh
No script, antes: cidade=[]                 « não exportada: o script não recebeu
No script, depois: cidade=[Manaus]
$ echo "No terminal: cidade=[$cidade]"
No terminal: cidade=[Recife]                « o terminal não mudou
$ export cidade
$ bash muda.sh
No script, antes: cidade=[Recife]           « agora o script recebeu a cópia
No script, depois: cidade=[Manaus]
$ echo "No terminal: cidade=[$cidade]"
No terminal: cidade=[Recife]                « e mesmo assim o terminal não mudou
  terminal (pai)            script (filho)
  cidade=Recife  ── cópia ──►  cidade=Recife
                               cidade=Manaus   (muda só a cópia)
  cidade=Recife  ◄── nada ──   (fim: a cópia some)

O ambiente só desce, de pai para filho. Nunca sobe.

E se eu quiser que o script mude o terminal?

Então não rode o script como filho: peça ao próprio Bash para ler e executar as linhas, com source (ou o ponto, ., que é o mesmo comando).

$ source muda.sh
No script, antes: cidade=[Recife]
No script, depois: cidade=[Manaus]
$ echo "No terminal: cidade=[$cidade]"
No terminal: cidade=[Manaus]                « agora mudou, porque não houve filho

É assim que funciona o source ~/.bashrc depois de editar o arquivo de configuração (veja Arquivos de Inicialização). As diferenças entre bash script.sh, ./script.sh e source estão em Formas de Executar.

Como confirmar que existe um filho

$$ é o número do processo (PID) do Bash atual. Compare: echo $$ e bash -c 'echo $$' mostram números diferentes (na máquina da Ana deu 24163 e 24167; na sua, serão outros). Números diferentes = processos diferentes = cadernos diferentes.

declare: variáveis com atributos

O comando declare cria variáveis e dá a elas atributos, como "só aceita número" ou "sempre em maiúsculas". Cada atributo é uma letra depois do -. O nome typeset é um sinônimo antigo (vem do ksh).

OpçãoOrigem do nomeO que faz
-iinteger (inteiro)Toda atribuição é calculada como conta.
-rreadonly (só leitura)Não pode mais ser mudada nem apagada.
-xexportO mesmo que export.
-llowercaseConverte o valor para minúsculas.
-uuppercaseConverte o valor para maiúsculas.
-pprintMostra a variável e os atributos.

Para tirar um atributo, troque o - por +: declare +x cidade desexporta (como export -n). O -a e o -A criam arrays e arrays associativos, vistos no Nível 3.

declare -i: a variável faz contas sozinha

$ declare -i total
$ total=5+3
$ echo $total
8                                     « sem o -i, ficaria o texto "5+3"
$ total=total*2
$ echo $total
16                                    « dentro da conta, o nome já vale o número
$ total=abc
$ echo $total
0                                     « "abc" foi lido como variável inexistente = 0

Repare na terceira atribuição: abc não deu erro, virou 0. Isso acontece porque, numa conta, uma palavra é tratada como nome de variável, e uma variável que não existe vale zero. Já um texto com espaço quebra a conta:

$ total="10 laranjas"
bash: 10 laranjas: erro de sintaxe aritmética na expressão (token de erro é "laranjas")
$ echo $?
1

As contas em si ($(( )), let, divisão inteira) são o assunto de Contas.

declare -l e -u: minúsculas e maiúsculas

$ declare -l cidade=RECIFE
$ echo $cidade
recife
$ declare -u sigla=pe
$ echo $sigla
PE
$ sigla+=ba
$ echo $sigla
PEBA                                  « o atributo continua valendo nas próximas atribuições

Útil para padronizar respostas do usuário (sim, Sim, SIM viram todas sim). O operador += acrescenta texto ao final. Esses atributos não existem no Bash 3.2 do macOS bash 4.0+.

declare -r e readonly: constantes

Uma variável só de leitura é uma constante: o valor fica fixo até o shell terminar.

$ declare -r PI=3.14
$ PI=3
bash: PI: a variável permite somente leitura
$ echo $?
1
$ unset PI
bash: unset: PI: impossível remover definição: variable somente-leitura
$ readonly SITE=guia
$ SITE=outro
bash: SITE: a variável permite somente leitura

readonly NOME=valor e declare -r NOME=valor fazem a mesma coisa. A mensagem do unset mistura português e inglês ("variable") porque a tradução do Bash está incompleta: é assim mesmo. Não há como "destravar" uma constante: só fechando o terminal (num script, ela some quando o script termina). readonly -p lista todas, inclusive as do próprio Bash, como UID.

declare -p: o raio-x

$ declare -p total cidade sigla
declare -i total="0"
declare -l cidade="recife"
declare -u sigla="PEBA"
$ declare -p nome
bash: declare: nome: não encontrado      « a variável não existe

Missão: o script abaixo mostra 7*6 em vez do resultado. Sem usar $(( )), faça ele mostrar 42 dando um atributo à variável conta.

#!/usr/bin/env bash
conta=7*6
echo "$conta"

#!/usr/bin/env bash
declare -i conta
conta=7*6
echo "$conta"

Missão: crie a variável sigla de um jeito que, ao digitar sigla=sp (em minúsculas), ela guarde SP. Confira com declare -p sigla.

Apagar: unset

unset (desfazer a definição) apaga a variável de verdade. Depois dele, ela não existe mais, nem vazia.

$ nome=Ana
$ unset nome
$ echo "[$nome]"
[]
$ declare -p nome
bash: declare: nome: não encontrado

Há uma diferença sutil entre vazia (nome=, existe com valor "") e inexistente (depois do unset). O echo mostra as duas iguais, mas declare -p e os testes [[ -v nome ]] distinguem. Essa diferença volta em Expansão de Parâmetros, com ${nome-padrão} e ${nome:-padrão}.

Apagar uma variável exportada também a tira do ambiente dos próximos filhos:

$ export cor=verde
$ unset cor
$ bash -c 'echo "cor no filho: [$cor]"'
cor no filho: []

Nomes válidos

Um nome de variável pode ter letras sem acento, números e _, e não pode começar com número. Maiúsculas e minúsculas são diferentes: nome, Nome e NOME são três variáveis.

NomeVálido?Por quê
nome, _ok, Nome2, total_geralSimLetras, números e _, começando com letra ou _.
2xNãoComeça com número.
meu-nomeNãoO hífen não é permitido. Use meu_nome.
preçoNãoLetra acentuada. Use preco.

Quando o nome é inválido, o Bash não reconhece aquilo como atribuição e tenta rodar a linha inteira como se fosse um comando:

$ 2x=5
bash: 2x=5: comando não encontrado
$ meu-nome=Ana
bash: meu-nome=Ana: comando não encontrado

Onde o nome termina

Ao ler $corclaro, o Bash procura a variável corclaro inteira, não cor seguida de "claro". Use chaves para marcar o fim do nome:

$ cor=azul
$ echo "$corclaro"
                                      « linha vazia: corclaro não existe
$ echo "${cor}claro"
azulclaro

Quando não funciona

"comando não encontrado" ao criar a variável 
$ nome = Ana
bash: nome: comando não encontrado
$ nome= Ana
bash: Ana: comando não encontrado

O que aconteceu: com espaço antes do =, o Bash entendeu nome como um comando com os argumentos = e Ana. Com espaço só depois, entendeu "rode o comando Ana com a variável nome vazia" (é a forma VAR=valor comando!).

Como resolver: nenhum espaço em volta do =: nome=Ana. Se o valor tiver espaço, use aspas: nome="Ana Souza".

O script não "vê" a variável que criei no terminal 
$ cidade=Recife
$ bash muda.sh
No script, antes: cidade=[]

O que aconteceu: a variável é só de shell; o script é um filho e não a recebeu.

Como confirmar: declare -p cidade mostra declare -- (sem -x).

Como resolver: export cidade, ou passe só para aquele comando: cidade=Recife bash muda.sh. Melhor ainda, para scripts: passe como argumento.

Rodei o script, mas a variável não mudou no terminal

O que aconteceu: é o escopo. O script é um filho e as mudanças dele morrem com ele, mesmo com export.

Como resolver: se a ideia é configurar o terminal, rode com source script.sh. Se a ideia é obter um valor, faça o script imprimir o valor e capture com valor=$(bash script.sh) (veja Substituição de Comando).

"a variável permite somente leitura" 
$ PI=3
bash: PI: a variável permite somente leitura

O que aconteceu: a variável foi criada com readonly ou declare -r (por você, por um script carregado com source ou pelo próprio Bash, como UID).

Como resolver: use outro nome. Não existe "desligar" o -r: num terminal, só abrindo um novo.

Não apareceu nada (linha vazia)

O que aconteceu: a variável não existe ou está vazia, e o Bash não reclama disso. Causas comuns: erro de digitação ($nmoe), maiúscula/minúscula trocada ($Nome), nome colado em texto ($corclaro) ou variável criada num filho.

Como confirmar: declare -p nome. Se responder "não encontrado", ela não existe neste shell. Em scripts, set -u transforma isso em erro (veja set -euo pipefail).

Resumo

  • Variável de shell fica no Bash atual; com export ela vira de ambiente e é copiada para os programas filhos.
  • env e printenv mostram o ambiente; declare -p mostra uma variável com seus atributos.
  • VAR=valor comando muda a variável só para aquele comando.
  • O ambiente só desce: um script filho nunca altera o terminal. Para isso, use source.
  • declare dá atributos (-i conta, -l/-u caixa, -r constante, -x exporta); unset apaga.
  • Nomes: letras sem acento, números e _, sem começar com número, sem espaço no =.
