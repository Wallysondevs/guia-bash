Bash ShellCheck

O ShellCheck é um programa que lê o seu script e aponta erros antes de você rodá-lo: aspas esquecidas, cd sem checagem, variáveis com nome errado, armadilhas que só aparecem com um nome de arquivo com espaço. É como ter um colega experiente revisando cada linha. É gratuito, funciona no terminal, no navegador e dentro do editor, e todo script sério deveria passar por ele.

Você vai aprender
  • A instalar o ShellCheck e a usá-lo sem instalar nada (shellcheck.net).
  • A ler a saída: linha, coluna, código SCxxxx, gravidade e sugestão.
  • O que significam e como corrigir os avisos mais comuns.
  • A desligar um aviso de propósito (# shellcheck disable=, .shellcheckrc).
  • As opções -S, -x, -s, -f gcc e -f diff.

O que é e por que usar

O Bash aceita muita coisa que "funciona por acaso": mv $f $destino funciona com foto.jpg e quebra com foto de férias.jpg. Você só descobre quando acontece. O ShellCheck faz uma análise estática: ele lê o código sem executá-lo (como o bash -n de Depurar), mas, em vez de checar só a gramática, conhece centenas de erros e más práticas.

  • Cada aviso tem um código (SC2086, SC2164…) e uma página explicativa na wiki do projeto.
  • Ele não muda o seu arquivo (a não ser que você peça, com -f diff).
  • As mensagens são em inglês; esta aula traduz e explica as mais comuns.

Os quatro avisos, traduzidos

SC2006 (style)
"Use $(...) em vez das crases antigas." As crases funcionam, mas não se aninham bem e se confundem com aspas. Veja Substituição de Comando.
SC2164 (warning)
"Use cd ... || exit caso o cd falhe." Se a pasta não existir, o mv roda na pasta errada. É o mesmo perigo do começo de Modo Estrito.
SC2010 (warning)
"Não use ls | grep. Use um curinga." A saída do ls é para humanos: nomes com espaço ou quebra de linha se partem. E o . do grep .jpg casa com qualquer caractere.
SC2086 (info)
"Use aspas duplas para evitar curingas e separação de palavras." Sem aspas, $f com o valor foto de férias.jpg vira três argumentos para o mv.

Repare que o ShellCheck não reclamou de $origem e $destino sem aspas: ele viu que os valores são fixos e sem espaços. Mesmo assim, aspas sempre são o hábito certo.

A versão corrigida

#!/usr/bin/env bash
# organiza.sh — move as fotos de Downloads para Imagens
set -euo pipefail
origem=~/Downloads
destino=~/Imagens
data=$(date +%F)
cd "$origem" || exit 1
for f in *.jpg; do
  [[ -e $f ]] || continue
  mv -- "$f" "$destino"/
done
echo "Fotos movidas em $data"

$ shellcheck organiza.sh
$ echo $?
0                                              « silêncio e código 0: nenhum aviso

O for f in *.jpg usa o curinga direto, sem ls. A linha [[ -e $f ]] || continue trata o caso de não haver nenhuma foto: aí o curinga não casa e $f fica com o texto literal *.jpg.

Missão: o simulador não tem o ShellCheck, mas você já leu os avisos acima. Corrija o script: troque as crases por $( ), acrescente || exit 1 ao cd (com "$origem" entre aspas) e ponha aspas em "$f". Se quiser ir além, troque o $(ls | grep .jpg) por *.jpg. Rode: a foto.jpg deve ir de Downloads para Imagens.

Desligar um aviso de propósito

Às vezes você sabe o que está fazendo. Por exemplo, numa variável com várias opções, você quer que ela se parta nos espaços. Diga isso ao ShellCheck com um comentário especial na linha de cima:

#!/bin/bash
opcoes="-l -h"
# shellcheck disable=SC2086  # quero mesmo separar as opções
ls $opcoes ~/Documentos

$ shellcheck desliga.sh
$ echo $?
0
# shellcheck
Um comentário para o ShellCheck (o Bash o ignora).
disable=SC2086
Desliga esse aviso só no comando seguinte. Vários: disable=SC2086,SC2046.
# quero mesmo…
Explique o porquê. Daqui a seis meses, você vai agradecer.

Colocado logo depois do shebang, antes do primeiro comando, o disable vale para o arquivo inteiro. Mesmo assim, prefira resolver o problema; neste exemplo, o melhor seria um array: opcoes=(-l -h); ls "${opcoes[@]}" ~/Documentos (veja Arrays).

Configuração para o projeto: .shellcheckrc

Para regras que valem para todos os scripts de uma pasta, crie um arquivo .shellcheckrc nela (ou em ~/.config/shellcheckrc, para todos os seus projetos). Cada linha é uma diretiva, sem o # shellcheck:

# não reclamar de crases neste projeto antigo
disable=SC2006
# sempre seguir os arquivos de "source"
external-sources=true
# ligar um aviso opcional: exigir ${var} com chaves
enable=require-variable-braces

Os avisos opcionais (desligados por padrão) aparecem com shellcheck --list-optional.

Opções úteis

-S: só a partir de certa gravidade

-S (severity) esconde os avisos menos graves. Com -S warning, ficam só warning e error:

$ shellcheck -S warning organiza.sh

In organiza.sh line 6:
cd $origem
^--------^ SC2164 (warning): Use 'cd ... || exit' or 'cd ... || return' in case cd fails.

Did you mean:
cd $origem || exit


In organiza.sh line 7:
for f in $(ls | grep .jpg); do
           ^-- SC2010 (warning): Don't use ls | grep. Use a glob or a for loop with a condition to allow non-alphanumeric filenames.
…                                              « encurtado: o style (SC2006) e o info (SC2086) sumiram

-f gcc: uma linha por aviso

-f (format) muda o formato da saída. O formato gcc (o mesmo do compilador de C) põe tudo numa linha, arquivo:linha:coluna: gravidade: mensagem [código], ótimo para editores e para o grep:

$ shellcheck -f gcc organiza.sh
organiza.sh:5:6: note: Use $(...) notation instead of legacy backticks `...`. [SC2006]
organiza.sh:6:1: warning: Use 'cd ... || exit' or 'cd ... || return' in case cd fails. [SC2164]
organiza.sh:7:12: warning: Don't use ls | grep. Use a glob or a for loop with a condition to allow non-alphanumeric filenames. [SC2010]
organiza.sh:8:6: note: Double quote to prevent globbing and word splitting. [SC2086]

Nesse formato, info e style aparecem como note. Outros formatos: -f json1 (para programas), -f checkstyle (para ferramentas de CI), -f quiet (nada; só o código de saída).

-f diff: as correções prontas

Para os avisos que têm "Did you mean", o ShellCheck pode gerar um diff, um arquivo com as mudanças, que o programa patch aplica:

$ shellcheck -f diff organiza.sh
--- a/organiza.sh
+++ b/organiza.sh
@@ -2,9 +2,9 @@
 # organiza.sh — move as fotos de Downloads para Imagens
 origem=~/Downloads
 destino=~/Imagens
-data=`date +%F`
-cd $origem
+data=$(date +%F)
+cd $origem || exit
 for f in $(ls | grep .jpg); do
-  mv $f $destino
+  mv "$f" $destino
 done
 echo "Fotos movidas em $data"
$ shellcheck -f diff organiza.sh | patch -p1
patching file organiza.sh

Linhas com - saem, linhas com + entram. Repare que o ls | grep (SC2010) não foi corrigido: esse exige reescrever o laço, e só você pode decidir como. Revise sempre o diff antes de aplicar.

Com #!/bin/sh, o ShellCheck também aponta bashismos, recursos que não existem no sh (veja POSIX sh e Bashismos):

$ cat posix.sh
#!/bin/sh
if [[ -f frutas.txt ]]; then
  echo "${HOME,,}"
fi
$ shellcheck -f gcc posix.sh
posix.sh:2:4: warning: In POSIX sh, [[ ]] is undefined. [SC3010]
posix.sh:3:9: warning: In POSIX sh, case modification is undefined. [SC3059]

No editor (ilustrativo)

O melhor jeito de usar o ShellCheck é deixá-lo rodando enquanto você digita: o editor sublinha o problema na hora, como um corretor ortográfico. Os nomes abaixo são os mais conhecidos; os detalhes de instalação mudam com o tempo, então siga a documentação de cada um.

EditorComo
VS Code / VSCodiumExtensão "ShellCheck" (de Timon Wong), ou a "Bash IDE", que usa o ShellCheck por baixo.
Vim / NeovimPlugins como ALE ou nvim-lint; ou :!shellcheck % para rodar no arquivo aberto.
EmacsFlycheck (já reconhece o ShellCheck).
Qualquer umO bash-language-server integra o ShellCheck em editores que falam LSP.
Antes de cada commitUm hook do Git (ou o pre-commit) roda shellcheck *.sh e impede o commit se houver avisos.

Quando não funciona

"shellcheck: comando não encontrado"

O que aconteceu: ele não vem instalado por padrão na maioria dos sistemas.

Como resolver: instale pela tabela acima, ou use o site shellcheck.net.

SC2148: "Tips depend on target shell and yours is unknown" 
$ shellcheck sem-shebang.sh

In sem-shebang.sh line 1:
echo "oi"
^-- SC2148 (error): Tips depend on target shell and yours is unknown. Add a shebang or a 'shell' directive.

O que aconteceu: o arquivo não tem shebang, e o ShellCheck não sabe se deve julgar como Bash ou sh.

Como resolver: acrescente #!/usr/bin/env bash. Para arquivos que só são carregados com source (sem shebang de propósito), use # shellcheck shell=bash na primeira linha, ou shellcheck -s bash.

Variáveis "não usadas" que vêm de outro arquivo (SC2034/SC2154)

O que aconteceu: as variáveis são definidas num arquivo carregado com source, e o ShellCheck não o abriu (SC1091).

Como resolver: shellcheck -x script.sh. Se o caminho do source é variável (SC1090), indique o arquivo com # shellcheck source=./config.sh na linha de cima.

O ShellCheck não reclamou, mas o script está errado

O que aconteceu: ele acha padrões de erro, não erros de lógica. "Somar em vez de subtrair" ou "o arquivo errado" passam sem aviso.

Como resolver: teste o script de verdade e depure com bash -x (Depurar).

Resumo

  • O ShellCheck lê o script sem executá-lo e aponta erros e más práticas, cada um com um código SCxxxx e uma página na wiki.
  • Os campeões: SC2086/SC2046 (aspas), SC2164 (cd sem ||), SC2006 (crases), SC2155 (local x=$( )), SC2162 (read sem -r), SC2181 ($?), SC2010 (ls | grep).
  • # shellcheck disable=SCxxxx desliga um aviso no comando seguinte; .shellcheckrc configura a pasta toda. Explique sempre o porquê.
  • -S warning filtra por gravidade, -f gcc dá uma linha por aviso, -f diff gera as correções, -x segue os source.
  • Instale (ou use shellcheck.net) e ligue no editor: é o hábito que mais melhora seus scripts.
