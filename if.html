Bash if, elif, else

O if ("se", em inglês) faz o script tomar decisões: se o arquivo existe, copie; senão, avise. No Bash ele tem uma particularidade que muda tudo: o if não testa uma "condição", ele roda um comando e olha o código de saída. Entendendo isso, você entende qualquer if.

Você vai aprender
  • A estrutura if / then / fi, e os ramos else e elif.
  • Que o if testa o código de saída de qualquer comando (if grep -q, if mkdir), não só [ ].
  • Escrever em uma linha ou em várias, e quando usar if aninhado, elif ou &&.
  • Ler os erros de sintaxe reais: falta de then, de ;, de fi.

A forma mais simples

Antes de copiar a lista de frutas, a Ana quer ter certeza de que ela existe. Em português: "se frutas.txt é um arquivo, então mostre 'Achei a lista', fim".

if COMANDO; then
  COMANDOS que rodam quando o COMANDO deu certo (código 0)
fi
if
"Se": rode o comando a seguir e olhe o código de saída.
[[ -f frutas.txt ]]
O comando testado. Aqui, um teste de arquivo.
;
Separa o comando do then quando estão na mesma linha.
then
"Então": o que vem a seguir roda se o código foi 0.
echo "Achei a lista"
O corpo do if.
fi
Fim do if. É if escrito ao contrário.
$ if [[ -f frutas.txt ]]; then echo "Achei a lista"; fi
Achei a lista
$ if [[ -f compras.txt ]]; then echo "Achei"; fi
$ echo $?
0                        « não apareceu nada, e o código é 0

No segundo caso o teste deu "falso", então o corpo não rodou e nada apareceu. O if inteiro devolve 0 quando nenhum ramo roda: não "achar" não é um erro.

Uma linha × várias linhas

No terminal, é prático escrever tudo numa linha, com ; separando as partes. Em scripts, o costume é uma parte por linha, com o corpo recuado (2 ou 4 espaços). As duas formas fazem a mesma coisa:

Uma linhaVárias linhas
if [[ -f a ]]; then echo ok; fi
if [[ -f a ]]; then
  echo ok
fi

A regra: then e fi precisam começar um "comando novo", ou seja, vir depois de um ; ou de uma quebra de linha. Por isso, em várias linhas, o ; antes do then só é necessário se o then estiver na mesma linha do if. Quando você digita várias linhas no terminal, o Bash mostra o prompt > até o fi:

$ if [[ -f compras.txt ]]; then
>   echo "Achei"
> else
>   echo "Não achei compras.txt"
> fi
Não achei compras.txt

O if testa o código de saída de qualquer comando

Aqui está o segredo. O if não sabe o que é "condição". Ele roda o comando que você escreveu e olha o $?: 0 → entra no then; qualquer outro número → não entra. Os testes [ ] e [[ ]] são apenas comandos que devolvem 0 ou 1. Qualquer comando serve.

if grep -q

O grep devolve 0 quando acha o texto e 1 quando não acha. A opção -q (quiet, "quieto") faz ele não mostrar as linhas: só o código importa.

$ grep -q uva frutas.txt; echo $?
0
$ grep -q kiwi frutas.txt; echo $?
1
$ if grep -q uva frutas.txt; then echo "Tem uva"; fi
Tem uva

Repare que não há colchetes: if [ grep -q uva frutas.txt ] estaria errado, porque aí você testaria o texto "grep", e não rodaria o grep.

if mkdir

Muitos comandos já dizem se deram certo. Em vez de perguntar antes ("a pasta existe?") e agir depois, você pode agir e testar o resultado:

$ if mkdir relatorios; then echo "Pasta criada"; fi
Pasta criada
$ if mkdir relatorios; then echo "Pasta criada"; else echo "Não deu para criar"; fi
mkdir: cannot create directory ‘relatorios’: Arquivo existe
Não deu para criar

Na segunda vez, o mkdir falhou (código 1) e o if foi para o else. A mensagem de erro é do próprio mkdir, e vem metade em inglês porque a tradução dele está incompleta. Para escondê-la, use mkdir relatorios 2>/dev/null.

Negar: if ! comando

O ! antes do comando inverte o código: sucesso vira falha e vice-versa.

$ if ! grep -q kiwi frutas.txt; then echo "Falta kiwi"; fi
Falta kiwi
Depois do ifPergunta
[[ -f arq ]]O arquivo existe? (Testes)
(( n > 5 ))A conta é verdadeira? (Contas)

Missão: escreva um if de uma linha que mostre Tem banana se o arquivo frutas.txt contém a palavra banana. Use o grep -q direto no if, sem colchetes.

Senão: else

O else ("senão") é o caminho para quando o comando falha. Só um dos dois blocos roda, nunca os dois.

if COMANDO; then
  roda quando deu certo
else
  roda quando falhou
fi

Missão: o script diz "par" quando o número é par, mas com 7 não mostra nada. Acrescente um else que mostre ímpar. Teste com outros números no campo de argumentos.

#!/usr/bin/env bash
n=$1
if (( n % 2 == 0 )); then
  echo "$n é par"
fi

#!/usr/bin/env bash
n=$1
if (( n % 2 == 0 )); then
  echo "$n é par"
else
  echo "$n é ímpar"
fi

Várias possibilidades: elif

Quando há mais de dois caminhos, use elif (else if, "senão, se"). O Bash testa na ordem, de cima para baixo, e roda só o primeiro bloco cujo comando deu certo. O else final é opcional e pega "todo o resto".

$ nota=8
$ if (( nota >= 9 )); then
>   echo "Excelente"
> elif (( nota >= 7 )); then
>   echo "Aprovado"
> else
>   echo "Reprovado"
> fi
Aprovado

Com nota=8: o primeiro teste (8 >= 9) falhou; o segundo (8 >= 7) deu certo, então "Aprovado" apareceu e o Bash pulou direto para o fi, sem olhar o else. A ordem importa: se o >= 7 viesse primeiro, uma nota 10 também cairia em "Aprovado".

Missão: o script separa menores e adultos. Acrescente um elif para que idades de 60 em diante mostrem Idoso. Pense na ordem dos testes! Experimente com 15, 30 e 65.

#!/usr/bin/env bash
idade=$1
if (( idade < 18 )); then
  echo "Menor de idade"
else
  echo "Adulto"
fi

#!/usr/bin/env bash
idade=$1
if (( idade < 18 )); then
  echo "Menor de idade"
elif (( idade >= 60 )); then
  echo "Idoso"
else
  echo "Adulto"
fi

Exemplo 1: conferir antes de copiar

A Ana quer um script que copie um arquivo para a pasta backup, mas que avise se o arquivo não existe e que não sobrescreva uma cópia que já está lá.

#!/usr/bin/env bash
origem=${1:?Uso: copiar.sh ARQUIVO}
destino=backup

if [[ ! -f $origem ]]; then
  echo "Erro: $origem não existe" >&2
  exit 1
fi

mkdir -p "$destino"
if [[ -e $destino/${origem##*/} ]]; then
  echo "Já existe uma cópia em $destino/"
else
  cp "$origem" "$destino/" && echo "Copiado para $destino/"
fi

2Pega o 1º argumento; se faltar, para com a mensagem de uso (:?).
5Se não (!) é um arquivo…
6–7…mostra o erro no canal de erros (>&2) e encerra com código 1. Esse padrão, "testa o problema e sai cedo", evita ifs dentro de ifs.
10Cria a pasta de destino (-p: sem erro se já existe).
11Se já existe algo com o mesmo nome no destino (${origem##*/} é o nome do arquivo sem as pastas)…
12…só avisa.
14Senão, copia, e só se a cópia deu certo (&&) mostra a confirmação.
$ bash copiar.sh Documentos/notas.txt
Copiado para backup/
$ bash copiar.sh Documentos/notas.txt
Já existe uma cópia em backup/
$ bash copiar.sh compras.txt
Erro: compras.txt não existe
$ echo $?

Exemplo 2: a situação de um aluno no alunos.csv

O arquivo Documentos/alunos.csv tem uma linha por aluno: nome,idade,cidade,nota. O script procura o aluno, separa os campos e decide a situação pela nota.

#!/usr/bin/env bash
nome=${1:?Uso: aluno.sh NOME}
linha=$(grep "^$nome," Documentos/alunos.csv)

if [[ -z $linha ]]; then
  echo "$nome não está na lista"
  exit 1
fi

idade=$(echo "$linha" | cut -d, -f2)
nota=$(echo "$linha" | cut -d, -f4)
inteira=${nota%.*}

echo "$nome tem $idade anos e tirou $nota"
if (( inteira >= 9 )); then
  echo "Situação: excelente"
elif (( inteira >= 7 )); then
  echo "Situação: aprovado"
else
  echo "Situação: recuperação"
fi
LinhaO que faz
3Guarda a linha do aluno ($( )). O ^ e a vírgula garantem que "Ana" não case com "Mariana".
5–8Se a linha veio vazia (-z), o aluno não existe: avisa e sai com código 1.
10–11cut -d, -f2 pega o 2º campo, separando por vírgula (idade); -f4 pega a nota.
12A nota é decimal (9.5) e (( )) só aceita inteiros: ${nota%.*} corta do ponto em diante e fica 9.
15–21O if/elif/else escolhe a situação.

$ bash aluno.sh Bruno

Situação: aprovado
$ bash aluno.sh Diego

if aninhado × elif × &&

Um if pode ficar dentro de outro (aninhado). Funciona, mas cada nível empurra o código para a direita:

$ idade=29
$ if (( idade >= 18 )); then
>   if (( idade >= 60 )); then
>     echo "Idoso"
>   else
>     echo "Adulto"
>   fi
> else
>   echo "Menor"
> fi
Adulto

Cada if precisa do seu próprio fi. O mesmo resultado, com elif, fica numa "escada" só, mais fácil de ler (é a solução da missão do idade.sh). Quando as duas condições precisam ser verdadeiras ao mesmo tempo, junte-as no mesmo teste: if [[ -f frutas.txt && -s frutas.txt ]].

O atalho && / || e sua armadilha

Para coisas curtas, comando && ação é um "if sem else" (veja ; && ||). Muita gente escreve A && B || C como se fosse um if/else, mas não é:

$ [[ -f frutas.txt ]] && echo "existe" || echo "não existe"
existe
$ [[ -f frutas.txt ]] && grep kiwi frutas.txt || echo "frutas.txt não existe"
frutas.txt não existe            « mentira! o arquivo existe; quem falhou foi o grep
$ if [[ -f frutas.txt ]]; then grep kiwi frutas.txt; else echo "frutas.txt não existe"; fi
                                 « o if faz o certo: o arquivo existe, o grep só não achou nada

No A && B || C, o C roda se A ou B falhar. Só é seguro quando B nunca falha (como um echo).

FormaMelhor quando…
cmd && açãoUma ação curta, sem "senão". Ex.: [[ -d tmp ]] || mkdir tmp.
if … then … fiMais de uma ação, ou quando a clareza importa.
if … else … fiDois caminhos. Prefira esta forma a A && B || C.
if … elif … else … fiTrês ou mais caminhos com condições diferentes (faixas de nota, de idade).
if aninhadoQuando o segundo teste só faz sentido depois do primeiro (ex.: o arquivo existe → então leia e teste o conteúdo).
caseComparar um valor com várias opções ou padrões (start|stop, *.jpg).

Quando não funciona

Faltou o then 
#!/usr/bin/env bash
if [[ -f frutas.txt ]]
  echo "Achei"
fi

$ bash e1.sh
e1.sh: linha 4: erro de sintaxe próximo ao token inesperado `fi'
e1.sh: linha 4: `fi'

O que aconteceu: o Bash leu o if, depois o echo (achando que ainda fazia parte da condição), e encontrou um fi sem ter visto o then. Repare que o erro aponta para a linha 4 (onde ele percebeu o problema), não para a 2 (onde está o problema). O código de saída é 2 e nenhuma linha do script rodou.

Como resolver: if [[ -f frutas.txt ]]; then.

Faltou o ; antes do then 
$ if [ -f frutas.txt ] then echo "Achei"; fi
bash: erro de sintaxe próximo ao token inesperado `fi'

O que aconteceu: sem o ;, a palavra then virou mais um argumento do comando [, e o Bash continuou procurando o then de verdade. Com [[ ]] o erro às vezes some, porque o ]] encerra o teste; mas não conte com isso.

Como resolver: if [ -f frutas.txt ]; then …. O mesmo vale para o fi na mesma linha: echo "Achei"; fi.

Faltou o fi 
#!/usr/bin/env bash
if [[ -f frutas.txt ]]; then
  echo "Achei"

echo "fim"

$ bash e3.sh
e3.sh: linha 6: erro de sintaxe: fim inesperado do arquivo do comando `if' na linha 2

O que aconteceu: o Bash chegou ao fim do arquivo procurando o fi do if que começou na linha 2. Desta vez a mensagem ajuda: diz onde o if começou. No terminal, o sintoma é o prompt > esperando para sempre: digite fi ou aperte Ctrl+C.

Como resolver: feche cada if com um fi. Recuar o corpo ajuda a ver qual ficou aberto.

else if e elseif 
#!/usr/bin/env bash
if [[ -f frutas.txt ]]; then
  echo a
elseif [[ -d x ]]; then
  echo b
fi

$ bash e6.sh
e6.sh: linha 4: erro de sintaxe próximo ao token inesperado `then'
e6.sh: linha 4: `elseif [[ -d x ]]; then'

O que aconteceu: elseif (de outras linguagens) não existe no Bash: ele achou que era um comando, e o then ficou sobrando. Já else if (separado) abre um novo if dentro do else, que precisa de outro fi; esquecê-lo dá o erro "fim inesperado do arquivo".

Como resolver: use elif.

Bloco vazio 
#!/usr/bin/env bash
if [[ -f frutas.txt ]]; then
fi

$ bash e4.sh
e4.sh: linha 3: erro de sintaxe próximo ao token inesperado `fi'
e4.sh: linha 3: `fi'

O que aconteceu: o then foi seguido direto pelo fi. O Bash não aceita um bloco sem nenhum comando.

Como resolver: se for de propósito (algo a fazer depois), use o comando :, que não faz nada: then :.

O if sempre vai para o else (ou nunca)

O que aconteceu: o comando testado deu um código diferente do que você imaginava. Causas comuns: um teste escrito errado (que devolve 2, com uma mensagem como [: faltando `]' ou [-f: comando não encontrado), colchetes em volta de um comando (if [ grep … ]) ou números comparados com <.

Como confirmar: rode o comando do if sozinho e depois echo $?.

Resumo

  • if CMD; then …; fi: roda o bloco se o CMD devolveu código 0. fi é if ao contrário.
  • Qualquer comando serve: [[ ]], (( )), grep -q, mkdir… e ! inverte.
  • else pega o caso contrário; elif testa outra condição, e só o primeiro bloco verdadeiro roda.
  • then e fi vêm depois de ; ou de quebra de linha. Erros de sintaxe apontam para onde o Bash percebeu, não onde está o erro.
  • A && B || C não é if/else: use if quando houver dois caminhos.
