Bash mapfile e readarray

O mapfile lê um arquivo (ou a saída de um comando) e guarda cada linha num elemento de um array, de uma vez só. É a forma mais curta e mais segura de transformar "um texto com várias linhas" em "uma lista que o script pode percorrer, contar e indexar". O readarray é o mesmo comando com outro nome. bash 4.0+

Você vai aprender
  • Ler um arquivo inteiro para um array com mapfile -t, e por que o -t quase sempre é obrigatório.
  • Pegar só algumas linhas (-n), pular o cabeçalho (-s) e trocar o separador (-d, inclusive -d '' com find -print0).
  • Ler a saída de um comando com < <(comando), e por que comando | mapfile "não guarda nada".
  • Quando usar mapfile e quando usar while read.

O problema: um arquivo, várias linhas

A Ana tem uma lista de tarefas em Documentos/notas.txt, uma por linha. Ela quer um script que mostre as tarefas numeradas, diga quantas são e consiga pegar "a terceira tarefa" sem ler o arquivo de novo. Para isso, o ideal é ter as linhas num array: tarefas[0] é a primeira, tarefas[1] a segunda, e assim por diante.

Você poderia montar o array à mão, com um laço while read e um += a cada volta (veja Ler Arquivos Linha a Linha). Funciona, mas são quatro linhas para uma tarefa tão comum. O mapfile faz isso numa linha só.

O nome vem do inglês map file, "mapear o arquivo" (para um array). O sinônimo readarray quer dizer "ler para um array". Os dois são comandos internos do Bash, não programas separados:

$ type mapfile readarray
mapfile é um comando interno do shell
readarray é um comando interno do shell

A forma mais simples: mapfile -t nome < arquivo

mapfile
O comando: lê linhas da entrada padrão e guarda cada uma num elemento.
-t
Tira (trim) a quebra de linha do fim de cada elemento. Explicado logo abaixo.
linhas
O nome do array que vai ser criado (ou substituído). Sem $: você está dando um nome, não lendo um valor.
< frutas.txt
Um redirecionamento: a entrada padrão do mapfile passa a ser o arquivo.
$ mapfile -t linhas < frutas.txt
$ declare -p linhas
declare -a linhas=([0]="banana" [1]="maçã" [2]="laranja" [3]="banana" [4]="uva" [5]="maçã" [6]="banana")

O primeiro comando não mostra nada: o mapfile só guarda. Para ver o que ficou no array usamos declare -p (print), que mostra a variável do jeito que o Bash a enxerga:

  • declare -a diz que linhas é um array indexado (array).
  • Cada [número]="texto" é um elemento. O primeiro é o [0], não o [1].
  • São 7 elementos, um por linha de frutas.txt, na mesma ordem do arquivo. As repetidas (banana aparece três vezes) continuam repetidas.

Agora o array se usa como qualquer outro:

$ echo "${#linhas[@]} linhas"
7 linhas                       « ${#nome[@]} = quantos elementos
$ echo "${linhas[2]}"
laranja                        « o índice 2 é a TERCEIRA linha
$ echo $?
0

O mapfile devolve 0 quando leu o arquivo sem problema, mesmo que ele esteja vazio (o array fica com 0 elementos). Se o arquivo não existe, quem reclama é o shell, ao preparar o <, e o código é 1:

$ mapfile -t x < nada.txt
bash: nada.txt: Arquivo ou diretório inexistente
$ echo $?
1

Por que o -t?

Sem o -t, cada elemento guarda a linha com o caractere de quebra de linha (\n) que existe no fim dela no arquivo. Veja a diferença no declare -p:

$ mapfile linhas < frutas.txt
$ declare -p linhas
declare -a linhas=([0]=$'banana\n' [1]=$'maçã\n' [2]=$'laranja\n' [3]=$'banana\n' [4]=$'uva\n' [5]=$'maçã\n' [6]=$'banana\n')

O $'banana\n' é a forma do Bash de escrever "banana seguida de uma quebra de linha". Isso estraga comparações e deixa linhas em branco a mais na tela:

$ [[ ${linhas[0]} == banana ]] && echo igual || echo diferente
diferente                      « "banana\n" não é igual a "banana"
$ echo "[${linhas[0]}]"
[banana
]                              « o \n guardado quebrou a linha
Regra prática

Use sempre mapfile -t. Sem o -t só faz sentido quando você quer reescrever as linhas exatamente como vieram, com printf '%s' "${linhas[@]}".

Percorrer o resultado

Com as linhas num array, numerar as tarefas da Ana fica fácil. O ${!tarefas[@]} devolve os índices (0, 1, 2, 3), e somamos 1 para mostrar a partir de 1:

$ readarray -t tarefas < Documentos/notas.txt
$ for i in "${!tarefas[@]}"; do echo "$((i+1)). ${tarefas[i]}"; done
1. Comprar café
2. Ligar para o João
3. Estudar Bash
4. Fazer backup das fotos

Repare que usamos readarray desta vez: o resultado é idêntico. Linhas com espaços ("Ligar para o João") continuam inteiras, num elemento só. Essa é a grande vantagem sobre tarefas=($(cat Documentos/notas.txt)), que quebraria cada palavra num elemento (veja o erro em Arrays).

Missão: leia Documentos/notas.txt para um array chamado tarefas (sem as quebras de linha) e mostre só a quarta tarefa com echo. Dica: a quarta tem índice 3.

Uma novidade por vez: as opções

-n: ler só as primeiras N linhas

mapfile
O comando.
-t
Sem a quebra de linha.
-n 2
Lê no máximo 2 linhas (number) e para. -n 0 = sem limite (o padrão).
primeiras
O array.
< frutas.txt
De onde ler.
$ mapfile -t -n 2 primeiras < frutas.txt
$ declare -p primeiras
declare -a primeiras=([0]="banana" [1]="maçã")

É o equivalente do head -n 2, mas o resultado já vai para um array. Útil para arquivos grandes, em que você só quer espiar o começo.

-s: pular as primeiras linhas (o cabeçalho)

O alunos.csv começa com uma linha de cabeçalho, nome,idade,cidade,nota, que não é um aluno. O -s 1 (skip, pular) descarta essa primeira linha:

$ mapfile -t -s 1 alunos < Documentos/alunos.csv
$ printf '%s\n' "${alunos[@]}"
Ana,29,Recife,9.5
Bruno,34,Curitiba,7.0
Carla,22,Salvador,8.5
Diego,41,Manaus,6.0
Elisa,27,Porto Alegre,10.0      « 5 alunos, sem o cabeçalho

O printf '%s\n' "${alunos[@]}" é o jeito seguro de mostrar um array, um elemento por linha: o printf repete o formato para cada elemento.

As opções combinam. -s 1 -n 2 = "pule 1 linha e depois leia 2":

$ mapfile -t -s 1 -n 2 dois < Documentos/alunos.csv
$ declare -p dois
declare -a dois=([0]="Ana,29,Recife,9.5" [1]="Bruno,34,Curitiba,7.0")

Missão: o script diz "6 alunos" e mostra "nome mora em cidade", porque leu o cabeçalho junto. Mude só a linha do mapfile para pular o cabeçalho e clique em Rodar. A saída deve começar com "5 alunos".

#!/usr/bin/env bash
mapfile -t alunos < Documentos/alunos.csv
echo "${#alunos[@]} alunos"
for linha in "${alunos[@]}"; do
  IFS=, read -r nome idade cidade nota <<< "$linha"
  echo "$nome mora em $cidade"
done

#!/usr/bin/env bash
mapfile -t -s 1 alunos < Documentos/alunos.csv
echo "${#alunos[@]} alunos"
for linha in "${alunos[@]}"; do
  IFS=, read -r nome idade cidade nota <<< "$linha"
  echo "$nome mora em $cidade"
done

Dentro do laço, o IFS=, read -r nome idade cidade nota <<< "$linha" divide cada linha nas vírgulas. Essa receita é explicada em Manipular Strings.

-d: outro separador em vez da quebra de linha

Por padrão, o mapfile corta o texto a cada \n. O -d (delimiter, delimitador) troca esse caractere. Com -d ,, cada pedaço entre vírgulas vira um elemento:

$ mapfile -t -d , campos < <(printf 'Ana,29,Recife,9.5')
$ declare -p campos
declare -a campos=([0]="Ana" [1]="29" [2]="Recife" [3]="9.5")

Com -d, o -t passa a remover o delimitador escolhido (a vírgula), não mais o \n. Por isso usamos printf, que não põe quebra de linha no fim. Com uma here-string (<<<), que sempre acrescenta um \n, o último campo vem "sujo":

$ mapfile -t -d , campos <<< "Ana,29,Recife,9.5"
$ declare -p campos
declare -a campos=([0]="Ana" [1]="29" [2]="Recife" [3]=$'9.5\n')     « o \n ficou no último

Para dividir uma única linha por vírgulas, IFS=, read -ra campos <<< "$linha" costuma ser mais simples (veja Manipular Strings). O -d brilha mesmo no caso seguinte.

-d '': nomes de arquivo com qualquer caractere

Nomes de arquivo podem ter espaços e até quebras de linha. O jeito 100% seguro de passar uma lista de nomes entre programas é separá-los pelo caractere nulo (o byte zero, que nenhum nome pode conter). O find -print0 faz isso, e o mapfile -d '' lê exatamente esse formato: '' (texto vazio) quer dizer "o delimitador é o nulo".

Para ver a diferença, a Ana cria um arquivo com espaços no nome dentro de Documentos:

$ touch "Documentos/lista de compras.txt"
mapfile -t
Lê sem o delimitador no fim.
-d ''
Corta no caractere nulo, não na quebra de linha.
docs
O array.
< <(find … -print0)
Lê a saída do find, que termina cada nome com um nulo. O <( ) é explicado logo abaixo.
$ mapfile -t -d '' docs < <(find Documentos -name '*.txt' -print0)
$ echo "${#docs[@]} arquivos"
2 arquivos
$ printf '[%s]\n' "${docs[@]}"
[Documentos/notas.txt]
[Documentos/lista de compras.txt]     « inteiro, com os espaços

Os colchetes no printf mostram onde cada elemento começa e termina. A ordem é a que o find encontrou no disco (não é alfabética). Compare com o jeito ingênuo, que separa nos espaços:

$ errado=($(find Documentos -name '*.txt'))
$ echo "${#errado[@]} arquivos"
4 arquivos                            « 4?! Há só 2 arquivos .txt
$ printf '[%s]\n' "${errado[@]}"
[Documentos/notas.txt]
[Documentos/lista]                    « "lista de compras.txt"
[de]                                  « virou três elementos
[compras.txt]

-O: continuar um array que já existe

Normalmente o mapfile apaga o array antes de preencher. O -O N (origin, origem) começa a gravar no índice N e mantém o que havia antes. Usando o tamanho atual como origem, você acrescenta no fim:

$ mapfile -t linhas < frutas.txt
$ mapfile -t -O "${#linhas[@]}" linhas < Documentos/notas.txt
$ echo "${#linhas[@]}"
11                             « 7 frutas + 4 tarefas

-C e -c: chamar uma função durante a leitura

Esta opção é rara, mas aparece em scripts por aí. O -C função (callback, "chamada de volta") faz o mapfile rodar uma função a cada -c N linhas lidas. A função recebe dois argumentos: o índice do elemento que vai ser gravado e a linha.

$ mostrar() { echo "lendo linha $1: $2"; }
$ mapfile -t -C mostrar -c 3 frutas < frutas.txt
lendo linha 2: laranja         « a cada 3 linhas…
lendo linha 5: maçã            « …a função é chamada
$ declare -p frutas
declare -a frutas=([0]="banana" [1]="maçã" [2]="laranja" [3]="banana" [4]="uva" [5]="maçã" [6]="banana")

O uso típico é mostrar progresso ("lidas 1000 linhas…") ao carregar arquivos enormes. Se você precisa processar cada linha, um laço for depois do mapfile é mais claro.

Sem nome: o array MAPFILE

Se você não der um nome, o resultado vai para o array MAPFILE (aqui sem -t, por isso o echo deixa uma linha em branco a mais):

$ mapfile < Documentos/notas.txt
$ echo "${#MAPFILE[@]}"
4
$ echo "${MAPFILE[0]}"
Comprar café
                               « a linha vazia é o \n guardado

Prefira sempre dar um nome que diga o que o array guarda.

Da saída de um comando: < <(comando)

Muitas vezes as linhas não estão num arquivo, mas na saída de um comando: ls, grep, find… Para isso, usamos a substituição de processo <(comando), que faz a saída do comando parecer um arquivo. O primeiro < é o redirecionamento de sempre; o segundo faz parte do <( ). O espaço entre eles é obrigatório.

$ mapfile -t contas < <(ls Downloads)
$ declare -p contas
declare -a contas=([0]="foto.jpg" [1]="fotos-viagem.zip" [2]="manual.pdf" [3]="musica.mp3" [4]="ubuntu-26.04-desktop-amd64.iso")

Os detalhes de como o <( ) funciona estão em Substituição de Processo.

Por que não comando | mapfile?

Parece o jeito óbvio, mas o array sai vazio:

$ ls Downloads | mapfile -t arquivos
$ echo "${#arquivos[@]}"
0                              « nada?!

O que aconteceu: cada lado de um pipe roda num subshell, uma cópia do shell. O mapfile encheu o array na cópia, e a cópia acabou junto com o pipe. O shell em que você digita nunca viu o array. Com < <(ls Downloads), quem roda à parte é o ls, e o mapfile fica no seu shell.

Em scripts, existe uma alternativa: shopt -s lastpipe faz o último comando do pipe rodar no shell atual. Ela só vale quando o controle de jobs está desligado, que é o normal num script (no terminal interativo não tem efeito):

#!/usr/bin/env bash
shopt -s lastpipe
ls Downloads | mapfile -t arquivos
echo "${#arquivos[@]} arquivos"

$ bash pipe.sh
5 arquivos

mapfile × while read: qual usar?

As duas formas leem linhas. A diferença é quando você trabalha com elas: o mapfile carrega tudo primeiro e você usa depois; o while read trata uma linha de cada vez, enquanto lê.

mapfile -t a < arqwhile IFS= read -r l; do …; done < arq
ResultadoUm array com todas as linhasUma linha por vez, na variável l
Tamanho do códigoUma linhaTrês ou mais linhas
MemóriaGuarda o arquivo inteiroGuarda só a linha atual
Contar, pegar a linha N, voltar atrásFácil: ${#a[@]}, ${a[N]}Precisa de contadores e variáveis extras
Dividir cada linha em camposPrecisa de um passo a mais (read no laço)Direto: while IFS=, read -r nome idade …
Última linha sem \n no fimÉ lida normalmenteÉ perdida, a não ser com || [[ -n $l ]]
Arquivos gigantes ou fluxo sem fim (tail -f)Ruim: espera tudo chegarBom: começa na hora
Bash4.0+Qualquer versão (até o sh)

Resumo da escolha: você precisa da lista inteira (contar, ordenar, acessar por posição, percorrer duas vezes)? mapfile. Vai tratar cada linha e esquecer? while read.

A linha "última linha sem \n" merece uma prova. O printf abaixo cria um arquivo cuja última linha não termina com quebra de linha (acontece com arquivos feitos em alguns editores):

$ printf 'um\ndois\ntrês' > semfim.txt
$ mapfile -t l < semfim.txt; declare -p l
declare -a l=([0]="um" [1]="dois" [2]="três")      « as 3 linhas
$ while read -r linha; do echo "$linha"; done < semfim.txt
um
dois                                               « o "três" sumiu

Quando não funciona

O array ficou vazio 
$ ls Downloads | mapfile -t arquivos
$ echo "${#arquivos[@]}"
0

O que aconteceu: o mapfile rodou no subshell do pipe; o array morreu com ele.

Como resolver: mapfile -t arquivos < <(ls Downloads). Em script, também serve shopt -s lastpipe.

As comparações falham e aparecem linhas em branco a mais 
$ mapfile linhas < frutas.txt
$ [[ ${linhas[0]} == banana ]] && echo igual || echo diferente
diferente

O que aconteceu: faltou o -t; cada elemento terminou com \n.

Como confirmar: declare -p linhas mostra $'banana\n'.

Como resolver: mapfile -t linhas < frutas.txt.

"mapfile: command not found" no Mac 
$ mapfile -t linhas < frutas.txt
bash: mapfile: command not found

O que aconteceu: o /bin/bash do macOS é a versão 3.2, anterior ao mapfile (que chegou no Bash 4.0). A saída acima é ilustrativa: o laboratório do guia usa o Bash 5.3.

Como confirmar: echo $BASH_VERSION.

Como resolver: instale um Bash novo (veja Bash em Cada Sistema) ou use a forma compatível: linhas=(); while IFS= read -r l; do linhas+=("$l"); done < frutas.txt.

"opção inválida" 
$ mapfile -t -z a < frutas.txt
bash: mapfile: -z: opção inválida
mapfile: uso: mapfile [-d delim] [-n número] [-O origem] [-s número] [-t] [-u fd] [-C chamada] [-c quantidade] [array]

O que aconteceu: o mapfile não tem -z (essa opção é de outros programas, como sort -z). A segunda linha mostra todas as opções válidas. Para ler nomes separados por nulo, use -d ''.

"lista de compras.txt" virou três elementos

O que aconteceu: o array foi montado com a=($(comando)), que separa nos espaços e ainda expande curingas.

Como resolver: mapfile -t a < <(comando) para uma linha por elemento, ou mapfile -t -d '' a < <(find … -print0) para nomes de arquivo.

Resumo

  • mapfile -t nome < arquivo põe cada linha num elemento; readarray é o mesmo comando. bash 4.0+
  • Use sempre o -t, senão cada elemento guarda o \n do fim.
  • -n limita, -s pula, -d troca o separador (-d '' com find -print0), -O acrescenta.
  • De um comando: mapfile -t a < <(comando). Com comando | mapfile o array some.
  • mapfile quando você precisa da lista inteira; while read para tratar linha a linha.
