Bash Opções do Shell

O Bash tem dezenas de "interruptores" que mudam o jeito como ele trabalha: parar no primeiro erro, mostrar cada comando antes de rodar, fazer o * entrar em subpastas, ignorar maiúsculas… Eles se ligam e desligam com dois comandos internos: set e shopt. Nesta aula você conhece os dois e as opções que mais fazem diferença no dia a dia.

Você vai aprender
  • A diferença entre set e shopt, e como ligar, desligar, listar e consultar opções.
  • As opções do set: -e, -u, -x, -f, -C, pipefail, posix, vi, e a variável $-.
  • As opções de curingas: nullglob, failglob, dotglob, globstar, extglob, nocaseglob.
  • Outras úteis: nocasematch, autocd, cdspell, histappend, lastpipe, inherit_errexit…
  • Onde ativar cada uma: no script ou no ~/.bashrc.

Cada linha tem o nome da opção e o estado (on/off). Para ver só algumas, passe os nomes:

$ shopt nullglob dotglob globstar extglob

O código de saída do shopt nomes… é 0 se todas estiverem ligadas e 1 se alguma estiver desligada. Para testar uma num if, use -q, que não mostra nada:

$ shopt -q extglob; echo $?
1                                  « 1 = desligada
$ shopt -p | head -5
shopt -u array_expand_once
shopt -u assoc_expand_once
shopt -u autocd
shopt -u bash_source_fullpath
shopt -u cdable_vars

O shopt -p mostra cada opção como o comando que a deixaria naquele estado. É útil para guardar e restaurar: antes=$(shopt -p nullglob), muda o que quiser e depois eval "$antes".

A variável $-

As opções de uma letra do set que estão ligadas aparecem juntas na variável especial $-:

$ echo $-
hiBHs
$ set -o noclobber; echo $-
hiBCHs                             « apareceu o C

hashall: lembra onde os comandos estão (PATH).
i
Shell interativo. Num script, não aparece. É o teste que o ~/.bashrc faz no começo.
B
braceexpand: as chaves {a,b} funcionam.
C
noclobber (o set -C).
H
histexpand: o !! do histórico.
s
Os comandos vêm da entrada padrão.

Num terminal com controle de jobs aparece também o m (monitor, veja Jobs). A variável $SHELLOPTS traz a mesma informação por extenso: braceexpand:emacs:hashall:histexpand:history:interactive-comments.

As três primeiras (-e, -u e pipefail) formam o famoso set -euo pipefail, que tem uma aula só para ele: set -euo pipefail. O -x é o assunto de Depurar. Aqui vai uma demonstração rápida de cada uma:

$ set -u
$ echo "Olá, $nmoe"                « erro de digitação: era $nome
bash: nmoe: variável não associada
$ set +u
$ set -C
$ echo oi > frutas.txt
bash: frutas.txt: impossível sobrescrever arquivo existente
$ set +C
$ set -f
$ echo *.txt
*.txt                              « com -f, o * não é curinga
$ set +f
$ false | true; echo $?
0                                  « sem pipefail: vale só o último (true)
$ set -o pipefail
$ false | true; echo $?
1                                  « com pipefail: a falha do false aparece
$ set -x
$ echo "$HOME"
+ echo /home/ana                   « o -x mostra o comando já expandido
/home/ana
$ set +x
+ set +x
  • "variável não associada" é como o Bash em português diz unbound variable: a variável nunca recebeu valor.
  • Com noclobber, você ainda pode forçar a escrita com >| (veja Redirecionamento).
  • O + set +x no fim é o próprio set +x sendo mostrado: ele ainda roda com o -x ligado.

set -o posix e bash --posix

O modo POSIX faz o Bash seguir o padrão em alguns pontos onde ele, normalmente, faz diferente. Ele não desliga os recursos do Bash (arrays e [[ ]] continuam funcionando). Para testar se um script roda no sh de verdade, use o próprio sh; veja POSIX sh e Bashismos.

$ bash --posix -c "echo \$POSIXLY_CORRECT; shopt -o posix"
y
posix               	on

(O shopt -o mostra opções do set com o formato do shopt.)

set -o vi

Muda os atalhos de edição da linha de comando para o estilo do editor vi: você digita no modo de inserção e aperta Esc para navegar com h, j, k, l. Para voltar ao normal: set -o emacs. Os atalhos do modo padrão estão em Editar a Linha.

Curingas sob medida (shopt)

A maior parte das opções do shopt muda o comportamento dos curingas (*, ?, [ ]). Para entender por que elas existem, comece pelo comportamento padrão.

Quando o curinga não casa com nada: nullglob e failglob

Na pasta pessoal da Ana não há nenhum PDF. Por padrão, um curinga que não casa com nada fica como está, com o * e tudo:

$ echo *.pdf
*.pdf                              « o padrão: o texto passa literalmente
$ ls *.pdf
ls: não foi possível acessar '*.pdf': Arquivo ou diretório inexistente

Num laço, isso é um problema: for f in *.pdf roda uma vez, com f valendo *.pdf. A opção nullglob ("curinga nulo") faz o curinga sem resultado sumir:

$ shopt -s nullglob
$ echo *.pdf
                                   « linha vazia: o *.pdf sumiu
$ for f in *.pdf; do echo "achei $f"; done; echo "fim"
fim                                « o laço não rodou nenhuma vez
A pegadinha do nullglob

Se o curinga some, o comando fica sem argumento. E vários comandos sem argumento agem sobre a pasta atual:

$ ls *.pdf
Área de trabalho
Documentos
Downloads
frutas.txt
Imagens
Modelos
Música
Público
Vídeos                             « virou só "ls": listou tudo!

Com nullglob, um ls *.pdf lista tudo e um grep texto *.log fica esperando o teclado. Por isso ele é ótimo em laços de scripts e perigoso no terminal. Ligue-o só no script, e de preferência só no trecho que precisa.

Já o failglob transforma o "não casou" num erro, e o comando nem roda:

$ shopt -s failglob
$ echo *.pdf
bash: sem correspondência: *.pdf
$ echo $?
1

Arquivos ocultos: dotglob

O * normalmente pula os arquivos que começam com ponto (os ocultos). Com dotglob, eles entram (mas . e .. continuam de fora):

$ echo *
Área de trabalho Documentos Downloads frutas.txt Imagens Modelos Música Público Vídeos
$ shopt -s dotglob
$ echo *
Área de trabalho .bash_history .bashrc Documentos Downloads frutas.txt Imagens Modelos Música .profile Público Vídeos

Entrar em subpastas: globstar e ** bash 4.0+

Com globstar ligado, ** casa com "qualquer quantidade de pastas", inclusive nenhuma. É um find simples feito pelo próprio Bash:

$ echo Documentos/*/*.html
Documentos/*/*.html                « só desce um nível, e o site está em projetos/site
$ shopt -s globstar
$ echo **/*.html
Documentos/projetos/site/index.html
$ echo Documentos/**
Documentos/ Documentos/acesso.log Documentos/alunos.csv Documentos/notas.txt Documentos/projetos Documentos/projetos/backup.sh Documentos/projetos/site Documentos/projetos/site/index.html Documentos/projetos/site/style.css Documentos/relatorio.odt
**
Qualquer caminho de pastas: Documentos, Documentos/projetos, Documentos/projetos/site…
/
Separador de pasta.
*.html
Um arquivo terminado em .html em qualquer uma delas.

Sem globstar, o ** funciona como um * comum. Cuidado em pastas enormes (como / ou ~ inteira): o Bash precisa visitar todas as subpastas antes de rodar o comando.

Missão: mostre, com um único echo e um curinga, todos os arquivos .html que estão em qualquer subpasta de Documentos. Você vai precisar ligar uma opção antes.

Padrões estendidos: extglob

O extglob (extended glob, "curinga estendido") acrescenta cinco padrões novos, todos no formato símbolo(alternativas), com as alternativas separadas por |:

PadrãoCasa com…Lembre como
!(lista)Tudo, menos o que casar com a lista! = "não"
@(lista)Exatamente uma das alternativas@ = "uma"
?(lista)Zero ou uma ocorrênciaComo o ? das regex
*(lista)Zero ou mais ocorrênciasComo o * das regex
+(lista)Uma ou mais ocorrênciasComo o + das regex
$ shopt -s extglob
$ echo !(*.txt)
acesso.log alunos.csv projetos relatorio.odt   « tudo, menos .txt
$ echo *.@(csv|log)
acesso.log alunos.csv                          « termina em .csv ou .log
$ echo +(a|n)*
acesso.log alunos.csv notas.txt                « começa com uma ou mais letras a ou n
$ echo ?(notas).txt
notas.txt
$ ls !(*.odt|projetos)
acesso.log
alunos.csv
notas.txt

O !( ) é o mais usado: "apague tudo menos os .conf" vira rm -- !(*.conf). Confira sempre antes com echo.

Ligue o extglob numa linha anterior

O Bash lê (analisa) uma linha inteira, ou uma função inteira, antes de rodar qualquer parte dela. Se o shopt -s extglob estiver na mesma linha, ou dentro da mesma função que usa !( ), o padrão é lido quando a opção ainda está desligada, e o ( vira erro de sintaxe:

$ shopt -s extglob; echo !(*.txt)
bash: erro de sintaxe próximo ao token inesperado `('

Em scripts, coloque o shopt -s extglob logo no começo, numa linha própria, fora de funções.

Missão: mostre com echo tudo o que há em Documentos, menos os arquivos .txt e .odt. Use um padrão !( ) com duas alternativas.

Maiúsculas e minúsculas: nocaseglob e globasciiranges

nocaseglob faz os curingas ignorarem maiúsculas/minúsculas: d* passa a achar Documentos.

$ echo d*
d*                                 « nada começa com d minúsculo
$ shopt -s nocaseglob
$ echo d*
Documentos Downloads

O globasciiranges (ligado por padrão desde o Bash 5.0) faz intervalos como [a-z] seguirem a ordem da tabela ASCII, e não a do idioma. Assim [a-z] pega só minúsculas, como a maioria das pessoas espera. Para "qualquer maiúscula, inclusive acentuada", o certo é a classe [[:upper:]]:

$ echo [[:upper:]]*
Área de trabalho Documentos Downloads Imagens Modelos Música Público Vídeos

Outras opções úteis do shopt

nocasematch: comparar sem ligar para maiúsculas

Vale para [[ == ]], [[ =~ ]] e para o case. Perfeito para respostas do usuário:

$ resp=SIM
$ [[ $resp == sim ]] && echo igual || echo diferente
diferente
$ shopt -s nocasematch
$ [[ $resp == sim ]] && echo igual || echo diferente
igual
$ case $resp in sim) echo "caiu no sim";; esac
caiu no sim

Missão: o usuário respondeu SIM, em maiúsculas, e o script cancelou. Faça o case aceitar a resposta em maiúsculas ou minúsculas ligando uma opção (sem mudar o case).

#!/usr/bin/env bash
read -r -p "Continuar? " resp
case $resp in
  sim|s) echo "Continuando" ;;
  *)     echo "Cancelado" ;;
esac

#!/usr/bin/env bash
shopt -s nocasematch
read -r -p "Continuar? " resp
case $resp in
  sim|s) echo "Continuando" ;;
  *)     echo "Cancelado" ;;
esac

autocd e cdspell: atalhos do terminal

Estas só fazem sentido no terminal interativo. Com autocd, digitar só o nome de uma pasta entra nela. Com cdspell, o cd corrige pequenos erros de digitação (uma letra trocada, faltando ou sobrando) e mostra o caminho corrigido:

$ shopt -s autocd
$ Documentos
cd -- Documentos                   « o Bash mostra o cd que ele fez por você
$ cd ~
$ shopt -s cdspell
$ cd Documetos
Documentos                         « corrigiu "Documetos"
$ cd ~
$ cd documentos
Documentos                         « e a maiúscula também

As do ~/.bashrc da Ana: histappend e checkwinsize

O ~/.bashrc do Ubuntu/Debian já vem com estas duas ligadas:

  • histappend: ao fechar, o Bash acrescenta o histórico ao ~/.bash_history, em vez de sobrescrever. Sem ela, com dois terminais abertos, o último a fechar apaga o histórico do outro (veja Histórico).
  • checkwinsize: depois de cada comando, o Bash confere o tamanho da janela e atualiza LINES e COLUMNS. Assim o texto não "embola" depois que você redimensiona o terminal. (Ligada por padrão desde o Bash 5.0.)

Para scripts: lastpipe e inherit_errexit

  • lastpipe bash 4.2+: a última parte de um pipe roda no shell atual, então cmd | while read … não perde as variáveis. Só funciona sem controle de jobs (em scripts). Explicação completa em Subshells.
  • inherit_errexit bash 4.4+: faz o set -e valer também dentro de $( ). Sem ela, um erro dentro da substituição de comando não para nada:
#!/usr/bin/env bash
set -e
x=$(false; echo "rodou mesmo assim")
echo "x = $x"
shopt -s inherit_errexit
y=$(false; echo "rodou mesmo assim")
echo "y = $y"

$ bash herda.sh
x = rodou mesmo assim              « sem inherit_errexit: o false não parou o $( )
$ echo $?
1                                  « com ela, o false parou o $( ), e o set -e parou o script

As mais úteis, e onde ativar

Regra geral: o que muda o conforto no terminal vai no ~/.bashrc (veja Arquivos de Inicialização); o que muda o resultado de comandos vai no começo de cada script que precisa. Um script nunca deve contar com algo do seu .bashrc: ele não é lido por scripts.

Quando não funciona

"erro de sintaxe próximo ao token inesperado `('" com !( ) 
$ bash ext.sh
ext.sh: linha 4: erro de sintaxe próximo ao token inesperado `('
ext.sh: linha 4: `  ls !(*.txt)'

O que aconteceu: o extglob estava desligado quando o Bash leu a linha 4. No ext.sh, o shopt -s extglob estava dentro da mesma função do ls !(*.txt); a função inteira é lida antes de rodar.

Como resolver: mova shopt -s extglob para o começo do script, numa linha própria, fora de funções.

"nome de opção de shell inválido" 
$ shopt -s nada
bash: shopt: nada: nome de opção de shell inválido
$ set -o nada
bash: set: nada: nome de opção inválido

O que aconteceu: erro de digitação, ou a opção é do outro quadro (por exemplo, shopt -s pipefail: pipefail é do set -o), ou ela não existe na sua versão do Bash.

Como resolver: confira em set -o e em shopt. Para usar o shopt com uma opção do set: shopt -s -o pipefail.

O ls *.pdf listou a pasta inteira

O que aconteceu: o nullglob está ligado e não há nenhum .pdf: o curinga sumiu e sobrou só ls.

Como confirmar: shopt nullglob. Como resolver: shopt -u nullglob no terminal; nos scripts, ligue o nullglob só em volta do laço.

Funciona no terminal, mas não no script (ou o contrário)

O que aconteceu: o terminal leu o ~/.bashrc (e o bash-completion, que liga o extglob); o script começa com as opções padrão. Também há opções que só valem no terminal (autocd, cdspell) e outras que só valem em scripts (lastpipe).

Como resolver: ligue no próprio script tudo o que ele usa. Para comparar, rode shopt -p nos dois lugares.

Exercícios

2. Tudo menos

3. O quadro certo

Complete para ligar o pipefail:

4. Um script faz for f in *.jpg; do convert "$f" …; done numa pasta sem nenhum .jpg. Qual opção faz o laço simplesmente não rodar?

Resumo

  • set (opções POSIX: -e -u -x -f -C, -o pipefail, -o posix): - liga, + desliga. $- mostra as letras ligadas.
  • shopt (opções do Bash): -s liga, -u desliga, -p mostra como comando, -q só testa.
  • Curingas: nullglob (some), failglob (erro), dotglob (ocultos), globstar (**), extglob (!( ) @( ) ?( ) *( ) +( )), nocaseglob.
  • extglob precisa estar ligado numa linha anterior, fora da função que o usa.
  • Conforto no ~/.bashrc; o que muda resultados, no começo do script.
