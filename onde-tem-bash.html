Bash em Cada Sistema

O Bash roda em quase todo lugar: em todo Linux, no macOS, no Windows e até no celular. Mas a versão muda, e às vezes muda muito. Nesta aula você vai descobrir como abrir o Bash no seu sistema, qual versão ele tem e o que fazer quando ela é antiga demais.

Você vai aprender
  • Como ter o Bash no Linux, no macOS, no Windows (WSL, Git Bash, MSYS2) e no Android (Termux).
  • Por que o macOS traz um Bash de 2006 e usa o zsh como padrão.
  • Como ver a versão com bash --version, $BASH_VERSION e BASH_VERSINFO.
  • Qual versão vem em cada distribuição e o que o selo bash 4.0+ deste guia quer dizer.

Qual versão eu tenho? bash --version

Comece por aqui, em qualquer sistema. O próprio Bash informa a sua versão:

bash
O programa Bash. Chamado assim, ele não abre um shell novo, porque recebe uma opção.
--version
Opção longa: "mostre a versão e saia".
$ bash --version
GNU bash, versão 5.3.9(1)-release (x86_64-pc-linux-gnu)          « a linha que importa
Copyright (C) 2025 Free Software Foundation, Inc.
Licença GPLv3+: GNU GPL versão 3 ou posterior <http://gnu.org/licenses/gpl.html>

Este é um software livre; você é livre para alterar e redistribuí-lo.
Há NENHUMA GARANTIA, na extensão permitida pela lei.             « tradução literal de "There is NO WARRANTY"

Só a primeira linha interessa. Leia assim:

5.3
A versão: 5 é a principal, 3 é a secundária. É o que o guia chama de "Bash 5.3".
.9
O número da correção (patch): consertos de erros, sem recursos novos.
(1)-release
Número de compilação e "versão de lançamento" (não é uma versão de teste).
x86_64-pc-linux-gnu
Para qual processador e sistema ele foi compilado. No Mac aparece apple-darwin; no Git Bash, msys.

Outras formas: variáveis do próprio Bash

Dentro do Bash, a versão também está em duas variáveis. Elas dizem a versão do shell que está rodando agora, o que é útil se o computador tiver mais de um Bash instalado:

$ echo $BASH_VERSION
5.3.9(1)-release
$ echo "${BASH_VERSINFO[@]}"
5 3 9 1 release x86_64-pc-linux-gnu           « a mesma informação, separada em partes
$ echo ${BASH_VERSINFO[0]}
5                                             « só a versão principal

BASH_VERSINFO é um array (uma variável com várias posições, numeradas a partir de 0; veja Arrays). Scripts usam a posição 0 para recusar versões antigas:

$ if (( BASH_VERSINFO[0] >= 4 )); then echo "Bash novo o bastante"; fi
Bash novo o bastante

Linux: já vem instalado

Em praticamente toda distribuição Linux de desktop ou servidor, o Bash já vem instalado e é o shell padrão. Abra o terminal (Ctrl+Alt+T na maioria) e ele está lá. A única exceção comum é o Alpine Linux (muito usado em contêineres Docker), que vem só com o ash do BusyBox; lá, instale com apk add bash.

macOS: o Bash antigo e o zsh

Desde o macOS Catalina (10.15, de 2019), o shell padrão do Terminal é o zsh. O Bash continua lá, em /bin/bash, mas parado na versão 3.2, de 2006. O motivo é a licença: a partir da 4.0, o Bash passou a usar a GPLv3, que a Apple não aceita incluir no sistema.

No Terminal do Mac, o resultado é este (saída ilustrativa, de um Mac com processador Apple):

$ echo $0
-zsh                               « o padrão é o zsh, como shell de login
$ bash --version | head -1
GNU bash, version 3.2.57(1)-release (arm64-apple-darwin24)     « em inglês e antigo
$ bash

The default interactive shell is now zsh.
To update your account to use zsh, please run `chsh -s /bin/zsh`.
For more details, please visit https://support.apple.com/kb/HT208050.

O aviso aparece toda vez que você abre o Bash 3.2 do sistema; ele só sugere voltar ao zsh. Para estudar com este guia, o zsh serve para os comandos do dia a dia, mas os scripts e as aulas do Nível 3 pedem um Bash novo.

Instalar um Bash novo com o Homebrew

O Homebrew é o gerenciador de pacotes mais usado no Mac. Com ele instalado, os passos abaixo trazem o Bash atual. Comandos ilustrativos, que não rodam no simulador:

$ brew install bash                                « instala o Bash mais novo
$ /opt/homebrew/bin/bash --version | head -1
GNU bash, version 5.3.3(1)-release (aarch64-apple-darwin24)
$ which -a bash
/opt/homebrew/bin/bash             « o novo (vem primeiro no PATH)
/bin/bash                          « o antigo continua lá, intocado
PassoComandoPara quê
1brew install bashInstala o Bash novo (em /opt/homebrew/bin/bash nos Macs com chip Apple; /usr/local/bin/bash nos Macs Intel).
2bashPara só usar: abra o Bash novo dentro do zsh. exit volta.
3 (opcional)sudo sh -c 'echo /opt/homebrew/bin/bash >> /etc/shells'Autoriza o Bash novo como shell padrão.
4 (opcional)chsh -s /opt/homebrew/bin/bashTorna o Bash novo o padrão (vale ao abrir uma nova janela). Veja Terminal e Shell.
Scripts no Mac: use #!/usr/bin/env bash

Um script que começa com #!/bin/bash roda sempre no Bash 3.2 do sistema, mesmo com o Bash novo instalado. Com #!/usr/bin/env bash, ele usa o primeiro bash do PATH, que é o novo. Veja Formas de Executar.

Não é só o Bash que muda no Mac

O macOS traz as versões BSD de ls, sed, grep, date… com opções diferentes das GNU usadas neste guia (por exemplo, sed -i '' em vez de sed -i). Se uma opção não funcionar, instale as versões GNU com brew install coreutils gnu-sed grep; elas ficam com o nome começando por g (gsed, gls).

Depois do wsl --install, o Windows Terminal ganha uma aba "Ubuntu". Abrindo-a, o prompt fica igual ao deste guia, com o seu usuário e o nome do computador (saída ilustrativa):

$ bash --version | head -1
GNU bash, version 5.2.21(1)-release (x86_64-pc-linux-gnu)
$ cd /mnt/c/Users/ana/Downloads     « a pasta Downloads do Windows, vista do Linux

A versão é a da distribuição instalada (Ubuntu 24.04 → 5.2; Ubuntu 26.04 → 5.3) e a mensagem vem em inglês porque o Ubuntu do WSL é instalado em inglês. Para trazê-lo para o português, é preciso instalar o idioma, como num Ubuntu comum.

Cuidado com arquivos editados no Windows

Programas do Windows terminam as linhas com dois caracteres (\r\n); o Bash espera um só (\n). Um script salvo no Bloco de Notas pode falhar com $'\r': comando não encontrado. Configure o editor para usar o fim de linha "LF" (no VS Code, canto inferior direito).

Android: Termux

O Termux é um aplicativo de terminal para Android que traz o Bash e um gerenciador de pacotes (pkg), sem precisar de root. Instale pelo F-Droid (a versão da Play Store costuma estar desatualizada). Depois de abrir, rode pkg upgrade para atualizar tudo. A pasta pessoal fica dentro do aplicativo, e o comando termux-setup-storage dá acesso às fotos e downloads do celular. Para um iniciante, é uma ótima forma de praticar no ônibus; para os projetos, prefira um computador.

O selo de versão deste guia

Este guia ensina o Bash 5.3. Quando um recurso não existe em versões que você pode ter, ele aparece com um selo assim:

SeloSignificadoQuem fica de fora
bash 4.0+Existe a partir do Bash 4.0Só o /bin/bash do macOS (3.2)
bash 5.1+Existe a partir do 5.1Servidores bem antigos e o macOS
bash 5.3+Novo na 5.3Debian 13, Ubuntu 24.04, Git Bash e outros com 5.2

Junto do selo, a aula sempre mostra uma alternativa que funciona nas versões anteriores. Sem selo, o recurso funciona em qualquer Bash razoavelmente atual (4.0 ou mais novo).

Quando não funciona

"command not found" ou "invalid option" num recurso moderno (macOS)

Saídas ilustrativas do Bash 3.2 do macOS:

$ declare -A idades
bash: declare: -A: invalid option
$ mapfile linhas < frutas.txt
bash: mapfile: command not found
$ nome=ANA; echo ${nome,,}
bash: ${nome,,}: bad substitution

O que aconteceu: arrays associativos, mapfile e ${x,,} chegaram no Bash 4.0. O Bash 3.2 não os conhece.

Como confirmar: echo $BASH_VERSION mostra 3.2.57(1)-release.

Como resolver: instale o Bash novo pelo Homebrew e rode o script com #!/usr/bin/env bash.

bash --version diz 5.3, mas o script se comporta como 3.2

O que aconteceu: há dois Bash no computador. O terminal acha o novo, mas o script começa com #!/bin/bash e usa o antigo.

Como confirmar: coloque echo $BASH_VERSION no começo do script e rode. Veja também type -a bash, que lista todos os bash do PATH:

$ type -a bash
bash é /usr/bin/bash
bash é /bin/bash                   « no Linux, os dois são o mesmo arquivo (/bin aponta para /usr/bin)

Como resolver: troque a primeira linha do script por #!/usr/bin/env bash.

$'\r': comando não encontrado no WSL ou no Git Bash 
$ bash script.sh
script.sh: linha 2: $'\r': comando não encontrado        « a linha 2 estava vazia: sobrou só o \r
script.sh: linha 3: $'ls\r': comando não encontrado      « o Bash procurou um comando chamado "ls\r"
$ echo $?
127

O que aconteceu: o arquivo foi salvo com o fim de linha do Windows (\r\n). O Bash vê o \r como parte do comando: a linha ls virou o comando ls\r, que não existe.

Como resolver: salve com fim de linha "LF" no editor, ou converta: sed -i 's/\r$//' script.sh.

Resumo

  • Linux: o Bash já vem (exceto Alpine). Ubuntu 26.04, Fedora e Arch têm o 5.3; Debian 13 e Ubuntu 24.04, o 5.2.
  • macOS: o padrão é o zsh e o /bin/bash é o 3.2; instale o novo com brew install bash e use #!/usr/bin/env bash.
  • Windows: WSL (Linux de verdade, o melhor para o guia), Git Bash ou MSYS2. Android: Termux.
  • bash --version, $BASH_VERSION e BASH_VERSINFO mostram a versão.
  • O selo bash 4.0+ marca recursos que não existem em versões anteriores.
