Bash Testes: [ ], [[ ]] e test

Um script precisa fazer perguntas: "o arquivo existe?", "a resposta foi sim?", "a nota é maior que 7?". No Bash, quem responde são os comandos de teste. Eles não mostram nada na tela: a resposta vem no código de saída, 0 para "sim" e 1 para "não". Nesta aula você aprende as três formas de testar e qual usar.

Você vai aprender
  • O que são test, [ ] e [[ ]], e por que os espaços são obrigatórios.
  • Os testes de arquivo (-e -f -d -s -r -w -x -L -nt -ot), de texto e de número.
  • Como combinar testes com !, && e ||.
  • Por que [ $var = sim ] quebra com variável vazia ou com espaço, e [[ ]] não.
  • Comparar com padrões (== *.jpg) e a tabela "qual usar".

Um teste é um comando que responde com o código de saída

Comece pelo mais simples, o comando test. A opção -f pergunta "isto é um arquivo comum?":

test
O comando de teste ("testar").
-f
A pergunta: é um arquivo (file) comum?
frutas.txt
Sobre quem é a pergunta.
$ test -f frutas.txt
$ echo $?
0                        « 0 = verdadeiro: é um arquivo

Repare: o test não mostrou nada. É assim mesmo. A resposta está no $?. Sozinho, isso parece inútil, mas é exatamente o que o if e os operadores && e || usam para decidir:

$ test -f frutas.txt && echo "existe"
existe

A forma com colchetes: [ ]

Escrever test é pouco legível, então existe um apelido para ele: o comando [. Isso mesmo, [ é o nome de um comando, e ele exige que o último argumento seja ], só para ficar bonito.

$ [ -f frutas.txt ]
$ echo $?
0
$ [ -d frutas.txt ]
$ echo $?
1                        « 1 = falso: frutas.txt não é uma pasta (directory)
$ type [
[ é um comando interno do shell

test -f frutas.txt e [ -f frutas.txt ] são o mesmo comando. Entender isso explica a regra mais importante desta aula.

Os espaços são obrigatórios

Como [ é um comando, ele precisa estar separado por espaço, como qualquer comando (você não escreve ls-l). E o ] é um argumento, que também precisa de espaço antes.

$ [-f frutas.txt ]
bash: [-f: comando não encontrado          « procurou um comando chamado "[-f"
$ [ -f frutas.txt]
bash: [: faltando `]'                      « o último argumento era "frutas.txt]", não "]"
$ echo $?
2                                          « 2 = o teste nem conseguiu rodar
  [ -f frutas.txt ]
   ↑  ↑          ↑
   espaço depois do [, entre cada parte, e antes do ]
Três códigos possíveis

Um teste devolve 0 (verdadeiro), 1 (falso) ou 2 (erro: o teste foi escrito errado). Quando um if vai sempre para o else sem motivo, rode o teste sozinho e veja o $?: se for 2, havia uma mensagem de erro que você não viu.

A forma moderna: [[ ]]

O Bash (assim como o ksh e o zsh) tem uma versão melhorada, com colchetes duplos. Ela não é um comando, e sim uma palavra-chave: o próprio Bash a interpreta, antes de separar palavras e expandir curingas. Isso a torna mais segura, como você vai ver.

$ [[ -d Documentos ]]
$ echo $?
0
$ type [[
[[ é uma palavra-chave do shell

Os espaços também são obrigatórios: [[-f frutas.txt ]] dá bash: [[-f: comando não encontrado.

Testes de arquivo

Todos funcionam igual em test, [ ] e [[ ]]. A letra vem quase sempre do inglês:

$ [ -e Documentos ]; echo $?

$ [ -s frutas.txt ]; echo $?
0
$ touch vazio.txt
$ [ -s vazio.txt ]; echo $?
1                        « existe, mas está vazio
$ [ -r frutas.txt ] && echo "pode ler"

$ [ -w /etc/passwd ] || echo "não pode escrever"

$ [ -x Documentos/projetos/backup.sh ]; echo $?
0                        « o backup.sh tem permissão de execução

Com um link e duas datas:

$ ln -s frutas.txt atalho.txt
$ [ -L atalho.txt ] && echo "é link"
é link
$ [ -f atalho.txt ] && echo "e aponta para um arquivo"

$ touch -d 2026-10-01 velho.txt
$ [ frutas.txt -nt velho.txt ] && echo "frutas é mais novo"
frutas é mais novo
$ [ velho.txt -ot frutas.txt ] && echo "velho é mais antigo"
velho é mais antigo

O -nt é útil para "só refaça o backup se o original mudou depois do último backup". Permissões (-r -w -x) são explicadas nos guias de cada sistema; aqui basta saber que o teste responde "você, com o seu usuário, pode?".

Missão: use [[ ]] para perguntar se Documentos/projetos/backup.sh pode ser executado. Depois rode echo $? para ver a resposta.

Testes de texto

0

Em [ ], > é redirecionamento!

[ 5 > 3 ] não compara nada: o > manda a saída do [ 5 ] para um arquivo chamado 3. O código é 0 (porque [ 5 ] é "texto não vazio") e aparece um arquivo 3 vazio na pasta. Para números, use -gt ou (( )); para textos, [[ ]].

Testes de número

Para comparar números em [ ] e [[ ]] existem operadores com letras, que vêm do inglês:

TesteSignificaOrigemEm (( ))
-eqigualequal==
-nediferentenot equal!=
-ltmenor queless than<
-lemenor ou igualless or equal<=
-gtmaior quegreater than>
-gemaior ou igualgreater or equal>=
$ [ 10 -eq 10 ]; echo $?
0
$ [ 3 -lt 10 ]; echo $?
0
$ [ 9 -ge 10 ]; echo $?
1

Por que não usar < para números?

Porque < em [[ ]] compara texto, letra por letra, como num dicionário. E no dicionário, "10" vem antes de "9" (porque 1 vem antes de 9):

$ [[ 10 < 9 ]]; echo $?
0                        « "verdadeiro"?! comparou como texto
$ [ 10 -lt 9 ]; echo $?
1                        « certo: 10 não é menor que 9
$ (( 10 < 9 )); echo $?
1                        « certo: dentro de (( )), < é numérico

Para números, a forma mais legível é (( )), vista em Contas: (( nota >= 7 )) se lê como na matemática. Os operadores com letras continuam úteis porque funcionam em [ ], inclusive no sh.

Todos os três aceitam só inteiros:

$ [ 9.5 -gt 9 ]
bash: [: 9.5: esperava número inteiro
$ [ abc -eq 1 ]
bash: [: abc: esperava número inteiro

Para comparar decimais (como as notas do alunos.csv), use bc ou awk (veja Números com vírgula).

Combinar testes: !, && e ||

Negar: !

$ [ ! -f nada.txt ]; echo $?
0                        « "não é arquivo" é verdade
$ ! [ -f nada.txt ]; echo $?
0                        « mesma coisa, negando o comando inteiro

Atenção ao espaço: ! -f, não !-f.

"E" e "ou"

Há três jeitos de escrever "o arquivo existe e a pasta existe":

$ [[ -f frutas.txt && -d Documentos ]]; echo $?
0                        « dentro de [[ ]]: && e ||
$ [ -f frutas.txt ] && [ -d Documentos ]; echo $?
0                        « dois comandos [ ] ligados por &&
$ [ -f frutas.txt -a -d Documentos ]; echo $?
0                        « -a (and) e -o (or): forma antiga

O -a e o -o dentro de [ ] são considerados obsoletos: com certos valores de variáveis (como um texto igual a ! ou (), o [ não consegue saber o que é operador e o que é dado. Use [[ … && … ]] ou [ … ] && [ … ]. E cada operador no seu lugar:

$ [ -f frutas.txt && -d Documentos ]
bash: [: faltando `]'          « o && cortou o comando [ antes do ]
$ [[ -f frutas.txt -a -d Documentos ]]
bash: erro de sintaxe na expressão condicional: token inesperado `-a'
bash: erro de sintaxe próximo a `-a'

Por que [ $var = x ] quebra (e [[ ]] não)

Este é o erro mais clássico de quem escreve testes. Lembre: [ é um comando, e o Bash expande as variáveis e separa as palavras antes de chamá-lo. Veja o que o [ recebe em cada caso:

$ x=
$ [ $x = sim ]
bash: [: =: esperava operador unário
$ echo $?
2

Com x vazio e sem aspas, $x some. O [ recebe só = sim ], olha para o = como se fosse um operador de um lado só (como -f, um operador "unário") e não entende.

$ x="não sei"
$ [ $x = sim ]
bash: [: número excessivo de argumentos
$ echo $?
2

Com espaço no valor, $x virou duas palavras: o [ recebeu não sei = sim ], argumentos demais para uma comparação.

Escritox valeO [ recebeResultado
[ $x = sim ](vazio)[ = sim ]erro: esperava operador unário
[ $x = sim ]não sei[ não sei = sim ]erro: número excessivo de argumentos
[ "$x" = sim ](vazio)[ "" = sim ]falso (1), sem erro
[[ $x = sim ]]qualquer(não há separação de palavras)falso (1), sem erro
$ x=
$ [ "$x" = sim ]; echo $?
1                        « com aspas: comparação correta
$ [[ $x = sim ]]; echo $?
1                        « [[ ]] não precisa das aspas na variável

O -n sem aspas é ainda mais traiçoeiro, porque não dá erro, dá a resposta errada:

$ x=
$ [ -n $x ]; echo $?
0                        « "não está vazia"?! O [ recebeu só "-n", um texto não vazio
$ [ -n "$x" ]; echo $?
1                        « certo

Regras práticas: em [ ], sempre coloque aspas nas variáveis. Em [[ ]], as aspas no lado esquerdo são opcionais (mas não fazem mal), e no lado direito têm um significado especial, que você vê a seguir.

Missão: a variável resp está vazia. Rode [ $resp = sim ] e veja o erro. Depois escreva um teste que compare $resp com sim sem erro, respondendo "falso" (código 1).

Padrões com == em [[ ]]

Dentro de [[ ]], o lado direito de == (e de = e !=) é um padrão, com os mesmos curingas dos nomes de arquivo. Isso permite perguntar "termina com .jpg?":

[[
Teste do Bash.
$arq
O texto a examinar.
==
"Casa com o padrão…"
*.jpg
Qualquer coisa seguida de .jpg. Sem aspas, para ser padrão.
]]
Fim.
$ arq=foto.jpg
$ [[ $arq == *.jpg ]]; echo $?
0                        « casa com o padrão
$ [[ $arq == "*.jpg" ]]; echo $?
1                        « com aspas: compara com o texto literal "*.jpg"
$ [[ $arq != *.png ]]; echo $?
0
$ [ $arq == *.jpg ]; echo $?
1                        « em [ ], o * não é padrão: virou nomes de arquivos ou texto

Se for comparar com muitas opções, o case costuma ficar mais limpo.

Regex: =~

[[ ]] também testa expressões regulares, um tipo de padrão muito mais poderoso, com o operador =~. Só como aperitivo:

$ cep=50000-000
$ [[ $cep =~ ^[0-9]{5}-[0-9]{3}$ ]] && echo "CEP válido"
CEP válido

Ler e escrever regex é assunto da aula Regex com [[ =~ ]].

Variável existe? -v

[[ -v nome ]] (sem $!) pergunta se a variável existe, mesmo vazia. É a diferença entre "vazia" e "não definida" de Variáveis:

$ unset v
$ [[ -v v ]]; echo $?
1
$ v=
$ [[ -v v ]]; echo $?
0                        « existe, embora vazia

Missão: o script reconhece .jpg como imagem, mas com perfil.png não mostra nada. Mude o teste para aceitar .jpg ou .png, usando || dentro do [[ ]].

#!/usr/bin/env bash
[[ $1 == *.jpg ]] && echo "imagem"

#!/usr/bin/env bash
[[ $1 == *.jpg || $1 == *.png ]] && echo "imagem"

Quando não funciona

"[: faltando `]'" 
$ [ -f frutas.txt]
bash: [: faltando `]'

O que aconteceu: faltou o espaço antes do ], ou um &&/; cortou o comando antes dele.

Como resolver: [ -f frutas.txt ], com espaço dos dois lados.

"[-f: comando não encontrado"

O que aconteceu: faltou o espaço depois do [ (ou do [[). O Bash procurou um comando com esse nome grudado.

Como resolver: [ -f arquivo ].

"[: =: esperava operador unário" e "[: número excessivo de argumentos"

O que aconteceu: uma variável sem aspas dentro de [ ] estava vazia (primeira mensagem) ou tinha espaços (segunda).

Como confirmar: declare -p x mostra o valor real da variável.

Como resolver: [ "$x" = sim ], ou troque por [[ $x = sim ]].

"esperava número inteiro" 
$ [ 9.5 -gt 9 ]
bash: [: 9.5: esperava número inteiro

O que aconteceu: -gt e companhia só aceitam inteiros. O valor era decimal, texto ou vazio (com aspas, vazio dá a mesma mensagem).

Como resolver: confira o valor antes; para decimais, use bc.

Apareceu um arquivo com nome de número na pasta

O que aconteceu: você usou > ou < dentro de [ ], e eles viraram redirecionamento.

Como resolver: apague o arquivo e use -gt/-lt ou (( )).

O teste sempre dá "verdadeiro"

O que aconteceu: causas comuns: [ -n $x ] sem aspas (sempre verdadeiro); [ $x ] com um texto qualquer; ou [ "$a"="$b" ] sem espaços em volta do =, que vira um texto só (não vazio = verdadeiro).

Como resolver: espaços em volta do operador e aspas nas variáveis: [ "$a" = "$b" ].

Exercícios

1. É uma pasta?

Complete para testar se Imagens é uma pasta:

[[ Imagens ]]

2. Maior ou igual

Complete para testar se idade é maior ou igual a 18 usando colchetes:

[ "$idade" 18 ]

3. Variável vazia

Complete para testar se nome está vazia:

[ "$nome" ]

4. Termina com .sh

Complete para testar se arq termina com .sh:

[[ $arq == ]]

Resumo

  • Testes respondem pelo código de saída: 0 verdadeiro, 1 falso, 2 erro no teste.
  • [ é um comando (igual a test): espaços obrigatórios em volta de [, ] e de cada operador.
  • Arquivos: -e -f -d -s -r -w -x -L -nt -ot. Texto: -z -n = !=. Números: -eq -ne -lt -le -gt -ge ou (( )).
  • Em [ ], sempre "$var" com aspas; [[ ]] não quebra com vazio ou espaço.
  • [[ ]] tem &&, ||, padrões com == e regex com =~. Num script Bash: [[ ]] para arquivos e textos, (( )) para números.
