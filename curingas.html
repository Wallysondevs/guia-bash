Bash Curingas

Curingas são caracteres especiais, como * e ?, que funcionam como a carta coringa do baralho: valem por "qualquer coisa". Com eles você escreve *.jpg e o Bash entende "todos os arquivos que terminam em .jpg". O detalhe mais importante desta aula: quem faz essa troca é o Bash, antes de o comando rodar.

Você vai aprender
  • Os curingas *, ? e [ ] (com faixas, negação e classes como [[:digit:]]).
  • Como ver, com echo, a lista que o Bash monta antes de chamar o comando.
  • O que acontece quando nada casa com o padrão, e por que isso cria arquivos chamados *.txt.
  • Por que os arquivos ocultos ficam de fora e como as aspas desligam o curinga.
  • Quais opções (nullglob, globstar, extglob) mudam esse comportamento.

O problema: escolher arquivos sem digitar cada nome

A Ana voltou de viagem com fotos, um mapa e um roteiro numa pasta. Ela quer ver só as fotos, depois só as que têm número, depois mover tudo que é imagem para outra pasta. Digitar cada nome cansa e erra. Com curingas ela descreve um padrão ("começa com foto", "termina em .jpg") e o Bash encontra os nomes.

Vamos criar a pasta de exemplo. O touch cria arquivos vazios (veja Criar, Copiar e Mover); aqui só os nomes importam:

$ mkdir viagem
$ cd viagem
$ touch foto1.jpg foto2.jpg foto10.jpg fotoA.jpg foto3.png mapa.pdf roteiro.txt Roteiro-antigo.txt
$ ls
foto10.jpg  foto2.jpg  fotoA.jpg  Roteiro-antigo.txt
foto1.jpg   foto3.png  mapa.pdf   roteiro.txt

Para repetir os exemplos no simulador, rode esses três comandos primeiro.

Quem expande o curinga é o Bash

Quando você digita ls *.jpg, o ls nunca vê o *. Acontece assim:

1. você digita:         ls *.jpg
2. o Bash procura na pasta os nomes que combinam com *.jpg
3. o Bash reescreve:    ls foto10.jpg foto1.jpg foto2.jpg fotoA.jpg
4. só agora o ls roda, recebendo 4 nomes comuns

Esse passo 2 se chama expansão de nomes de arquivo (em inglês, pathname expansion ou globbing; os padrões são chamados de globs). Como é o Bash que faz, os curingas funcionam com qualquer comando: ls, cp, rm, wc, echo…

A prova com echo

O echo só repete os argumentos que recebeu. Então ele é perfeito para ver o resultado da expansão:

$ echo *.jpg
foto10.jpg foto1.jpg foto2.jpg fotoA.jpg     « o echo recebeu 4 nomes, não "*.jpg"

A prova com set -x

Com set -x ligado, o Bash mostra, numa linha começando com +, o comando exatamente como ele vai rodar, já expandido:

$ set -x
$ ls *.txt
+ ls --color=auto frutas.txt                 « o Bash trocou *.txt por frutas.txt
frutas.txt
$ set +x
+ set +x

O --color=auto apareceu porque ls é um alias definido no .bashrc da Ana (veja Listar). set +x desliga o modo. Ele é estudado em Depurar.

Hábito de ouro: teste com echo antes

Antes de um rm *.log ou mv *.jpg fotos/, rode o mesmo comando com echo na frente: echo rm *.log. Você vê exatamente quais arquivos seriam afetados, sem afetar nenhum.

*: qualquer quantidade de caracteres

O asterisco casa com qualquer sequência de caracteres, inclusive com nenhum caractere.

foto
Texto fixo: o nome tem que começar exatamente com "foto".
*
Depois, qualquer coisa (ou nada).
$ echo *
foto10.jpg foto1.jpg foto2.jpg foto3.png fotoA.jpg mapa.pdf Roteiro-antigo.txt roteiro.txt
$ echo foto*
foto10.jpg foto1.jpg foto2.jpg foto3.png fotoA.jpg     « começam com "foto"
$ echo *a*
mapa.pdf Roteiro-antigo.txt                            « têm um "a" em qualquer lugar
$ echo *roteiro.txt
roteiro.txt                                            « aqui o * casou com nada

Em *a*, repare que fotoA.jpg ficou de fora: A maiúsculo e a minúsculo são letras diferentes para o Bash. E Roteiro-antigo.txt entrou por causa do "a" de "antigo".

Por que foto10 vem antes de foto1?

O Bash devolve a lista em ordem alfabética, seguindo o idioma do sistema (LANG=pt_BR.UTF-8). Nessa ordem, a pontuação é deixada de lado na primeira comparação: foto10.jpg é comparado como "foto10jpg" e foto1.jpg como "foto1jpg". Na quinta posição, "0" vem antes de "j". Por isso numerar com zero à esquerda (foto01, foto02…) deixa tudo em ordem; as chaves fazem isso com {01..10}.

?: exatamente um caractere

A interrogação vale por um caractere, qualquer um. Nem zero, nem dois.

$ echo foto?.jpg
foto1.jpg foto2.jpg fotoA.jpg      « um caractere entre "foto" e ".jpg"
$ echo foto??.jpg
foto10.jpg                         « dois caracteres
$ echo ?????.*
foto1.jpg foto2.jpg foto3.png fotoA.jpg     « nome com 5 caracteres antes do ponto

Use ? quando o tamanho importa, por exemplo para pegar foto1 a foto9 sem pegar foto10.

[ ]: um caractere de uma lista

Os colchetes também valem por um caractere só, mas você escolhe quais são aceitos.

foto
Texto fixo.
[12]
Um caractere que seja 1 ou 2.
.jpg
Texto fixo.
$ echo foto[12].jpg
foto1.jpg foto2.jpg
$ echo [mr]*
mapa.pdf roteiro.txt               « começa com m ou r (minúsculos)

Faixas: [1-3], [a-z]

Um hífen entre dois caracteres indica uma faixa: [1-3] é o mesmo que [123]; [0-9] é qualquer algarismo; [a-z] é qualquer letra minúscula sem acento.

$ echo foto[1-3].*
foto1.jpg foto2.jpg foto3.png
[a-z] não pega maiúsculas no Bash moderno

No Bash 5 (e no 4.3 com a opção ligada), as faixas seguem a tabela ASCII: [a-z] é só de "a" a "z" minúsculos e [A-Z] só maiúsculas, sem acentos. Quem controla isso é a opção globasciiranges, ligada por padrão. Versões antigas seguiam o idioma, e [a-z] podia incluir maiúsculas. Para não depender disso, use as classes (logo abaixo).

Negação: [!x] ou [^x]

Um ! logo depois do [ inverte a lista: "um caractere que não seja estes". O Bash também aceita ^ no lugar do !; o ! é o padrão POSIX, funciona em qualquer shell.

$ echo foto[!0-9].jpg
fotoA.jpg                          « depois de "foto", algo que não é algarismo
$ echo foto[^0-9].jpg
fotoA.jpg                          « mesma coisa

Classes: [[:digit:]] e companhia

Dentro dos colchetes você pode usar nomes de classes de caracteres. Repare nos colchetes duplos: os de fora são o curinga, os de dentro (com dois-pontos) são o nome da classe.

$ echo foto[[:digit:]].*
foto1.jpg foto2.jpg foto3.png      « um algarismo depois de "foto"
$ echo [[:upper:]]*
Roteiro-antigo.txt                 « começa com letra maiúscula
ClasseCasa comMais ou menos igual a
[[:digit:]]Um algarismo[0-9]
[[:alpha:]]Uma letra, inclusive acentuada[a-zA-Z] + acentos
[[:upper:]]Uma letra maiúscula (inclusive Á)[A-Z] + acentos
[[:lower:]]Uma letra minúscula[a-z] + acentos
[[:alnum:]]Letra ou algarismo[a-zA-Z0-9] + acentos
[[:space:]]Espaço, Tab…
[[:punct:]]Pontuação (. , - _ !…)

Na pasta pessoal da Ana, a diferença aparece com o "Á" de "Área de trabalho":

$ echo [A-F]*
Documentos Downloads               « "Área" não entra: Á não está entre A e F
$ echo [[:upper:]]*
Área de trabalho Documentos Downloads Imagens Modelos Música Público Vídeos

Missão: você está na pasta viagem. Usando echo e curingas, mostre só as fotos numeradas com um único algarismo, de qualquer extensão: foto1.jpg foto2.jpg foto3.png (sem foto10.jpg e sem fotoA.jpg).

Curingas funcionam com qualquer comando

Como a expansão é do Bash, o mesmo padrão serve para mover, copiar, apagar, contar. Na pasta Downloads, a Ana separa os arquivos compactados:

$ ls
foto.jpg          manual.pdf  ubuntu-26.04-desktop-amd64.iso
fotos-viagem.zip  musica.mp3
$ mkdir compactados
$ echo mv *.zip *.iso compactados/
mv fotos-viagem.zip ubuntu-26.04-desktop-amd64.iso compactados/    « conferindo antes
$ mv *.zip *.iso compactados/
$ ls
compactados  foto.jpg  manual.pdf  musica.mp3
$ ls compactados
fotos-viagem.zip  ubuntu-26.04-desktop-amd64.iso
$ mv compactados/* .               « desfazendo, para os próximos exemplos
$ rmdir compactados
mv
Move arquivos. Quando recebe vários nomes, o último é a pasta de destino.
*.zip *.iso
Dois padrões. O Bash expande cada um e junta tudo numa lista só.
compactados/
O destino. A / no fim deixa claro que é uma pasta.
Um espaço a mais pode ser uma tragédia

rm *.bak apaga os arquivos que terminam em .bak. Já rm * .bak (com espaço) são dois argumentos: *, que vira todos os arquivos da pasta, e .bak. Por isso o hábito do echo rm … antes. Mais sobre apagar com segurança em Apagar com Segurança.

Nomes com espaço continuam inteiros

Um bom motivo para usar curingas em vez de copiar a saída do ls: cada nome encontrado vira um argumento, mesmo que tenha espaços.

$ touch "minha foto.jpg"
$ for f in *.jpg; do echo "[$f]"; done
[foto10.jpg]
[foto1.jpg]
[foto2.jpg]
[fotoA.jpg]
[minha foto.jpg]                   « um item só, com o espaço
$ rm "minha foto.jpg"              « desfazendo, para os próximos exemplos

O for repete o echo para cada nome; os colchetes no texto só mostram onde cada item começa e termina. Laços são assunto de for, e o porquê de não usar $(ls) está em Boas Práticas.

Missão: você está na pasta bagunca. Crie a pasta imagens e mova para ela, com um único mv, todos os .jpg e .png. Os .txt e o .mp3 devem ficar onde estão. Dica: confira primeiro com echo mv ….

Curingas e pastas

Um curinga casa com uma parte do caminho por vez: o * nunca "atravessa" uma barra /. Para olhar dentro de pastas, escreva a barra no padrão:

$ echo */*.jpg
Downloads/foto.jpg Imagens/ferias.jpg viagem/foto10.jpg viagem/foto1.jpg viagem/foto2.jpg viagem/fotoA.jpg
$ echo */
Área de trabalho/ Documentos/ Downloads/ Imagens/ Modelos/ Música/ Público/ viagem/ Vídeos/
$ echo */*/*/*.html
Documentos/projetos/site/index.html          « três níveis de pasta

Um padrão terminado em / (como */) só casa com pastas.

ls com curinga que pega pastas

Quando o Bash entrega uma pasta ao ls, ele lista o conteúdo dela. Por isso ls D* parece estranho:

$ ls D*
Documentos:
acesso.log  alunos.csv  notas.txt  projetos  relatorio.odt

Downloads:
foto.jpg          manual.pdf  ubuntu-26.04-desktop-amd64.iso
fotos-viagem.zip  musica.mp3
$ ls -d D*
Documentos  Downloads              « -d: mostre as pastas, não o que há dentro

Quando nada casa: o padrão fica como está

Se nenhum arquivo combina com o padrão, o Bash não dá erro. Ele simplesmente deixa o padrão como foi digitado, com o * e tudo, e passa assim para o comando:

$ echo *.doc
*.doc                              « nenhum .doc: o echo recebeu o texto "*.doc"
$ ls *.JPG
ls: não foi possível acessar '*.JPG': Arquivo ou diretório inexistente
$ echo $?
2

No segundo caso, quem reclamou foi o ls: ele recebeu o nome *.JPG literalmente e foi procurar um arquivo com esse nome estranho. (Não havia .JPG em maiúsculas; os curingas diferenciam maiúsculas de minúsculas.) O código 2 é o jeito do ls dizer "problema sério". O rm faz o mesmo:

$ rm *.tmp
rm: não foi possível remover '*.tmp': Arquivo ou diretório inexistente
$ echo $?
1

A pegadinha: um arquivo chamado *.doc

Com um comando que cria arquivos, o padrão literal vira um nome de arquivo de verdade:

$ touch *.doc
$ ls
'*.doc'       foto1.jpg   foto3.png   mapa.pdf             roteiro.txt
 foto10.jpg   foto2.jpg   fotoA.jpg   Roteiro-antigo.txt
$ rm '*.doc'                       « aspas: apague o arquivo chamado *.doc, e só ele

O ls mostra '*.doc' entre aspas porque o nome tem um caractere especial. Para apagá-lo, as aspas são obrigatórias: um rm *.doc sem aspas também funcionaria aqui (o padrão casaria com o próprio arquivo *.doc), mas, se houvesse outros .doc na pasta, todos iriam junto.

Se você prefere outro comportamento, o Bash tem duas opções (ligadas com shopt -s, apresentadas mais abaixo):

$ shopt -s nullglob
$ echo *.xyz
                                   « nullglob: sem correspondência, o padrão some
$ shopt -u nullglob
$ shopt -s failglob
$ echo *.xyz
bash: sem correspondência: *.xyz   « failglob: vira erro, e o comando nem roda
$ echo $?
1
$ shopt -u failglob

Arquivos ocultos ficam de fora

No Linux, um nome que começa com ponto (.bashrc, .profile) é "oculto". Os curingas respeitam isso: * e ? não casam com o ponto inicial. Para pegar ocultos, o padrão tem que começar com um ponto escrito por você:

$ echo *
Área de trabalho Documentos Downloads frutas.txt Imagens Modelos Música Público viagem Vídeos
$ echo .*
.bash_history .bashrc .profile

Repare que .* não trouxe . (a pasta atual) nem .. (a pasta de cima). Isso é novidade do bash 5.2+ (opção globskipdots). Em versões antigas, .* incluía os dois, e um rm -r .* tentava apagar a pasta de cima! Se o seu Bash for mais velho, use .[!.]*.

O mesmo vale dentro de pastas: *.jpg não pega .escondido.jpg. Para os curingas incluírem ocultos, existe a opção dotglob.

Aspas desligam o curinga

Entre aspas, simples ou duplas, o *, o ? e os [ ] são caracteres comuns. A barra invertida desliga um caractere só:

$ echo *.jpg
foto10.jpg foto1.jpg foto2.jpg fotoA.jpg
$ echo "*.jpg"
*.jpg
$ echo '*.jpg'
*.jpg
$ echo \*.jpg
*.jpg

Isso é útil quando o programa precisa receber o padrão, e não a lista. O find é o exemplo clássico: em find . -name '*.jpg', as aspas fazem o * chegar intacto ao find, que procura em todas as subpastas (veja grep, sed, awk e cia.). E é por isso que ls "*.jpg" dá erro: o ls procura um arquivo chamado, literalmente, *.jpg.

Com variáveis acontece a mesma coisa. Sem aspas, o valor da variável passa pelos curingas; com aspas, não:

$ padrao="*.txt"
$ echo $padrao
frutas.txt                         « sem aspas: o Bash expandiu o * do valor
$ echo "$padrao"
*.txt                              « com aspas: o texto exato

É um dos motivos para escrever "$var" sempre: um valor com * sem aspas pode virar uma lista de arquivos sem você perceber. A aula Aspas e Escapes detalha tudo isso.

Opções que mudam os curingas

O comando shopt (shell options) liga (-s, set) e desliga (-u, unset) comportamentos do Bash. Estas são as que mexem com curingas. Aqui fica só a apresentação; o assunto completo está em Opções do Shell.

Um gostinho do globstar e do extglob:

$ shopt -s globstar
$ echo **/*.html
Documentos/projetos/site/index.html      « achou em qualquer profundidade
$ shopt -s extglob
$ echo Downloads/!(*.iso)
Downloads/foto.jpg Downloads/fotos-viagem.zip Downloads/manual.pdf Downloads/musica.mp3

Para ver como uma opção está agora, rode shopt seguido do nome:

$ shopt nullglob dotglob globstar
nullglob                off
dotglob                 off
globstar                off

Curingas ou chaves?

As chaves ({jpg,png}, {1..5}) se parecem com curingas, mas são outra coisa: elas geram texto, existindo arquivo ou não. Os curingas procuram arquivos que existem.

$ echo foto[1-5].jpg
foto1.jpg foto2.jpg                       « só os que existem
$ echo foto{1..5}.jpg
foto1.jpg foto2.jpg foto3.jpg foto4.jpg foto5.jpg   « gera os 5, existam ou não
Quero…UseExemplo
Qualquer nome com certo começo/fim*ls *.pdf
Nomes com tamanho certo?ls foto?.jpg
Um caractere entre alguns[ ]ls foto[1-3].*
Um caractere de um tipo (algarismo, maiúscula…)[[:classe:]]ls [[:upper:]]*
Criar nomes que ainda não existemchavestouch nota{1..3}.txt
Procurar em todas as subpastas** (globstar) ou findfind . -name '*.jpg'

Missão: na sua pasta pessoal, use echo e um curinga para mostrar só os arquivos ocultos (os que começam com ponto). Depois compare com echo *.

Quando não funciona

"não foi possível acessar '*.xyz'" 
$ ls *.xyz
ls: não foi possível acessar '*.xyz': Arquivo ou diretório inexistente

O que aconteceu: nenhum arquivo casou com o padrão; o Bash passou o texto *.xyz literalmente, e o ls não achou arquivo com esse nome.

Como confirmar: echo *.xyz. Se aparecer o próprio padrão, nada casou.

Como resolver: confira a pasta (pwd), as maiúsculas (*.JPG × *.jpg) e se o padrão não ficou entre aspas.

Apareceu um arquivo chamado *.txt

O que aconteceu: você rodou algo como touch *.txt ou echo oi > *.txt numa pasta sem nenhum .txt. O padrão ficou literal e virou nome.

Como resolver: apague com aspas: rm '*.txt'. Para criar vários arquivos, use chaves: touch nota{1..3}.txt.

"Lista de argumentos muito longa" 
$ rm *.log
bash: /usr/bin/rm: Lista de argumentos muito longa
$ echo $?
126

O que aconteceu: a pasta tinha 40 mil arquivos .log. O Bash expandiu o padrão sem problema, mas a lista ficou grande demais para o sistema entregar a um programa externo (o limite é de alguns megabytes de argumentos). O código 126 quer dizer "o comando não pôde ser executado".

Como resolver: deixe outro programa procurar os arquivos, como o find: find . -name '*.log' -delete. Ou use o printf, que é interno do Bash (não tem esse limite), junto com o xargs, que divide a lista em pedaços:

$ printf '%s\0' *.log | xargs -0 rm
$ echo $?
0
O curinga pegou pastas junto 
$ cp * /tmp
cp: -r não especificado; omitindo o diretório 'Área de trabalho'
cp: -r não especificado; omitindo o diretório 'Documentos'
…                                  « encurtado: uma linha para cada pasta
$ echo $?
1

O que aconteceu: o * casa com qualquer nome, inclusive de pastas. O cp copiou os arquivos e reclamou das pastas.

Como resolver: seja específico (cp *.txt /tmp) ou, se queria as pastas também, use cp -r.

O padrão não pegou arquivos com maiúsculas ou ocultos

O que aconteceu: *.jpg não casa com FOTO.JPG, e * não casa com .config.

Como resolver: liste as variações (*.jpg *.JPG, ou *.[jJ][pP][gG]), use .* para ocultos, ou as opções nocaseglob e dotglob.

Resumo

  • * = qualquer coisa (até nada); ? = um caractere; [ ] = um caractere da lista, faixa ([0-9]), negação ([!x]) ou classe ([[:digit:]]).
  • Quem expande é o Bash, antes de o comando rodar. Veja a lista com echo ou set -x.
  • Se nada casa, o padrão fica literal: o ls reclama e o touch cria um arquivo chamado *.txt.
  • Ocultos ficam de fora (use .*); maiúsculas e minúsculas são diferentes.
  • Aspas e \ desligam o curinga; por isso "$var" é mais seguro.
  • nullglob, failglob, dotglob, globstar e extglob mudam as regras: veja Opções do Shell.
