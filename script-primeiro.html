Bash Seu Primeiro Script

Um script é um arquivo de texto com comandos do Bash, um embaixo do outro. Em vez de digitar os mesmos comandos todo dia, você escreve uma vez, dá um nome ao arquivo e passa a rodá-lo como se fosse um programa novo. Nesta aula você cria o seu primeiro, linha por linha, e aprende a resolver os erros que todo mundo encontra na primeira vez.

Você vai aprender
  • Como criar um arquivo de script no terminal e no editor.
  • O que é a primeira linha #!/usr/bin/env bash (o shebang) e por que ela importa.
  • Como escrever comentários e dar permissão de execução com chmod +x.
  • Por que se roda com ./ola.sh, e como rodar só com ola.sh, de qualquer pasta.
  • O que fazer com "Permissão negada", "comando não encontrado" e "/bin/bash^M: interpretador incorreto".

O que é um script

Pense numa receita de bolo. Você não inventa os passos toda vez: eles estão escritos, em ordem, e qualquer pessoa pode seguir. Um script é a receita; o Bash é quem cozinha. Ele lê o arquivo de cima para baixo e executa cada linha como se você tivesse digitado.

Exemplo do dia a dia: toda manhã a Ana abre o terminal e digita os mesmos três comandos para ver quem ela é, onde está e quantos arquivos tem ali. Três comandos, todo dia. Com um script, vira um comando só.

  sem script                         com script
  ─────────────────────              ─────────────────────
  $ echo "Olá, $USER!"               $ ./ola.sh
  $ echo "Você está em: $PWD"          (o arquivo ola.sh tem
  $ ls | wc -l                          as três linhas dentro)

Para um arquivo virar um script que roda sozinho, são três passos. Esta aula é exatamente esses três passos:

  1. Escrever o arquivo, com a linha #! no topo.
  2. Dar permissão de execução: chmod +x.
  3. Rodar: ./nome-do-arquivo.

Passo 1: escrever o arquivo

Um script é texto puro, então qualquer editor de texto serve. Os mais comuns:

  • nano: editor simples, dentro do terminal. nano ola.sh abre o arquivo; Ctrl+O salva e Ctrl+X sai. Ótimo para começar.
  • vim: poderoso, também no terminal, mas tem uma curva de aprendizado (para sair sem salvar: Esc e :q!).
  • VS Code (ou outro editor gráfico): code ola.sh. Confortável, com cores e verificação de erros.

Nesta aula vamos criar o arquivo direto no terminal, com o cat e um here-doc. Assim você pode repetir exatamente o que está aqui, e vê o conteúdo junto com o comando.

cat
O programa que repete o que recebe. Aqui ele recebe as linhas que você digitar.
> ola.sh
Grava o que o cat repetir no arquivo ola.sh (cria ou substitui). Veja Redirecionamento.
<<'EOF'
"A entrada são as próximas linhas, até aparecer uma linha só com EOF" (end of file, fim do arquivo). As aspas simples em volta de EOF fazem o texto ser gravado exatamente como você digitou, sem trocar $USER pelo valor. Detalhes em Here-docs.
$ cat > ola.sh <<'EOF'
> #!/usr/bin/env bash
> # ola.sh — meu primeiro script
> # Cumprimenta quem rodou e diz onde a pessoa está.
>
> echo "Olá, $USER!"
> echo "Você está em: $PWD"
> echo "Esta pasta tem $(ls | wc -l) itens."   # conta as linhas do ls
> EOF
$

O > no começo das linhas do meio é o prompt de continuação do Bash: ele avisa que o comando ainda não acabou. Você não digita esse sinal. Quando você digita a linha EOF, o comando termina e o prompt normal volta, sem mostrar nada. Silêncio, aqui, é sucesso.

O arquivo ficou assim:

#!/usr/bin/env bash
# ola.sh — meu primeiro script
# Cumprimenta quem rodou e diz onde a pessoa está.

echo "Olá, $USER!"
echo "Você está em: $PWD"
echo "Esta pasta tem $(ls | wc -l) itens."   # conta as linhas do ls

Linha por linha

LinhaO que faz
#!/usr/bin/env bashO shebang: diz ao sistema qual programa deve ler este arquivo. Tem que ser a primeira linha. Explicado logo abaixo.
# ola.sh — meu primeiro scriptComentário: o Bash ignora. Serve para pessoas.
# Cumprimenta quem…Outro comentário, dizendo para que o script serve.
(linha vazia)Ignorada. Use para separar blocos e deixar o script legível.
echo "Olá, $USER!"Mostra uma saudação. $USER é trocado pelo nome do usuário (variáveis).
echo "Você está em: $PWD"$PWD guarda a pasta atual (print working directory).
echo "… $(ls | wc -l) itens."$( ) roda ls | wc -l (conta os itens da pasta) e coloca o resultado no meio do texto. Depois do #, um comentário no fim da linha.
A extensão .sh é opcional

No Linux, quem decide como rodar o arquivo é o shebang, não o nome. O .sh é só um costume que ajuda você (e o editor, que pinta as cores certas) a reconhecer um script. Muitos scripts instalados no sistema não têm extensão nenhuma.

O shebang: #!/usr/bin/env bash

O nome vem de hash (#) + bang (!), "jogo da velha e exclamação". Quando você manda rodar um arquivo, o Linux lê os dois primeiros caracteres. Se forem #!, o resto da linha diz qual programa deve executar o arquivo.

#!
A marca: "a seguir vem o interpretador". Tem que estar no começo da primeira linha, sem espaço antes.
/usr/bin/env
Um programa que procura outro programa no seu PATH (a lista de pastas onde ficam os comandos) e o executa.
bash
O programa que o env vai procurar. Ele vai achar o bash que você também usaria ao digitar bash no terminal.

Na prática, quando você roda ./ola.sh, o sistema transforma isso em /usr/bin/env bash ./ola.sh. O Bash abre o arquivo, pula a primeira linha (para ele, ela é só um comentário, porque começa com #) e executa o resto.

#!/usr/bin/env bash ou #!/bin/bash?

Você vai ver as duas formas. As duas funcionam no Linux. A diferença é onde o Bash é procurado:

#!/usr/bin/env bash#!/bin/bash
Onde procuraNo seu PATH, como no terminal.Exatamente no caminho /bin/bash.
Linux (Ubuntu, Debian, Fedora, Arch)Funciona.Funciona.
macOS com Bash novo (Homebrew)Usa o Bash 5 instalado (/opt/homebrew/bin/bash).Usa o /bin/bash do sistema, que é o 3.2, de 2007.
FreeBSD, NixOS, TermuxFunciona.Falha: lá o Bash não fica em /bin.
Passar opções (-e, -x…)Não dá direto na linha (use set -e dentro do script).Dá: #!/bin/bash -e.

Qual usar? Neste guia usamos #!/usr/bin/env bash, porque ele roda o mesmo Bash que você testou no terminal, em qualquer sistema. Se você só vai rodar o script em servidores Linux, #!/bin/bash também está ótimo. O que não serve é #!/bin/sh num script que usa recursos do Bash: sh pode ser outro shell, mais simples (no Debian e no Ubuntu é o dash). Veja POSIX sh e Bashismos.

E se eu esquecer o shebang?

Rodando de dentro do Bash, o script costuma funcionar mesmo assim: o Bash percebe que não há #! e executa o arquivo com ele mesmo. Mas aí depende de quem chamou. Se for outro programa (o cron, um atalho do sistema, o zsh), o resultado muda. Escreva sempre o shebang: é uma linha só, e tira a dúvida.

Comentários: #

Tudo o que vem depois de um # até o fim da linha é comentário: o Bash ignora. Comentários são para quem vai ler o script depois, inclusive você daqui a seis meses.

Dois detalhes que confundem no começo. O # só começa um comentário quando está no início de uma palavra, e nunca dentro de aspas:

$ echo "# isto não é comentário"
# isto não é comentário         « dentro de aspas, # é um caractere qualquer
$ echo oi#tchau
oi#tchau                        « grudado numa palavra, também
$ echo oi #tchau
oi                              « com espaço antes: daqui para a frente é comentário
O que comentar

No topo: o nome do script, para que serve e como usar. No meio: o porquê das partes que não são óbvias. Não comente o óbvio (# mostra olá em cima de echo "Olá" não ajuda ninguém).

Passo 2: dar permissão de execução

Vamos tentar rodar o script do jeito que acabamos de criar. Primeiro, veja as permissões do arquivo com ls -l:

$ ls -l ola.sh
-rw-rw-r-- 1 ana ana 223 out 15 10:30 ola.sh
$ ./ola.sh
bash: ./ola.sh: Permissão negada
$ echo $?
126                              « 126 = o arquivo existe, mas não pode ser executado

O começo -rw-rw-r-- mostra as permissões: r (read, ler) e w (write, escrever), mas nenhum x (execute, executar). Todo arquivo novo nasce assim, sem permissão de execução, por segurança. Por isso o sistema recusou.

chmod
Muda as permissões (change mode).
+x
Acrescenta (+) a permissão de execução (x).
ola.sh
O arquivo.
$ chmod +x ola.sh
$ ls -l ola.sh
-rwxrwxr-x 1 ana ana 223 out 15 10:30 ola.sh       « apareceram três x

Os três x são para três grupos de pessoas: a dona do arquivo, o grupo dela e os outros. O chmod +x é feito uma vez só: a permissão fica gravada no arquivo, mesmo que você edite o conteúdo depois.

FormaResultadoQuando usar
chmod +x ola.sh-rwxrwxr-xO normal: todos que podem ler, podem executar.
chmod u+x ola.sh-rwxrw-r--Só você (u = user, dona) pode executar.
chmod 755 ola.sh-rwxr-xr-xForma numérica, comum em tutoriais e instaladores.

Passo 3: rodar com ./

./
"Nesta pasta aqui". O ponto é a pasta atual, e a barra separa o nome do arquivo.
ola.sh
O script.
$ ./ola.sh
Olá, ana!
Você está em: /home/ana
Esta pasta tem 10 itens.
$ echo $?
0                                « o script terminou bem

Cada echo do script virou uma linha na tela, na ordem em que estão no arquivo. O $USER virou ana, o $PWD virou a pasta atual e o $(ls | wc -l) virou o número de itens (os 9 da pasta pessoal mais o próprio ola.sh). O código de saída de um script é o do último comando que ele rodou; aqui, o último echo deu certo, então 0. Mais sobre isso em Código de Saída.

Por que não basta digitar ola.sh?

$ ola.sh
bash: ola.sh: comando não encontrado
$ echo $?
127                              « 127 = não achei esse comando

Quando você digita um nome sem barra, o Bash não procura na pasta atual. Ele procura só nas pastas da variável PATH (como /usr/bin, onde moram ls, cat…). É uma proteção: se alguém deixar um arquivo chamado ls numa pasta, ele não roda no lugar do ls de verdade só porque você entrou nela. Com uma barra no nome (./ola.sh, ../ola.sh, /home/ana/ola.sh), você diz o caminho exato e o PATH não é consultado.

O caminho é relativo a onde você está. De dentro de Documentos, o script está uma pasta acima:

$ cd Documentos
$ ./ola.sh
bash: ./ola.sh: Arquivo ou diretório inexistente        « não existe ola.sh aqui dentro
$ ../ola.sh
Olá, ana!
Você está em: /home/ana/Documentos                      « $PWD é a pasta de onde você rodou
Esta pasta tem 5 itens.

Repare: o script mostra a pasta de onde você rodou, não a pasta onde o arquivo está.

Missão: o script backup-rapido.sh já está na pasta da Ana, mas ./backup-rapido.sh dá "Permissão negada". Confira com ls -l backup-rapido.sh, corrija a permissão e rode o script até aparecer Backup pronto.

Onde guardar seus scripts

Ter que escrever ./ ou o caminho todo cansa. Para rodar seu script só pelo nome, de qualquer pasta, como um comando de verdade, coloque-o numa pasta que esteja no PATH. As pastas pessoais tradicionais para isso são:

  • ~/.local/bin: o padrão moderno (é onde o pip e outros instaladores colocam programas do usuário).
  • ~/bin: o jeito antigo, mais fácil de ver (não é oculta).

No Ubuntu e no Debian, o arquivo ~/.profile já acrescenta essas pastas ao PATH, se elas existirem quando você entra no sistema. Veja o que acontece:

$ echo "$PATH"
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
$ mkdir -p ~/.local/bin
$ mv ola.sh ~/.local/bin/
$ ola.sh
bash: ola.sh: comando não encontrado          « a pasta foi criada depois do login
$ source ~/.profile                           « relê o .profile (ou feche e abra o terminal)
$ echo "$PATH"
/home/ana/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
$ type ola.sh
ola.sh é /home/ana/.local/bin/ola.sh
$ cd Imagens
$ ola.sh
Olá, ana!
Você está em: /home/ana/Imagens
Esta pasta tem 2 itens.

Linha por linha: o PATH não tinha a pasta; o mkdir -p criou ~/.local/bin (o -p cria as pastas do meio e não reclama se já existir); o mv moveu o script para lá; a primeira tentativa falhou porque o .profile só olha as pastas quando você entra no sistema; depois de reler o .profile, a pasta apareceu no começo do PATH, o type mostra onde o Bash achou o comando, e ola.sh funciona de qualquer lugar.

Sistema~/.local/bin e ~/bin no PATH?
Ubuntu, DebianSim, pelo ~/.profile, se a pasta existir no login.
FedoraSim, pelo ~/.bashrc padrão.
Arch, macOS e outrosNão. Acrescente no ~/.bashrc: export PATH="$HOME/.local/bin:$PATH"

Como o PATH funciona por dentro, e como escolher um nome que não esconda um comando do sistema, está em PATH e Onde os Comandos Moram.

Quando não funciona

"Permissão negada" 
$ ./ola.sh
bash: ./ola.sh: Permissão negada
$ echo $?
126

O que aconteceu: o arquivo não tem permissão de execução.

Como confirmar: ls -l ola.sh mostra -rw-rw-r--, sem nenhum x.

Como resolver: chmod +x ola.sh. Se o arquivo está num pendrive ou partição do Windows (que não guardam permissões), rode com bash ola.sh (veja Formas de Executar).

"comando não encontrado" 
$ ola.sh
bash: ola.sh: comando não encontrado
$ echo $?
127

O que aconteceu: sem barra no nome, o Bash procurou só nas pastas do PATH, e o script está na pasta atual.

Como resolver: rode com ./ola.sh, ou mova o script para ~/.local/bin (seção acima).

"Arquivo ou diretório inexistente" com ./ 
$ ./ola.sh
bash: ./ola.sh: Arquivo ou diretório inexistente

O que aconteceu: você está em outra pasta, ou o nome está diferente (maiúsculas contam: Ola.sh não é ola.sh).

Como confirmar: pwd e ls. Como resolver: vá para a pasta do script com cd ou use o caminho certo (../ola.sh, ~/ola.sh).

"/bin/bash^M: interpretador incorreto" 
$ ./bomdia.sh
bash: ./bomdia.sh: /bin/bash^M: interpretador incorreto: Arquivo ou diretório inexistente
$ echo $?
126

Com #!/usr/bin/env bash, o mesmo problema aparece assim:

$ ./bomdia2.sh
env: ‘bash\r’: Arquivo ou diretório inexistente
env: usa -[v]S para passar opções em linhas shebang

O que aconteceu: o arquivo foi salvo com o fim de linha do Windows. No Windows, cada linha termina com dois caracteres invisíveis, \r\n; no Linux, só com \n. O \r sobrando vira parte do nome: o sistema procura um programa chamado bash + \r, que não existe. O ^M e o \r são duas formas de mostrar esse caractere. Acontece com arquivos criados no Bloco de Notas, baixados de e-mail ou copiados de um editor configurado para Windows.

Como confirmar: o cat -A mostra os invisíveis: $ é o fim de linha e ^M é o \r. O file também avisa:

$ cat -A bomdia.sh
#!/bin/bash^M$
echo "Bom dia"^M$                « ^M antes de cada fim de linha
$ file bomdia.sh
bomdia.sh: Bourne-Again shell script, ASCII text executable, with CRLF line terminators

Como resolver: apague o \r do fim de cada linha com o sed (ou com dos2unix bomdia.sh, se estiver instalado). No VS Code, clique em "CRLF" na barra de baixo e troque para "LF".

$ sed -i 's/\r$//' bomdia.sh
$ cat -A bomdia.sh
#!/bin/bash$
echo "Bom dia"$
$ ./bomdia.sh
Bom dia

No sed: -i altera o próprio arquivo; s/\r$// troca (s) um \r no fim da linha ($) por nada.

"interpretador incorreto" com o shebang digitado errado 
$ ./digitado.sh
bash: ./digitado.sh: /bin/bahs: interpretador incorreto: Arquivo ou diretório inexistente
$ head -n 1 digitado.sh
#!/bin/bahs                       « "bahs" em vez de "bash"

O que aconteceu: o programa que o shebang aponta não existe. A mensagem cita o caminho exato que foi procurado; compare letra por letra. Com env, o erro seria env: ‘bahs’: Arquivo ou diretório inexistente.

Como resolver: corrija a primeira linha para #!/usr/bin/env bash. Ela precisa ser a linha 1, começar com #! sem espaço antes e não pode vir depois de uma linha em branco.

Digitei cat > ola.sh e o terminal "travou"

O que aconteceu: sem o <<'EOF', o cat fica esperando você digitar o conteúdo, sem mostrar prompt. Não travou: está gravando cada linha que você digita.

Como resolver: digite as linhas do script e, numa linha vazia, aperte Ctrl+D (fim da entrada). O arquivo é gravado com o que você digitou. Se quiser desistir, Ctrl+C.

Rodei e não apareceu nada

O que aconteceu: o script só tem comandos que não mostram nada (atribuir variáveis, cd, mkdir…), ou o arquivo está vazio.

Como confirmar: cat ola.sh mostra o conteúdo; echo $? logo depois de rodar diz se terminou bem (0). Para ver cada linha sendo executada, rode com bash -x ola.sh (veja Depurar).

Resumo

  • Um script é um arquivo de texto com comandos; o Bash executa de cima para baixo.
  • A primeira linha é o shebang: #!/usr/bin/env bash. O resto depois de # são comentários.
  • chmod +x arquivo uma vez; depois ./arquivo. Sem o x: "Permissão negada" (126). Sem o ./: "comando não encontrado" (127).
  • Para rodar pelo nome, de qualquer pasta, guarde em ~/.local/bin (ou ~/bin).
  • ^M no erro = fim de linha do Windows: confira com cat -A e corrija com sed -i 's/\r$//'.
