Bash Ver Arquivos

Grande parte do trabalho no terminal é olhar arquivos: ler uma anotação, conferir as últimas linhas de um log, contar quantos alunos há numa planilha. Nesta aula você conhece os comandos que fazem isso: cat, less, head, tail, wc e file. Nenhum deles muda o arquivo: eles só leem.

Você vai aprender
  • Mostrar um arquivo inteiro com cat, com números de linha (-n) e com os caracteres invisíveis à mostra (-A).
  • Ler arquivos grandes, página por página, com less.
  • Ver só o começo ou só o fim com head e tail, incluindo -n +2 (pular o cabeçalho) e -f (acompanhar um log).
  • Contar linhas, palavras e caracteres com wc e descobrir o tipo de um arquivo com file.
  • O que é o "uso inútil do cat" e o que fazer quando o comando "trava".

Os exemplos acontecem na pasta pessoal da Ana (/home/ana), na máquina fictícia notebook. Os arquivos que aparecem aqui (frutas.txt, Documentos/notas.txt, Documentos/alunos.csv, Documentos/acesso.log) já existem no simulador, então você pode repetir tudo.

Antes da sintaxe: que perguntas você faz a um arquivo?

Pense numa planilha impressa. Às vezes você quer ler tudo. Às vezes ela tem 300 páginas e você quer folhear. Às vezes só quer o título (o começo) ou o último registro (o fim). Às vezes só quer saber quantas linhas ela tem. Cada pergunta tem um comando:

PerguntaComandoNome vem de…
"Mostre tudo."catconcatenate, "encadear" (juntar arquivos)
"Deixe eu folhear com calma."lessBrincadeira com o antigo more ("mais"): less is more
"Só o começo."head"cabeça"
"Só o fim."tail"cauda"
"Quantas linhas / palavras?"wcword count, "contagem de palavras"
"Que tipo de arquivo é este?"file"arquivo"

Nenhum desses é um comando do Bash. São programas separados (do pacote GNU coreutils, quase sempre). O papel do Bash é ler a linha que você digitou, separar as palavras, expandir coisas como *.txt e entregar a lista de nomes ao programa. Isso vai fazer diferença várias vezes nesta aula.

cat: mostrar o arquivo inteiro

cat
O programa. Lê os arquivos que recebeu e escreve o conteúdo na tela, do começo ao fim.
frutas.txt
O argumento: o arquivo a mostrar. O caminho é relativo à pasta atual (aqui, ~).
$ cat frutas.txt
banana
maçã
laranja
banana
uva
maçã
banana
$ echo $?
0                     « 0 = deu certo

O cat não enfeita nada: o que está no arquivo aparece igual na tela, linha por linha. Cada linha do arquivo é uma linha da saída. Depois, echo $? mostra o código de saída do último comando: 0 quer dizer sucesso (veja Código de Saída).

Um arquivo dentro de outra pasta é só um caminho mais longo:

$ cat Documentos/notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos

Numerar as linhas: -n

A opção -n (de number) coloca o número de cada linha na frente. Ótimo quando alguém diz "o erro está na linha 3".

cat
O programa.
-n
Numera todas as linhas da saída. A forma longa é --number.
frutas.txt
O arquivo.
$ cat -n frutas.txt
     1  banana
     2  maçã
     3  laranja
     4  banana
     5  uva
     6  maçã
     7  banana

O número vem alinhado à direita, seguido de uma tabulação. O arquivo não mudou: os números só existem na tela. O comando nl (number lines) faz quase o mesmo, mas por padrão pula as linhas em branco.

Vários arquivos: é para isso que o cat existe

"Concatenar" é juntar uma coisa depois da outra. Dê dois nomes ao cat e ele mostra um arquivo logo depois do outro, sem separação nenhuma:

$ cat frutas.txt Documentos/notas.txt
banana
maçã
laranja
banana
uva
maçã
banana
Comprar café              « daqui para baixo é o notas.txt
Ligar para o João
Estudar Bash
Fazer backup das fotos

Juntando com o >, você grava a junção num arquivo novo: cat parte1.txt parte2.txt > inteiro.txt. O > é assunto de Redirecionamento.

E se um dos arquivos não existir? O cat reclama daquele, mostra os outros e, no fim, devolve 1:

$ cat frutas.txt nada.txt
banana
maçã
laranja
banana
uva
maçã
banana
cat: nada.txt: Arquivo ou diretório inexistente
$ echo $?
1                     « basta um arquivo falhar para o código não ser 0

Quem expande o * é o Bash

Você pode usar curingas com o cat. Mas repare: o cat nunca vê o *. O Bash troca *.txt pela lista de arquivos que terminam em .txt e só então chama o cat com essa lista. Com set -x o Bash mostra o comando já expandido, numa linha que começa com +:

$ set -x
$ cat *.txt
+ cat notas.txt            « o Bash já trocou *.txt por notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ set +x
+ set +x

Os curingas têm uma aula só para eles: Curingas.

Ver o invisível: -A

Um arquivo de texto tem caracteres que você não vê: a quebra de linha, a tabulação, o "retorno de carro" dos arquivos vindos do Windows. A opção -A (de show all, "mostre tudo") troca cada um por um símbolo visível:

Símbolo no cat -AO que é
$ no fim da linhaA quebra de linha (o "Enter" gravado no arquivo).
^IUma tabulação (tecla Tab).
^M antes do $O retorno de carro (\r) dos arquivos do Windows, que terminam as linhas com \r\n.
M-CM-) e parecidosBytes acima de 127: as letras acentuadas em UTF-8 ocupam dois bytes, e o -A mostra cada byte em código.

Veja um arquivo que parece normal, mas veio de uma planilha do Windows:

$ printf 'nome\tidade\r\nAna\t29\r\n' > planilha.txt
$ cat planilha.txt
nome    idade
Ana     29                « parece perfeito…
$ cat -A planilha.txt
nome^Iidade^M$
Ana^I29^M$                « …mas tem Tab (^I) e o \r do Windows (^M)

O printf da primeira linha só serve para criar o arquivo de exemplo: \t vira uma tabulação e \r\n é o fim de linha do Windows. Esse ^M escondido é a causa de muitos erros estranhos em scripts copiados do Windows (como $'\r': comando não encontrado).

Com acentos, o -A fica esquisito, mas é só a forma de mostrar os bytes:

$ cat -A Documentos/notas.txt
Comprar cafM-CM-)$        « "é" ocupa dois bytes em UTF-8
Ligar para o JoM-CM-#o$
Estudar Bash$
Fazer backup das fotos$

Outro uso do -A: descobrir se a última linha tem quebra de linha. Repare que o b abaixo não tem $:

$ printf 'a\nb' > semfim.txt
$ cat -A semfim.txt
a$
bana@notebook:~$          « o "b" não tem "$", e o prompt grudou nele

O printf 'a\nb' grava "a", uma quebra de linha e "b", sem quebra no fim. Como o arquivo termina logo depois do b, o cursor fica na mesma linha e o próximo prompt do Bash aparece grudado: b + ana@notebook:~$.

Isso importa, porque o wc -l conta quebras de linha. Para ele, esse arquivo de duas linhas tem uma só (você vai ver o wc daqui a pouco).

Não use cat em arquivos que não são texto

Uma foto, um PDF ou um programa são bytes que não foram feitos para a tela. Se você der cat num deles, aparecem símbolos estranhos, o terminal pode apitar e, às vezes, fica com as letras trocadas. Para consertar, digite reset e aperte Enter (mesmo sem ver o que digita). Para saber se um arquivo é texto antes de abrir, use file (mais abaixo).

less: folhear arquivos grandes

O cat despeja tudo de uma vez. Num arquivo de 5 mil linhas, o começo some lá em cima antes de você ler. O less abre o arquivo numa tela própria, mostra uma página e espera você mandar.

less
O "paginador": mostra uma tela por vez e deixa você andar para frente, para trás e buscar.
Documentos/acesso.log
O arquivo a abrir.

Depois de less Documentos/acesso.log, a tela fica mais ou menos assim (ilustração, encurtada):

192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200
~
~
(END)                      ← o less está esperando uma tecla

Os ~ marcam linhas vazias depois do fim do arquivo. Na última linha, o less mostra : (quando há mais para ler) ou (END) (quando chegou ao fim). Você não volta ao prompt até apertar q.

TeclaO que faz
Espaço ou PgDnAvança uma página.
b ou PgUpVolta uma página (back).
↓ / ↑ (ou j / k)Uma linha para baixo / para cima.
g / GVai para o começo / para o fim do arquivo.
/texto EnterBusca "texto" para a frente. Os achados ficam destacados.
?texto EnterBusca para trás.
n / NPróximo / anterior resultado da busca (next).
hAjuda com todas as teclas (q sai da ajuda).
qSai do less e volta ao prompt (quit).

Duas opções úteis: less -N arquivo numera as linhas (como o cat -n) e less +G arquivo já abre no fim. As mesmas teclas valem para o man, que usa o less por baixo (veja Obtendo Ajuda).

No simulador

O terminal simulado deste guia não tem tela interativa: lá, less mostra o arquivo inteiro de uma vez, como o cat. Pratique as teclas no seu terminal de verdade, por exemplo com less /etc/services, que é bem comprido.

head e tail: só o começo ou só o fim

head: as primeiras linhas

head
Mostra o começo do arquivo. Sem opção, as 10 primeiras linhas.
-n 3
Quantas linhas (number). O número vem logo depois do -n.
frutas.txt
O arquivo.
$ head -n 3 frutas.txt
banana
maçã
laranja

Pedir mais linhas do que o arquivo tem não é erro: o head mostra o que existe e devolve 0.

$ head -n 20 frutas.txt
banana
maçã
laranja
banana
uva
maçã
banana                « o arquivo só tem 7 linhas
$ echo $?
0

Você também vai ver a forma curta head -3, sem o n. Ela funciona, mas é antiga; prefira -n 3, que é a forma padrão e mais fácil de ler.

tail: as últimas linhas

O tail é o espelho do head. Ele é o preferido para logs, onde o que interessa é o que aconteceu por último:

$ tail -n 3 Documentos/acesso.log
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200

Pular o cabeçalho: tail -n +2

Com um + na frente do número, o significado muda: tail -n +2 quer dizer "comece na linha 2 e vá até o fim". É o jeito clássico de tirar o cabeçalho de um CSV:

tail
O programa.
-n +2
"A partir da linha 2". Sem o +, seria "as 2 últimas".
Documentos/alunos.csv
A planilha, cuja linha 1 é nome,idade,cidade,nota.
$ head -n 1 Documentos/alunos.csv
nome,idade,cidade,nota          « o cabeçalho
$ tail -n +2 Documentos/alunos.csv
Ana,29,Recife,9.5               « só os dados, sem o cabeçalho
Bruno,34,Curitiba,7.0
Carla,22,Salvador,8.5
Diego,41,Manaus,6.0
Elisa,27,Porto Alegre,10.0

O head tem o contrário: head -n -2 (com menos) mostra tudo menos as 2 últimas linhas.

$ head -n -2 frutas.txt
banana
maçã
laranja
banana
uva                   « faltam "maçã" e "banana", as duas últimas

Vários arquivos de uma vez

Com mais de um arquivo, head e tail põem um título ==> nome <== antes de cada um. Aqui o Bash expandiu *.csv *.txt antes de o head rodar:

$ head -n 1 *.csv *.txt
==> alunos.csv <==
nome,idade,cidade,nota

==> notas.txt <==
Comprar café

Uma linha no meio: juntando head e tail

Para ver só a linha 3, pegue as 3 primeiras e, delas, a última. A barra | (o pipe) liga a saída do primeiro comando à entrada do segundo; ele tem uma aula própria em Pipes.

$ head -n 3 Documentos/alunos.csv | tail -n 1
Bruno,34,Curitiba,7.0           « linha 3 = segundo aluno (a 1 é o cabeçalho)

O sed faz o mesmo de forma mais direta: sed -n 3p Documentos/alunos.csv ("imprima só a linha 3"). Ele aparece em grep, sed, awk e cia.

Acompanhar um arquivo que cresce: tail -f

Um servidor escreve no log o tempo todo. Com -f (de follow, "seguir"), o tail mostra as últimas linhas e fica esperando: cada linha nova que entrar no arquivo aparece na sua tela na hora.

tail
O programa.
-n 2
Comece mostrando as 2 últimas linhas.
-f
Não termine: continue lendo o que for acrescentado.
servidor.log
O arquivo a acompanhar.
$ tail -n 2 -f servidor.log
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200
192.168.0.99 - - [15/Oct/2026:10:30:05] "GET /novo HTTP/1.1" 200   « chegou agora
^C                                                                 « Ctrl+C para parar

A terceira linha não estava no arquivo quando o comando começou: outro programa a escreveu enquanto o tail esperava. O cursor fica parado e o prompt não volta. Isso é normal. Para sair, aperte Ctrl+C. (No laboratório, a linha nova foi escrita por um comando em segundo plano; o ^C é o que você vê ao apertar Ctrl+C no terminal.)

tail -f no simulador

No simulador nada escreve no arquivo enquanto você olha, então lá o tail -f só faz sentido no seu terminal de verdade, por exemplo com um log do sistema.

Missão: mostre só as 2 últimas linhas do arquivo Documentos/acesso.log. Depois, experimente head -n 1 no mesmo arquivo para ver a primeira.

wc: contar linhas, palavras e caracteres

wc
Conta. Sem opção, mostra três números: linhas, palavras e bytes.
frutas.txt
O arquivo a contar.
$ wc frutas.txt
 7  7 47 frutas.txt
NúmeroSignifica
7Linhas (na verdade, quantas quebras de linha).
7Palavras: pedaços separados por espaço, Tab ou quebra de linha. Cada fruta é uma palavra.
47Bytes, o tamanho do arquivo.

Na prática, você quase sempre pede um número só:

$ wc -l frutas.txt
7 frutas.txt                    « -l = linhas (lines)
$ wc -w Documentos/notas.txt
12 Documentos/notas.txt         « -w = palavras (words)
$ wc -c frutas.txt
47 frutas.txt                   « -c = bytes
$ wc -m frutas.txt
43 frutas.txt                   « -m = caracteres

Por que 47 bytes e 43 caracteres? Porque ç e ã ocupam dois bytes cada em UTF-8, e maçã aparece duas vezes: 4 letras acentuadas, 4 bytes "a mais". Para texto em português, se você quer contar letras, use -m.

Vários arquivos e o total

$ wc -l frutas.txt Documentos/notas.txt Documentos/alunos.csv
  7 frutas.txt
  4 Documentos/notas.txt
  6 Documentos/alunos.csv
 17 total                       « a soma, de brinde

Com um curinga, o Bash monta a lista. Mas cuidado: o * sozinho também pega pastas, e o wc não sabe contar uma pasta:

$ wc -l *
      6 acesso.log
      6 alunos.csv
      4 notas.txt
      0 projetos
wc: projetos: É um diretório      « o Bash entregou a pasta junto
      0 relatorio.odt
     16 total
$ echo $?
1

Repare também no 0 relatorio.odt: um arquivo do LibreOffice não é texto, então "linhas" não fazem sentido para ele. Seja específico: wc -l *.txt *.csv *.log.

Só o número, sem o nome

Quando o arquivo chega pelo <, o wc recebe só o conteúdo e não sabe o nome. Então mostra só o número, perfeito para usar num script:

$ wc -l < frutas.txt
7

Lembra do arquivo sem quebra de linha no fim? O wc -l diz que ele tem 1 linha, embora você veja duas:

$ wc -l semfim.txt
1 semfim.txt                    « conta quebras de linha; a última linha não tem

Missão: quantos alunos existem em Documentos/alunos.csv? O arquivo tem uma linha de cabeçalho que não é aluno. Faça o terminal mostrar só o número 5, usando tail -n +2, | e wc -l.

file: que tipo de arquivo é este?

No Linux, a extensão (.txt, .jpg) é só parte do nome. Ela não manda em nada. O file abre o arquivo, olha os primeiros bytes e diz o que ele realmente é.

file
Examina o conteúdo e descreve o tipo.
frutas.txt Documentos …
Um ou mais arquivos (ou pastas).
$ file frutas.txt Documentos Documentos/projetos/backup.sh planilha.txt
frutas.txt:                    Unicode text, UTF-8 text
Documentos:                    directory
Documentos/projetos/backup.sh: Bourne-Again shell script, ASCII text executable
planilha.txt:                  ASCII text, with CRLF line terminators
RespostaEm português
Unicode text, UTF-8 textTexto com acentos, codificado em UTF-8. Pode usar cat.
directoryÉ uma pasta.
Bourne-Again shell scriptUm script do Bash (Bourne-Again shell é o nome completo do Bash), descoberto pela linha #!.
with CRLF line terminatorsLinhas terminadas no estilo Windows (\r\n), o mesmo ^M do cat -A.

A prova de que a extensão não importa: copie o frutas.txt com nome de foto.

$ cp frutas.txt foto.jpg
$ file foto.jpg
foto.jpg: Unicode text, UTF-8 text      « o nome diz .jpg, o conteúdo é texto

O file responde em inglês mesmo com o sistema em português. E tem uma pegadinha: se o arquivo não existe, ele avisa na própria saída, mas devolve 0:

$ file nada
nada: cannot open `nada' (No such file or directory)
$ echo $?
0                     « o file "conseguiu" responder, então diz sucesso

O "uso inútil do cat"

Quem começa costuma escrever cat arquivo | outro-comando, como se todo comando precisasse do cat para ler um arquivo. Funciona, mas o cat está sobrando: o grep, o wc, o head, o sort e quase todos os outros recebem o nome do arquivo direto.

$ cat frutas.txt | grep banana       « funciona, mas são dois programas
banana
banana
banana
$ grep banana frutas.txt              « mesmo resultado, um programa só
banana
banana
banana

Esse hábito ficou conhecido, com bom humor, como useless use of cat, "uso inútil do cat". Não é um erro grave, mas cria um processo a mais, e em alguns casos você perde informação: wc -l frutas.txt mostra o nome do arquivo, e head com vários arquivos mostra os títulos ==>, coisas que somem quando tudo chega por um |.

Em vez de…Escreva
cat frutas.txt | grep uvagrep uva frutas.txt
cat frutas.txt | wc -lwc -l frutas.txt (ou wc -l < frutas.txt para só o número)
cat acesso.log | tail -n 5tail -n 5 acesso.log
cat frutas.txt | sortsort frutas.txt

O cat continua sendo a escolha certa para o que ele faz de melhor: mostrar um arquivo curto, juntar vários e revelar invisíveis com -A.

Quando não funciona

"Arquivo ou diretório inexistente" 
$ cat nada.txt
cat: nada.txt: Arquivo ou diretório inexistente
$ echo $?
1

O que aconteceu: não há arquivo com esse nome na pasta atual. Ou o nome está errado (maiúsculas contam: Notas.txt ≠ notas.txt), ou o arquivo está em outra pasta.

Como confirmar: pwd mostra onde você está; ls mostra o que há ali.

Como resolver: use o caminho certo (cat Documentos/notas.txt) e deixe o Tab completar o nome para você (veja Completar com Tab).

Nome com espaço virou três arquivos 
$ cat lista de compras.txt
cat: lista: Arquivo ou diretório inexistente
cat: de: Arquivo ou diretório inexistente
cat: compras.txt: Arquivo ou diretório inexistente

O que aconteceu: o arquivo se chama lista de compras.txt, mas o Bash separa as palavras nos espaços. O cat recebeu três argumentos: lista, de e compras.txt.

Como resolver: diga ao Bash que é um nome só, com aspas ou barra invertida:

$ cat "lista de compras.txt"
pão
leite
$ cat lista\ de\ compras.txt
pão
leite

As aspas são o assunto de Aspas e Escapes.

"É um diretório" 
$ cat Documentos
cat: Documentos: É um diretório
$ tail -n 5 Documentos
tail: erro ao ler 'Documentos': É um diretório

O que aconteceu: cat, head e tail leem arquivos. Para ver o que há dentro de uma pasta, o comando é outro.

Como resolver: ls Documentos (veja Listar) e depois cat Documentos/notas.txt.

Não apareceu nada e o prompt não volta 
$ cat
█                     « o cursor fica parado esperando

O que aconteceu: sem nenhum arquivo, o cat lê do teclado. Ele está esperando você digitar; cada linha que você digitar ele repete. O mesmo acontece com head, wc, sort… sem arquivo, e com o tail -f, que espera de propósito.

Como resolver: aperte Ctrl+D (avisa "acabou a entrada") ou Ctrl+C (interrompe). Depois, rode de novo com o nome do arquivo. Se foi uma aspa que ficou aberta e o prompt virou >, também é Ctrl+C (veja Aspas).

"número inválido de linhas" 
$ head -n abc frutas.txt
head: número inválido de linhas: ‘abc’
$ echo $?
1

O que aconteceu: o que vem depois de -n tem que ser um número. Isso acontece muito quando o número vem de uma variável vazia ou errada, num script.

Como resolver: confira o valor: head -n 5 frutas.txt. Num script, mostre a variável com echo "$n" antes.

O terminal ficou cheio de símbolos estranhos

O que aconteceu: você deu cat (ou head) num arquivo que não é texto, como uma foto ou um .zip. Alguns bytes são comandos para o terminal e mudam cores ou letras.

Como resolver: digite reset e Enter, mesmo que as letras apareçam erradas. Da próxima vez, confira antes com file arquivo.

Script dá $'\r': comando não encontrado

O que aconteceu: o arquivo foi salvo no Windows e cada linha termina com \r\n. O Bash enxerga o \r como parte do comando.

Como confirmar: cat -A script.sh mostra ^M$ no fim das linhas; file script.sh diz with CRLF line terminators.

Como resolver: remova os \r: sed -i 's/\r$//' script.sh (ou o programa dos2unix, se instalado).

Resumo

  • cat mostra (e junta) arquivos; -n numera e -A revela Tab, \r e fim de linha.
  • less folheia arquivos grandes: Espaço avança, / busca, q sai.
  • head -n N e tail -n N mostram o começo e o fim; tail -n +2 pula o cabeçalho; tail -f acompanha um log.
  • wc -l conta linhas (quebras de linha); -m conta caracteres; wc -l < arq dá só o número.
  • file diz o tipo pelo conteúdo, não pela extensão.
  • Nomes com espaço precisam de aspas, quem expande * é o Bash, e um comando "parado" sem arquivo está lendo o teclado: Ctrl+D ou Ctrl+C.
